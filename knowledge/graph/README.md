# AMFE — проект графа знаний
Дата: 2026-11-10 · Статус: схема, не реализованная графовая БД.

## Математическая основа
Ориентированный типизированный граф свойств G=(V,E), с атрибутами узлов и рёбер. Позднее при необходимости: временной граф, мультиграф, гиперграф для отношений с более чем двумя участниками.

## Классы узлов
LIT (публикация/источник), CLAIM (утверждение), IDEA (идея), HYP (проверяемая гипотеза), METH (метод), EXP (эксперимент), RESULT (результат), DEC (решение), Q (вопрос), VAR (экономическая переменная), COUNTRY, SECTOR, ENTITY, EDGE (экономическая связь), MODEL, DATASET, EVENT, PERSON, INSTITUTION.

## Типы рёбер
CITES (цитирует), SUPPORTS (поддерживает), CONTRADICTS (противоречит), DERIVED_FROM (происходит из), PROPOSES (предлагает), TESTS (проверяет), USES_METHOD (использует метод), USES_DATASET (использует данные), EXPLAINS (объясняет), DEPENDS_ON (зависит от), AFFECTS (воздействует на), REPLACES (заменяет), RELATES_TO (связано с).

Каждое ребро хранит source_id, target_id, type, provenance, created_at, valid_from/valid_to при необходимости, confidence и evidence_id. Типы связей и их семантика документируются; «связано с» не заменяет доказательного отношения.

## Пример маршрута
LIT-001 → SUPPORTS → HYP-001 → TESTED_BY → EXP-001 → PRODUCES → RESULT-001 → INFORMS → DEC-001.
Этот пример **иллюстративный**, не утверждение, что LIT-001 действительно поддерживает HYP-001.

## Запросы
- Какие гипотезы поддерживают/опровергают статьи о влиянии логистики на инфляцию?
- Какие методы применялись к похожим гипотезам и что показали эксперименты?
- Какие предпосылки связывают курсы валют, ставки ЦБ и межстрановые производственные сети?
- Какие идеи были отложены, но стали актуальны после новых публикаций?

## Поиск и производительность
Использовать сочетание графового обхода, полнотекстового поиска и векторного семантического поиска. Граф улучшает структурированную навигацию, но не гарантирует ускорения всех запросов. Нужны индексы, дедупликация, контроль качества сущностей, измерение precision/recall, latency и cost.

## Этапы реализации
1. Согласовать онтологию и стабильные ID.
2. Ввести машинно-читаемые карточки JSON/YAML или таблицы и валидатор ссылочной целостности.
3. Построить минимальный граф из существующих LIT/IDEA/METH/EXP и проверить запросы.
4. Сравнить PostgreSQL (таблицы связей), графовую БД и гибрид; выбрать по измерениям.
5. Добавить provenance, темпоральность, поиск и визуализацию.
