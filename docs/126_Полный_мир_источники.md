## 2. WIOD 2016: что скачано и что распарсено

- Архив: `data/mrio/wiod_2016/archive/WIOTS_in_STATA.zip`, **638 963 496 байт**,
  SHA-256 `00563a9e996887454643513b8d68f2a50c1ddf4fa9c219c47dcf5ef54e006fc1`,
  MD5 `cde6085d4233fec2356877aedf21d950de912b78` (совпал с Dataverse-метаданным).
- Внутри — **15 файлов** `WIOT2000_October16_ROW.dta` … `WIOT2014_October16_ROW.dta`
  (по ~55,2 МБ каждый), разбивка по годам; DOI набора `10.34894/PJ2M1C`.
- Проверенная структура (на 2014): 2 472 строки × 2 690 колонок; 44 страны (включая RoW) ×
  **56 отраслей**; на страну 61 value-колонка (`v<ISO3>1..56` — отрасли, `v<ISO3>57..61` —
  категории конечного спроса); колонка `TOT` — выпуск; нижний блок `TOT`: `II_fob`, `TXSP`,
  `EXP_adj`, `PURR`, `PURNR`, `VA`, `IntTTM`, `GO`.
- Проверено численно: **строчный баланс `x = Z·1 + y` выполняется точно** (max |residual| =
  1,4·10⁻⁹ на 2014), `TOT` (строка) и `GO` (колонка) совпадают точно; колоночный баланс
  `1'Z + VA + TXSP + IntTTM = GO` выполняется с max |residual| = **64,49 USD млн**
  (max относительный 0,139 на малых/нулевых отраслях; глобально 4·10⁻⁷ от мирового выпуска
  `160 997 198` USD млн). Это не ошибка парсера: строки-корректировки WIOD (`TXSP`, `IntTTM`,
  `EXP_adj`, `PURR/PURNR`) не сводятся к одной строке поблочно.
- Конвертер (`--convert wiod_2016 --years 2014`) обрабатывает год за **6,7 с**, поддерживает
  несколько лет и `--jobs N` (процесс на год).

**Почему конвертация заблокирована.** Замороженная схема `amfe.mrio.dataset.v1` требует
`y >= 0` и `va >= -1e-6`. В WIOD 2014 при 44×56:
- **50 ячеек** конечного спроса отрицательны (изменения запасов), минимум **−9 189,24 USD млн**;
- **2 ячейки** добавленной стоимости отрицательны, минимум **−22,17 USD млн**;
- максимум колоночного остатка **64,49 USD млн**.

Схема отвергает такой документ до записи (`SchemaError: y[6] is negative`). Fail-closed:
невалидный датасет **не записан**, вместо него — отчёт с точными числами выше. Чтобы WIOD
конвертировался, нужна правка **схемы v1.1** (не в этом треке): (а) отдельный вектор
`inventory_changes` (или `final_demand_adjustments`), вычитаемый из `y` и из `x` строки, с
проверкой сбалансированности; (б) минимальный допуск на отрицательные ячейки/`va`; (в) явный
допуск на строки-корректировки WIOD в валидаторе колоночного баланса. Альтернатива — принять
«балансирующую» добавленную стоимость как остаток `x − 1'Z` (изменение ≤64 USD млн) и обнулять
отрицательный конечный спрос с переносом в метаданные; это **меняет опубликованные значения** и
требует отдельного решения владельца, поэтому в этом треке не применялось.

## 3. Что заблокировано и точные шаги для пользователя

**OECD ICIO (60+ стран, 1995-2022, 45 отраслей) — рекомендуемый основной источник полного мира.**
Автоматическая загрузка невозможна (403/406/404 выше). Нужен браузерный шаг пользователя:
1. Открыть `https://www.oecd.org/en/data/datasets/inter-country-input-output-tables.html`
   (или `https://data-explorer.oecd.org/` → ICIO) в браузере.
2. Прочитать/принять OECD Terms and Conditions; при необходимости сохранить текст условий.
3. Скачать релиз 2025 (ICIO 1995-2022, блоки 1995-2000/2001-2005/2006-2010/2011-2015/2016-2022)
   — архив ReadMe + csv/Rdata.
4. Положить файлы в `data/mrio/oecd_icio/archive/` и сообщить Lead: парсер ICIO (long-format
   csv по блокам) нужно дописать; текущий конвертер реализует только WIOD-раскладку.

**Eora (190 стран, 1990-2022).** Нужна регистрация с академической почтой:
1. `https://www.worldmrio.com/` → регистрация, принятие академической лицензии.
2. Скачать country/aggregate MRIO-архив (Eora26/Eora-full); коммерческое использование — покупка.
3. Положить в `data/mrio/eora_mrio/archive/`; парсер Eora (текстовый формат) в этой волне не
   реализован.

**Comtrade** — не MRIO; для торгового слоя нужен актуальный preview-эндпоинт/ключ (сейчас 404).

   текущий статус локальных данных — `BLOCKED_DATA` (это честный fail-closed, не потеря данных).

## 5. Воспроизведение

```powershell
# прямой URL + размер/статус (браузерный UA, HEAD/Range), отчёт в data/mrio/reports/probe.json
python tools/alt_mrio_import.py --probe --report
# докачка/проверка архива (resume, size + sha256 + md5)
python tools/alt_mrio_import.py --download wiod_2016
# список членов архива (без значений)
python tools/alt_mrio_import.py --inspect wiod_2016
# конвертация (нужен pandas; bundled runtime DSH: .../dependencies/python/python.exe)
& $py tools/alt_mrio_import.py --convert wiod_2016 --years 2014 --jobs 1
# статус локальных данных
python tools/alt_mrio_import.py --check
# тесты (офлайн, без сети/pandas)
python -m unittest tests.test_alt_mrio_import -v
```

Результат `--convert` на 2026-11-14: `BLOCKED_CONVERSION`, 44 страны × 56 отраслей, год 2014,
6,7 с; причины — `y` (50 отрицательных ячеек, min −9 189,24), `va` (2 ячейки, min −22,17),
колоночный остаток 64,49 USD млн.

## 6. Ограничения

- Импорт проверен только на WIOD 2016 (Stata-архив); Excel/R-версии не скачивались (та же
  таблица, 919/642 МБ) — при необходимости `--download` использует только URL из матрицы.
- ICIO/Eora-парсеры не реализованы: нет доступного файла, а раскладки без файла не угадываются.
- `--convert` требует pandas; на системном Python 3.12 его нет, использовался bundled runtime
  (pandas 3.0.1). Это ограничение окружения, не кода.
- Отрицательные запасы — экономически корректны; блокирует именно замороженная схема.
  Решение о схеме v1.1 — за владельцем/Lead, здесь только зафиксировано.
- `data/mrio/` закрыт правилом `.gitignore` (`/data/mrio/`, строка 23): локальные данные и
  архив WIOD в git не попадут (проверено `git check-ignore`).
- Не коммитилось, не пушилось; `src/**`, `tools/registry.py`, frozen-файлы не изменялись.
