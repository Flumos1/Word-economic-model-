## 1. Проблема

Валидационный отчёт docs/91 показал для T2_GDP_GROWTH h=0:

- 360 origins (W1 204 + W2 156); у **111 из 360** origins квантили ансамблевой смеси экстремальны;
- **q95 до ~18 624.9** при точечном прогнозе и факте ~2–4 п.п. годового роста;
- средний CRPS контроля (`ENSEMBLE_EQUAL`) **158.5**, максимальный CRPS одного origin **893.9** при

RMSE-агрегаты T2 не затронуты (точечные прогнозы нормальные).

## 2. Диагностика (реальные данные, HEAD `0e4f527`)

### 2.1 Геометрический факт: один битый член отравляет всю смесь

Квантиль смеси CDF всегда лежит **внутри оболочки членов**: в точке `m = max_i q95_i` каждый член
имеет CDF ≥ 0.95 (для max-члена ровно 0.95, для остальных — выше), поэтому средняя CDF ≥ 0.95 и
квантиль уровня 0.95 смеси не превосходит `m`. Аналогично для q05. Следствие: если один член
«уехал» (q95 = 18 600), смесь не может это компенсировать — q95 смеси подтягивается к q95 битого
члена. Именно это и наблюдалось: mixture q95 ≤ max member q95 = 18 624.9.

### 2.2 Кто именно сломался: SPF-член и unit-ошибка actuals

Цепочка до исправления D-147 (коммит `fd0e597`):

1. `amfe.evaluation.actuals.actual_pair` возвращал для T1/T2 **сырой уровень ряда**, а не цель
   протокола (docs/91 §2 документирует этот дефект отдельно). Для GDPC1 это ~8 000–19 000.
2. `amfe.ensemble.history.external_error_quantiles` строит распределение SPF-члена из ошибок
   «факт − прогноз SPF». С уровнем вместо процентов ошибки получались ~8 000–19 000, а q95
   вектора SPF — **≈18 600** (это уровень ВВП 2018–2019, а не п.п. роста).
3. SPF-член (`SPF_GDP_MEDIAN`) входит в ансамбль только на месяцах дедлайнов SPF. Я прогнал все 360
   origins на текущих данных: SPF-член доступен ровно на **111 origins** — это в точности число
   аномальных origins в отчёте (111/360). Совпадение однозначно указывает на SPF-член как источник.
4. Один битый член из пяти даёт mixture q95 до ~18 600; CRPS штрафуется 5%-пинболом:
   `0.05 · 18 600 ≈ 930`, что объясняет наблюдённый max CRPS = 893.9 и средний 158.5.

## 3. Что изменено

`src/amfe/evaluation/distributions.py`: `mixture_quantiles` по умолчанию `robust=True` (три слоя,
все неактивны на корректных входах). Протокольное определение смеси сохранено: внутри [q05,q95] CDF
кусочно-линейна, за пределами — гауссов хвост, смесь — **равновесное среднее CDF членов** (не среднее
квантилей); меняются только входы смеси (документированное допущение) и крышка хвоста.

### 3.1 Винзоризация членов

Для каждого члена с вектором `q_5..q_95` (19 квантилей):

- робастный масштаб `s = q75 − q25` (при вырождении — `(q95−q05)/2`, затем пол `1e-12`);
- собственный предел: `q' = clip(q, q50 ± K_w · s)`, `K_w = 10`;
- **консенсусная оболочка**: `L = median_i(q05_i) − K_c · median_i(s_i)`,
  `U = median_i(q95_i) + K_c · median_i(s_i)`, `K_c = 6`; затем `q' = clip(q', L, U)`;
- монотонность восстанавливается `np.maximum.accumulate` (монотонный вход остаётся монотонным).

«Уехавший» член (например, SPF с q95 = 18 600 при нормальных остальных) срезается оболочкой до
диапазона соседей и уже не может утащить смесь. Все члены обрабатываются одинаково — это не выбор
по результатам.

### 3.2 Крышка гауссова хвоста

Хвостовая CDF строится, как и раньше, гауссом по наклону крайних квантилей:
`σ_hi = (q95−q90)/(z95−z90)` (и аналогично для нижнего хвоста), но

`σ_hi = min(σ_hi, K_t · s)`, `σ_lo = min(σ_lo, K_t · s)`, `K_t = 2`.

Для нормального члена `σ = s/1.349 = 0.741·s < K_t·s`, поэтому хвост не меняется; для «плоского»
или тяжёлого члена хвостовая экстраполяция ограничена разумным масштабом данных.

### 3.3 Финальный guard `q95 > k·(q75−q25)`

После инверсии смеси квантили клипуются к
`q50 ± K_f · (q75 − q25)`, `K_f = 25`, затем снова делаются монотонными. Для нормальных входов
`(q95−q50)/IQR ≈ 1.22 << 25`, так что guard не срабатывает и не искажает смесь; для катастрофы это
математическая гарантия отсутствия «взрыва» (и `diagnostics.final_guard_triggered` фиксирует факт).

### 3.4 Совместимость

- `robust=False` воспроизводит историческое поведение (без винзоризации, без крышки, без guard).
- На корректных входах `robust=True` даёт **бит-в-бит** тот же результат, что `robust=False`
  (проверено тестом `test_well_formed_inputs_are_unchanged`, maxdiff = 0.0): T1 и текущий T2 не
  меняются.
- `return_diagnostics=True` возвращает отчёт: `winsorized_members`, `consensus_envelope`,
  `final_guard_triggered`, `final_bounds`, `q05/q50/q95`, допущения; это позволяет писать в отчётах,
  что именно было исправлено, а не молча менять числа.
- Константы зафиксированы в `ROBUST_ASSUMPTIONS` (winsor_k=10, consensus_k=6, tail_sigma_k=2,
  final_spread_k=25) и покрыты тестом.

### 3.5 Проверка на историческом дефекте

Синтетика, воспроизводящая форму битого SPF-члена (q05 ≈ 9 000, q95 = 18 600) вместе с четырьмя
нормальными членами:

| Путь | q95 смеси |
| --- | ---: |
| старая логика (`robust=False`) | 12 300.2 |
| новый `robust=True` | **12.37** |
| отчёт диагностики | `winsorized_members=[5]`, монотонность сохранена |

## 4. Влияние на CRPS и выводы

- **T1 (CPI y/y):** смесь не изменилась (бит-в-бит); CRPS T1 остаётся прежним и годным.
- **T2 на текущих данных:** смесь не изменилась (max q95 = 8.945, `robust == plain` для реальных
  членов), поэтому новый CRPS будет определяться исправленными actuals и нормальными членами, а не
  защитным слоем. Ожидаемый средний CRPS — единицы, а не 158.5.
- **Старые CRPS-агрегаты T2 из docs/91 недействительны** и не переиспользуются: 111/360 origins
  имели member q95 из unit-ошибки. Подлежат пересчёту: `ENSEMBLE_EQUAL/INVERSE_MSE/BAYES/ADAPTIVE`,
  CRPS-относительные потери, DM и Romano–Wolf по CRPS. RMSE-агрегаты T2 не меняются.
- **Отчёт валидации надо перегенерировать** и в `data_quality.T2_GDP_GROWTH/h0` поставить
  `crps_usable=true` с ссылкой на этот документ; docs/91 §5 обновить (CRPS T2 — действительно
  результат после перегенерации). Это работа владельца/Lead (вне границ task-31).
- **C1/C2 T2 по CRPS** в harness используют `mixture_quantiles` и также получают защиту; на
  корректных членах результат не меняется. Замороженные `tools/evaluate.py`, R3, протокол v4,
  NF-SIM и состав компаратора **не менялись**.

## 6. Границы и открытые пункты

1. **Weighted-путь вне границ.** `amfe/ensemble/mixture.py::weighted_mixture_quantiles` (чужой
   модуль, не менялся по границам task-31) вызывает `_member_cdf` напрямую и получает только
   крышку хвостовой σ (пункт 3.2), но **не** получает межчленную консенсус-винзоризацию (3.1).
   На текущих данных это неважно (0 аномалий, `robust == plain`), но при будущем unit-баге
   взвешенные схемы уязвимее равновесной. Рекомендация: отдельной задачей перевести
   `weighted_mixture_quantiles` на общий robust-путь (например, вызвать
   `mixture_quantiles(..., robust=True)` для равновесного случая и вынести общий helper для
   произвольных весов) и добавить такой же тест. Это не блокирует пересчёт T2 CRPS сейчас.
2. **Константы — это допущение, а не оценка.** Они выбраны так, чтобы (а) быть неактивными на
   нормальных входах (проверено бит-в-бит), (б) отсекать unit-ошибки порядков величины. Если
   появится содержательная тяжёлохвостая модель, константы нужно пересмотреть протокольной
   заметкой, а не подгонкой под результат.
3. **Полный перезапуск ансамблей** (все 4 схемы, W1/W2, T1 h=1 и T2 h=0) — за владельцем: новый
   код надо закоммитить, зафиксировать code hash `distributions.py` в отчёте, перегенерировать
   `protocols/ensemble_validation_report.json` и обновить docs/91 §5.
4. **PIT-дисциплина** не затронута: изменён только способ смешивания уже готовых PIT-прогнозов;
   никакие фактические значения не используются в построении распределения.
5. Слой `amfe.evaluation.actuals` (unit-исправление D-147) — чужая зона, не менялся; полагаемся на
