## 2. Архитектура

```
amfe.international.TwoCountryWorld (стадия 3, без изменений)
   │  record_trade(exporter, importer, value, currency)
   │      ├─ on_external_claim(holder=exporter, issuer=importer, …)
   │      ├─ on_external_flow(CA, country=exporter, +numeraire)
   │      └─ on_external_flow(CA, country=importer, −numeraire)
   ▼
amfe.world.open.OpenPostingHook  (реализует ExternalAccountsHook)
   │  переводит numeraire → локальную валюту по курсу транзакции
   │  и постит в книги обеих стран:
   ├─ книга экспортёра:  export_goods(local X)
   └─ книга импортёра:   import_goods(local M)
   │  на close_period: on_revaluation(country, amount) → fx_revaluation(...)
   ▼
amfe.accounts.open.OpenAccountSystem  (по одной книге на страну)
   ├─ 4 резидентных сектора + row
   ├─ current: exports / imports (счёт ROW)
   └─ financial: external_claim / external_liability (зеркалятся с row)
   ▼
OpenWorldCore: цикл периода, open-инварианты, WorldPeriodReport (блок open_sfc)
```

### 2.1 Хартия открытой экономики

| Счёт | Измерение | Роли / ориентация |
|---|---|---|
| `exports` | current | ROW, только отрицательные проводки: расход ROW на экспорт резидентов |
| `imports` | current | ROW, только положительные проводки: доход ROW от импорта резидентов |
| `external_claim` | financial | активы: резидентные секторы; обязательство: `row`; сумма по счёту = 0 |
| `external_liability` | financial | актив: `row`; обязательства: резидентные секторы; сумма по счёту = 0 |

Остальные счета (`output`, `wages`, `transfer`, `direct_tax`, `interest`,
`household_consumption`, `government_consumption`, `deposit`, `loan`, `bond`) наследуются из
`DEFAULT_CHART` без изменений; типы транзакций расширены на `export` и `import`.

## 3. Проводки импорта и экспорта

Соглашение ядра (сохранено из docs/77): выпуск признаётся доходом при производстве, а продажа —
превращение запаса в депозит; поэтому у экспортёра нет текущего дохода в момент продажи.

**Экспорт X** (резидентская фирма продаёт ROW):

```
firm:  real inventory −X,  financial external_claim +X
row:   financial external_claim −X,  current exports −X
```

Закрытие секторов: фирма `0 = −X + X`; ROW `−X = −X`. Зеркальность `external_claim` = 0.

**Импорт M** (домохозяйство потребляет импортный товар):

```
household: current household_consumption −M,  financial external_liability −M
row:       financial external_liability +M,   current imports +M
```

Закрытие: домохозяйство `−M = −M`; ROW `M = M`. Импорт разрешён для домохозяйства и государства
(государственный импорт идёт в `government_consumption`); импорт фирмы как промежуточного
потребления в прототипе не реализован (§8).

**Открытый ВВП** (`C` включает импортное потребление):

```
Y_prod = Y_income = C + G + ΔInventories + GFCF + exports − imports
```

Проверка: проданный/экспортированный товар и импорт одновременно не увеличивают и не уменьшают
ВВП дважды; `ΔInventories = planned investment + imports − exports`.

## 4. FX-перевод, NFA и сходимость BoP/IIP

**NFA** — чистая внешняя позиция резидентов:

```
NFA = Σ_residents external_claim (signed) + Σ_residents external_liability (signed)
    = внешние активы − внешние обязательства
ROW net worth = −NFA                       (проверяется тождественно)
```

**FX-переоценка.** Перед закрытием внешнего слоя `OpenWorldCore` рассчитывает переоценку каждой
двусторонней позиции в локальных валютах обеих стран (та же формула, что в
`TwoCountryWorld.close_period`: `close_local − open_local − tx_local`), передаёт её в хук как
«подготовленную», а хук постит её при событии `on_revaluation` как нетранзакционную проводку
`fx_revaluation` (резидентная часть + автоматическое зеркало ROW). Поэтому:

* FX-переоценка — не поток: CA/FA не меняются, меняется только NFA и чистая стоимость;
* `ΔNW = сбережения + переоценка` продолжает выполняться по каждому сектору, включая ROW;
* сумма переоценок двух книг в numeraire даёт ровно `IIP_close − IIP_open − FA`, как в
  международном модуле.

**Сходимость слоёв** (проверяется каждый период в `OpenWorldCore`):

| Величина | Сверка |
|---|---|
| NFA | `NFA_local × closing_rate = IIP_net` (numeraire) |
| текущий счёт BoP | `(exports − imports)_local × rate_tx = CA` (numeraire) |
| финансовый счёт BoP | `(exports − imports)_local × rate_tx = FA` |
| переоценка IIP | `NFA_close·rate_close − NFA_open·rate_prev − (экспорт−импорт)·rate_tx = iip.revaluation` |
| двусторонняя зеркальность | книги A и B, переведённые в numeraire: позиции резидентов A + B = 0, `ROW_A` = позиции B, `ROW_B` = позиции A (допуск 1e-9 из-за независимого округления локальных проводок) |
| мировое богатство | `Σ_residents NW_local × rate = Σ real_assets × rate`; `Σ ROW net worth × rate = 0` |

Результаты на контрольных прогонах (12 периодов, базовый сценарий): 72 проверки на период,
все зелёные; digest 6-периодного базового прогона
`84a1a897e211088b9f4d68534f7d64ac14eac0fc742406d7d6b4ace4d37a3dd5`, расширенного
(`extended_open_scenario(settlement_share=0.05)`) —
`6829e2700133a7e17dcbde23f52c58b36c324e5723d703995a5a35f2b3c0bdf1`. Активы/обязательства и NFA
растут с дисбалансом торговли (страны экспортируют долю своего ВВП по текущему курсу; полное
равновесие торговли не предполагается). Девальвация (B 2.0 → 1.7 в периоде 4): в периоде 3
постится переоценка A `+2.870963367242`, B `−0.842036897590` (в локальных валютах), NFA_A
становится `−6.725707575011` против IIP `−6.7257075750112`; периоды 0–2 совпадают с базовым

## 5. Инварианты открытого ядра

**Уровень счетов (`OpenAccountSystem.close_period`)** — все закрытые инварианты docs/77 остаются
в силе, поскольку книга «резиденты + ROW» снова замкнута:

* F01/F02/F03: зеркальность финансовых инструментов (включая внешние), ориентация остатков,
  `Σ NW = Σ реальных активов`;
* P01: `ΔNW = сбережения + капитальные трансферты + переоценка + OVC` для каждого сектора,
  включая ROW;
* P02/P03: капитальный и финансовый счёт сходятся, `NLB = ΔF`, потоки по инструментам зеркальны;
* C01: `Σ NLB = 0`, `Σ валовых сбережений = Σ накопления`;
* G01: бюджетное ограничение государства; G02 (закрытый ВВП) заменён открытым тождеством ниже.

Дополнительно:

| Проверка | Формула |
|---|---|
| открытый ВВП | `Y_prod = Y_income = C + G + ΔInv + GFCF + exports − imports` |
| NFA-зеркало | `NFA + NW_ROW = 0` |
| мост NFA | `ΔNFA = (exports − imports) + переоценка внешних позиций` |
| мировое богатство | `NW_residents + NW_ROW = реальные активы` |

**Уровень мира (`OpenWorldCore`)** — 72 проверки на период: физические (материальный баланс,
`VA = Σd`, пределы энергии/труда), счётные (три метода открытого ВВП, `Y = P·VA`,
потребление/госзакупки/инвестиции, ликвидность домохозяйств), долговые (`debt_step` +
точное flow-тождество), открытые (NFA/IPP, CA/FA BoP, переоценка IIP, мост богатства,
ROW-зеркало, мост запасов `ΔInv = planned investment + imports − exports`, точное равенство
торговых проводок значениям хука, доходные/капитальные проводки и определения CA/GNI), двусторонние (см. §4) и внешние проверки
`TwoCountryWorld` (BoP/IIP/зеркала/невязки). При любом нарушении — `WorldError`/`IntegrationError`,
отчёт не выдаётся как успешный.

## 5a. Расширение task-44: услуги, доходы, капитальные трансферты, расчёты ROW

### 5a.1 Новые счета и проводки

| Счёт / операция | Проводка | Смысл |
|---|---|---|
| `exports_goods` / `exports_services` | `firm: real inventory −X, external_claim +X; row: external_claim −X, exports_* −X` | экспорт товаров/услуг; услуги отличаются только кодом потока и отчётной строкой |
| `imports_goods` / `imports_services` | `household: household_consumption −M, external_liability −M; row: external_liability +M, imports_* +M` | импорт товаров/услуг; `C` включает импортное потребление |
| `primary_income` (получение) | `household: current primary_income +n, external_claim +n; row: primary_income −n, external_claim −n` | первичный доход из-за границы (не входит в ВВП, входит в ВНД) |
| `primary_income` (выплата) | `household: primary_income −n, external_liability −n; row: primary_income +n, external_liability +n` | первичный доход за границу |
| `secondary_income` (получение/выплата) | зеркально, с кодом `secondary_income` | вторичные доходы (текущие трансферты) |
| капитальный трансферт (получение/выплата) | `resident: capital_transfer ±n, external_claim/liability ±n; row: capital_transfer ∓n, зеркальный финансовый инструмент` | капитальный счёт с ROW (роль `capital_transfer` расширена на `row`) |
| `settle_external_claim` | `firm: external_claim −n, deposit +n; row: external_claim +n, deposit −n` | ROW гасит своё обязательство через депозит в домашнем банке |
| `settle_external_liability` | `household: external_liability +n, deposit −n; row: external_liability −n, deposit +n` | резидент гасит внешнее обязательство депозитом |

Для депозита роль `row` добавлена как **актив** (ROW хранит депозиты в домашнем банке); отрицательные
депозиты ROW запрещены, поэтому `settle_external_claim` требует достаточного остатка (иначе
`TransactionRejected`, атомарный откат). `export_transfer` оставлен как устаревший примитив и
по-прежнему поднимает `AccountingError` (обратная совместимость).

### 5a.2 Обновлённые агрегаты

```
C_total = domestic consumption + imports_goods + imports_services
exports = exports_goods + exports_services
imports = imports_goods + imports_services
net exports = exports − imports
CA (current account) = net exports + net primary income + net secondary income
KA (capital account) = net capital transfers
GNI  = GDP + net primary income
GNDI = GNI + net secondary income
NFA  = external assets − external liabilities − ROW deposits
ΔNFA = CA + KA + переоценка внешних позиций
```

Товарный/сервисный и доходный каналы не меняют открытый ВВП
`Y = C+G+ΔInv+GFCF+exports−imports` (в нём нет первичных/вторичных доходов): ВВП по-прежнему
сходится тремя методами, а первичные доходы отражаются только в ВНД/счёте текущих операций.

### 5a.3 Проверки расширения

Все прежние инварианты сохранены; добавлены и проверяются каждый период:

| Проверка | Смысл |
|---|---|
| `open_bop_current` | `CA_accounts × rate = CA` из `TwoCountryWorld` |
| `open_bop_capital` | `KA_accounts × rate = KA` |
| `open_bop_financial` | `(CA+KA)_accounts × rate = FA` |
| `open_iip_revaluation` | `ΔNFA − (CA+KA) = переоценка IIP` |
| `open_income_posted` | доходные/капитальные проводки в книгах = локальные значения хука |
| `open_inventory_bridge` | `ΔInv = planned investment + imports − exports` (товары и услуги) |
| `open_current_account_definition` | `CA = net exports + net primary + net secondary` |
| `open_gni_definition` | `GNI = GDP + net primary` |
| `open_row_mirror`, `open_nfa_mirror`, `open_two_book_mirror`, `open_world_wealth` | как прежде |

На базовом (товарном) сценарии 72 проверки на период; расширенные потоки проверяются тем же
набором.

### 5a.4 Расчёты/депозиты ROW

`OpenWorldCore` при `settlement_share > 0` (только в расширенном сценарии) симметрично
рассчитывается по остаткам обеих книг: каждая книга сначала получает депозиты ROW (гасит
обязательства), затем платит по требованиям — депозит ROW возвращается к нулю, зеркальность книг
и NFA сохраняются, но валовые внешние активы/обязательства уменьшаются. Это финансовые операции:
CA, KA, NFA и мировое богатство не меняются. Внешний модуль `TwoCountryWorld` при этом не
сальдируется (в нём нет депозитного канала расчётов), поэтому **валовые** требования в IIP и в
книгах могут расходиться — согласованы нетто-позиции; это ограничение §8 п.3.

### 5a.5 Сценарии расширения

Базовый `WorldScenario` не изменился (товарная торговля, 72 проверки, 28-тестовый контракт
прежний). Расширенные потоки включаются только через
`OpenFlowScenario`/`extended_open_scenario()` (`include_services`, `include_income`,
`include_capital_transfers`, `settlement_share`; по умолчанию — выключены). Все значения —
экзогенные допущения класса SCENARIO: доля услуг 2%, доходность первичного дохода 1% на
открывающиеся требования, вторичные доходы 0.5% ВВП, капитальные трансферты 0.3% ВВП, расчёт 5%
минимальной валовой позиции.

## 8. Что осталось / ограничения

1. **Внешние потоки агрегированы.** Товары и услуги разделены только по коду потока; нет
   отраслевой разбивки, цен и количеств; первичные/вторичные доходы и капитальные трансферты —
   экзогенные агрегаты сценария (доходность, доли ВВП), а не оценённые потоки.
2. **Расчёты не согласованы с внешним модулем по валовым позициям.** В книгах сальдирование
   идёт через депозиты ROW, а `TwoCountryWorld` не имеет депозитного канала: согласованы
   нетто-позиции (NFA=IIP), валовые требования расходятся; нужны корреспондентские счета/ЦБ.
3. **Один агрегированный экспортёр/импортёр.** Экспорт проводит фирма, импорт — домохозяйство/
   государство; промежуточный импорт фирмы, импорт инвестиционных товаров и распределение по
   отраслям не моделируются.
4. **Торговые стоимости — доли ВВП по текущему курсу.** Физические количества, цены, логистика и
   импортное содержание не связаны с `amfe.resources`; выравнивание торговли не предполагается,
   поэтому NFA систематически растёт/убывает по сценарию.
5. **Многосторонние позиции.** Только двусторонние требования A↔B; нет третьих стран, корзины
   валют, резервной валюты, ЦБ и банковской системы, дефолтов/ликвидности.
6. **FX-переоценка** покрывает только валютный канал; переоценки по цене актива, объёмных
   изменений и процентов по внешним инструментам нет.
7. **Калибровки нет.** Все параметры сценарные; V2/V3 NOT_APPLICABLE.
8. `tests/test_open_sfc.py` не добавлен строкой в `.github/workflows/accounting-regression.yml`
   (вне границ задачи; недельный workflow подхватит его по маске `tests/test_*.py`).

## 9. Следующие шаги

1. Расчёты и сальдирование внешних позиций (депозиты ROW, корреспондентские счета) — вместе с
   банковским блоком и ЦБ.
2. Согласовать валовые внешние позиции при расчётах с внешним модулем (депозитный канал и
   корреспондентские счета); отраслевая детализация товаров/услуг и доходов.
3. Связь торговли с физическим слоем (`resources.logistics`/`balances`): количества, цены,
   импортное промежуточное потребление, выравнивание торгового баланса.
4. Многосторонняя модель (3+ страны) и общая резервная единица; позиции не только двусторонние.
5. Калибровка по point-in-time данным (этап 6, docs/92) и OOS-проверка сценариев.
