## 0. Как читать

Статусы: **READY** — работает на уровне прототипа/исследования; **PARTIAL** — часть есть, нужна
доработка; **GAP** — возможности пока нет. Любой кейс с пометкой «нет admitted-модели» — это
исследовательский результат, не инвестиционная рекомендация. Приоритет/волна — куда попадает
доработка (P0 — ближайшие волны).

## 3. Топ-10 коммерческих кейсов (что продавать первым)

1. **UC-13/14 FLAKS (закупки)**: сравнение поставщиков, TCO, бюджет закупок — понятная боль CFO;
   пилот на реальных данных, оплата за пилот/подписку.
2. **UC-44 scorecard внешних прогнозов**: «кто точнее» — подписка для инвесторов/медиа; требует
   task-54 (внешние источники и лицензии).
3. **UC-05/23 сценарии нефти/Ормуза**: сценарные отчёты для корпораций и трейдеров; уже есть
   прототип, нужно оформить как продукт с API.
4. **UC-45 API-подписка**: живой шлюз прогнозов/сценариев; тарифы по квотам.
5. **UC-17/18 логистика/запасы**: «что будет при сбое» — высокий спрос, но нужен блок 8.
6. **UC-40 тарифы/санкции**: сценарная библиотека страна×отрасль (блок 16).
7. **UC-10 отраслевой макро-оверлей**: связка макро→отрасли/акции (мост прогноз→мир).
8. **UC-31 портфельный макро-оверлей**: для управляющих активами.
9. **UC-48 Simulator UI**: демо/обучение/продажи, вход в вузы и корпоративные тренинги.
10. **UC-49/50 мониторинг/аудит**: governance-сервис для клиентов, которым нужна проверяемость.

## 4. Что это меняет в разработке

Каждый кейс раскладывается на «данные → модель → сценарий → интерфейс → лицензия». Забытые
capability-группы (внешние прогнозы, логистика/запасы, геополитика, технологии, ЦБ/фискал,
живой API) становятся отдельными треками, а не «когда-нибудь». Матрица приоритетов — в docs/173;
задачи — task-54…task-59 (scorecard, мост, C6, V2/sign-off, горизонты, 17 блоков).
