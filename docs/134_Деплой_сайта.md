# 134. Деплой сайта (GitHub Pages) — статус LIVE

Дата: 2026-11-14. Статус: **LIVE**. Основание: D-167/D-169 (сайт RU/EN, публичный репозиторий, деплой).\n\n**Живой сайт:** https://flumos1.github.io/Word-economic-model-/ (RU) · https://flumos1.github.io/Word-economic-model-/en/ (EN).
Сайт — статический снимок `site/` (RU + EN), генерируется `tools/site_build.py` из реальных
артефактов; **деплой не пересобирает данные и ничего не меняет в репозитории**.

## 1. Что уже сделано в репозитории

- `site/` (RU) и `site/en/` (EN) закоммичены в `main`.
- `.github/workflows/pages.yml`: при push в `main` (изменения в `site/**` или workflow) пакет
  `site/` загружается как артефакт и публикуется через GitHub Pages (`actions/deploy-pages`).
  Workflow read-only по содержимому, без секретов, без commit/push.

## 2. Включение Pages (делает владелец репозитория, один раз)

1. GitHub → репозиторий `Flumos1/Word-economic-model-` → **Settings → Pages**.
2. **Build and deployment → Source: GitHub Actions** (не «Deploy from a branch»).
3. При необходимости выбрать окружение `github-pages` (workflow сам создаст).
4. Запустить workflow: **Actions → Deploy site (GitHub Pages) → Run workflow** (или дождаться push).
5. Адрес появится в выводе job `deploy` (`page_url`) и в Settings → Pages.

**Важно про тариф:** репозиторий **приватный** (публичный API GitHub отдаёт 404). GitHub Pages
для приватных репозиториев доступен на платных планах GitHub (Pro/Team/Enterprise). Если плана нет:
- вариант A — сделать репозиторий public (учтите: данные MRIO в git не лежат, но код и документация
  станут публичными);
- вариант B — хостить `site/` на любом статическом хостинге (Netlify/Vercel/Cloudflare Pages/свой
  сервер): загрузить содержимое `site/` как есть, без сборки; внешние URL в сайте отсутствуют,
  поэтому ограничений нет;
- вариант C — локальный просмотр: `start site/index.html` (или `python -m http.server` в `site/`).

## 3. Обновление сайта

```powershell
python tools/product_pack.py          # если обновились прогнозные артефакты
python tools/world_reports.py         # если обновились сценарии
python tools/site_build.py            # RU + EN
git add site && git commit -m "site: refresh" && git push
```

Push в `site/**` автоматически запускает деплой (если Pages включён). Если артефакты не
пересобирались, сайт покажет прежние числа — это снимок, а не живой расчёт.

## 4. SEO и краулеры

Сборка кладёт в `site/` файлы `sitemap.xml` (**30 URL:** 18 research RU+EN и 12 коммерческих
`business/**` с 2026-11-21, см. docs/211, `lastmod` = дата снимка) и `robots.txt`
(разрешает обход и указывает `Sitemap`). Абсолютные URL есть только в этих двух файлах; HTML/CSS
остаются без внешних ресурсов. После включения Pages `sitemap.xml` можно добавить в Google Search
Console / Яндекс Вебмастер вручную.

## 5. Безопасность и ограничения

- В `site/` нет сырых третьих данных, только агрегаты и прогнозы AMFE (licence_policy).
- Нет JS, внешних шрифтов, аналитики, cookie и форм — только HTML+CSS; риски XSS/утечек минимальны.
- Деплой не означает допуск модели: на всех страницах статусы CANDIDATE/SHADOW_TEST и дисклеймер
  «research only, not admission, not investment advice».
- Если Pages недоступен по тарифу, workflow останется безвредным (не запускается до включения
  Source=GitHub Actions); артефакт можно скачать из Actions и разместить вручную.
