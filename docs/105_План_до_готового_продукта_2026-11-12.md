## 0. Резюме

1. **Сделано:** замороженная цепочка оценки (протокол v4 → R3 1.0.1 → NF-SIM → состав компаратора),
   плотный винтажный архив ALFRED на 19 рядов, ворота R2 — 333 пары (123 до 2000), 0 расхождений,
   harness C1–C6 с полным Romano–Wolf, первая REAL_TIME-оценка, 7 зарегистрированных кандидатов,
   калиброванное мировое ядро с 15 V2-проверками, релизные инструменты и 6 CI-workflow.
2. **Проверено сейчас:** **57/57** тестовых файлов зелёные (98 с); `release_check` — **CONDITIONAL,
   21 проверка, 0 блокеров, 3 предупреждения** (см. §3.1); `c4_analysis --check` — **FAIL**
   (устаревший пин состава, числа C4 не затронуты).
3. **Остановились:** последний коммит — итоги четвёртой волны (D-150); решения владельца (C4/v5,
   тег 1.0) не приняты; T3 (рецессия) не оценивался ни разу; forward-журнал пуст и не автоматизирован;
   продуктовый слой отсутствует.
4. **Ближайший реальный шаг по статусу — `SHADOW_TEST`** (требует C1, C2, C4, C5). Для T1/T2 он
   заблокирован C4/W1 (нехватка данных), для T3 — не начатой оценкой и отсутствием решения о
   кандидате. Это **разные** блокеры и снимаются разными работами.
5. **Потолок по протоколу v4:** T1 и T3 не могут стать `ACTIVE` (нужно 8 независимых исходов;
   у T1 цель y/y даёт ~1 исход в год) — их проектный статус `LIMITED_DEPLOYMENT`. `ACTIVE`
   реалистичен только для T2 h=4 и не раньше ~2031.
6. **Календарный пол:** C6 — 12 разрешённых прогнозов. Если журнал начнёт заполняться в
   ноябре–декабре 2026, то `LIMITED_DEPLOYMENT` для T1 h=1 возможен не раньше конца 2027 — Q1 2028.
7. **«Готовый продукт» возможен в двух смыслах:** (а) исследовательский продукт — платформа с
   регулярными прогнозами в статусах `CANDIDATE`/`SHADOW_TEST`, бюллетенем и дашбордом (достижимо
   за 4–6 недель агентских волн); (б) продукт с допущенной моделью — только через календарь C6,
   то есть 2028+. Смешивать эти два трека нельзя.

## 1. Что считается «готовым продуктом»

Определения — из [ТЗ §8](02_Техническое_задание_AMFE.md) (выходные продукты) и §9 (испытания и
приёмка); уровни введены здесь для планирования.

| Уровень | Определение | Критерии приёмки | Статус на 2026-11-12 |
|---|---|---|---|
| **P0. Платформа 1.0** | воспроизводимая исследовательская платформа: замороженная цепочка, данные, harness, отчёты, CI, релизные notes | `release_check` PASS/CONDITIONAL без блокеров; полная регрессия зелёная; frozen-пины совпадают; тег по решению владельца | **95%**: CONDITIONAL / 0 блокеров, тега нет |
| **P1. Продукт-минимум (MVP)** | регулярный прогнозный продукт по США: T1/T2/T3 с распределениями и интервалами, недельный бюллетень, forward-журнал, read-only дашборд, ≥1 пара в `SHADOW_TEST`, релиз 2.0 | прогнозы публикуются по расписанию; статусы честные; журнал пишется до фактов; дашборд/API отдают прогноз и неопределённость; acceptance-тесты продукта | **0%** (есть только прототипы инструментов) |
| **P2. Полный продукт** | мировая модель: этапы 2–5 интегрированы, открытое SFC по умолчанию, PIT-калибровка, сценарии, мониторинг/самообучение, API + БД + дашборд + планировщик, мультистрановой охват (EA, CN), регулярная публикация | V2-адекватность на реальных данных; инварианты и воспроизводимость; OOS-проверка сценариев; эксплуатационная надёжность; лицензионная чистота | **10–15%** (прототипы этапов 2–8, калибровка latest-tape) |
| **P3. Научный продукт** | статья/методология AMFE, независимая (не-LLM) проверка, публикация, открытая методология без сырых третьих данных | рецензируемый текст; воспроизводимость; лицензионное заключение | **10%** (методология и документация есть; статьи и внешней проверки нет) |

**Честная рамка.** «Готовый продукт» здесь — воспроизводимая система вероятностного
прогнозирования с явно указанным статусом каждой пары и честными ограничениями. Прогностическое
превосходство над сильными базовыми моделями остаётся проверяемой гипотезой, а не обещанием
(ТЗ §1.3, [концепция](01_Концепция_AMFE.md) §Исследовательские гипотезы H1–H6).

## 5. Критический путь и календарные ограничения

### 5.1 Лестница статусов (протокол v4, `admission.stages`)

| Переход | Условия | Что сейчас мешает |
|---|---|---|
| `CANDIDATE` → `SHADOW_TEST` | C1, C2, C4 (где применяется) и C5 на REAL_TIME-истории | T1/T2 — C4/W1; T3 — не оценивался |
| `SHADOW_TEST` → `LIMITED_DEPLOYMENT` | C6: ≥12 разрешённых прогнозов, отн. потеря ≤1,00, покрытие интервалов ±10 п.п. (T3 — калибровка) | журнал пуст, автозаписи нет |
| `LIMITED_DEPLOYMENT` → `ACTIVE` | повтор C6 на втором непересекающемся блоке, отсутствие дрейфа, ≥8 независимых исходов | календарь (T1: ~8 лет; T2 h=4: ~2 года после C6) |

Потолки: **T1 и T3 — `LIMITED_DEPLOYMENT`** (`pairs_expected_to_hit_ceiling`, `T3_ceiling`);
`ACTIVE` реалистичен только для T2 h=4.

### 5.2 Календарный расчёт C6

- T1 h=1, месячные origin: 12 разрешённых прогнозов = 12 месяцев после первой записи.
- Если первая запись — декабрь 2026, резолв 12-й — декабрь 2027, решение `LIMITED_DEPLOYMENT` —
  Q1 2028 (при прохождении C6).
- T2 h=1: резолв через квартал, 12 прогнозов = 3 года (2028–2029); h=4 — дольше.
- T3 h=3/6/12: резолв по completeness deadline, 12 прогнозов — 1–3 года.

**Следствие:** «допущенная модель» — не вопрос ближайших недель. Продукт до 2028 — это
исследовательский продукт с честными статусами, а не `ACTIVE`-модель.

### 5.3 Что можно и нельзя ускорить

- **Можно ускорить:** код и документацию (волны), продуктовый слой, T3-оценку, отчётный слой C4
  (вариант B), исправление техдолга.
- **Нельзя ускорить:** 12 месяцев forward-журнала; доступность PIT-данных 1990–1996; 8 независимых
  исходов для `ACTIVE`; внешнюю человеческую рецензию.
- **Можно обойти (только решением владельца):** v5 с PSEUDO в C4, min4 для T2, изменение правил
  C6/потолков — это меняет замороженные правила и требует prospective-протокола, а не «тихого» pass.

## 9. Критерии готовности продукта (acceptance)

**Технические:** полная регрессия зелёная; `release_check` без блокеров; frozen-пины совпадают;
воспроизводимость отчётов (хеши, детерминизм); CI зелёный; бэкап/восстановление БД.

**Научные:** по каждой паре — явный статус и отчёт C1–C6; C6-журнал заполняется до фактов;
никаких заявлений выше статуса; отрицательные результаты сохраняются.

**Продуктовые:** прогнозы по расписанию (1/3/6/12 мес., вероятность рецессии) с интервалами;
недельный бюллетень; панель/API; журнал изменений прогноза; задержка публикации ≤ 1 рабочий день
после релиза данных; дашборд доступен и мониторится.

**Юридические/лицензионные:** сырые третьи данные не в git; атрибуция; условия источников
проверены и захешированы; публикация согласована.
