# 237. Единая приёмка M1: одна команда

Дата: 2026-11-25. Роль: M1 (docs/207). Код — [tools/m1_demo_bundle.py](../tools/m1_demo_bundle.py),
тесты — [tests/test_m1_demo_bundle.py](../tests/test_m1_demo_bundle.py). Связка:
[docs/171](171_Client_Pack_v2.md) (Client Pack), [docs/178](178_Мост_прогноз_мир.md) (мост),
[docs/231](231_Simulator_демо_сценарий.md) (демо), [docs/234](234_Мост_PARTIAL_INPUTS_решение.md)
(решение по partial bridge), [docs/235](235_Simulator_live_smoke.md) (live smoke).

## 0. Зачем

До этого приёмка M1 состояла из отдельных проверок в разных документах: собрать мост, собрать
Client Pack, проверить PDF, прогнать демо. Ошибка в любом звене обнаруживалась только вручную.
Теперь есть **одна команда**, которая прогоняет все проверки и печатает машинный вердикт.

**Это не модель и не прогноз.** Бандл — агрегатор проверок: `RESEARCH_ONLY`, `admission=false`,
никаких утверждений о точности, ROI, SLA или деплое.

## 1. Команды

```powershell
python tools/m1_demo_bundle.py --check      # список проверок, ничего не строит
python tools/m1_demo_bundle.py --run        # полная приёмка (с PDF)
python tools/m1_demo_bundle.py --run --no-pdf   # быстрый прогон без LibreOffice
python -m unittest tests.test_m1_demo_bundle
```

Выход: JSON (`schema=amfe.m1.acceptance.v1`, `status=RESEARCH_ONLY`, `admission=false`),
код 0 — всё прошло, 1 — есть непройденная проверка, 2 — прогон сломался.

## 2. Что проверяется

| id | Проверка | Как |
|---|---|---|
| `bridge_built` | мост «прогноз → мир» собран | `tools/forecast_world_bridge.py --partial` (PARTIAL_INPUTS допускается, [docs/234](234_Мост_PARTIAL_INPUTS_решение.md)) |
| `client_pack` | Client Pack v2: 9 модулей + Bridge/Blocks | `client_pack_v2.build_pack(..., include_blocks=True)` |
| `client_pack_pdf` | три PDF (Executive/Methodology/Licence) | headless LibreOffice; без него проверка честно `false` |
| `no_violations` | нет claims о допуске и сырых данных | `status=RESEARCH_ONLY`, `admission.admitted=false` |
| `simulator_demo` | 6 шагов демо, все `RESEARCH_ONLY` + digest | `simulator_demo.run_demo` в процессе |

Куда пишется: `--out` (по умолчанию временный каталог). **В репозиторий не пишется ничего**:
мост собирается в `build/m1_bundle/forecast_world_bridge` (Client Pack не принимает путь вне
`build/`), а после прогона этот каталог удаляется; `--keep-bridge` оставляет его для отладки.

## 3. Наблюдаемые значения (2026-11-25, локально)

- мост: `PARTIAL_INPUTS`, `sfc_pass=true`, `no_raw_data=true`, 3 сценария (росту `BLOCKED_INPUT`);
- Client Pack: `ok=true`, `RESEARCH_ONLY`, 9 модулей, bridge `available=true`, 3 сценария,
  7 детерминированных файлов + 3 PDF;
- демо: 6/6 сценариев, у каждого `status=RESEARCH_ONLY`, `admission=false`, `causal_claim=false`, digest;
- итоговая проверка: `failed=[]`, `ok=true`.

## 4. Границы (честно)

1. **Не SLA и не деплой.** Бандл ничего не публикует: ни сервер, ни TLS, ни прокси, ни DNS.
2. **LibreOffice необязателен**: без него `client_pack_pdf=false` — это отражение среды, а не
   «упавшая сборка»; пакет всё равно собирается.
3. **PARTIAL_INPUTS — не дефект**: сценарий роста заблокирован отсутствием T2 в продуктовом фиде,
   а не ошибкой моста ([docs/234](234_Мост_PARTIAL_INPUTS_решение.md)).
4. **Демо — на объявленной синтетической фикстуре** геополитики; с артефактом числа другие,
   контракт и проверки те же.
5. **Проверяется локальная сборка**, а не «готовность к продаже»: NDA, договоры и данные клиента
   остаются вне этого контура.
6. Ни одна проверка не «подкручивает» статусы: если входы неполные или артефакт не проходит
   fail-closed, вердикт будет `ok=false` и код 1.

## 5. Место в плане

Закрывает требование M1 «демо 30 минут и зелёная сборка» в части автоматической проверяемости:
приёмка воспроизводится одной командой на чистой машине (кроме отсутствующей опциональной
зависимости LibreOffice). Дальше по плану — данные 3/15 → 5/15 (отдельный трек), Prometheus/алерты
([docs/233](233_Prometheus_метрики_и_алерты.md)) и GO/NO-GO beta 05.12.
