## 3. PIT-правила (что именно проверяется)

1. `release_date` не может быть раньше конца периода: релиз за 2024Q1 до 2024-03-31 — ошибка
   `PITViolationError` (данные «из будущего»).
2. `as_of(origin)` оставляет только наблюдения с `release_date <= origin`; для WDI —
   `period_end <= origin`, потому что дат релизов нет.
3. `assert_pit_clean(origin)` падает, если в уже нарезанном ряде есть наблюдение позже origin.
4. Модель не может использовать будущее: тест `test_pit_lookahead_cannot_change_forecast`
   добавляет фиктивное наблюдение с релизом после origin и проверяет, что прогноз не меняется.
5. Горизонт всегда строго после последнего использованного периода: `target = last_period + h`,
   `h ∈ {1,2,3,4}`; нарушение — ошибка.
6. Для WDI PIT **не заявляется**: `FINAL_VINTAGE_NO_PIT`, в отчёте и в этом документе написано,
   что годовой OOS несёт revision look-ahead и оптимистичен по времени публикации.

## 4. Модели (кратко)

- `RW`: последнее опубликованное значение; интервал — эмпирический разброс h-шаговых изменений.
- `AR_BIC`: AR(p) с константой, p выбирается по BIC (≤4); коэффициенты при необходимости
  сжимаются так, чтобы max|корень| ≤ 0.99 (детерминированная проекция устойчивости).
- `PANEL_AR1`: pooled AR(1) со страновыми средними, только ряды одного `source_class`; нужно ≥2
  страны и ≥8 наблюдений на страну. Для одной страны модель недоступна (это видно в отчёте).
- `BRIDGE`: `y_t = b0 + b1·y_{t-1} + b2·x_{t-1}`, где x — другая цель страны (GDP↔CPI);
  будущие x итерируются вспомогательной AR(1). Нужно ≥10 общих периодов.
- Интервалы 80%: `point ± 1.2816·σ_h`, где σ_h — остаточный масштаб модели (для RW — разброс
  h-шаговых изменений). Это **не** откалиброванные прогнозные распределения.

## 7. Лицензии и гигиена данных

  В отчёте есть `sources` с лицензией и ссылкой; сами значения WDI лежат только в

- **Локальный PIT CSV** — файл пользователя; адаптер читает его, но не коммитит и не перепубликует.
  Ответственность за лицензию — на поставщике файла.
- **Синтетика** — не третьи данные; лицензия в отчёте: `synthetic; no third-party data`.
- **Сырые данные не коммитятся**: `data/external/`, `data/mrio/`, `data/raw/` в `.gitignore`;
  CLI отказывается писать отчёты в `data/`, `protocols/`, `src/`.
- **В отчёте нет исторических значений**: проверка `_assert_no_raw_arrays` запрещает числовые массивы
  длиннее 8 и ключи `observations/values/history/raw_values/series_values`; тест
  `test_report_is_aggregates_only` это фиксирует.

## 8. Ограничения (без них числа читаются неверно)

1. **Нет реального квартального PIT-источника.** OECD/IMF/Eurostat с винтажами и датами
   публикаций не подключены; `data/raw` — только США. Поэтому квартальные «прогнозы» —
   синтетика, и их нельзя цитировать как прогноз по EA/CN/GB.
2. **WDI — годовой final vintage.** Ревизии не сохранены, дат публикаций нет; OOS оптимистичен
   по времени (начало = конец года, а WDI выходит позже) и несёт revision look-ahead.
3. **EA отсутствует в WDI-кэше.** Агрегат еврозоны не строился: без официальных весов и
   методологии это был бы выдуманный ряд. EA в годовом режиме — только синтетика/`NOT_AVAILABLE`.
4. **Малое n.** 30 годовых наблюдений, 15–18 OOS-начал на горизонт; 4 клетки на страну/цель.
   Этого мало для C1/C2/C4/C6 и для вывода «модель лучше RW».
5. **Простые модели.** Нет факторных моделей, mixed-frequency, байесовских панелей, режимов,
   структурных ограничений; bridge — одно уравнение.
6. **Интервалы не откалиброваны.** 80% интервал — остаточный масштаб, а не покрытие.
7. **UC-07/UC-08 не закрыты.** Страновой риск (долг/платежи/политика) и FX-прогноз здесь не
   моделируются; это только входные ряды роста/инфляции для будущих моделей.
8. **Нет допуска.** `RESEARCH_ONLY`; статус не двигается, C6 недоступен, forward-журнал не
   ведётся. Числа не являются инвестиционной рекомендацией.

## 9. Воспроизведение и тесты

```bash
# квартальный режим (синтетика, 0 реальных пар)
python tools/country_forecast.py --frequency quarterly --countries EA,CN,GB \
  --targets GDP,CPI --horizons 1,2,3,4 --out build/country_forecast_q

# годовой режим (CN/GB — реальные WDI, EA — синтетика/нет агрегата)
python tools/country_forecast.py --frequency annual --countries EA,CN,GB \
  --targets GDP,CPI --horizons 1,2,3,4 --out build/country_forecast_a

# fail-closed: квартальных реальных данных нет -> exit 2, отчёт не пишется
python tools/country_forecast.py --frequency quarterly --countries CN --require-real

# тесты
python -m unittest tests.test_country_forecast
```

### 12.2 PIT-статус: `FINAL_VINTAGE_NO_PIT` у всех шести рядов

| Что проверено | Результат |
|---|---|
| Дата публикации на наблюдение в Eurostat JSON-stat | нет: только `time` + `value` |
| Винтажи в канале DBnomics (Eurostat / OECD / ONS) | нет: отдаётся последняя редакция |
| «Первая оценка» ONS (PN2) как винтаж | существует, но привязки «издание → наблюдение» в канале нет |
| Выдумывались ли даты релизов | **нет**: в кэше `release_dates: null`, адаптер ставит `FINAL_VINTAGE_NO_PIT` |

Следствия, которые нельзя прятать:

1. Начала OOS — **концы периодов**, а не даты публикаций. Реальный лаг публикации (flash EA ~30 дней,
   ONS ~40–50, OECD QNA ~60–90) не моделируется → OOS **оптимистичен по времени**.
2. Ряды — последняя редакция, поэтому в OOS есть **revision look-ahead**: модель «видит» то, что
   в реальном времени было предварительным.
3. Это **не** real-time PIT и не сопоставимо напрямую со SPF/Consensus. Для настоящего PIT нужны
   архивы винтажей: для EA — ECB RTDB или vintage-архив Eurostat, для GB — ONS dataset editions с
   привязкой к наблюдениям, для CN — OECD MEI vintages. В этой среде они недоступны.
4. Если появится настоящая дата публикации, формат уже поддержан: `release_dates` (список ISO-дат)
   в кэше переключает ряд в `REAL_PIT` без правок кода — тест `test_cache_with_release_dates_is_real_pit`.

### 12.5 Что `NOT_AVAILABLE` и почему (ничего не выдумано)

1. **BRIDGE для EA и GB — 16 прогнозных клеток `NOT_AVAILABLE`** (и только они). Причина одна и та
   же: модель требует, чтобы обе цели страны были опубликованы **до одного и того же периода**, а
   покрытия не совпадают — EA CPI кончается 2025Q4 против EA GDP 2026Q3; GB GDP 2026Q2 против
   GB CPI 2026Q3. Ослаблять правило ради «красивой» таблицы не стали: это изменило бы PIT-контракт.
   Исторический OOS моста при этом считается (96 OOS-строк `OK`), т.к. на прошлых датах периоды совпадают.
2. **Годовой EA — по-прежнему `NOT_AVAILABLE`** (нет агрегата еврозоны в кэше WDI; агрегировать
   членов без весов не стали). В годовом режиме реальны только CN и GB: 4 пары, 88 прогнозов.
3. **Винтаж EA HICP в этой среде кончается 2025Q4** (все каналы согласованы: Eurostat REST,
   DBnomics Eurostat, ECB ICP), хотя GDP EA есть до 2026Q3, а GB CPI — до 2026Q3. Поэтому цели EA CPI
   на 1–4 шага — 2026Q1…Q4. Это ограничение доступности данных, а не «прогноз задним числом»:
   отчёт честно печатает `last_period = 2025Q4`.
4. **Настоящего real-time PIT нет** (§12.2) — это `FINAL_VINTAGE_NO_PIT`, а не `REAL_PIT`.
5. Уточнение к §9: повторный прогон годового режима тем же кодом даёт **84 `OK` / 12
   `NOT_AVAILABLE`** из 96 OOS-строк (8 — панель для EA: в синтетическом классе одна страна; 4 —
   BRIDGE EA CPI: релизы CPI и GDP в фикстуре разъезжаются на 30 дней). Прежняя формулировка
   «88 `OK`; 8 `NOT_AVAILABLE`» была неточной; фактические числа — здесь.

### 12.7 Ограничения и следующий шаг

1. **Нет real-time PIT** — главное ограничение; OOS оптимистичен по времени публикации и по
   ревизиям. Следующий шаг — vintage-архив (ECB RTDB / ONS editions / OECD vintages), а не
   «дорисовывание» дат.
2. **EA CPI — производный ряд** (месячный индекс → квартальное среднее → г/г). Официального
   квартального HICP Евростат не публикует; для сверки нужно взять квартальные средние HICP
   или квартальный дефлятор потребления.
3. **Покрытия не синхронны** (EA CPI 2025Q4, EA GDP 2026Q3, CN 2026Q1, GB 2026Q2/Q3): мост
   недоступен там, где последние периоды разные; для mixed-frequency моста нужен отдельный слой.
4. **Малый выигрыш, нет значимости**: 0.958–0.969 в среднем при разбросе 0.79–1.24; DM-тест,
   робастные потери и отдельная обработка COVID-2020 — до любых заявлений о преимуществе.
5. **Интервалы не откалиброваны** (80% — остаточный масштаб), **C1/C2/C4/C6 не считались**,
   `admission=false`, `causal_claim=false`, инвестиционной рекомендации нет.
6. **Лицензии**: Eurostat — open data (Decision 2011/833/EU), ONS — OGL v3.0, OECD via DBnomics —
   атрибуция обязательна, условия OECD в этой задаче повторно не аудировались. Значения не
   публикуются и не коммитятся; при публикации — атрибуция и запись в
   [`protocols/source_registry.json`](../protocols/source_registry.json) (не менялся в этой задаче).
