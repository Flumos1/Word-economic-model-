## 1. Что определено

Два кандидата в порядке регистрации (**сначала контроль без SPF, затем SPF-версия**):

| id | роль | члены | смысл |
|---|---|---|---|
| `ENSEMBLE_T2_NOT_SPF` | control | 4 внутренних: `AO`, `AR_BIC`, `BVAR_MINNESOTA`, `OWN_NOWCAST_BRIDGE` | «текущий ансамбль без SPF» — эталон из docs/95 |
| `ENSEMBLE_T2_SPF` | candidate | те же 4 + `SPF_GDP_MEDIAN` **когда медиана публична на начало** | SPF-augmented вариант; иначе — fallback на контроль |

Цель — только `T2_GDP_GROWTH` (квартальный рост реального ВВП, `400·ln(GDP_q/GDP_{q-1})`,
annualised). Горизонты протокола: **0, 1, 2, 4**; h=3 (`drgdp5`) существует в SPF-файле, но не входит
в сетку T2 и запрещён (`CandidateError`). T1/T3 запрещены: SPF не публикует помесячный CPI г/г и
NBER-вероятность рецессии (docs/86 §3).

## 2. Точная спецификация

### 2.1 Схема весов

`ENSEMBLE_EQUAL` — объявленная контрольная схема слоя ансамбля (docs/81): равные веса по членам,
доступным на начало; при входе/выходе SPF-члена веса **пересчитываются** (не фиксируются), отсутствующие
члены перенормируются. Точечный прогноз — взвешенное среднее; распределение — смесь CDF членов (тот же
`combine_member_forecasts`, что у компаратора/harness).

### 2.2 Правило доступности SPF (три условия)

SPF-медиана становится публичной в **дату новостного релиза**, а не в дедлайн ответов (docs/86 §5).
Член входит в набор тогда и только тогда, когда:

1. квартал опроса — real time (≥ 1990Q3);
2. начало — конец **среднего месяца** квартала опроса (замороженное правило выравнивания
   `amfe.ensemble.sources`, protocol `origin_policy.spf_alignment`);
3. начало ≥ официальной даты релиза из `src/amfe/ensemble/spf_calendar.py`
   (точные anchors `spf-release-dates.txt` + консервативный fallback — последний день среднего месяца).

Иначе — **fallback без SPF**: набор = 4 внутренних члена, прогноз **побитово равен контролю**;
в результате явно `spf_available=false`, `spf_fallback=true`, `spf_reason=<код>` (например
`ORIGIN_IS_NOT_AN_SPF_DEADLINE_MONTH`, `SPF_NEWS_RELEASE_NOT_PUBLISHED_AT_ORIGIN`,
`SPF_NOT_REAL_TIME_BEFORE_1990Q3`, `SPF_VALUES_NOT_DOWNLOADED`). Скрытых «нулевых» SPF-значений нет.

### 2.3 Маппинг горизонтов (docs/86 §2–3)

| T2 horizon | SPF code | смысл (официальная документация SPF §3) |
|---:|---|---|
| 0 | `drgdp2` | квартал опроса T+0 (q/q annualized) |
| 1 | `drgdp3` | T+1 |
| 2 | `drgdp4` | T+2 |
| 4 | `drgdp6` | T+4 |
| 3 | `drgdp5` | **не используется**: h=3 нет в сетке T2 |

`INFCPI1YR`/`INFCPI10YR` — не T1-прогнозы (средняя инфляция за 4 квартала / 10 лет) и в кандидате не
используются (docs/86 §4).

### 2.4 Формат forecast (harness-compatible)

`candidate_forecast(candidate_id, target, origin, horizon, series_id=None, mode="auto", data_root=None)`
возвращает dict того же вида, что `amfe.ensemble.candidate_forecast` / `amfe.candidates.models`:

```
candidate_id, target, origin, horizon, point, quantiles(19), probability(None),
data_class (REAL_TIME/PSEUDO_REAL_TIME), members, member_weights, member_kinds,
distribution_members, external_forecasts, weights/diagnostics, notes, …
+ candidate_variant ("NOT_SPF"/"SPF"), spf_available, spf_reason, spf_fallback,
  spf_horizon_code (drgdp2/3/4/6), base_ensemble_id, definition {tool, target, registration_status}
```

`publish_external_values=False`: значение SPF-медианы в вывод не попадает (только точка смеси и
атрибуция Philadelphia Fed в `external_forecasts`). `quantiles` — 19 квантилей 5%…95% (монотонные,
конечные), пригодные для `evaluate.crps`/`evaluate.rmse_squared_error` (проверено тестами).

### 2.5 Публичный API инструмента

| Имя | Назначение |
|---|---|
| `CANDIDATE_IDS` | `(ENSEMBLE_T2_NOT_SPF, ENSEMBLE_T2_SPF)` — порядок регистрации |
| `CANDIDATE_DESCRIPTION` | описания для регистрационного документа |
| `candidate_forecast(...)` | forecast-API для dispatcher/harness |
| `member_plan(...)` | чистая логика состава членов и доступности (без прогнозов; тестируется офлайн) |
| `candidate_definition(id)` / `candidates_document()` | готовые регистрационные фрагменты (`registered=false`) |
| `spec()` | машиночитаемая спецификация (docs/tests) |
| `availability_plan(window)` | сколько начал получают SPF-члена (по горизонтам) |
| `internal_members(horizon)` | 4 внутренних члена из R3 |
| CLI | `--definition`, `--spec`, `--check --window W1/W2/W3`, `--origin … --horizon … --candidate …` |

## 3. Доступность SPF-члена (план по протокольным началам)

`python tools/spf_augmented_candidate.py --check --window W1|W2` (локальные значения SPF; в CI без
артефакта все причины будут `SPF_VALUES_NOT_DOWNLOADED`, поведение fallback то же):

| окно | горизонт | начал | SPF-член входит | доля | примечание |
|---|---:|---:|---:|---:|---|
| W1 | 0 | 204 | **66** | 32.35% | 1990-08-31 … 2006-11-30 |
| W1 | 1 | 67 | 0 | 0% | квартальные начала: правило выравнивания не пускает SPF |
| W1 | 2 | 66 | 0 | 0% | то же |
| W1 | 4 | 64 | 0 | 0% | то же |
| W2 | 0 | 156 | **51** | 32.69% | 2007-02-28 … 2019-11-30 |
| W2 | 1 | 51 | 0 | 0% | то же |
| W2 | 2 | 50 | 0 | 0% | то же |
| W2 | 4 | 48 | 0 | 0% | то же |

Итого h=0: 117 из 360 протокольных начал (32.5%), из них **91 REAL_TIME** (после исключения
PSEUDO_REAL_TIME 1990–1996) — это ровно подвыборка docs/95. Ограничение «SPF только на h=0» —
следствие замороженного правила выравнивания; чтобы SPF входил и на квартальных началах h=1/2/4,
нужна правка слоя внешних прогнозов (`src/amfe/ensemble`, решение Lead), а не подмена правила в
кандидате. Кандидат поэтому **идентичен контролю на h=1/2/4** — это заявлено явно, а не скрыто.

## 4. Почему кандидат предлагается: результат docs/95

Sensitivity-анализ (docs/95, `protocols/spf_t2_sensitivity_report.json`) на REAL_TIME-началах h=0:
paired-сравнение на 91 начале, где медиана публична:

| | RMSE no-SPF | RMSE with-SPF | отн. | DM p | RW adj p | CRPS отн. | DM p (CRPS) |
|---|---:|---:|---:|---:|---:|---:|---:|
| W1 (n=40) | 1.4419 | 1.4108 | 0.9784 | 0.0133 | 0.0245 | 0.9535 | 0.0008 |
| W2 (n=51) | 1.5976 | 1.5060 | 0.9427 | 0.0437 | 0.0570 | 0.8813 | 0.0159 |
| W1+W2 (n=91) | 1.5350 | 1.4664 | 0.9554 | 0.0207 | 0.0425 | 0.9114 | 0.0036 |

CRPS T2 валиден после docs/94 (sanity-гейт смеси: 368 смесей, 0 отклонений). Кандидат
`ENSEMBLE_T2_SPF` — формализация именно этого варианта для честной оценки через C1–C6; сам по себе
sensitivity-результат допуском не является.

## 5. Регистрация и оценка (действия Lead)

1. **Регистрация кандидатов.** Взять `python tools/spf_augmented_candidate.py --definition` (JSON) и
   добавить оба фрагмента в `protocols/candidates_<date>.json` **в порядке**
   `ENSEMBLE_T2_NOT_SPF`, затем `ENSEMBLE_T2_SPF`; в `registered_before_evaluation` — дата,
   `code_file`/`code_sha256` уже в фрагментах (sha меняется при любой правке файла — пересчитать).
2. **Диспетчер harness.** В `tools/run_real_evaluation.py` (вне write-scope этой задачи) добавить
   ветку до/после проверки `ENSEMBLE_IDS`:
   ```python
   from spf_augmented_candidate import CANDIDATE_IDS as SPF_CANDIDATE_IDS
   from spf_augmented_candidate import candidate_forecast as spf_candidate_forecast
   ...
   if candidate_id in SPF_CANDIDATE_IDS:
       return spf_candidate_forecast(candidate_id, target, origin, horizon,
                                     series_id=series_id, mode=mode)
   ```
   (`sys.path` уже содержит `tools/`.) Формат возврата совместим с `build_window`/`evaluate_admission`;
   `data_class` вычисляется слоем ансамбля.
3. **Данные.** До оценки восстановить приватный артефакт `r2-metadata` в `data/raw` (SPF-значения и
   винтажи); без SPF-файла кандидат честно уйдёт в fallback и будет равен контролю — это не ошибка, но
   делает оценку неинформативной.
4. **Оценка.** `--candidate ENSEMBLE_T2_NOT_SPF` и `--candidate ENSEMBLE_T2_SPF` на T2 h=0 (и h=1/2/4,
   где различий не будет по §3): C1–C6, при необходимости forward-registry C6. Сравнение — только
   paired на REAL_TIME-началах со SPF; иначе full-sample разбавляет эффект (docs/95 §3.2).
5. **Публикация.** Только агрегаты/дайджесты; значения SPF не коммитить, атрибуция Philadelphia Fed
   обязательна (`PHILADELPHIA_FED`, research use).

## 7. Ограничения

1. **Кандидат не зарегистрирован и не оценён**: любые ссылки на него — proposal, не допуск; регистрация
   и оценка — Lead через harness.
2. **Mapping объявлен проектом** (docs/86) на основе официальной документации SPF; `INFCPI10YR` не
   подтверждён и не используется; `drgdp5`/h=3 не входит в сетку T2.
3. **SPF только на h=0** из-за замороженного правила выравнивания (средний месяц); на h=1/2/4 кандидат
   тождественен контролю — расширение требует правки frozen-слоя внешних прогнозов.
4. **SPF — последняя редакция файла, не винтаж**: дата релиза фиксирует доступность, ревизии/errata
   после опроса не аудированы (docs/86 §8); для PIT-строгости нужен аудит ревизий.
5. **Распределение SPF — производная статистика проекта** (эмпирические ошибки SPF, центрированные на
   медиане), не плотность Philadelphia Fed.
6. **Вес фиксирован схемой** (equal weights; SPF получает 1/5 там, где входит); adaptive/inverse-MSE
   варианты не определяются этим кандидатом (их можно добавить отдельным id).
7. **T2-only**: T1/T3 невозможны без новых SPF-рядов; никакой интерполяции (protocol
   `origin_policy.spf_alignment`, docs/86 §3).
8. **CI без данных**: без приватного артефакта `r2-metadata` SPF-файл отсутствует → кандидат
   автоматически равен контролю (fallback), что делает CI-оценку неинформативной, но не ломает harness.
9. **Лицензия**: значения SPF — third-party, research use, не коммитятся; атрибуция обязательна;
   публикуются только производные статистики (docs/84, docs/90).
