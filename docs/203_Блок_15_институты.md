## 1. Зачем блок и что именно сделано

**Зачем.** В docs/177 блок 15 — единственный полностью отсутствующий, и это не случайность:
институты дороги в данных (лицензии V-Dem/WGI), плохо сводятся к одному числу и легко
превращаются в «рейтинг вместо механизма» (docs/177 §5, «чего сознательно не делаем»). Но без
блока 15 два практических вопроса остаются без языка: (а) почему одинаковая политика/санкция даёт
разный результат (docs/181 §7, UC-41/UC-43), (б) как передать «качество правил» в премию за риск
и инвестиции, не выдумывая страновые ряды (UC-07).

**Что сделано.** Минимальный прототип M15 по образцу M8/M16: не «индексы вместо механизма», а
**механизм поверх явно заданных институциональных характеристик**. Пользователь (или другой блок)
задаёт шесть чисел, сценарий задаёт их сдвиг, движок считает композит, премию и два макро-канала —
и всё это проверяемо и воспроизводимо.

| Объект | Класс | Где | Что проверяется |
|---|---|---|---|
| `InstitutionalIndicators` | **ASSUMPTION_BASED** | `world/institutions.py` | шесть измерений в [0, 100]; clip при сдвиге |
| `institutional_score` / `_breakdown` | **ASSUMPTION_BASED** | там же | композит = Σ wᵢxᵢ в [0, 100]; сумма весов = 1 |
| `normalise_weights` | **ASSUMPTION_BASED** | там же | равные веса по умолчанию; частичные/отрицательные/нулевые веса — ошибка |
| `InstitutionScenario` | **SCENARIO** | там же | kind ∈ 4, id, magnitude, |Δ|·m ≤ 100, рампа ≥ 1 |
| `scenario_overlay` | **SCENARIO** | там же | знаки, границы, премия ≥ 0, инвестиции ∈ [0, 1] |
| `as_scenario_modifier` | **SCENARIO** | там же | три канала + `gating=false` для блоков 5/11–12/16 |
| `OverlayParameters` | **ASSUMPTION_BASED** | там же | β, γ, потолок премии, база инвестиций, эластичности |
| `run_all`, `load_bundle` | сервис | там же | детерминизм, отсутствие raw-данных, fail-closed |
| `tools/institutions_scenarios.py` | CLI | `tools/` | JSON+MD, digest, exit 0/1/2, no-raw |

Классы — по контракту docs/38: `ASSUMPTION_BASED` — допущение без оценки, `SCENARIO` — экзогенный
«что если». `IDENTITY` в блоке нет намеренно: институциональное качество не имеет accounting-тождества,
и притворяться, что имеет, было бы хуже, чем честно считать его индексом.

## 2. Уравнения

Обозначения: шесть измерений `x_i ∈ [0, 100]` (voice, stability, effectiveness, regulatory,
rule_of_law, corruption; выше — лучше по всем шести), веса `w_i ≥ 0`, `Σw_i = 1`, сдвиг сценария
`d_i` в пунктах, `m` — magnitude, `t = 1..H` — годы.

### 2.1 Композит и разброс

```
score      = Σ_i w_i · x_i                                  ∈ [0, 100]
dispersion = sqrt( (1/6) · Σ_i (x_i − x̄)² )                  (population stdev)
dimensions: accountability = mean(voice, corruption)
            state_capacity = mean(stability, effectiveness)
            property_rights = mean(regulatory, rule_of_law)
```

`dispersion` — мера **несогласованности** правил, а не качества: высокий разброс означает, что
часть измерений сильная, а часть слабая (пример `EXAMPLE-POLARIZED`). Равные веса — конвенция по
умолчанию (A2), а не результат оценки; измерения — представление (A1), а не данные.

### 2.2 Сценарий и рампа

```
x_i(t)  = clip(x_i + m · d_i · r_t, 0, 100)
r_t     = min(1, t / ramp_years)                            рампа, t = 1..H
score_t = Σ_i w_i · x_i(t)
gap_t   = score_base − score_t                              > 0 при ухудшении
```

`ramp_years` — единственный «лаг» блока: реформа (4 года) разворачивается медленнее, чем эрозия
(2 года) и поляризация (2 года). Это допущение A6, а не оценка скорости институциональных
изменений.

### 2.3 Премия за риск (б.п.)

```
premium_delta_t = β · gap_t + γ · (dispersion_t − dispersion_base)      β = 4,0; γ = 2,0
premium_t       = clip(premium_base + premium_delta_t, 0, premium_cap) premium_base = 120; cap = 2000
```

Два канала: **уровень** (β на пункт разрыва) и **несогласованность** (γ на пункт изменения
разброса). Именно второй делает `POLARIZATION` отличимым от `DETERIORATION`: композит падает
меньше, а премия сопоставима. Премия — условная величина в б.п., **не** суверенный спред и не
доходность (A4).

### 2.4 Инвестиции и рост

```
Δinvestment_pp_t = e_inv · (score_t − score_base)           e_inv = 0,04 п.п. ВВП на пункт
investment_t     = clip(investment_base + Δinvestment_pp_t/100, 0, 1)   investment_base = 0,22
Δgrowth_pp_t     = e_g · (score_t − score_base)             e_g = 0,02 п.п. на пункт
```

`Δinvestment_pp` — в процентных пунктах ВВП, `Δgrowth_pp` — в п.п. потенциального роста. Обе
эластичности — допущения A5. Обратной связи «инвестиции → качество институтов» нет (A9): это
модификатор, а не полноценная модель роста.

### 2.5 Модификатор для других блоков

```
modifier = { risk_premium_bps,            Δ премии при полной рампе
             investment_ratio_delta,      Δ инвестиций как доля ВВП
             growth_delta_pp,             Δ роста, п.п.
             applies_to: [block_5_investment, block_11_12_policy_fiscal, block_16_geopolitics],
             gating: false, causal_claim: false }
```

`as_scenario_modifier(report)` — единственный экспорт «наружу». Он не гейтит допуск и не является
прогнозом; это способ передать три числа в сценарные библиотеки, не выдавая их за оценку.

## 4. Сценарии и ключевые числа

Демо-прогон (`--demo`): четыре иллюстративных профиля × четыре сценария. Числа ниже — **агрегаты
сценарного расчёта при допущениях A1–A10**, не прогноз и не страновые значения. Горизонт 5 лет,
полная рампа, β=4, γ=2, база премии 120 б.п.

Профиль `EXAMPLE-MID` (композит 51,50; разброс 2,43):

| Сценарий | Δ композита, пункты | Δ премии, б.п. | Δ инвестиций, п.п. ВВП | Δ роста, п.п. | Рампа, лет |
|---|---|---|---|---|---|
| `STATUS-QUO` | 0,00 | 0,0 | 0,000 | 0,000 | 1 |
| `REFORM` | **+6,00** | **−23,5** | **+0,240** | +0,120 | 4 |
| `DETERIORATION` | **−6,67** | **+30,0** | **−0,267** | −0,133 | 2 |
| `POLARIZATION` | −4,17 | **+25,6** | −0,167 | −0,083 | 2 |

Путь `REFORM` по годам (профиль `EXAMPLE-MID`): композит 51,50 → 53,00 → 54,50 → 56,00 → 57,50,
премия 120,0 → 114,0 → 108,1 → 102,3 → 96,5 б.п.; дальше эффект насыщается (рампа 4 года).

Что показывают числа:

* **`STATUS-QUO` — контрольная линия, а не «в реальности ничего не меняется».** Нулевой сдвиг
  композита даёт нулевые каналы по построению.
* **`DETERIORATION` дороже, чем кажется по композиту.** −6,67 пункта дают +30 б.п. премии: это
  β·6,67 = 26,7 б.п. плюс вклад разброса (+1,67 пункта → +3,3 б.п.).
* **`POLARIZATION` — главный аргумент блока.** Композит теряет всего 4,17 пункта (мягче
  `DETERIORATION`), но премия +25,6 б.п.: β·4,17 = 16,7 плюс γ·4,49 = 9,0 за расширение разброса.
  Один и тот же «средний балл» может скрывать разные риски — именно этого в блоке не хватало.
* **Одинаковый сценарий — разные числа у разных профилей.** `REFORM` даёт −25,0 б.п. у
  `EXAMPLE-LOW`, −23,5 у `EXAMPLE-MID`, −21,9 у `EXAMPLE-HIGH`, −23,6 у `EXAMPLE-POLARIZED`:
  различие идёт от изменения разброса, а не от «качества страны». Это иллюстрация механизма
  docs/181 §7 («почему одинаковая санкция даёт разный результат»), но без данных — только
  иллюстрация.
* **Знаки устойчивы, величины — нет.** Смена эластичности меняет числа, но не знаки: это и есть
  честное утверждение, которое можно делать сейчас.

## 5. Что можно и чего нельзя утверждать

**Можно:**

* «При допущениях A1–A10 сдвиг шести измерений на N пунктов даёт такую-то премию и такое-то
  изменение инвестиций/ВВП» — с указанием версии блока, профиля и digest отчёта.
* «Знак эффекта определяется знаком сдвига качества и знаком эластичности; композит ограничен
  [0, 100]; премия не может быть отрицательной».
* «Поляризация добавляет канал несогласованности: при равном изменении композита премия может
  различаться» — как свойство **механизма**, а не как факт о стране.
* «Блок 15 экспортирует модификатор для блоков 5/11–12/16 с `gating=false`» — как интеграционный
  контракт.

**Нельзя:**

* «Институты страны X равны Y» — страновой таблицы в блоке нет и не появится без §6.
* «Премия вырастет на N б.п. в реальности» — эластичности не оценены; это условная величина.
* «Реформа даст +0,24 п.п. инвестиций» — это арифметика при допущении, а не эффект реформы;
  причинность не устанавливалась (`causal_claim=false`).
* «Вероятность реформы/ухудшения равна p» — вероятности не оцениваются (это слой блока 14).
* «Блок 15 закрывает UC-07/UC-41/UC-43» — он даёт им сценарный язык, но не данные и не оценку.
* «Блок 15 — `model`» — нет калибровки, нет данных, нет OOS: статус прототипа.

Что нужно сделать до любой калибровки (порядок важен):

1. **Лицензионный аудит** по каждому источнику: разрешено ли хранить, переиспользовать,
   публиковать производные значения; кто владелец; нужна ли атрибуция. Без этого — только план.
2. **Маппинг в шесть измерений**: WGI ближе всего; ICRG/BTI/V-Dem — через явную таблицу
   соответствия, с фиксацией потерь. Нельзя складывать несопоставимые шкалы (docs/07 P-010).
3. **Нормировка 0–100 и правило ресемплинга** (годовая частота, PIT-дата публикации, ревизии).
4. **Оценка весов и эластичностей** на данных с проверкой устойчивости; до этого A2/A4/A5
   остаются допущениями.
5. **Прereg критериев** до прогона (как A1–A6/B1–B6 в docs/177 §4): иначе «улучшение» не
   засчитывается.
6. **Отдельные ворота** для перехода `prototype → model`; этот MVP их не открывает.

## 7. Как встроить в 17-блочную матрицу

Блок 15 остаётся **модификатором**, а не восемнадцатым механизмом (docs/177 §5):

| Блок | Что получает от 15 | Через что | Чего не получает |
|---|---|---|---|
| 5 (инвестиции, капитал) | Δ инвестиций/ВВП в п.п. | `investment_ratio_delta` из модификатора | не заменяет CAPEX-модель и амортизацию |
| 3 (перераспределение) | намёк на «ρ(q)»: слабое правоприменение → другая эффективность перераспределения | только как сценарная пометка | функции `ρ = g(q, θ)` в коде нет (идея docs/59) |
| 11–12 (ЦБ, госфинансы) | премия за риск → стоимость обслуживания долга | `risk_premium_bps` | правило Тейлора и тождество `r−g` не пересчитываются |
| 16 (геополитика) | модификатор «одинаковая санкция — разный результат» | `applies_to: block_16_geopolitics` | асимметрия выгод (P-008) не считается |
| 1 (производство) | Δ потенциального роста | `growth_delta_pp` | TFP-рядов и сдвига коэффициентов нет |
| 7 (MRIO) | ничего напрямую | — | шоков в матрицу `A` блок не даёт |

Практическая интеграция — один вызов:

```python
from amfe.world.institutions import find_example_profile, default_scenarios, scenario_overlay, as_scenario_modifier
modifier = as_scenario_modifier(scenario_overlay(find_example_profile("EXAMPLE-MID"),
                                                 default_scenarios()[1]))  # REFORM
# modifier["risk_premium_bps"], modifier["investment_ratio_delta"], modifier["growth_delta_pp"]
```

Ограничение: модификатор — **числа при допущениях**, а не оценённый эффект. Подключать его к
P2/M16 можно только с пометкой `RESEARCH_ONLY`/`not_calibrated` в отчёте и без влияния на
`admission`.

## 8. Acceptance (предлагаемые критерии M15)

Критерии фиксируются до прогона; ниже — статус по факту этой задачи. Как и в docs/177 §4, это
критерии **прототипа**, а не допуска. По правилу [docs/164](164_План_и_статус_проекта.md) §1
неприменимый критерий помечается `NOT_APPLICABLE`, а не `PASS`.

|---|---|---|---|
| C1 | Композит в [0, 100] для любых допустимых входов и сценариев | `checks.score_bounds`, 43 теста | **PASS** |
| C2 | Веса нормированы, сумма = 1; частичные/отрицательные веса отклоняются | `checks.weights_normalised`, тесты весов | **PASS** |

## 9. Ограничения

1. Нет данных и калибровки: индикаторы, веса, сдвиги, β, γ и эластичности — допущения A1–A10.
2. Композит линеен и аддитивен: нет порогов, комплементарности и «критического» измерения.
3. Институты не смоделированы как механизм: нет прав собственности, судов, регулирования,
   политического процесса — только агрегированный сдвиг и три макро-канала.
4. Встроенные профили `EXAMPLE-*` иллюстративны; пользовательский JSON не проверяется на
   истинность (это ответственность пользователя, помечено `USER_INPUT`).
5. Премия — не суверенный спред и не доходность; γ-канал (разброс) — гипотеза, а не оценка.
6. Лагов, кроме рампы, нет; обратной связи «инвестиции → качество» нет; период годовой.
7. Вероятности сценариев не оцениваются; причинность не утверждается; `admission` не меняется.
