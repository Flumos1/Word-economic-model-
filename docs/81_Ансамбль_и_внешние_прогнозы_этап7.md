# 81. Ансамбль и внешние прогнозы (этап 7)

Дата: 2026-11-12. Статус: реализация выполнена, тесты зелёные (`tests/test_ensemble.py`, 48 тестов).
Код не заморожен: константы весов и хеши модулей (раздел 11) фиксируются при регистрации
кандидатов-ансамблей — это делает Lead через `protocols/candidates_<дата>.json` до первой оценки
(protocol v4 `model_class_rules.registry_access`). Frozen-файлы, `src/amfe/forecast`,
`tools/evaluate.py` не изменялись; модуль только импортирует их.

## 1. Назначение и границы

Этап 7 — адаптивный ансамбль собственных и внешних прогнозов:

* собственные члены — 7 базовых моделей R3 (`amfe.forecast`), каждая уже отдаёт point + 19
  квантилей (T1/T2) или вероятность события (T3);
* внешний член — медианы SPF (Philadelphia Fed) для T2; значения — сторонние данные, лежат
  только в git-ignored `data/raw/spf/spf_median.json`, в репозиторий не попадают;
* веса — по горизонту, наблюдаемому режиму, исторической ошибке и корреляции ошибок, с
  регуляризованной ковариацией, inverse-MSE и байесовским обновлением;
* контрольные ансамбли — равновесный, inverse-MSE, байесовский; основной кандидат —
  адаптивный;
* выход — dict, совместимый с harness `tools/evaluate.py`: `point`, `quantiles` (19),
  `probability` (T3), `data_class`, `target`, `origin`, `horizon`; T3 — только вероятность.

За границами задачи: прогон допуска C1–C6 (это `tools/evaluate.py` + раннер Lead), регистрация
кандидатов в `protocols/`, публикация отчётов, загрузка RTDSM/SPF.

## 2. Архитектура

```
src/amfe/forecast (R3, frozen) ─┐
                                ├─> history.py ──> weights.py ──┐
data/raw/spf (git-ignored) ─────┘        │                       v
                                         └──> ensemble.py <── mixture.py
                                                    │
                                                    v
                                  dict candidate: point/quantiles/probability
                                                    │
                                                    v

```

| Модуль | Роль |
|---|---|
| `src/amfe/ensemble/sources.py` | реестр происхождения источников, классификация «внешний прогноз / статистика», загрузка SPF, маппинг горизонтов и правила доступности, статус RTDSM |
| `src/amfe/ensemble/weights.py` | схемы весов: equal, inverse-MSE, min-variance на shrinkage-ковариации, байесовское обновление, адаптивная смесь; prior/регуляризация и перераспределение весов отсутствующих членов |
| `src/amfe/ensemble/mixture.py` | взвешенная смесь CDF для 19 квантилей (то же определение, что у протокола), пул вероятностей T3, диагностика |
| `src/amfe/ensemble/history.py` | walk-forward история членов и первых публикаций фактических значений, PIT-доступность, кэш прогнозов, наблюдаемый режим |
| `src/amfe/ensemble/ensemble.py` | 4 ансамбля, комбинирование, публичный API `ensemble_forecast` / `candidate_forecast`, диагностика |
| `tests/test_ensemble.py` | 48 тестов (синтетика + локальные данные при наличии) |

Кэш прогнозов членов (`history._MEMBER_FORECAST_CACHE`, `E.clear_cache()`) — только оптимизация:
одинаковый вызов (member, target, horizon, origin, series, mode) возвращает тот же результат.

## 3. Источники и правила различения «внешний прогноз vs статистика»

Классификация (`SOURCE_CLASSIFICATION` в `sources.py`, `classify_member`, `member_kind`):

| Вид | Пример | Признак | Публикация |
|---|---|---|---|
| `INTERNAL_MODEL` | RW, AO, AR_BIC, BVAR_MINNESOTA, PROBIT_SPREAD, SAHM_RULE, OWN_NOWCAST_BRIDGE | наша модель, наш код и числа | можно публиковать |
| `EXTERNAL_FORECAST` | `SPF_GDP_MEDIAN` | сторонний опубликованный прогноз (Philadelphia Fed SPF), `third_party=true` | только производные статистики; сырые значения не коммитятся/не публикуются, обязательна атрибуция |
| `DERIVED_STATISTIC` | `SPF_GDP_ERROR_QUANTILES`, `EQUAL_WEIGHT_MEAN`, `ENSEMBLE_WEIGHTS`, `ENSEMBLE_CONCENTRATION` | вычислено нами из прогнозов/ошибок | можно публиковать как нашу статистику |
| `EXTERNAL_DATA_VINTAGE_SOURCE` | `RTDSM` | внешний архив данных, не прогноз; `status=METADATA_ONLY` | значения не скачаны, в ансамбль не входят |

Правила:

1. Ансамбль использует внешний прогноз только как **point-прогноз**; его распределение (если
   нужно) — наша производная статистика: эмпирические квантили исторических ошибок SPF,
   отцентрированные на текущей медиане (`distribution_kind=DERIVED_STATISTIC`).
2. По умолчанию `publish_external_values=False`: в результате ансамбля внешний прогноз
   представлен кодом, survey-quarter, маппингом и атрибуцией, но без числового значения; при
   необходимости (внутренний аудит) значение можно включить флагом.
3. `is_third_party_forecast()` — только `EXTERNAL_FORECAST` c `third_party=true`; средние,
   веса, HHI, gap — статистики, не прогнозы (в т.ч. в `ensemble_diagnostics`).
4. `protocols/spf_metadata.json` содержит только метаданные (URL, хеши, coverage) и не содержит
   значений; это проверяется тестом. Значения SPF читаются из `data/raw/spf/spf_median.json`,
   который git-ignored (`.gitignore: /data/raw/`).

## 4. SPF: маппинг горизонтов и доступность

Опубликованные коды `medianGrowth.xlsx` (`drgdp2..drgdp6`) — пятиквартальные прогнозы:
`drgdp2` — текущий квартал опроса, далее +1…+4 квартала. Эмпирическая проверка на 1990Q1–2026Q3
(147 опросов): `drgdp2` коррелирует с ростом квартала опроса на 0.88, остальные коды не имеют
такой корреляции ни с одним отдельным кварталом, что согласуется с прогнозами на 1–4 квартала
вперёд. **Это объявленный маппинг проекта** (официальная документация SPF задаёт коды, но
точное соответствие «код → смещение» в ней не распарсено, docs/71 §3.3):

| Цель/horizon | Код SPF | Смещение квартала от квартала опроса |
|---|---|---|
| T2 h=0 | `drgdp2` | 0 |
| T2 h=1 | `drgdp3` | +1 |
| T2 h=2 | `drgdp4` | +2 |
| T2 h=4 | `drgdp6` | +4 |
| T2 h=3 | — | `drgdp5` есть в файле, но h=3 нет в сетке протокола |
| T1 | — | у SPF нет помесячного y/y CPI (только q/q annualised и Q4/Q4), инвентаризовать внутриквартальный путь запрещено |
| T3 | — | у SPF нет вероятности NBER-рецессии; «probability of a decline in real GDP» — другое событие, файл вероятностей не скачан |

Доступность (`spf_forecast`):

* origin — конец месяца; SPF считается доступным, только если месяц origin — **средний месяц
  квартала опроса** (февраль/май/август/ноябрь), т.е. origin совпадает с дедлайном SPF (протокол
  `origin_policy.spf_alignment`: сравнения с SPF идут на дате дедлайна, а не на произвольных
  концах месяцев);
* дополнительно origin должен быть ≥ `survey_date` + 14 дней (`SPF_MIN_LAG_DAYS`) — консервативная
  защита, т.к. точный день дедлайна не парсится (якорь `survey_date` = 1-е число среднего месяца);
* если источник/квартал/код недоступны — член исключается с явной причиной в
  `excluded_members` (`ORIGIN_IS_NOT_AN_SPF_DEADLINE_MONTH`, `SPF_VALUES_NOT_DOWNLOADED`,
  `SURVEY_QUARTER_NOT_IN_SPF_FILE`, `NO_SPF_HORIZON_CODE_FOR_H3`,
  `NO_MONTHLY_YOY_CPI_FORECAST`, `NO_NBER_RECESSION_PROBABILITY_AND_EVENT_MISMATCH`),
  а не подменяется нулём/интерполяцией.

Следствие для T2: на стандартных квартальных origin'ах h≥1 (третий месяц квартала) SPF
отсутствует; он входит только на origin'ах среднего месяца квартала (например, h=0 по протоколу
использует все концы месяцев, так что SPF участвует в части h=0-прогнозов, а также в специальных
SPF-выравненных прогонах на дату дедлайна). Это и есть штатная «поддержка отсутствующих
источников»: ансамбль работает на доступном подмножестве, веса перенормируются.

## 5. Веса

Все схемы возвращают неотрицательные веса с суммой 1 (`WeightResult`) и имеют prior-регуляризацию:
член без истории калибровки сохраняет prior-долю, а не исчезает. На этапе комбинирования вес
недоступного в данный момент члена пропорционально перераспределяется на доступных
(`renormalize_available`).

| Схема | Формула / правило |
|---|---|
| `EQUAL_WEIGHTS` | `w_i = 1/m` — контроль |
| `INVERSE_MSE` | `w_i ∝ 1/(MSE_i + floor)`, `MSE_i` — средний квадрат ошибки на истории; `floor = max(1e-12, 0.01·median(MSE))`; опциональное winsorizing ошибок (`robust_clip=0.99`) |
| `MIN_VARIANCE_SHRINKAGE_COVARIANCE` | `Σ = (1-s)S + s·diag(S) + ridge·tr(Σ)/m·I` (Ledoit-Wolf-подобное сжатие к диагонали, `s=0.5`); веса — решение `min w'Σw` при `w≥0, Σw=1` проекционным градиентом на симплексе; при < m+2 полных наблюдений — fallback на inverse-MSE (помечается `method=INVERSE_MSE_FALLBACK_CORRELATION`) |
| `BAYES_DIRICHLET_UPDATE` | на каждом прошлом origin «победитель» — член с минимальной абсолютной ошибкой (tie делятся); счётчики `wins_i`; апостериорное среднее `(α0·prior + wins)/Σ`; `decay` геометрически дисконтирует старые origin'ы; один катастрофический origin не обнуляет хорошего члена |
| `ADAPTIVE_HORIZON_REGIME_ERROR_CORRELATION` | `w ∝ 0.45·inverse-MSE + 0.30·min-variance + 0.25·Bayes`; затем `w → (1-λ_h)w + λ_h·uniform`, `λ_h = min(0.5, 0.5·h/12)` (длиннее горизонт ⇒ меньше независимых наблюдений ⇒ сильнее сжатие к равновесному); при ≥4 исторических origin'ах текущего режима — смесь 50/50 с режим-специфичными весами |

Режим (regime) — **собственная наблюдаемая статистика**, а не хронология NBER: знак спреда
GS10−TB3MS по последнему опубликованному месяцу (`INVERTED_OR_FLAT` / `POSITIVE_SPREAD`).
NBER-даты не используются для классификации текущего режима, потому что публикуются с лагом
(иначе look-ahead). Слабые режимы (`UNKNOWN`) дают fallback на общие веса.

PIT-дисциплина калибровки (`history.py`):

* в историю попадают только origin'ы, чья цель **разрешена и известна до текущего origin**:
  для T1/T2 — дата первой публикации (винтаж) ≤ текущего origin, иначе период + лаг
  публикации; для T3 — конец интервала события + 12 месяцев ≤ текущего origin;
* фактические значения — первые публикации из `amfe.evaluation.actuals.actual_pair`; если слой
  оценки недоступен/значение не найдено — latest-лента с пометкой `LATEST_TAPE_FALLBACK` в
  `history.actual_sources`;
* калибровка внешнего члена (квантили ошибок SPF) использует те же правила: каждая историческая
  ошибка считается только по уже разрешённой цели (`as_of` = текущий origin).

### Объявленные константы (фиксируются хешем кода до оценки)

`ADAPTIVE_OPTIONS` (`src/amfe/ensemble/ensemble.py`):
`blend=(0.45, 0.30, 0.25)`, `shrink=0.5`, `bayes_decay=0.05`, `horizon_scale=12.0`,
`max_horizon_shrink=0.5`, `regime_weight=0.5`, `min_regime_observations=4`,
`prior_strength=0.02`, `robust_clip=0.99`; `DEFAULT_LOOKBACK = {T1:12, T2:8, T3:10}`,
`MIN_HISTORY_ROWS=4`. Если Lead хочет другие значения — это новая ревизия **до** регистрации
кандидата, не после просмотра результатов.

## 6. Смеси распределений и T3

Для T1/T2 результат ансамбля — точечный прогноз (взвешенное среднее доступных точек) и 19
квантилей **взвешенной смеси CDF**: та же кусочно-линейная CDF между 5% и 95% квантилями и
гауссовы хвосты, что в `amfe.evaluation.distributions`. Равновесный ансамбль делегирует
`mixture_quantiles` слоя оценки (бит-в-бит, проверено тестом); произвольные веса считаются тем же
алгоритмом с весами (`weighted_mixture_quantiles`). Средние квантили членов не усредняются —
это было бы неверной смесью.

Для T3 — взвешенный **линейный пул** вероятностей (по аналогии с event-пулом протокола);
опционально доступен log-odds пул (явно помечается). Вероятность клиппируется в [1e-4, 1-1e-4];
клиппирование log-score [0.01, 0.99] остаётся на слое оценки.

Выход (`ensemble_forecast`/`candidate_forecast`) содержит:

```
candidate_id, target, origin, horizon,
point | None, quantiles[19] | None, probability | None,
data_class ("REAL_TIME" iff все использованные члены REAL_TIME, иначе PSEUDO_REAL_TIME),
member_data_classes, members, member_weights (сумма 1), member_weights_all,
member_kinds, distribution_members, point_members, probability_members,
excluded_members (причины), weight_method, weight_diagnostics, effective_n, history,
external_forecasts (без значений по умолчанию, с атрибуцией), external_sources, notes
```

`data_class` внешнего SPF-прогноза — REAL_TIME (это опубликованный до origin прогноз), но
итоговый класс ансамбля понижается, если хоть один внутренний член PSEUDO_REAL_TIME. Для T1
поле `quantiles` всегда есть, если есть хотя бы один распределённый член; иначе `None` с пометкой.

## 7. Контрольные ансамбли и диагностика

| id | Роль |
|---|---|
| `ENSEMBLE_EQUAL` | контроль: равные веса, смесь распределений |
| `ENSEMBLE_INVERSE_MSE` | контроль: inverse-MSE |
| `ENSEMBLE_BAYES` | контроль: байесовское обновление весов |
| `ENSEMBLE_ADAPTIVE` | основной кандидат: ошибка + корреляция + Байес + горизонт + режим |

`ensemble_diagnostics(result)` — производные статистики для отчёта: HHI, эффективное число
членов, доли весов внешних/внутренних, agreement (ст. отклонение точек членов), внутренне-внешний
gap, среднее/разброс вероятностей T3. Эти величины — `DERIVED_STATISTIC`, не прогнозы, и не
входят в потери.

## 8. API и пример

```python
import sys; sys.path.insert(0, "src")
from amfe.ensemble import (
    ENSEMBLE_ADAPTIVE, ENSEMBLE_EQUAL, candidate_forecast, ensemble_forecast,
    ensemble_diagnostics, fit_weights, classify_member, spf_forecast,
)

# кандидат-ансамбль на один origin (формат совместим с tools/evaluate.py)
result = ensemble_forecast(
    ENSEMBLE_ADAPTIVE, "T2_GDP_GROWTH", "2015-06-30", 1, lookback=8,
)
result["point"], result["quantiles"], result["probability"], result["data_class"]

# короткий алиас с сигнатурой amfe.candidates.candidate_forecast (для раннера)
candidate_forecast(ENSEMBLE_ADAPTIVE, "T1_CPI_YOY", "2008-06-30", 1)

# веса на готовой истории (для оффлайн-анализа/симуляций)
weights = fit_weights(ENSEMBLE_BAYES, "T1_CPI_YOY", 1, rows)

# происхождение источника
classify_member("SPF_GDP_MEDIAN")   # -> EXTERNAL_FORECAST, third_party=True
spf_forecast("T2_GDP_GROWTH", "2008-05-31", 1)   # -> available=True, code=drgdp3
```

Для допуска: кандидат должен быть зарегистрирован (id, code_sha256, targets, horizons) до
оценки; `candidate_forecast` возвращает ровно те поля, что принимает `tools/evaluate.py`
(`point`, `quantiles`, `probability`, `data_class`). Раннер `tools/run_real_evaluation.py`
сейчас вызывает `amfe.candidates.candidate_forecast`; чтобы гонять ансамбли, Lead должен
подключить `amfe.ensemble.candidate_forecast` (изменение вне моей write-scope).

## 9. Тесты

```powershell
python tests/test_ensemble.py
```

Результат на 2026-11-12: `Ran 48 tests ... OK` (~6 с; системный Python 3.12, только numpy).
Классы тестов:

* `WeightSchemes` (14): неотрицательность/сумма 1; inverse-MSE упорядочивает; missing member
  через prior; устойчивость к выбросу; PSD и обусловленность shrinkage-ковариации;
  min-variance веса уменьшают дисперсию портфеля; fallback при короткой истории; байесовское
  обновление и его устойчивость; дисконт; сжатие к равновесию на длинном горизонте; режимные
  веса; перераспределение весов; валидация.
* `DistributionMixtures` (5): равенство равновесной смеси протокольной `mixture_quantiles`
  (≤1e-10); монотонность и попадание в конверт членов; вырожденные веса; пулы вероятностей;
  диагностика смеси.
* `SourceClassification` (3): виды источников; RTDSM metadata-only и не член ансамбля; SPF
  значения не в репозитории/метаданные без значений/каталог git-ignored.
* `SpfMapping` (5): маппинг drgdp(h+2); доступность только на дедлайне; отсутствие h=3/T1/T3;
  отсутствующий файл не подменяется; детекция квартала опроса.
* `HistoryCalibration` (6): PIT-правила first-publication для T1/T2 и 12-мес. лаг T3;
  выравнивание ошибок; `fit_weights` по истории и fallback; наблюдаемый режим.
* `EnsembleCombination` (7): точка+смесь; перераспределение весов; T3-пул; data_class;
  внешний член и скрытие значений; диагностика; ошибки неверных входов.
* `HarnessCompatibility` (3): выход принимается функциями `tools/evaluate.py` (CRPS/RMSE,
  Brier/log-score); inverse-MSE улучшает held-out MSE на синтетике.
* `LocalEnsembleSmoke` (5, skip без `data/raw`): T1 равновесный и адаптивный с историей; T2 со
  SPF только на дедлайне; T3-вероятность; алиас и детерминизм кэша.

## 10. Ограничения и открытые вопросы

1. **SPF values ещё не «включены» в скоринг.** Значения скачаны локально
   (`data/raw/spf/spf_median.json`) и читаются ансамблем, но:
   * официальный маппинг `drgdp2..6` → смещение квартала не подтверждён по документации SPF
     (docs/71 §3.3 требует сверки); текущий маппинг объявлен проектом и проверен эмпирически;
   * точный день дедлайна SPF не парсится (якорь + 14 дней — консервативно);
   * SPF не входит в RECESS/score-слой; чтобы оценить ансамбль со SPF на W1/W2, нужен
     утверждённый mapping-документ и регистрация кандидата (Lead).
2. **T1 не поддерживает SPF** (нет помесячного y/y) — ансамбль T1 чисто внутренний; **T3** —
   SPF не имеет NBER-вероятности (файл вероятностей не скачан, событие другое).
3. **RTDSM**: значения не скачаны (metadata-only probe, docs/71). RTDSM — винтажный канал
   данных, не прогноз; он не может быть членом ансамбля. Остаётся: скачать под лицензией,
   использовать для actuals/входов моделей.
4. **Горизонты**: у SPF есть `drgdp5` (h=3), но в сетке протокола T2 нет h=3; у T1 нет
   SPF-эквивалента ни на одном горизонте. Комбинация «SPF + T2 h∈{0,1,2,4}» — весь доступный
   охват.
5. **Калибровочные факты**: первые публикации из квартального винтажного архива — приближение
   точной даты релиза (docs/75); если первая публикация недоступна, используется latest-лента с
   пометкой. Внутри истории T3 — 12-месячный лаг разрешения события (консервативно; протокол
   допускает 24-месячный дедлайн полноты).
6. **Режим** — наша статистика (знак спреда доходностей по последней опубликованной ставке), а
   не NBER; это сознательный выбор против look-ahead. Альтернативные режимы (безработица,
   инфляция) не реализованы.
7. **Производительность**: история весов пересчитывается на каждом origin; кэш прогнозов
   помогает, но полный прогон W1+W2 для T3 может занимать минуты (PROBIT/SAHM на каждый
   исторический origin). Это ограничение скорости, не корректности; для массовой оценки
   желателен предрасчёт панели прогнозов (future task).
8. **Веса не по CRPS**: и внутренние, и внешние члены взвешиваются по точечной ошибке (T1/T2)
   или Brier-ошибке (T3), распределения смешиваются после. CRPS-взвешивание — возможный вариант
   следующей ревизии (требует объявления до регистрации).
9. **Публикация внешних значений**: по умолчанию в результате нет числового SPF-прогноза, только
   атрибуция и маппинг. Любой отчёт с SPF обязан нести атрибуцию Philadelphia Fed; сырые
   значения не публикуются.

## 13. Что осталось (следующие шаги)

1. **Регистрация кандидатов-ансамблей** (Lead, `protocols/candidates_<дата>.json`): id, хеши из
   §11, targets/horizons, контрольные ансамбли; после этого — прогон C1–C6 через
   `tools/evaluate.py` (нужно подключить `amfe.ensemble.candidate_forecast` в раннер).
2. **SPF values в скоринг**: утвердить mapping-документ (`drgdp2..6` → h0..4) и способ
   определения точного дедлайна; после этого SPF-член может участвовать в оценке T2 на
   SPF-выравненных origin'ах.
3. **RTDSM**: скачать значения под лицензией → использовать как винтажный канал actuals/входов
   моделей; членом ансамбля он быть не может по определению (не прогноз).
4. **Горизонты**: T2 h=3 отсутствует в протоколе (SPF `drgdp5` не используется); T1 SPF не
   поддерживает; расширение возможно только новой версией протокола.
5. **CRPS-взвешивание** и предрасчёт панели прогнозов для скорости — кандидаты на следующую
   ревизию (не менять после просмотра результатов).
