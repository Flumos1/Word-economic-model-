## 2. Схема пайплайна

```
                       (только чтение, без сети)
  protocols/…  ────────────────┐
  registry/forecasts.jsonl ────┤
  protocols/data_log.json ─────┤   tools/weekly_report.py ──► build/weekly_report.md
  protocols/r2_gate_report.json┘        (детерминированный Markdown-снимок)

  tests/test_*.py ─────────────► tools/regression_report.py ──► protocols/regression_report.json
                                     (каждый файл — отдельный процесс)      + Markdown-строка в stdout

  .github/workflows/weekly-report.yml: schedule (Mon 06:00 UTC) + workflow_dispatch
                                     └─► артефакт amfe-weekly-<run_id> (build/ + regression_report.json, 90 дней)
```

Оба инструмента **ничего не коммитят** и не меняют файлы протокола/реестров: бюллетень — снимок
закоммиченного состояния, регрессия — отчёт о прогоне. Это соответствует правилу протокола:
замороженные документы не переписываются задним числом, а состояние фиксируется отдельными
отчётами.

## 3. Недельный бюллетень (`tools/weekly_report.py`)

Входы (все — локальные файлы; отсутствие или поломка любого входа не падает, а попадает в раздел
«Риски»):

- `protocols/evaluation_protocol_v4.json` (+ `.sha256`) — протокол v4, окна, критерии C1–C6,
  правила стадий, forward_registry;
- `protocols/r3_specification.json` (+ `.sha256`) — R3 1.0.1 (FROZEN), open_items, freeze-hashes;
- `protocols/nf_sim_thresholds.json` (+ `.sha256`) и `protocols/comparator_composition_*.json`
  (+ `.sha256`) — замороженная таблица порогов и состав компаратора;
- `protocols/candidates_2026-11-11.json` — зарегистрированные кандидаты;
- `protocols/first_real_evaluation_report.json` — последняя реальная оценка (кандидат, data_class,
  admission, C1–C6, множественность);
- `protocols/data_plan.json`, `protocols/data_log.json` — план дат и журнал загрузки (7 latest +
  6 vintage-рядов, `vintage_check`, chunks, merged);
- `protocols/r2_gate_report.json` — ворота R2 (178 пар / 73 до 2000 / 0 mismatches);
- `registry/forecasts.jsonl` — forward-журнал (сейчас 0 записей).

Разделы бюллетеня: 1) сводка; 2) данные и винтажи (таблицы latest/плотных винтажных наборов и ворот
R2); 3) протокол, R3 и цепочка хешей (комутированные пины и статус `OK`/`РАСХОЖДЕНИЕ`, а также
сверка ссылок из отчёта оценки с текущими файлами); 4) кандидаты и стадии допуска; 5) критерии
C1–C6 с фактическими числами (relative loss, adjusted p, статусы C4, C6); 6) forward registry;
7) риски; 8) следующие шаги; 9) источники и LF-normalised sha256.

Детерминизм и офлайн:

- в теле отчёта нет текущего времени и длительностей: единственная дата — `--date` (по умолчанию
  сегодня UTC); одинаковые файлы + одинаковая дата → **байт-идентичный** Markdown;
- все списки сортируются, числа печатаются с фиксированной точностью, хеши — LF-normalised (в той
  же форме, что пины проекта);
- сеть не используется (модуль не импортирует `urllib`/`requests`/`socket`; проверяется тестом);
- отчёт **не присваивает** статусы кандидатов — только сообщает записанные в отчёте оценки статусы
  и правило стадий; итоговая строка так и говорит.

Запуск:

```
python tools/weekly_report.py --date 2026-11-12 --out build/weekly_report.md
python tools/weekly_report.py --root <копия репозитория> --date 2026-11-12   # Markdown в stdout
```

## 4. Сводная регрессия (`tools/regression_report.py`)

- находит все `tests/test_*.py` (сортировка по имени), запускает каждый **отдельным процессом**
  `python tests/test_x.py` с рабочим каталогом корня репозитория и таймаутом (по умолчанию 900 с);
- собирает по каждому файлу: `file`, `status` (`passed`/`failed`/`timeout`), `returncode`,
  `duration_seconds`, число `skipped` (из `OK (skipped=N)`), `output_tail` для упавших;
- пишет `protocols/regression_report.json`: `report_id = AMFE-REGRESSION-REPORT`, `generated_at`,
  `python`, `totals {total, passed, failed, skipped, duration_seconds}`, `passed`, `failures`,
  `markdown`, `tests[]`;
- печатает одну Markdown-строку для CI (`**AMFE regression: N/N passed** — T s (… skipped tests)`
  или список упавших) и опционально `--markdown-out`;
- **exit code 0 только если все файлы зелёные**; пустой каталог и отсутствующий корень — отчёт без
  падения, exit 1 (нечего проверять / не найдено).

Запуск:

```
python tools/regression_report.py \
  --json-out protocols/regression_report.json --markdown-out build/regression_report.md
```

Ограничение границ: инструмент проверяет ровно то, что лежит в рабочем дереве (в CI — то, что
закоммичено). Отчёт о прогоне содержит `generated_at` и длительности, поэтому не является
байт-стабильным документом — это артефакт прогона, а не замороженный отчёт.

## 5. CI

Новый workflow `.github/workflows/weekly-report.yml` (`schedule: 0 6 * * 1` — понедельник 06:00 UTC;
`workflow_dispatch`; `permissions: contents: read, actions: read`; concurrency-группа `weekly-report`):

1. `python -m pip install --quiet numpy` — тесты слоя моделей/оценки импортируют numpy; без него
   regression-шаг падал бы на import вместо проверки кода;
2. восстановление последнего приватного артефакта `data-refresh` (`gh run download`, `data/raw/`
   git-ignored): часть тестов проверяет локальный PIT-слой и без данных скипается, а
   `tests/test_evaluation_layer.py` импортирует свой модуль только при наличии `data/raw`; с
   восстановленными данными регрессия прогоняет полный набор. Сырые данные остаются приватными —
   артефакт читается внутри раннера, ничего не коммитится; если успешного артефакта нет, шаг
   предупреждает и data-зависимые тесты скипаются;
3. `python tools/weekly_report.py --date "$(date -u +%F)" --out build/weekly_report.md`;
4. `python tools/regression_report.py --json-out protocols/regression_report.json
   --markdown-out build/regression_report.md` (падение любого теста → шаг и run красные);
5. Markdown-строка регрессии дописывается в `$GITHUB_STEP_SUMMARY` (`if: always()`);
6. артефакт `amfe-weekly-<run_id>`: `build/` (бюллетень + Markdown-строка) и
   `protocols/regression_report.json`, хранение 90 дней (`if: always()`).

Существующий `accounting-regression.yml` и остальные workflows не изменялись; новый workflow
ничего не коммитит (артефакт — приватный, как и для сырых данных).

- офлайн: в исходнике инструмента нет сетевых модулей;
- деградированные входы: пустой корень → отчёт с рисками без плейсхолдеров; пустой forward-журнал —
  нормальное состояние первого дня; невалидная JSONL-строка — риск, не падение; записи журнала
  считаются, если они есть;
- CLI: `--out` пишет ровно то же, что `build_markdown`, и возвращает 0; невалидная `--date` → 2.

`python tests/test_regression_report.py` — 5 тестов на синтетическом каталоге:

- зелёный набор → exit 0, `passed=true`, пропуски посчитаны (`skipped=1`);
- падающий тест → exit 1, `failures` содержит файл, `output_tail` содержит `AssertionError`;
- пустой каталог → отчёт без падения (`total=0`, exit 1, «no test files found»);
- отсутствующий корень → отчёт без падения;
- структура JSON (все поля, pattern, timeout, UTF-8/ISO-время).

Полная локальная регрессия этим инструментом (2026-11-12, рабочее дерево с параллельными
in-progress задачами): **32/34 passed за 42.3 s**; упали только два ещё не закоммиченных

они вне границ этой задачи; все 30 закоммиченных тестов и оба новых теста зелёные. После

зелёным.

## 7. Ограничения

- Бюллетень — **статусный снимок**, а не оценка: он не присваивает кандидатам статусы, стадии и не
  заменяет harness допуска; §5 просто пересказывает числа замороженного протокола.
- Отчёт читает только локальные файлы; сеть не используется, поэтому он не проверяет свежесть
  данных — за это отвечает workflow `data-refresh` и журнал `protocols/data_log.json`.
- В CI нет сырых данных (`data/raw/` git-ignored): workflow восстанавливает последний успешный
  приватный артефакт `data-refresh`; если артефакта нет (истёк срок 90 дней / ещё не было
  успешного прогона), data-зависимые тесты скипаются, а не падают — кроме уже известного
  `test_evaluation_layer.py`, который без данных не импортирует свой модуль (это чужая тестовая
  особенность, не правилась в этой задаче).
- Workflow зависит от доступности приватного артефакта данных (retention 90 дней, регулярный
  `data-refresh` его продлевает); при смене артефактной схемы шаг восстановления нужно обновить.
- Расхождения цепочки хешей и ссылок отчёта оценки выводятся как риски, но **не исправляют**
  замороженные файлы: обновление R3/композиции и перезапуск оценки — отдельное решение владельца.
- `protocols/regression_report.json` не коммитится: это артефакт прогона с `generated_at` и
  длительностями; в репозитории он устаревал бы мгновенно.
- Недельный отчёт не заменяет независимую проверку и не публикуется как научный результат.
