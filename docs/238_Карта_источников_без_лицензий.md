## 1. Правило владельца и категории

**Решение владельца 2026-11-26 — `NO_PAID_LICENCES`.** Дословно из `org.json.owner_policy`:

> «Владелец: лицензии/платные подписки пока не используем; любые данные ищет и приносит
> OSINT-агент из открытых источников S1–S3.»

Режим: `OSINT_ONLY`, `subscriptions = 0`, S4 (лицензированный датасет) — `DEFERRED`, S5
(закрытый/непубличный) — запрещён всегда. Данные и новые источники ищет и документирует **только
`osint-scout`**; остальные роли данные не ищут. Платный или закрытый источник → `NOT_FETCHED` с
блокером, без обхода и без «примерной реконструкции»; если нужна лицензия — фиксируется предложение
владельцу, работа по источнику останавливается.

Категории этой карты (по правилу владельца, а не по статусу реестра):

| Категория | Значение | Что можно делать |
|---|---|---|
| **FREE_PUBLIC** | открытые публичные данные: public domain / CC / открытая лицензия с атрибуцией; доступа по договору не требуется | искать OSINT-путём в классах S1–S3 (маршруты — §7), загружать только после записи условий и провенанса; цитировать как наблюдение — только если источник `VERIFIED` и только в зафиксированном срезе |
| **MANUAL_OR_GATED** | доступ формально открыт, но использование требует решения человека: нестандартная лицензия (NC-SA), не подтверждённые условия, ручное извлечение таблиц | **не использовать** до решения владельца/человека; `NOT_FETCHED` + блокер; можно читать открытую аннотацию как S3 (grade B/C), но не цитировать как наблюдение |
| **PAID_LICENCE** | подписка/договор/платный API (S4/G2) | **не используем** до отдельного решения владельца; `NOT_FETCHED`, никаких чисел из источника, никакой замены «похожими» данными S3 |

Связь классов: `S1–S3` разрешены и соответствуют `G0` (public) / `G1` (free registration);
`S4/G2–G3` — `DEFERRED`; `S5/G4` — запрещён. Важно: **открытая аннотация платного отчёта — это
S3/B, а не доступ к S4**: читать можно, цитировать как наблюдение — нельзя.

решение о покупке. «Примерно то же» из S3 вместо лицензионного источника **запрещено** (RL-19/RL-24).

реконструкций».

## 8. Что можно и что нельзя цитировать — свод правил

1. **Наблюдение** = значение из запиненного файла `VERIFIED`-источника в его зафиксированном
   срезе (§4). Всё остальное — метаданные, условия, аннотации.
2. `CATALOGUED`/`PARTIAL` — нельзя цитировать как наблюдение, даже если цифра «широко известна»;
   можно писать «источник каталогизирован, условия прочитаны/не прочитаны».
3. `MANUAL_OR_GATED` и `PAID_LICENCE` — нельзя цитировать как наблюдение вообще; для платных нельзя
   и «примерно по памяти» — это обход правила владельца (RL-19/RL-24).
4. Открытая аннотация/пресс-релиз платного отчёта — S3 grade B/C, только контекст; цитата ≤300
   символов, без воспроизведения таблиц.
5. Любая публикация — производные статистики (`OPEN`/`ATTRIBUTION`) с атрибуцией каждому источнику;
   `RESTRICTED`/`UNKNOWN` не публикуются (лицензионная матрица docs/205).
6. Если условий источника нет в журнале — писать **«не проверено»**, не домысливать.

## 10. Ограничения и что осталось

1. **Классификация — документальная**, по фактам реестра/докета/лицензионных записей; это не
   юридическое заключение. Для 7 источников часть evidence отсутствует (докет docs/205):
   условия `OPEC`, `USDA_PSD`, `USDA_FAS_EXPORT_SALES`, `ICE_NYMEX_SETTLEMENTS`, `IEA`, `KPLER`,
   `VORTEXA` в журнале не зафиксированы — помечено «не проверено».
2. **Статусы реестра не менялись** (VERIFIED 5 / CATALOGUED 6 / NOT_DOWNLOADED 4). Поднять статус
   может только человек после реальной загрузки и провенанса; эта карта ничего не «промоутит».
3. **Платные источники не заменяются** открытыми «похожими» данными: недоступность settlement/OMR/
   real-time flows/фрахта зафиксирована как ограничение плана (§5), а не как повод для оценки.
4. **PIT-слой** для macro доступен через FRED/ALFRED (`vintage_support=full`) и BLS через ALFRED,
   но это `CATALOGUED`/`PARTIAL`: до загрузки и провенанса цитировать наблюдения нельзя. Для 1990–1996
   в проекте есть отдельный контур реконструкции PIT (docs/108/docs/166) — он не отменяет правила:
   это RECONSTRUCTED_PIT, а не новый `VERIFIED` источник.
5. **FAO NC-SA** и **OPEC manual** требуют решения человека; до него — `NOT_FETCHED` с блокером.
6. **Другие роли данные не ищут**: поиск и документация новых источников — только `osint-scout`
   (owner policy; RL-24). Нарушение → отчёт не принимается.
7. Следующий шаг для плана: закрыть evidence `USDA_PSD`/`USDA_FAS_EXPORT_SALES` (public domain,
   самый дешёвый канал для сои), затем FRED/ALFRED (PIT), затем решить по FAO/OPEC; платные — только
   через предложение владельцу.
