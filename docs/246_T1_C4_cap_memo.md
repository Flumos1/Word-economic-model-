# 246. T1 C4: фиксация потолка CANDIDATE (memo)

Дата: 2026-11-26. Плановый пункт [docs/207](207_План_до_конечного_продукта.md) §6 («03.12 — T1 C4 cap
memo»). Решение по существу принимает владелец; этот документ фиксирует факты, предлагает потолок и
условия его переоткрытия. Статусы не меняются: `RESEARCH_ONLY`, `admission=false`.

## 1. Факты (без пересказа «на веру»)

| Факт | Значение | Источник |
|---|---|---|
| Оценка по prereg 0.3 | C4 W1_EXT **FAIL**: относительная потеря **1,0774564** на **16** рецессионных началах | [docs/170](170_Оценка_по_предрегистрации_0_3.md), [docs/200](200_G4_решение_prereg_0_3.md) |
| Независимая проверка V2 | **NOT_CONFIRMED** | [docs/164](164_План_и_статус_проекта.md) |
| Предрегистрация 0.3 | **PROPOSED**, не активирована | [docs/164](164_План_и_статус_проекта.md) |
| Решение по G4 | **B** — не активировать 0.3, зафиксировать отрицательный результат | [docs/206](206_G4_решение_B.md) |
| Замороженный протокол | **v5.0.1 FROZEN**, SHA `48c2f6a1…`; C4 считается на W1_EXT | [docs/164](164_План_и_статус_проекта.md) |
| Текущий статус T1 | `CANDIDATE` (потолок не назначен формально) | [protocols/registry](../protocols) |

Вывод из фактов: критерий C4 по замороженному протоколу **не выполняется**, независимая проверка
отрицательная, а предрегистрация, по которой получен результат, официально не активирована. Значит
T1 не может претендовать ни на `LIMITED_DEPLOYMENT`, ни на `ACTIVE`.

## 2. Предлагаемое решение

**Потолок T1 = `CANDIDATE` до появления новых данных или нового дизайна оценки.**

Расшифровка:

1. T1 остаётся `CANDIDATE` (не понижается до «провала» и не повышается до допуска).
2. `LIMITED_DEPLOYMENT` и `ACTIVE` для T1 **запрещены** до выполнения условий §4.
3. Это решение **не влияет** на C6: гейт идёт по календарю релизов, а не по желанию ускорить
   (сейчас **0/12** прогнозов, **1/4** периода).
4. Продукт (сценарии, Client Pack, Simulator, API) продолжает работать и продаваться как
   `RESEARCH_ONLY`; нигде не заявляется точность T1.

## 3. Почему не «чинить» сейчас

- «Улучшить» C4 без новых данных = подгонка под известный результат: это нарушает правило
  проекта (не переписывать прошлые отчёты, не подгонять под исход).
- Сменить окно/метрику «после факта» = ослабить критерий; замороженный протокол v5.0.1 это
  запрещает.
- Активировать prereg 0.3 задним числом = решение, которое владелец уже отклонил (вариант B).

Поэтому корректный шаг — **зафиксировать потолок и условия выхода**, а не улучшать цифру.

## 4. Условия переоткрытия (все, а не одно)

1. **Новые данные**: расширение PIT-окна и/или новые ревизии, которых не было при оценке.
2. **Новый дизайн**: отдельная предрегистрация (например, 0.4) с SHA-256, зафиксированная
   **до** прогона, с явной мощностью и правилом multiplicity.
3. **Независимая проверка** нового дизайна (не тем же исполнителем).
4. **Прогон по замороженному протоколу** без изменения метрики C4 задним числом.
5. **Запись результата** в журнал решений и в реестр — включая отрицательный результат.

До выполнения всех пяти пунктов потолок остаётся `CANDIDATE`.

## 5. Что запрещено

- менять `protocols/evaluation_protocol_v4.json`, v5, R3, NF-SIM, comparator, prereg 0.3;
- переписывать docs/170 и прошлые отчёты;
- объявлять «C4 пройден» по подвыборке, другому окну или другой метрике;
- использовать T1 для рекламных утверждений о точности/вероятности;
- ускорять C6 ради красивого статуса.

## 6. Что нужно от владельца

1. Подтвердить потолок `CANDIDATE` для T1 (или предложить иной — но с явным обоснованием).
2. Подтвердить, что новый дизайн 0.4 готовится **после** данных, а не вместо них.
3. Подтвердить, что C6 не ускоряется.

## 7. Влияние на план

| Веха | Влияние |
|---|---|
| M1 (19.12) | нет: продаём сценарии, не точность |
| M2 beta (Q1 2027) | требуется, чтобы статус T1 оставался честным в клиентских материалах |
| M3 v1 (Q2 2027) | `LIMITED_DEPLOYMENT` — только если §4 выполнен; иначе остаётся `RESEARCH_ONLY` |
| C6 | без изменений: 0/12, 1/4; ориентир ~май 2027 |
