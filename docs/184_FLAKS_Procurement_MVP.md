## 3. Модель

### 3.1 TCO (UC-13)

```
composite_risk = 0,45·country_risk + 0,30·financial + 0,15·supply + 0,10·compliance
TCO/ед. = price
        + freight_per_unit
        + price · duty_rate                         (пошлина страны)
        + price · composite_risk · 0,12             (риск-премия)
        + price · defect_ppm/10⁶ · 3,0              (переделка/возвраты)
        + price · (1 − OTIF) · 0,35                 (поздняя поставка)
        + price · lead_days/365 · 0,09              (замороженный капитал)
```

Все коэффициенты (`RISK_COST_RATE=0,12`, `REWORK_MULTIPLIER=3,0`, `LATE_PENALTY_RATE=0,35`,
`CARRYING_RATE=0,09`) публикуются в `macro.derived` и меняются только в коде с тестами — это
допущения порядка величины, не оценки по данным.

### 3.2 Скоринг (UC-13)

Нормализация — «best-in-class» **внутри категории** (относительная, а не абсолютная):

| Компонента | Формула | Направление |
|---|---|---|
| `price` | `min_price / price` | меньше — лучше |
| `tco` | `min_tco / tco` | меньше — лучше |
| `risk` | `(1 − composite_risk) / max(1 − composite_risk)` | меньше — лучше |
| `quality` | `0,5·min(defect)/defect + 0,3·OTIF/max(OTIF) + 0,2·audit/max(audit)` | больше — лучше |
| `delivery` | `min(lead_days) / lead_days` | меньше — лучше |

`score = Σ_k w_k · component_k`, вклад каждой компоненты `w_k·component_k` публикуется в
`contributions` пп и **суммируется ровно в балл** (проверяется тестом и `checks`). Классы:
A ≥ 0,92 «предпочтительный», B ≥ 0,82 «допустимый», C < 0,82 «рискованный».

Веса по умолчанию: `price 0,20`, `tco 0,30`, `risk 0,20`, `quality 0,20`, `delivery 0,10`.
Переопределение: `--weights price=0.2,tco=0.3,risk=0.2,quality=0.2,delivery=0.1`; сумма обязана
быть 1,0 (допуск 1e-9), иначе `WeightsError` → exit 2.

### 3.3 Сценарии (UC-14)

Драйверы сценария и их источники:

| Драйвер | Как получается | Источник |
|---|---|---|
| `cpi_pp` (эффективный сдвиг) | `cpi_delta_pp + oil_delta_pct · 0,015` | фид T1 + допущение oil→CPI |
| `oil_price_pct` (эффект на цены) | `oil_delta_pct · 2,364 / 100` | линеаризация агрегата моста цены |
| `freight_price_pct` | `freight_delta_pct · 0,35` | допущение доли транспорта |
| `fx_pct` | сдвиг курса валют закупок к EUR | объявленный шок |

| id | ΔCPI, пп | Нефть, % | Фрахт, % | FX, % | Объём, % |
|---|---|---|---|---|---|
| `base` | 0 | 0 | 0 | 0 | 0 |
| `inflation_plus_1pp` | +1,0 | 0 | 0 | 0 | 0 |
| `oil_plus_20` | +0,30 (из нефти) | +20 | +6 | 0 | 0 |
| `hormuz_6m` | +1,5 (+1,877 из нефти) | +125,141 | +35 | 0 | −2 |
| `stress_combo` | +2,0 (+0,6 из нефти) | +40 | +15 | +5 | −5 |

Цена категории: `Δp_c = Σ_k incidence_{c,k} · driver_k` (инцидентности — объявленная таблица:
например, полимер 2,10 по нефти, логистика 1,00 по фрахту).

Бюджет: для каждого **действующего** контракта
`forecast = base·(1+applied/100)`, объёмный эффект — отдельно:
`with_volume = forecast·(1+Δобъём/100)`. Интервал — перенос 5–95 прогноза CPI
(`cpi ± (q − point)`), конвенция docs/178 §4; на нижней границе срабатывает `floor_zero` (все 8
контрактов демо), на верхней — `cap` там, где он ниже сырой индексации.

### 3.4 Индексация контрактов (UC-16)

```
raw     = cpi_share·Δcpi + ppi_share·(oil_inc·Δoil_price + freight_inc·Δfreight_price) + fx_share·Δfx
applied = min(raw, cap), затем max(applied, 0) если floor_zero
indexation = base · applied/100
```

Флаги: `CAP_BINDING` (сырая индексация выше cap), `FLOOR_BINDING` (отрицательная сырая при
нулевом поле). `индексация` и прогноз публикуются по каждому договору; фиксированная доля
`1 − cpi − ppi − fx` показывается явно (в демо у части контрактов она равна 0,2–0,3).

## 6. Детерминизм

Фиксированы: порядок категорий (объявленный), порядок поставщиков (балл по убыванию, затем `id`),
порядок сценариев, порядок контрактов (`category`, `supplier_id`), `sort_keys=True`, `indent=1`,

двух прогонов побайтово.

## 7. Ограничения

- **Демонстрационные данные**: поставщики, цены, контракты и таблицы риска/пошлин вымышлены;
  выводы о «лучшем поставщике» на них — иллюстрация механики, а не рыночный факт.
- **Веса — управленческое допущение**: другой набор весов меняет порядок (это проверено тестом
  `test_price_heavy_weights_change_the_recommendation`); «правильных» весов нет, есть объявленные.
- **Нормализация относительна**: компоненты считаются внутри категории, поэтому при смене состава
  участников меняются все баллы; абсолютного «качества» балл не измеряет.
- **TCO — формула, не учёт**: нет скидок за объём, бонусов, ретро, штрафов, НДС, таможенного
  оформления, складских мощностей и стоимости переключения; это не бухгалтерская себестоимость.
- **Пошлины и риск страны — допущения**: таблица `COUNTRIES` не является таможенным тарифом и не
  взята из рейтинговых агентств; для пилота её нужно заменить реальными источниками (см. §9).
- **Сценарии линейны**: CPI→цена 1:1, нефть→цена линеаризована по агрегату моста цены; шаги
  больше ~30 % выходят за линеаризацию, и числа становятся индикативными, а не прогнозными.
- **Интервал только по CPI**: неопределённость нефти, фрахта и FX в интервал не входит (она
  публикуется точкой); 5–95 берётся из фида T1, а не пересчитывается заново.
- **Индексация без юридического слоя**: формулировки договора («индекс потребительских цен
  Евростата», база, дата, оспаривание) не разбираются; применяется объявленная модель cap/floor.
- **«Экономия» — иллюстрация**: перевод всего объёма на min-TCO поставщика игнорирует
  концентрацию риска, мощность, квалификацию и сроки; это верхняя граница, а не план.
- **Не допуск**: `admission=false`, `RESEARCH_ONLY`; никаких заявлений о превосходстве или точности.

## 8. Тесты

`python -m unittest tests.test_flaks_procurement -v` — **44 теста**, офлайн, без внешних чтений
(интеграционные проверки якорей пропускаются, если артефактов `build/` нет):

- набор: встроенное демо валидно и синтетично, фикстура совпадает с демо и даёт идентичный отчёт,
  `--dump-suppliers` даёт валидный набор;
- веса: сумма 1, объявленный состав, отказ при сумме ≠ 1 / неизвестном / нулевом весе, смена
  лидера при price-heavy весах, балл = взвешенная сумма компонент;
- скоринг: вклады суммируются в балл, компоненты в (0,1], лучший по компоненте = 1,0, порядок
  детерминирован (балл, затем `id`), классы по порогам, риск-композит и качество пересчитаны вручную;

  пересчитаны, пошлина > 0 только вне ЕС, «дешёвая цена ≠ дешёвый TCO» (плёнка, полимер), экономия

  сумма действующих контрактов, CPI-сценарий = инцидентность CPI, нефтяной сценарий сильнее бьёт по
  полимеру/плёнке/логистике, чем по металлу, `hormuz_6m` использует сдвиг моста цены и упирается в
  cap, интервал упорядочен и `floor_zero` срабатывает на нижней границе, объёмный эффект отделён,
  floor блокирует отрицательную индексацию, доли контракта в сумме 1;
- fail-closed: реальные данные, битая схема, 16 видов порч полей (17 кейсов: цена, объём, лид, OTIF,

## 9. План пилота (4 шага, 2–3 недели)

| Шаг | Что делаем | Данные | Выход | Критерий готовности |
|---|---|---|---|---|
| 0. Подготовка (1–2 дня) | NDA, шаблон выгрузки, анонимизация, `source_class="anonymized_fixture"` | 3–6 категорий, 2–4 поставщика на категорию, 1 год факта | заполненный JSON-набор | набор проходит валидацию; номера договоров/имена заменены |
| 1. Калибровка (1 день) | воркшоп с CFO/закупками по весам и порогам cap/floor | веса, политика классов A/B/C | зафиксированные веса в отчёте | веса согласованы и сумма = 1; лидеры объяснимы построчно |
| 2. Бэктест (3–5 дней) | прогон сценариев на прошлый год, сверка с фактом | факт бюджета, фактические индексации | MAE бюджета, список сработавших cap/floor | ошибка бюджета в объявленной полосе; все расхождения объяснены |
| 3. Пилот (1–2 недели) | 2–4 категории в живом цикле, ежемесячный отчёт | выгрузки по мере заключения договоров | отчёт CFO + журнал решений | решение go/no-go по объявленным критериям |

Что нужно заменить перед пилотом (сейчас — допущения):

| Блок | Сейчас | Заменить на |
|---|---|---|
| пошлины | `COUNTRIES[*].duty_rate` | таможенный тариф ЕС (TARIC) / условия соглашений |
| риск страны | `COUNTRIES[*].risk` | страновые индексы (OECD CRP, World Bank WGI) или внутренний скоринг |
| цены/фрахт | цены контрактов | фактические счёта + котировки перевозчиков |
| CPI/нефть | якоря фида и моста цены | те же артефакты, обновляемые по расписанию |
| качество | `defect_ppm`, `OTIF`, аудит | данные входного контроля и рекламаций |

Критерии успеха пилота: (1) отчёт воспроизводим побайтово на тех же данных; (2) каждое число
объясняется формулой из §3 без обращения к автору; (3) бюджет-прогноз попадает в объявленную
полосу на ретро-прогоне; (4) ни одна строка данных клиента не покидает его контур (в репозиторий
попадает только агрегат и код); (5) CFO подтверждает, что отчёт отвечает на вопросы UC-13/14/16.
