## 0. Короткий вывод

1. Пилот закрывает разрыв между «демо-набором» docs/184 и реальной выгрузкой: клиент заполняет
   два CSV/XLSX по шаблону, инструмент проверяет схему, типы, обязательные поля, дубликаты, единицы
   и выбросы, анонимизирует идентификаторы и прогоняет **существующий** скоринг/TCO/бюджет без
   правок модели.
2. Все артефакты пилота выводятся в `build/flaks_pilot/<scenario>/`: JSON, Markdown, DOCX для CFO и
   manifest с SHA-256. Исходные файлы не копируются; в манифесте только хеши, без имён.
3. Анонимизация выполняется **до** расчёта: `ANON-SUP-NNN` / `ANON-CT-NNN` и «Анонимный поставщик
   NNN»; leak-scan проверяет JSON, Markdown и XML DOCX и останавливает прогон при утечке.
4. Fail-closed: битая схема, пустое обязательное поле, нечисловое значение, дубликат id, сиротский
   договор, несовместимая единица или неизвестный сценарий → exit 2, **ни один файл не пишется**.
5. Детерминизм: два прогона с одним `--generated-at` байт-идентичны (JSON, MD, DOCX, manifest),
   включая zip-таймстампы DOCX и `docProps/core.xml`.
6. Ограничения честные: один договор на поставщика, 4 категории, 10 стран, валютные цены не
   пересчитываются по курсу, риск/пошлины — демонстрационные допущения до замены на
   TARIC/OECD CRP/WGI.

## 1. Что делает пилот и чего не делает

| Вопрос | Ответ пилота |
|---|---|
| UC-13: какой поставщик лучше? | 5-компонентный балл с прозрачными весами, вклады по каждой компоненте, класс A/B/C, TCO из 7 компонент |
| UC-14: каким будет бюджет? | 5 объявленных сценариев CPI/нефть/фрахт/FX/объём, интервал 5–95 по CPI |
| UC-16: сколько индексации? | по каждому договору: доли cpi/ppi/fx, cap, floor_zero, флаги `CAP_BINDING`/`FLOOR_BINDING` |
| Качество данных? | missing, defaults, дубликаты, IQR-выбросы, единицы и конверсии, кросс-полевые предупреждения |
| Что с приватностью? | псевдонимы до расчёта, leak-scan, никаких исходных имён/номеров в артефактах |

Чего пилот **не** делает:

- не проверяет поставщика как юридическое лицо и не даёт закупочную рекомендацию;
- не заменяет бухгалтерский учёт, аудит счетов и юридическую экспертизу договора;
- не пересчитывает валютные цены по курсу (валютный риск — только через `fx_share`);
- не строит вероятностный прогноз: сценарии линейны, интервал — перенос 5–95 CPI;
- не является допуском модели: `status=RESEARCH_ONLY`, `admission=false`.

## 2. Данные и контур

### 2.1 Две таблицы

| Таблица | Колонок | Строк в шаблоне | Один ряд = |
|---|---|---|---|
| `suppliers` | 16 | 4 (примеры, помечены «ПРИМЕР») | один поставщик за 12 месяцев |
| `contracts` | 9 | 4 (примеры) | один договор; ровно один на поставщика |

Обязательные поля поставщика: `supplier_id, country, category, annual_volume, unit_price,
lead_time_days, otif, defect_ppm, audit_score, risk_financial, risk_supply, risk_compliance`.
Необязательные: `name, currency, unit, freight_per_unit` — при пустом значении применяются
объявленные значения по умолчанию, и это фиксируется в отчёте качества.

Поля договора: `contract_id, supplier_id, status, cpi_share, ppi_share, fx_share, cap_pct,
floor_zero, payment_days`; суммы долей ≤ 1, `fx_share > 0` только для USD/CNY.

Полный словарь, диапазоны, справочники категорий/стран/единиц и правила качества —
[`pilot/flaks/data_dictionary.md`](../pilot/flaks/data_dictionary.md).

### 2.2 Масштаб

Пилот рассчитан на 2–4 категории, 2–4 поставщика на категорию, 4–50 строк поставщиков и столько
же договоров, 12 месяцев факта. Максимум — 5 000 строк и 64 колонки; полный журнал закупок не
нужен и не принимается. Минимум, который пропускает валидация: **2 поставщика и 1 действующий
договор в каждой заявленной категории** (иначе сравнение и бюджет невозможны).

### 2.3 Анонимизация и NDA

- До NDA файлы не передаются; канал — защищённое облако/файлообменник клиента, не публичные ссылки.
- Клиент может сам заменить коды и имена; инструмент всё равно анонимизирует повторно.
- `supplier_id` → `ANON-SUP-NNN`, `contract_id` → `ANON-CT-NNN`, `name` → «Анонимный поставщик
  NNN». Нумерация — по сортировке исходных id, поэтому порядок строк не влияет на псевдонимы.
- Обратное соответствие не сохраняется. В manifest — только SHA-256 входов, без имён файлов.
- После сборки leak-scan ищет исходные id/имена в JSON, Markdown и XML DOCX; при совпадении —
  остановка (exit 2), файлы не пишутся.
- Реальные данные не коммитятся: `build/*` уже в `.gitignore`, локальная папка
  `pilot/flaks/inbox/` исключена отдельным `.gitignore`. После пилота исходники удаляются по
  регламенту клиента.

### 2.4 Что не присылать

Персональные данные, банковские реквизиты, полные тексты договоров и переписку, прайс-листы
целиком, секреты/токены/ключи, данные, запрещённые NDA или внутренней политикой. Нужны только
агрегированные строки по шаблону (см. README).

## 3. Как устроен intake

```
CSV/XLSX ──► reader (encoding/delimiter/sheet)
           ──► schema check (unknown/missing columns)
           ──► types & ranges (num/bool/enum/units)
           ──► join suppliers ↔ contracts (1:1)
           ──► quality report (missing/defaults/dups/outliers/units/warnings)
           ──► anonymization (ANON-…, no reverse map)
           ──► flaks_procurement.build_report()  ← модель не меняется
           ──► JSON + MD + DOCX + manifest(SHA-256)
```

Особенности реализации:

- **CSV**: UTF-8 (BOM), UTF-8, CP1251; разделитель `,`, `;`, tab, `|` определяется по заголовку;
  десятичная запятая поддерживается; «1 234,56», «40 %», «6%» разбираются.
- **XLSX**: `openpyxl`, активный лист, значения читаются как есть; `.xls` не поддерживается —
  сохраните как `.xlsx`.
- **Схема**: неизвестная колонка — ошибка, а не «тихо проигнорировать»; пустая колонка без данных
  отбрасывается, колонка без имени с данными — ошибка.
- **Единицы**: кг/т и отправка; т приводится к кг (объём ×1000, цена и фрахт ÷1000); несовместимая
  единица (например, кг для логистики) — ошибка.
- **Качество**: IQR ×3 внутри категории при n ≥ 4; выброс — предупреждение, не ошибка. Дубликаты
  `supplier_id`/`contract_id` и дубликаты строк разделены: первые блокируют, вторые предупреждают.
- **Модель**: `fp.build_report()` вызывается на временном JSON с `source_class="anonymized_fixture"`;
  в отчёте путь заменён на `pilot intake (anonymized)`, хеш — SHA-256 анонимизированного набора.
- **Упаковка**: JSON сортирован (`sort_keys`, indent 1), Markdown и DOCX собираются из того же
  payload; DOCX-даты и zip-таймстампы прибиты к `--generated-at`.

## 6. Тесты

`python -m unittest tests.test_flaks_pilot -v` — **33 теста**, офлайн, ~5 с, только временные
каталоги:

- шаблоны: заголовки совпадают со схемой, 4+4 строки, `load_intake` даёт quality OK; полный прогон
  на шаблонах; XLSX даёт те же scoring/budget, что CSV;
- валидация: нет обязательной колонки, неизвестная колонка, нечисловое значение с номером
  строки/колонки, дубликат `supplier_id`, дубликат `contract_id`, сиротский договор, поставщик без
  договора, плохой `status`/`floor_zero`, сумма долей > 1, `fx_share` при EUR, категория с одним
  поставщиком, категория без active, неизвестный сценарий;
- качество: missing + defaults (name/currency/unit/freight), конверсия т→кг и неизменность базы,
  несовместимая единица, дубликаты строк как предупреждение, IQR-выброс на 7 наблюдениях;
- анонимизация: исходные id/имена/номера договоров отсутствуют в JSON/MD/DOCX; псевдонимы
  стабильны при перестановке строк; leak-scan ловит подсаженный идентификатор и не печатает его;
- fail-closed CLI: битые данные → exit 2, `BLOCKED_INPUT`, выходной каталог не создан; `--check`
  ничего не пишет и падает на битых данных; неизвестный сценарий → exit 2;
- артефакты: manifest SHA-256 совпадает с файлами, входы без имён; побайтовый детерминизм
  JSON/MD/DOCX/manifest; DOCX — валидный zip с `word/document.xml`, `docProps/core.xml` и
  разделами CFO; `--json` печатает полный отчёт; база = сумма действующих договоров; в Markdown
  нет `FAIL`.

Регрессия движка: `python -m unittest tests.test_flaks_procurement -v` — 44 теста, не менялись.

## 7. Fail-closed и коды возврата

| Ситуация | Поведение | Код |
|---|---|---|
| нет файла/формат не CSV/XLSX | `BLOCKED_INPUT` в stderr, ничего не пишется | 2 |
| нет обязательной/неизвестная колонка | то же, со списком колонок | 2 |
| пустое обязательное поле, не число, вне диапазона | то же, с таблицей/строкой/колонкой | 2 |
| дубликат `supplier_id`/`contract_id` | то же | 2 |
| сиротский договор / поставщик без договора / >1 договор | то же | 2 |
| категория с <2 поставщиками или без active | то же | 2 |
| единица несовместима с категорией | то же | 2 |
| сумма долей > 1, `fx_share` при EUR, cap вне [0,25] | то же | 2 |
| неизвестный сценарий / битый `--generated-at` | то же | 2 |
| утечка исходного идентификатора (leak-scan) | то же | 2 |
| всё в порядке | JSON+MD+DOCX+manifest, `status=RESEARCH_ONLY` | 0 |
| `--check` и данные валидны | отчёт качества в stdout, файлы не пишутся | 0 |

Проверка «ничего не записано» — отдельный тест: каталог отчёта после отказа не создаётся.

## 8. Риски

| Риск | Вероятность | Эффект | Митигация |
|---|---|---|---|
| клиент присылает персональные данные/реквизиты | средняя | утечка, остановка | README «что не присылать», NDA, возврат файла, не читать лишнее |
| мало поставщиков/нет active в категории | высокая | пилот не стартует | расширить выборку или исключить категорию; `--check` показывает точную причину |
| несколько договоров на поставщика | средняя | MVP не поддерживает | агрегировать до одного договора или отложить |
| выбросы/опечатки в ценах | высокая | искажение скоринга | IQR-предупреждение + сверка с первичными счетами (День 3) |
| неизвестная страна/категория | средняя | отказ | словарь; расширение модели — только с источником пошлины/риска |
| утечка идентификаторов в DOCX | низкая | остановка | псевдонимы до расчёта + leak-scan по XML |
| «демо» приняли за реальные данные | средняя | ложные выводы | строки «ПРИМЕР», дисклеймер в каждом артефакте, docs/189 §5.1 |
| реальные данные попали в git | низкая | инцидент | `build/*` и `pilot/flaks/inbox/` в `.gitignore`, проверка `git status` на приёмке |

## 9. Что заменить на реальные источники

| Блок | Сейчас в движке | Заменить на | Кто даёт |
|---|---|---|---|
| Пошлины | `COUNTRIES[*].duty_rate` (демо) | таможенный тариф ЕС TARIC / условия соглашений | аналитик + открытые источники |
| Риск страны | `COUNTRIES[*].risk` (демо) | OECD Country Risk, World Bank WGI или внутренний скоринг | аналитик / клиент |
| Цены и фрахт | цены из шаблона | фактические счета + котировки перевозчиков | клиент |
| CPI/нефть | якоря фида T1 и моста цены | те же артефакты, обновляемые по расписанию | FLAKS |
| Качество | `defect_ppm`, `otif`, `audit_score` | данные входного контроля, рекламаций, аудита | клиент |
| Индексация | доли cpi/ppi/fx, cap, floor | формулировки договора (база, дата, оспаривание) | клиент + юрист |
| FX | `fx_share` без курса | курс на дату + хедж (вне MVP) | клиент / казначейство |

Правило: замена таблицы допущений не должна менять код модели; источники и даты фиксируются в
manifest/журнале решений.

## 10. Ограничения

- Один договор на поставщика; 4 категории; 10 стран; 5 000 строк.
- Валютные цены сравниваются номинально, без пересчёта по курсу; FX — только через `fx_share`.
- Риск страны и пошлины — демонстрационные допущения (docs/184 §7, §9), не TARIC и не рейтинг.
- Сценарии линейны; шаги > ~30 % выходят за линеаризацию; интервал — только CPI 5–95.
- Нормализация скоринга относительна внутри категории; смена состава меняет все баллы.
- TCO — формула, не бухгалтерская себестоимость; «экономия» — иллюстрация без концентрации риска.
- Нет юридического слоя индексации: cap/floor применяются как объявлены, текст договора не
  парсится.
- Пилот не является допуском: `RESEARCH_ONLY`, `admission=false`.

## 11. Что нужно от клиента для старта

1. Подписанный NDA и согласованный канал передачи (не публичная ссылка).
2. 2–4 категории, 2–4 поставщика на категорию, 12 месяцев факта — CSV/XLSX по шаблону.
3. Договоры: статус, доли cpi/ppi/fx, cap, floor_zero, payment_days — один договор на поставщика.
4. Подтверждение, что выгрузка разрешена внутренней политикой; контакт по данным.
5. Согласие на EUR как базовую валюту отчёта и на веса по умолчанию (или своё решение на
   воркшопе Дня 4).
6. Факт бюджета за прошлый период (агрегат), если нужен ретро-бэктест.

Без пунктов 1–3 пилот не стартует. После получения файлов первый шаг — `--check`; он ничего не
пишет и показывает, что именно нужно исправить.
