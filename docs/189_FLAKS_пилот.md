# 189. FLAKS: пилот на реальных данных (2 недели)

Дата: 2026-11-19. Инструмент: [tools/flaks_pilot.py](../tools/flaks_pilot.py) (33 теста);
MVP-модель: [docs/184](184_FLAKS_Procurement_MVP.md), [tools/flaks_procurement.py](../tools/flaks_procurement.py).
Статус: **RESEARCH_ONLY, admission=false** — не закупочная рекомендация и не аудит поставщиков.

## 1. Цель пилота

Проверить на данных клиента, что FLAKS помогает:
1) сравнивать поставщиков по **TCO**, а не по цене;
2) прогнозировать бюджет закупок на 6–12 месяцев при сценариях (инфляция/нефть/Ормуз);
3) считать индексацию контрактов и ловить CAP/FLOOR;
4) выдавать CFO отчёт с прозрачными весами и оговорками.

Критерий успеха — не «точность прогноза», а **управленческое решение**: экономия/риск/время.

## 2. Что нужно от клиента

Две таблицы (CSV или XLSX), шаблоны в `pilot/flaks/`:

- `suppliers_template.csv` — поставщики: страна, категория, валюта, объём, цена, фрахт, лид-тайм,
  OTIF, дефекты ppm, аудит, три риска (финансовый/поставки/комплаенс);
- `contracts_template.csv` — договоры: поставщик, статус, доли CPI/PPI/FX, CAP, floor_zero,
  отсрочка платежа.

Минимум для пилота: **≥8 активных поставщиков, ≥4 категории, ≥10 договоров, 12 месяцев истории**.
Данные можно обезличить: имена/ID заменяются псевдонимами до расчёта (`--anonymize` включён всегда).

**Не присылать:** персональные данные, коммерческую тайну в открытом виде, банковские реквизиты,
цены, запрещённые NDA. Формат — без Excel-макросов; лучше CSV.

## 3. Команды

```powershell
# 1) только проверить данные (ничего не пишет)
python tools/flaks_pilot.py --suppliers pilot/flaks/suppliers_template.csv `
  --contracts pilot/flaks/contracts_template.csv --check

# 2) полный пилот-отчёт
python tools/flaks_pilot.py --suppliers <suppliers.csv> --contracts <contracts.csv> `
  --scenario hormuz_6m --out build/flaks_pilot --anonymize --generated-at 2026-11-19T00:00:00Z
```

Выход: `report.json`, `report.md`, `CFO_report.docx`, `manifest.json` (SHA-256), quality report.
Битые/неполные данные → exit 2, файлы не пишутся.

## 4. План на 2 недели

| День | Что делаем | Результат |
|---|---|---|
| 1 | NDA, список категорий, шаблоны, ответственные | согласованный объём |
| 2–3 | выгрузка данных, обезличивание, `--check` | quality report, список пробелов |
| 4–5 | базовый скоринг/TCO, сравнение с текущим выбором | первая таблица «кто дешевле по TCO» |
| 6–7 | бюджет на 6–12 мес (base/inflation/oil/hormuz), CAP/FLOOR | сценарии для CFO |
| 8 | интервью с закупками/финансами, проверка допущений | корректировки весов |
| 9 | финальный отчёт, презентация, обсуждение рисков | CFO-пакет |
| 10 | решение: продолжать/пилот на 2-й категории/стоп | критерии и метрики |

## 5. Acceptance

- данные прошли валидацию, quality report без критичных пробелов;
- TCO-ранжирование объяснимо (вклад цены/фрахта/риска/качества);
- бюджет-сценарии воспроизводимы (SHA-256), допущения видны;
- CAP/FLOOR срабатывают и объяснены;
- клиент подтверждает: «решение стало быстрее/дешевле/прозрачнее» (метрика пилота).

## 6. Ограничения

- данные синтетические в демо; реальные — только у клиента, в git не попадают;
- риск страны/пошлины — демо-допущения (заменить на TARIC/OECD CRP/WGI);
- сценарии линейные; интервал только по CPI; TCO — формула, не бухучёт;
- «экономия» без концентрации риска; не аудит и не юридическое заключение.
