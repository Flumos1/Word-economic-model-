# Техническое задание AMFE 1.0 — рабочий проект
Версия 0.1 · Статус: на согласовании

## 1. Назначение и цели
1.1. AMFE — автономная адаптивная исследовательская платформа вероятностного экономического прогнозирования.
1.2. Система получает независимые прогнозы и наблюдения, строит собственные прогнозы, оценивает ошибки, обновляет параметры и допускает изменения только после проверок.
1.3. Научная цель — измеримая добавленная точность относительно сильных базовых моделей; гарантий превосходства нет.
1.4. Базовые выходы: численные прогнозы, вероятности событий, интервалы неопределённости, сценарии, объяснение факторов, еженедельный отчёт.

## 2. Архитектура
Семь логических уровней: цели → данные → экономическая модель → математическое ядро → ансамбль → обучение/валидация → отчёты. Связи двусторонние. Экономическая модель: микро, мезо, макро; геополитика, технологии, финансы — сквозные механизмы.

## 3. Предметная модель
Обязательный каталог — все 17 блоков из 01_Концепция_AMFE.md. Распределение и перераспределение не сливать с производством и потреблением. Науку учитывать как отдельную подсистему, различая открытия, разработки и внедрение.

## 4. Данные
4.1. 20+ потенциальных внешних источников; каждый источник классифицировать: прогноз, nowcast, индикатор, аналитический текст.
4.2. Исторические винтажи; время события, публикации, получения и допустимости для прогноза.
4.3. Метаданные качества, лицензии, частоты, пропуски, пересмотры, география, горизонты.
4.4. Отдельные хранилища: сырые наблюдения, обработанные признаки, исходные прогнозы, результаты, тексты и векторные представления.

## 5. Математическое ядро
5.1. Обязательные базовые модели: наивные/авторегрессионные, регуляризованные регрессии, DFM/state-space и равновесовой ансамбль.
5.2. Кандидаты: SFC, input-output, ODE/SDE/DDE, нелинейные модели, графовые и нейросетевые подходы.
5.3. Любая модель должна иметь определённые переменные, единицы, источники, частоты, уравнения, параметры, процедуру идентификации и границы применимости.
5.4. Финансовые и материальные потоки согласовывать, исключать двойной учёт.

## 6. Ансамбль
Внешние прогнозы не смешивать без различения с фактической статистикой. Оценивать веса по горизонту, режиму, исторической ошибке и корреляции ошибок. Хранить простые контрольные ансамбли. Выдавать распределения, не только точечные оценки.

## 7. Самообучение
Ежедневный/еженедельный сбор по публикациям; частота обучения определяется доступностью фактов. Быстрый контур обновляет оценки состояния, медленный — параметры. Мониторинг drift; версионирование; проверка кандидата против действующей версии; автоматический откат при ухудшении.

## 8. Выходные продукты
Панель состояния, графики, прогнозы на 1/3/6/12 месяцев, вероятность рецессии, неопределённость, сценарии, журнал причин изменений и регулярный еженедельный бюллетень. Прогнозы финансовых рынков — отдельный поздний модуль.

## 9. Испытания и приёмка
Rolling-origin backtest с честными винтажами; MAE, RMSE, Brier, калибровка, покрытие интервалов, качество кризисных сигналов. Сравнение с наивной моделью, авторегрессией, равновесовым ансамблем, внешними источниками. Статистическая значимость и устойчивость на разных режимах. Критерии допуска новой модели ещё требуют решения.

## 10. Программная реализация
Предварительный стек: Python, PostgreSQL, планировщик задач, API, дашборд, журнал экспериментов, Git. Система должна работать модульно и без обязательного мощного GPU на начальном этапе. Необходимые лицензии, вычислительные ресурсы и размещение — открытые вопросы.

## 11. Открытые вопросы
Единственный канонический реестр — 03_Открытые_вопросы.md. Никакой нерешённый вопрос не скрывать в тексте ТЗ без ссылки на этот реестр.

## Управление изменениями
Новые идеи добавлять в мастер-концепцию, связывать с разделами ТЗ, фиксировать в журнале решений. Отклонённые гипотезы сохранять с обоснованием. До начала разработки согласовать минимальный прогнозный набор и критерии качества.
