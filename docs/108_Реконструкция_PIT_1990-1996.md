## 2. Метод

1. **Значение наблюдения** — ячейка **первого непустого винтажного столбца** merged-файла
   `data/raw/<SERIES>/vintages.zip` (первая архивная публикация, «tape of first prints»),
   значение копируется дословно.
2. **Дата полной истории** — первый реальный винтажный столбец источника, в котором ≥ 120
   непустых наблюдений (`MIN_FULL_HISTORY_OBS`).
3. **Tape-override.** Реальные столбцы *до* даты полной истории — разреженные снимки (~1.5 года
   истории), поэтому они **заменяются tape-колонками на ту же дату**; реальные столбцы
   сохраняются дословно только начиная с даты полной истории. Правило «реальный столбец выигрывает
   на коллизии с датой сетки» применяется только к датам ≥ даты полной истории; до неё выигрывает
   tape. Для месяца, в котором есть подлинный винтаж (дата ≥ даты полной истории), tape-колонка на
   15-е не пишется — подлинный винтаж полнее и точнее и всё равно новее.
4. **Сетка** — ежемесячные tape-даты 15-го числа 1990-01-15 … 1996-11-15 плюс tape-колонки на
   заменённых реальных датах (поэтому у CPIAUCSL 85 колонок, а не 83).
5. **Правило включения наблюдения** — только если период завершился до даты винтажа:
   - месячные: `period_end < vintage_date`;
   - `GDPC1`: `quarter_end + 1 месяц < vintage_date` (консервативно: advance-оценка квартала
     выходит примерно через месяц после его конца).
6. **Формат** — один CSV в zip (столбцы `SERIES_YYYYMMDD`, строки — даты наблюдений) + `README.txt`;
   совместим с `load_vintages`/`available_series` без правок. `latest.csv` — побайтовая копия из
   `data/raw` для 7 рядов. Детерминизм: фиксированная метка времени членов zip, CSV в UTF-8 с BOM и
   `\n`, никакой сети и случайности; повторный прогон даёт тот же дайджест (проверено).

## 3. Tape-override: даты полной истории и объём замены

| Ряд | Дата полной истории | Наблюдений в ней | Заменено реальных дат | Сохранено реальных | Tape-колонок | Carrier-lag: ячеек / max дней / наблюдений |
|---|---|---|---|---|---|---|
| CPIAUCSL | **1994-03-16** | 566 | **16** (1990-03-20 … 1993-12-10) | 131 | 85 | 31 707 / 1 521 / 577 |
| CPILFESL | 1996-12-12 | 479 | 0 | 120 | 83 | 36 271 / 2 523 / 478 |
| GDPC1 | 1991-12-20 | 131 | 0 | 140 | 63 | 4 427 / 1 072 / 197 |
| UNRATE | 1990-03-09 | 506 | 0 | 147 | 56 | 1 090 / 54 / 559 |
| GS10 | 1996-12-03 | 524 | 0 | 120 | 83 | 40 006 / 2 514 / 523 |
| TB3MS | 1996-12-03 | 755 | 0 | 120 | 83 | 59 179 / 2 514 / 754 |

Только у CPIAUCSL архив начинается с разреженных снимков; у остальных первый же столбец полный,
поэтому для них tape-override фактически не срабатывает (заменено 0 дат), а tape-колонки нужны
лишь потому, что реальный архив начинается в 1990–1991 или 1996-12.

Carrier-lag — сколько ячеек/наблюдений вошло в tape-винтаж раньше, чем этот отпечаток появился в
архиве (самый ранний отпечаток может быть в более поздней колонке; сетка источника квартальная,
поэтому дни — верхняя оценка). Для CPIAUCSL это плата за полную историю: значения 1990–1993 —
отпечатки, архивные до 1994-03-16.

**Раскрытие.** CPIAUCSL 1990-03…1994-02 — RECONSTRUCTED_PIT (ревизии CPI измерены и малы, §4),
обязательна чувствительность REAL_TIME-only. GDPC1 — MATERIAL, для T2 реконструкцию **не
использовать**. Ставки — ревизий нет, реконструкция значений точна. Это аналог
`data_depth.first_release_tape` — осознанная и объявленная tape-аппроксимация, не «тихая» подмена.

## 4. Ревизии (измерено на источнике; в досье — только агрегаты)


## 9. Ограничения и риски

1. **Это реконструкция, а не подлинные первые релизы.** Размер ревизий раскрыт (§4); для CPI
   обязательна чувствительность REAL_TIME-only, для GDP выводы невозможны.
2. **Tape-override — объявленная аппроксимация.** Для CPIAUCSL 1990–1993 полная история собрана из
   отпечатков, архивных до 1994-03-16 (carrier-lag до 1 521 дня). Это даёт вычислимость T1 h=1 и
   рецессию 1990–91 для C4, но переносит ревизии CPI в 1990–1993. Оценка допуска должна быть
   устойчива к срезу без этих origin; если C4 проходит только на реконструкции — это условный
   результат с раскрытием (docs/106 §3, §7).
3. **Разреженная сетка источника** (~147 квартальных винтажных столбцов, не месячная сетка
   публикаций): «шаг 1 винтаж» в досье — шаг по архивной сетке; в месяце с подлинным винтажом
   tape-колонка на 15-е не пишется.
4. **Подлинные архивы 1990–1996** и лицензии на них (D-5, вариант D) по-прежнему нужны: tape —
   предрегистрируемая аппроксимация, а не замена архиву.
5. **Протокол v4 не менялся.** Классы `REAL_TIME_RECONSTRUCTED_MARKET`/`RECONSTRUCTED_PIT` —
   предложение для v5 (docs/106 §3); в v4 такие origin должны явно маркироваться, а не считаться
   полноценным REAL_TIME. Досье имеет `status: PROPOSED` до решения владельца (U-3).
6. Досье не содержит значений рядов (только агрегаты) — требование лицензионной политики,
   проверяется тестом.
