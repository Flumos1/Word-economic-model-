# 192. Simulator UI MVP: локальное веб-демо сценариев AMFE

Дата: 2026-11-19. Роль: `dense-vintages` (G5). Кейс: UC-48 «Simulator UI» из
[docs/174](174_50_кейсов_использования.md), оркестрация — [docs/175](175_Агентная_оркестрация_и_обучение.md).
Код — [tools/simulator_ui.py](../tools/simulator_ui.py), тесты —
[tests/test_simulator_ui.py](../tests/test_simulator_ui.py). Спецификация агентного слоя —
[docs/150](150_Агентный_симулятор.md) (этот MVP — интерфейс к **рыночным** моделям, не ABM-прототип).

## 0. Коротко

Один локальный процесс на stdlib: страница с формой «сценарий + параметры → Рассчитать»,
JSON-API и карточки/таблица/график/SVG без единой внешней зависимости и без CDN. Демо вызывает
**существующие** модели проекта и переводит их выход в понятные корпоративному зрителю величины
(цены, CPI, домохозяйство, риск, отраслевые эффекты, страновой выпуск).

Это **не прогноз и не допуск**: `status=RESEARCH_ONLY`, `admission=false`, `causal_claim=false`,
на странице и в каждом ответе — предупреждение «это не прогноз». Никаких сырых данных: только
объявленные допущения, агрегаты моделей и пути длиной ≤ 12 точек.

## 1. Запуск

```powershell
python tools/simulator_ui.py                        # http://127.0.0.1:8090, локальное демо без ключей
python tools/simulator_ui.py --host 0.0.0.0 --port 8091
python tools/simulator_ui.py --check                # диагностика JSON и выход (без сервера)
python tools/simulator_ui.py --quiet                # только предупреждения
python tools/simulator_ui.py --geopolitics synthetic  # не читать предрасчитанный артефакт

# режим готовности к шлюзу: ключи + квоты (см. §7)
$env:AMFE_SIM_KEYS = "demo_free_key_01:free,demo_pro_key_01:pro"
python tools/simulator_ui.py --require-auth --quota-per-hour 60
```

Порт по умолчанию `8090` (живой шлюз прогнозов из [docs/183](183_Forecast_API_шлюз.md) занимает
`8080`, чтобы демо и шлюз не конфликтовали). Сервер печатает одну строку JSON с фактическим URL.

Проверка вручную:

```powershell
Invoke-WebRequest http://127.0.0.1:8090/api/health -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:8090/api/run -Method Post -ContentType "application/json" `
  -Body '{"scenario":"hormuz_base","price":75,"shock":100,"country":"US"}' -UseBasicParsing
```

## 2. Сценарии

| id | Модель | Что показывает | Параметры |
|---|---|---|---|
| `hormuz_base` | `amfe.markets.oil` (`oil.brent`) → `tools/hormuz_us_impact.py` | Brent по месяцам, бензин/дизель в США, вклад в CPI, расходы домохозяйства, иллюстративный соцриск; мультипликаторы издержек по корзинам | Brent (USD/bbl), потеря потока Ормуза (%), страна |
| `hormuz_stress` | то же + стресс-надбавки `hormuz_us_impact` | то же плюс сланцевый слэт, потеря венесуэльской тяжёлой нефти, фрахт/страховка, обход, крек дизеля и авиакеросина | те же |
| `gas_shock` | `amfe.markets.gas` (`gas.lng_eu`, сценарий `hard_winter_pipeline_shock_6m`) | TTF/JKM по месяцам, ПХГ, диверсия СПГ, арбитражный режим; проверки балансов | TTF (EUR/MWh), потеря трубопроводов (bcm/год), страна |
| `geopolitics` | `tools/geopolitics_scenarios.py` (FIGARO MRIO) | изменение выпуска по странам и отраслям (сравнительная статика), асимметрия выгоды/ущерб | геополитический сценарий (15 из протокола), страна |

Параметры — это **параметры моделей**, а не «наши оценки»:

- нефть: `base_price` (Brent) и `closure_share` (доля потерянного потока пролива);
- газ: `ttf_price_eur_per_mwh` и `pipeline_loss_bcm_y`;
- геополитика: id сценария из `protocols/geopolitics_scenarios.json`.

Геополитический сценарий по умолчанию читается из предрасчитанного отчёта
`build/geopolitics/report.json` (FIGARO, 50 стран × 64 отрасли, SHA-256 артефакта попадает в
`provenance`). Если артефакта нет — сценарий пересобирается на объявленной синтетической фикстуре
протокола и честно помечается `synthetic`. Режим `--geopolitics artifact` запрещает подмену
(отказ 503), режим `synthetic` — всегда пересчёт.

## 3. Валидация (fail-closed)

| Параметр | Диапазон | При нарушении |
|---|---|---|
| `price` (нефть) | 20…300 USD/bbl | 400 `PARAM_OUT_OF_RANGE` |
| `shock` (нефть) | 0…100 % | 400 `PARAM_OUT_OF_RANGE` |
| `price` (газ) | 0.5…300 EUR/MWh | 400 `PARAM_OUT_OF_RANGE` |
| `shock` (газ) | 0…150 bcm/год | 400 `PARAM_OUT_OF_RANGE` |
| `country` | 2–3 латинские буквы (`US`, `DE`, `UK`, `ROW`) | 400 `INVALID_COUNTRY` |
| `geo_scenario` | id из протокола/артефакта | 400 `UNKNOWN_SCENARIO` / `INVALID_SCENARIO_ID` |

Также отказывают: неизвестный сценарий (400 `UNKNOWN_SCENARIO`), нечисловое/`null`/`NaN`
значение (400 `INVALID_PARAM`), пустое или битое тело (400 `EMPTY_BODY` / `INVALID_JSON` /
`INVALID_BODY`), тело больше 64 КБ (400 `BODY_TOO_LARGE`), неверный путь (404 `NOT_FOUND`),
`GET /api/run` (400 `METHOD_NOT_ALLOWED` + `Allow: POST, OPTIONS`). Отказ модели — 503
`MODEL_FAILED`. Ничего не «исправляется» молча.

## 4. API

| Метод и путь | Что отдаёт |
|---|---|
| `GET /` | HTML-страница демо (инлайн CSS/JS, CSP, без внешних запросов) |
| `GET /api/health` | статус, версия, список сценариев с параметрами и диапазонами, страны, наличие артефакта геополитики, лимиты |
| `GET /api/scenarios` | только каталог сценариев (для встраивания) |
| `POST /api/run` | результат сценария целиком (см. §5) |

Пример запроса и ответа (сокращённо):

```json
{"scenario": "hormuz_stress", "price": 90, "shock": 100, "country": "DE"}
```

## 5. Что видит зритель

- **Карточки**: пик Brent, пик бензина и дизеля, вклад в CPI (п.п.), расходы домохозяйства
  (USD/мес), иллюстративный соцриск; для газа — TTF/JKM, ПХГ, диверсия; для геополитики —
  Δвыпуска, страна, крупнейший эффект.
- **График**: инлайновый SVG, строится в браузере (`createElementNS`), без библиотек: линии по
  месяцам, для геополитики — горизонтальные бары топ-10 стран.
- **Таблица**: месяцы × (Brent, бензин, дизель, CPI, домохозяйство) или TTF/JKM/спред; для
  геополитики — страны и доли |Δ|.
- **Отраслевые эффекты**: мультипликаторы издержек по корзинам (нефть, через объявленный мост
  `pass_through=0.6`) либо отрасли MRIO (геополитика).
- **Страна**: для США — потребительский пересчёт `hormuz_us_impact`; для остальных — Δвыпуска
  страны из MRIO-сценария Ормуза; где модель страну не считает — честная пометка, а не выдуманное
  число.
- **Проверки и ограничения**: чипы `checks` (балансы, положительные цены, `aggregate_only`),
  список `limitations`, дисклеймер.
- **Скачать JSON**: кнопка сохраняет ровно тот документ, который вернул `/api/run`
  (`amfe_<scenario>_<country>.json`) — его можно приложить к письму или разобрать в ноутбуке.
- **API-ключ**: поле появляется только в режиме `--require-auth`; ключ уходит заголовком
  `X-API-Key`, на сервере и в браузере не сохраняется (см. §7).

## 6. Безопасность и «no raw»

- сервер по умолчанию слушает `127.0.0.1`; наружу выставлять только осознанно (`--host`);
- CSP `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; connect-src
  'self'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`;
- каждый документ проходит `_scan_aggregate`: запрещённые поля (`raw`, `observations`,
  `source_rows`, `data_points`, `vintage_dates`, …), локальные пути (`C:\…`, `/home/…`), внешние
  URL и списки длиннее 128 элементов → ответ **не отдаётся** (503 `RAW_DATA_BLOCKED` /
  `PATH_LEAK` / `URL_LEAK` / `NOT_AGGREGATE`);
- пути моделей — не более 12 точек, таблицы — агрегаты, третьи данные не читаются вообще
  (нефть и газ считаются на объявленных допущениях модулей, геополитика — на предрасчитанном
  агрегированном отчёте);
- в локальном режиме ключи не нужны; в `--require-auth` хранятся только SHA-256-дайджесты ключей,
  плейнтекст не попадает ни в ответы, ни в логи (см. §7).

## 7. Аутентификация и квоты (опционально, готовность к шлюзу)

По умолчанию демо остаётся локальным и открытым — поведение прежнее. Флаг `--require-auth`
включает режим, в котором демо можно показать наружу через reverse proxy: ключи, тарифы, квоты и
коды 401/403/429. Это **не** замена [docs/183](183_Forecast_API_шлюз.md): там живой шлюз с суточными
квотами, CORS, OpenAPI и снапшотом фидов, здесь — защита демо-эндпоинта.

### 7.1 Как включить

```powershell
# ключи через env (не через командную строку — она видна в истории процессов)
$env:AMFE_SIM_KEYS = "demo_free_key_01:free,demo_pro_key_01:pro,ops_key_01:internal"
python tools/simulator_ui.py --require-auth --quota-per-hour 60

# или явным флагом
python tools/simulator_ui.py --require-auth `
  --api-keys "demo_pro_key_01:pro,ops_key_01:internal" --quota-per-hour 120
```

- формат `ключ[:тариф],...` (разделители — запятая, точка с запятой, пробел); тариф по
  умолчанию `free`; ключ короче 8 символов, неизвестный тариф и дубликат отклоняются;
- ключ передаётся только заголовком `X-API-Key: <key>` или `Authorization: Bearer <key>`;
  в query-строке ключ не принимается (иначе он утекает в access-логи и прокси);
- `GET /`, `GET /api/health`, `OPTIONS` и `/favicon.ico` открыты без ключа — health нужен
  прокси/мониторингу, а страница должна загрузиться, чтобы показать поле для ключа;
- без `--require-auth` режим выключен; если ключи заданы (флагом или env), а режим выключен,
  процесс не стартует (exit 2), чтобы нельзя было «включить ключи и забыть про режим».

### 7.2 Тарифы, эндпоинты и квоты

| Тариф | `GET /api/scenarios` | `POST /api/run` | Комментарий |
|---|---|---|---|
| `free` | да | **403** `PLAN_FORBIDDEN` | только чтение каталога; сценарии не считает |
| `pro` | да | да | полный доступ к демо |
| `internal` | да | да | полный доступ (внутренний контур) |

Квота — **на ключ**, фиксированное окно в один час: `--quota-per-hour N` (по умолчанию 60,
целое > 0). Счётчик живёт в памяти процесса; исчерпание одного ключа не блокирует другие.
`free`-ключ тратит квоту на чтение каталога, `pro`/`internal` — на чтение и запуски. Отказ по
тарифу квоту не тратит; отказ 429 счётчик не увеличивает.

Тарифы — политика **демо**; в шлюзе [docs/183](183_Forecast_API_шлюз.md) `free/pro/internal` —
это частотные лимиты, а не запрет на запуск. Не переносите эту таблицу в продакшен-шлюз.

### 7.3 Коды и заголовки

| HTTP | `code` | Когда | Заголовки |
|---|---|---|---|
| 401 | `MISSING_API_KEY`, `INVALID_API_KEY`, `INVALID_AUTH_SCHEME` | нет ключа, ключ не найден, `Authorization` не `Bearer` | `WWW-Authenticate: ApiKey realm="amfe-simulator"` |
| 403 | `PLAN_FORBIDDEN` | валидный ключ с тарифом без права на `POST /api/run` | `X-RateLimit-*`, `X-Plan`; в `details` — `plan`, `required_scope`, `allowed_plans` |
| 429 | `RATE_LIMITED` | исчерпана часовая квота ключа | `Retry-After`, `X-RateLimit-Limit/Remaining/Reset/Window`, `X-Plan` |

Успешный аутентифицированный ответ несёт `X-RateLimit-Limit`, `X-RateLimit-Remaining`,
`X-RateLimit-Reset` (секунд до сброса), `X-RateLimit-Window` (3600) и `X-Plan`. Ошибки — обычный
конверт `kind="error"` с `research_status=RESEARCH_ONLY`, `admission=false`, `causal_claim=false`.

```powershell
$K = "demo_pro_key_01"
curl.exe -s -H "X-API-Key: $K" -H "Content-Type: application/json" `
  -d '{\"scenario\":\"hormuz_base\",\"price\":75,\"shock\":100,\"country\":\"US\"}' `
  http://127.0.0.1:8090/api/run
curl.exe -s -H "Authorization: Bearer $K" http://127.0.0.1:8090/api/scenarios
curl.exe -s http://127.0.0.1:8090/api/health          # без ключа
```

`GET /api/health` в режиме `--require-auth` отдаёт блок `auth`: `required`, `plans` (имена,
`can_run`, описание), `quota_per_hour`, `public_paths` и способ передачи ключа. Дайджестов и
самих ключей там нет.

### 7.4 Fail-closed конфигурация

- `--require-auth` без ключей (ни флага, ни env) → exit 2 `BLOCKED_CONFIG`, сервер не стартует;
- ключи без `--require-auth` → exit 2 (не «тихо открытый» режим);
- ключ короче 8 символов, неизвестный тариф, дубликат ключа, `--quota-per-hour < 1` → exit 2;
- неверный/отсутствующий ключ → 401, а не анонимный запуск; превышение → 429;
- `--check` с плохой конфигурацией печатает `BLOCKED_CONFIG` и возвращает 2;
- в логах — только `client=<8 hex>` (префикс SHA-256), тариф и остаток квоты; плейнтекст ключа
  не логируется, не эхоируется в ответах и не попадает в `details`.

### 7.5 Ограничения (честно)

1. Счётчики квот — в памяти процесса: перезапуск сбрасывает, несколько воркеров считают
   независимо. Общий лимит — задача reverse proxy/Redis.
2. Нет TLS, HSTS, WAF, биллинга, выдачи ключей self-service и ролей пользователей; наружу —
   только через прокси, ключи — из секрет-стора, не из командной строки.
3. Нет суточных квот, CORS и OpenAPI — это есть в шлюзе [docs/183](183_Forecast_API_шлюз.md);
   здешний режим защищает демо, а не заменяет контракт подписки.
4. `free` — только чтение: это политика демо, а не тариф продакшен-шлюза.
5. Health открыт и раскрывает имена тарифов и лимит; ключей и дайджестов в нём нет. Если это
   нежелательно — закрыть health на прокси по IP.
6. Поле «API-ключ» на странице отправляет ключ только заголовком и не сохраняет его, но браузер
   и devtools его видят: для реального клиента нужен HTTPS-прокси, а не прямой `--host 0.0.0.0`.

## 8. Ограничения (честно)

1. **Не прогноз и не допуск.** Все сценарии — `RESEARCH_ONLY`; числа — сценарная арифметика на
   объявленных допущениях. Никаких claims о вероятности, прибыли или «эффекте политики».
2. **CPI считается только для США** (там есть объявленный пересчёт `hormuz_us_impact`). У газа и
   геополитики CPI нет — API отдаёт `cpi.available=false` с пояснением, а не подставленное число.
3. **Страновой разбивки у газа нет** (модель — хаб-агрегат TTF/JKM/Henry Hub); у геополитики нет
   цен (сравнительная статика выпуска). Демо показывает то, что модель реально считает.
4. **Соцриск — иллюстративный индекс** на объявленных порогах, не вероятность беспорядков и не
   причинное утверждение.
5. **Геополитика** — сравнительная статика MRIO: нет цен, замещения, динамики и обратных связей;
   числа относятся к пику шока. Артефакт может быть устаревшим относительно текущего протокола —
   сверяйте `provenance.artifact_sha256` и `--check`.
6. **Стресс-надбавки** (`hormuz_stress`) — объявленные допущения (качество сырья, фрахт, обход,
   креки), а не оценки; они не меняют ценовой путь нефтяного модуля, а надстраивают пересчёт.
7. **Демо-сервер не рассчитан на нагрузку**: один поток на запрос; аутентификация и квоты
   опциональны (`--require-auth`) и живут в памяти процесса, поэтому для пилота нужен шлюз из
   [docs/183](183_Forecast_API_шлюз.md), а не этот режим.

## 9. Как использовать в продажах и демо

**Позиционирование.** «Не ещё один прогноз, а песочница: вот модель, вот её допущения, вот что
меняется, если Ормуз закрыт на 6 месяцев. Все допущения на экране — их можно заменить данными
клиента». Сильный аргумент — прозрачность: `checks`, `digest`, `limitations` видны в том же окне,
что и цифры.

**Пятиминутный сценарий разговора:**

1. Открыть сценарий `hormuz_base`, нажать «Рассчитать» (≈0.1 с), показать карточки: пик Brent,
   бензин, вклад в CPI, расходы домохозяйства.
2. Подвинуть Brent (например, 75 → 95) и потерянный поток (100 % → 60 %): показать, что модель
   реагирует и что это параметры, а не «магические» числа.
3. Включить `hormuz_stress`: дизель/авиакеросин, качество сырья, фрахт — «вот где у клиента
   реально растёт себестоимость».
4. Переключить страну: US → потребительский пересчёт, DE → Δвыпуска страны в MRIO; проговорить,
   что страновых CPI у нас нет и мы это не выдумываем.
5. Открыть `gas_shock`: TTF/JKM, ПХГ, диверсия — «это уже энергетика и закупки».
6. Скачать JSON и показать `checks`, `digest`, `limitations`: воспроизводимость и границы.

**Кому и что показывать:**

- CFO/закупки: `hormuz_stress` + бюджет топлива и дизеля, `gas_shock` для энергозатрат;
- казначейство/риск: `hormuz_base` + `risk`-полоса и триггеры мониторинга (`details.monitoring`);
- инвесторы/аналитики: `geopolitics` (страна×отрасль, выгоды/ущерб) как макро-оверлей;
- вузы/тренинги (UC-48): вся форма — «покрутите параметры и объясните, почему так»;
- внутренние ревью: демо как тест на честность формулировок (если на слайде появляется «прогноз» —
  это ошибка).

**Чего не обещать:** вероятностей, точности в процентах, «эффекта ИИ», автоматического обновления
данных, страновых CPI для газа, разрешения на использование как допуска. Любую цифру из демо
сопровождать словами «сценарий на объявленных допущениях».

## 10. Тесты

```powershell
python tests/test_simulator_ui.py     # 48 тестов, ~2.0 с
```

Покрыто: контракт `/api/health` и `/api/scenarios`; четыре сценария (карточки, пути, таблицы,
отраслевые эффекты, страна); статус `RESEARCH_ONLY` / `admission=false` / `causal_claim=false`;
детерминизм и digest (в т.ч. смена digest при смене параметра); чувствительность (Brent ↑ → бензин
↑, шок ↓ → пик Brent ↓); отказы (неизвестный сценарий/страна/сценарий геополитики, диапазоны,
`NaN`, `null`, `bool`, битый и пустой JSON, тело > 64 КБ, неверный метод/путь); «no raw» и
отсутствие путей/URL; HTML-страница (кнопка «Рассчитать», «не прогноз», нет `<script src=` и CDN,
только namespace SVG); живой `http.server` (200/400/404/204/HEAD, `Allow`, CSP, `no-store`);
поведение без артефакта (синтетический пересчёт и строгий режим 503).

Аутентификация/квоты (21 тест): 401 без ключа/неверный ключ/неверная схема + `WWW-Authenticate`;
`X-API-Key` и `Bearer` дают один и тот же digest; 403 `PLAN_FORBIDDEN` для `free`-тарифа на
`POST /api/run` (и 200 на каталог); 429 с `Retry-After`/`X-RateLimit-*`/`X-Plan`; заголовки
успешного ответа; два ключа независимы; квота восстанавливается после окна; отказ не увеличивает
счётчик; health и `/` открыты; защищённые маршруты требуют ключ; ключи не логируются и не
эхоируются; fail-closed конфигурация (нет ключей, ключи без `--require-auth`, короткий ключ,
неизвестный тариф, дубликат, нулевая квота, `--check`/exit 2); живой HTTP 401/200/429.
