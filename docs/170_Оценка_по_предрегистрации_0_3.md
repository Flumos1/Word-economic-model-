Дата первой версии: 2026-11-17. **Перевыпуск по V2: 2026-11-18 (task-67)**. Волна G4-E.
Статус: **PROVISIONAL** — предрегистрация
[AMFE-PIT-PREREG-0.3](../protocols/pit_preregistration_0_3.json) сама в статусе `PROPOSED`;
это не допуск, не финальный результат и не основание для продуктовых заявлений
(`admission=false`).
Инструмент: [tools/run_pit_prereg_evaluation.py](../tools/run_pit_prereg_evaluation.py);
тесты: [tests/test_pit_prereg_evaluation.py](../tests/test_pit_prereg_evaluation.py) (28).
Отчёт: [protocols/pit_prereg_evaluation_report.json](../protocols/pit_prereg_evaluation_report.json)
(schema `amfe.pit_prereg_evaluation.v2`).

Независимая проверка: [docs/172](172_Независимая_V2_оценки_0_3.md) — вердикт V2

## 1. Что сделано

Инструмент **не пересчитывает прогнозы сам**: он берёт свежие отчёты
`tools/run_real_evaluation.py` по protocol v5, проверяет все пины предрегистрации и собирает
отчёт в форме preregistration: C4 на W1_EXT 1990–2006 с классами origin, C4 на W2, обязательные
sensitivity-срезы (каждый — отдельный расчёт), C1/C2/C5 только на REAL_TIME-окнах, правило
`CONDITIONAL_DATA_CLASS`.

Проверенные пины (fail-closed):
- файл предрегистрации: SHA-256 `026bab7d…`; поддержаны **оба** имени пина —
  `pit_preregistration_0_3.sha256.txt` и `pit_preregistration_0_3.json.sha256.txt`; пин
  обязателен (без него прогон падает);
- внутренний `content_sha256 f86bfe9e…` — **пересчитывается** канонизацией JSON без самого поля,
  а не копируется;
- protocol v5 `5.0.1`: `48c2f6a1…`; protocol v4: `bd965f4d…`;
- досье реконструкции `pit_reconstruction.json`: `8154e319…`;
- coverage audit `data/reconstructed/g4_coverage.json`: `tree_digest 726f5666…` —
  **пересчитывается из data root** (`reconstruct_pit.tree_digest`, сам coverage-файл исключён),
  поле внутри аудита не считается доверенным.

Прогоны (fresh, **без кэша прогнозов**):
- расширенный (primary): `--protocol v5 --extended-c4 --data-root data/reconstructed`, 204 начала
  W1_EXT (121 REAL_TIME + 83 reconstructed), дополнительно считает C4 на REAL_TIME-подмножестве
  внутри того же прогона (`c4_slices.real_time_window`);
- стандартный (REAL_TIME-only срез C4): `--protocol v5` по `data/raw`, 121 начало с `1996-12-31`;
- стандартный на reconstructed root с полом `1996-12-31` (tape-free срез). Этот прогон физически
  не содержит tape-origins 1990–1996.

### ENSEMBLE_INVERSE_MSE (T1_CPI_YOY, h=1)

|---|---|
| W1_EXT origins | **204** (121 REAL_TIME + 83 reconstructed, доля 0.406863) |
| C4 W1_EXT (RMSE) | **FAIL**, relative loss рецессионных начал **1.0774564** (16 начал, min 12) |
| C4 W2 (RMSE) | **PASS**, relative loss **0.9406** (18 начал) |
| REAL_TIME-only C4 (standard, `data/raw`) | **INCONCLUSIVE**, **1.0672202** (8 начал < 12) |
| reconstructed-excluded C4 (внутри primary) | **INCONCLUSIVE**, **1.0672202** (8 начал) |
| tape-free C4 (standard на reconstructed root) | **INCONCLUSIVE**, **1.0672202** (8 начал) |
| LOO эпизоды (RMSE) | 1990-91: **0.5809326**; 2001: **0.5705337**; 2007-09: **0.8629** |
| C1 / C2 / C5 | PASS / PASS / PASS |
| Итоговая метка | **CANDIDATE** (C4 W1_EXT FAIL; условного pass нет) |

In-episode относительные потери (не LOO): 1990-91 = 1.0992, 2001 = 1.0672, 2007-09 = 0.9456 —
то есть провал C4 создают рецессионные эпизоды 1990-91 и 2001; LOO по каждому из них < 1
означает «падает не на одном эпизоде целиком», но pooled-отношение всё равно > 1.

### ENSEMBLE_EQUAL (контроль)

| Показатель | Значение |
|---|---|
| W1_EXT origins | **204** (121 REAL_TIME + 83 reconstructed, доля 0.406863) |
| C4 W1_EXT (RMSE) | PASS, relative loss **1.0000** (16 начал) — **тождество**: `ENSEMBLE_EQUAL` по построению и есть равновесная смесь компаратора |
| C4 W2 (RMSE) | PASS, **1.0000** (18 начал) — то же тождество |
| REAL_TIME-only / reconstructed-excluded / tape-free | **INCONCLUSIVE**, 1.0000 (8 начал) |
| LOO эпизоды | 1.0 / 1.0 / 1.0 |
| C1 / C2 / C5 | FAIL / FAIL / PASS |
| Итоговая метка | **FAIL** (гейтовые C1/C2); `conditional_data_class` = true, потому что C4 W1_EXT формально pass при reconstructed origins |

**Главный вывод:** расширение C4 на реконструированные origins 1990–1996 не даёт pass у
`ENSEMBLE_INVERSE_MSE`: C4 на W1_EXT — **FAIL** 1.0774564. На реальных началах C4 **не FAIL**, а
**INCONCLUSIVE** (8 рецессионных начал < 12): срез по построению не гейтит и не может быть назван
ни pass, ни fail. Условный `CONDITIONAL_DATA_CLASS` у INVERSE не возникает именно потому, что pass
нет. Ворота G4 по-прежнему не пройдены.

Про `ENSEMBLE_EQUAL`: его C4 «PASS 1.0» — не свидетельство качества, а фиксированная точка
(кандидат совпадает с равновесной смесью компаратора, relative loss ≡ 1). Метку пары это не
улучшает: C1/C2 fail → **FAIL**.

## 3. Обязательные срезы prereg

Все три среза — **разные расчёты**, не алиасы (docs/172 §4):

| Срез | Как получен | Итог INVERSE |
|---|---|---|
| REAL_TIME-only C4 | отдельный стандартный прогон v5 по `data/raw`; W1 1996-12…2006-12 | INCONCLUSIVE, 1.0672202 (8 начал) |
| reconstructed-excluded | C4, пересчитанный **внутри** primary-прогона на его REAL_TIME-подмножестве (`c4_slices.real_time_window`) | INCONCLUSIVE, 1.0672202 (8) |
| tape-free origins | отдельный стандартный прогон v5 на reconstructed root с полом `1996-12-31` | INCONCLUSIVE, 1.0672202 (8) |
| leave-one-episode-out | 1990-91 и 2001 из `c4_episodes.W1_EXT`, 2007-09 из `c4_episodes.W2` | 0.5809326 / 0.5705337 / 0.8629 (RMSE) |

Числа трёх срезов совпадают не потому, что это один расчёт, а потому что для T1 все три среза
убирают ровно одни и те же начала (до первого реального винтажа `1996-12-31`) и пост-1996 данные
в обоих root’ах совпадают. Инструмент падает fail-closed, если два среза указывают на один и тот
же отчёт (алиас) или если в стандартном отчёте есть начало < `1996-12-31` (это был бы cache replay).

Срезы не подменяют primary C4 и не используются для выбора модели; они reporting-only, как и
требует prereg.

## 4. Ограничения

- Предрегистрация `PROPOSED`: отчёт **PROVISIONAL**, `admission=false`; активация — решение
  владельца (D-205), после неё отчёт перевыпускается с той же процедурой.
- `w1_data_class` = `REAL_TIME`: REAL_TIME-окно по построению содержит только реальные начала
  (инструмент отвергает до-1996 начало). Признак прогона (`relies_on_reconstructed_origins`)
  отделён от условного pass (`criteria.conditional_data_class`).
- REAL_TIME-only срез reporting-only: 8 рецессионных начал < 12 → `INCONCLUSIVE`; prereg называет
  такой случай `NOT_APPLICABLE` (не FAIL). В отчёте используется `INCONCLUSIVE` как «не pass».
- T2/T3 в эту оценку не входят; параметры моделей не подбирались; W2 (2007–2019) не использовался
  для настройки (C4 W2 и LOO 2007-09 — reporting-only проверки).
- В отчёте только агрегаты и дайджесты; сырых наблюдений/значений прогнозов нет.
- Числа зависят от локального `data/reconstructed`; в CI нужен приватный артефакт data-refresh +
  прогон `python tools/reconstruct_pit.py --g4`.
- Кэш прогнозов: этот перевыпуск выполнен **без кэша**. Дефект ключа кэша (не учитывает
  `--data-root`) — отдельная задача task-68; до её закрытия standard-прогон нельзя запускать с
  общим `build/eval_cache`.

## 5. Воспроизведение

```bash
# 1) приватные данные и реконструкция
python tools/fetch_data.py --plan protocols/data_plan.json
python tools/reconstruct_pit.py --g4

# 2) расширенный primary-прогон (без --cache-dir), для каждого кандидата
python tools/run_real_evaluation.py --candidate ENSEMBLE_INVERSE_MSE --target T1_CPI_YOY \
  --horizon 1 --protocol protocols/evaluation_protocol_v5.json --extended-c4 \
  --data-root data/reconstructed --data-class REAL_TIME_RECONSTRUCTED \
  --skip-candidate-registration \
  --out protocols/prereg_eval_ENSEMBLE_INVERSE_MSE_T1_h1_v5.json

# 3) стандартный прогон REAL_TIME-only среза (data/raw)
python tools/run_real_evaluation.py --candidate ENSEMBLE_INVERSE_MSE --target T1_CPI_YOY \
  --horizon 1 --protocol protocols/evaluation_protocol_v5.json --data-class REAL_TIME \
  --skip-candidate-registration \
  --out protocols/prereg_std_ENSEMBLE_INVERSE_MSE_T1_h1_v5.json

# 4) стандартный прогон tape-free среза (reconstructed root, пол 1996-12-31 ставит код)
python tools/run_real_evaluation.py --candidate ENSEMBLE_INVERSE_MSE --target T1_CPI_YOY \
  --horizon 1 --protocol protocols/evaluation_protocol_v5.json --data-class REAL_TIME \
  --data-root data/reconstructed --skip-candidate-registration \
  --out protocols/prereg_tapefree_ENSEMBLE_INVERSE_MSE_T1_h1_v5.json

  --prereg protocols/pit_preregistration_0_3.json \
  --report protocols/prereg_eval_ENSEMBLE_INVERSE_MSE_T1_h1_v5.json \
  --standard-report protocols/prereg_std_ENSEMBLE_INVERSE_MSE_T1_h1_v5.json \

  --tape-free-report protocols/prereg_tapefree_ENSEMBLE_EQUAL_T1_h1_v5.json \
  --out protocols/pit_prereg_evaluation_report.json
```

### B.3. Честный статус

- Отчёт и prereg — **PROVISIONAL/PROPOSED**, `admission=false`; это не допуск и не финальный
  результат. Активация prereg 0.3 остаётся на паузе до решения владельца.
- **C4 W1_EXT FAIL у `ENSEMBLE_INVERSE_MSE` остаётся** (1.0774564) — главный содержательный вывод
  V2 подтверждён.
- **REAL_TIME-only C4 — `INCONCLUSIVE`, а не FAIL** (8 < 12): формулировка «C4 падает и на
  REAL_TIME-only срезе» снята как неверная; правильная — «реальные начала не дают ни pass, ни fail,
  они ниже минимума по конструкции».
- C4 W2 у INVERSE — PASS 0.9406, но это не отменяет FAIL на W1_EXT и не является admission-условием.
- `ENSEMBLE_EQUAL` C4 «PASS 1.0» — тождество (кандидат = компаратор), не свидетельство качества;
  метка пары FAIL из-за C1/C2.
- Изменение 202→204 начал и LOO 0.5131/0.5025 → 0.5809/0.5706 объясняется чистыми прогонами:
  архивный отчёт содержал 56 `member_failures` и два выпавших начала (1993-01/02), чего на
  запиненном root нет.
- V2 остаётся независимой проверкой **другого экземпляра модели**, а не человеческой подписью;
  подпись docs/160 не заменяется.
