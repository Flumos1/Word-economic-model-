# 170. Оценка по предрегистрации 0.3 (PIT 1990–1996): W1_EXT C4 + REAL_TIME C1/C2/C5

Дата: 2026-11-17. Волна G4-E. Статус: **PROVISIONAL** — предрегистрация
[AMFE-PIT-PREREG-0.3](../protocols/pit_preregistration_0_3.json) сама в статусе `PROPOSED`;
это не допуск, не финальный результат и не основание для продуктовых заявлений.
Инструмент: [tools/run_pit_prereg_evaluation.py](../tools/run_pit_prereg_evaluation.py);
тесты: [tests/test_pit_prereg_evaluation.py](../tests/test_pit_prereg_evaluation.py) (10).
Отчёт: [protocols/pit_prereg_evaluation_report.json](../protocols/pit_prereg_evaluation_report.json).

## 1. Что сделано

Инструмент **не пересчитывает прогнозы сам**: он берёт свежие отчёты
`tools/run_real_evaluation.py` по protocol v5, проверяет все пины предрегистрации и собирает
отчёт в форме prerequisite: C4 на W1_EXT 1990–2006 с классами origin, обязательные
sensitivity-срезы, C1/C2/C5 только на REAL_TIME-окнах, правило `CONDITIONAL_DATA_CLASS`.

Проверенные пины (fail-closed):
- файл предрегистрации: SHA-256 `026bab7d…` (пин `pit_preregistration_0_3.sha256.txt`), внутренний
  `content_sha256 f86bfe9e…`;
- protocol v5 `5.0.1`: `48c2f6a1…`; protocol v4: `bd965f4d…`;
- досье реконструкции `pit_reconstruction.json`: `8154e319…`;
- coverage audit `data/reconstructed/g4_coverage.json`, `tree_digest 726f5666…`.

Прогоны (fresh, с кэшем прогнозов):
- расширенный (primary): `--protocol v5 --extended-c4 --data-root data/reconstructed`;
- стандартный (для REAL_TIME-only среза C4): `--protocol v5` без `--extended-c4`.

**Главный вывод:** расширение C4 на реконструированные origins 1990–1996 не даёт pass:
у INVERSE_MSE C4 падает и на W1_EXT, и на REAL_TIME-only срезе (relative loss > 1.00 в
рецессионных месяцах). Условный `CONDITIONAL_DATA_CLASS` не возникает именно потому, что pass
нет; попытка «купить» C4 реконструкцией проваливается на реальных началах тоже. Ворота G4
по-прежнему не пройдены.

| Срез | Как получен | Итог (INVERSE_MSE) |

| REAL_TIME-only C4 | отдельный стандартный прогон v5 (W1 1996-12…2006-12) | FAIL, 1.1058 |

Срезы не подменяют primary C4 и не используются для выбора модели; они reporting-only, как и
требует prereg.

## 4. Ограничения

- Предрегистрация `PROPOSED`: отчёт **PROVISIONAL**, `admission=false`; активация — решение
  владельца (D-205), после неё отчёт перевыпускается с той же процедурой.
- Срезы REAL_TIME-only/reconstructed-excluded/tape-free взяты из отдельного стандартного прогона
  v5, а не из расширенного (в расширенном режиме W1_EXT заменяет стандартный C4-окно W1).
- T2/T3 в эту оценку не входят; параметры моделей не подбирались; W2 (2007–2019) не использовался
  для настройки.
- В отчёте только агрегаты и дайджесты; сырых наблюдений/значений прогнозов нет.
- Числа зависят от локального `data/reconstructed`; в CI нужен приватный артефакт data-refresh +
  прогон `python tools/reconstruct_pit.py --g4`.

## 5. Воспроизведение

```bash
# 1) приватные данные и реконструкция
python tools/fetch_data.py --plan protocols/data_plan.json
python tools/reconstruct_pit.py --g4

# 2) расширенный primary-прогон (для каждого кандидата)
python tools/run_real_evaluation.py --candidate ENSEMBLE_INVERSE_MSE --target T1_CPI_YOY \
  --horizon 1 --protocol protocols/evaluation_protocol_v5.json --extended-c4 \
  --data-root data/reconstructed --data-class REAL_TIME_RECONSTRUCTED \
  --cache-dir build/eval_cache --out protocols/prereg_eval_ENSEMBLE_INVERSE_MSE_T1_h1_v5.json

# 3) стандартный прогон для REAL_TIME-only среза C4
python tools/run_real_evaluation.py --candidate ENSEMBLE_INVERSE_MSE --target T1_CPI_YOY \
  --horizon 1 --protocol protocols/evaluation_protocol_v5.json --data-class REAL_TIME \
  --cache-dir build/eval_cache --out protocols/prereg_std_ENSEMBLE_INVERSE_MSE_T1_h1_v5.json

# 4) сборка отчёта (повторяется для ENSEMBLE_EQUAL)
python tools/run_pit_prereg_evaluation.py \
  --prereg protocols/pit_preregistration_0_3.json \
  --report protocols/prereg_eval_ENSEMBLE_INVERSE_MSE_T1_h1_v5.json \
  --standard-report protocols/prereg_std_ENSEMBLE_INVERSE_MSE_T1_h1_v5.json \
  --out protocols/pit_prereg_evaluation_report.json
```

## Приложение: независимая V2-проверка (2026-11-18)

Сокращённая независимая проверка — [docs/172](172_Независимая_V2_оценки_0_3.md), вердикт
**CONFIRMED_WITH_NOTES**. Головной вывод подтверждён: C4 FAIL, статус CANDIDATE/PROVISIONAL,
`admission=false`, ворота G4 не пройдены. Но зафиксированы расхождения, которые нельзя скрывать:

1. Стандартный W1 в отчёте начинается 1990-01 (204 origin, 16 рецессионных месяцев), а не
   1996-12 (121 origin); подпись «REAL_TIME-only» в итоговом отчёте фактически шире.
2. Обязательный срез ровно 1996-12…2006-12 (8 начал) не посчитан; LOO 2007-09 в итоговый отчёт
   не включён (хотя есть в исходном W2-отчёте).
3. Внутриэпизодные relative loss: 1,099 и 1,067 (>1); формулировка «оба < 1» относится ко всему
   W1_EXT без эпизода — нужна оговорка.
4. C1/C2/C5 в итоговом отчёте взяты из extended-отчёта (C1 0,9361), а не из standard REAL_TIME
   (C1 0,7649); report-level class не раскрыт.

Вывод о FAIL не меняется (8 начал < 12), но отчёт и docs/170 требуют исправления: точный
REAL_TIME-срез, LOO 2007-09, per-origin потери, явный report-level class. До этого активация
prereg 0.3 остаётся под вопросом; задача на исправление — task-67.
