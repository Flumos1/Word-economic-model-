## 1. Что делает инструмент

`tools/source_verification.py` читает оба локальных реестра и строит **docket** — производный
аудит-вид, а не новый источник истины:

* счётчики: всего / **VERIFIED / PARTIAL / UNVERIFIED** (вердикт docket) и отдельно статусы
  реестра (`CATALOGUED / NOT_DOWNLOADED / ACCESS_VERIFIED / VERIFIED`);
* evidence по каждому источнику: URL, дата получения данных, SHA-256 датасета, лицензия,
  запись журнала условий, terms-хеш/условия — и **чего именно не хватает** до VERIFIED;
* матрицу совместимости лицензий `OPEN / ATTRIBUTION / RESTRICTED / UNKNOWN`;
* список пробелов (все не-VERIFIED источники с блокирующими пунктами).

Жёсткие правила (реализованы и покрыты тестами):

1. **Без сети.** Ни один сетевой модуль не импортируется; тест подменяет `socket` на
   исключение и docket всё равно строится.
2. **Никакого автоматического promotion.** Статус реестра — вход, а не выход. Вердикт
   `VERIFIED` в docket возможен только там, где реестр уже `VERIFIED`; обратное тоже
   запрещено (авто-понижения нет). Изменить статус может только человек после загрузки данных.
3. **Fail-closed.** Бит/отсутствующий/чужой реестр, неизвестный статус или уровень, дубликат
   id, VERIFIED без даты получения, `--out` в файл реестра → `SourceVerificationError`,
   exit 2, файл не пишется. Нарушения внутренней целостности → exit 1, docket не публикуется.

| Команда | Что делает | Код |
|---|---|---|
| `python tools/source_verification.py` | сводка RU: счётчики, пробелы, матрица | 0/1 |
| `python tools/source_verification.py --check` | docket + инварианты (`OK: 15 … нарушений нет`) | 0 ok, 1 нарушения, 2 вход |
| `python tools/source_verification.py --json` | машиночитаемый docket (`AMFE-SOURCE-DOCKET/1.0.0`) | 0/1/2 |
| `python tools/source_verification.py --out PATH` | канонический JSON атомарно; отказ, если PATH — вход | 0/1/2 |
| `--registry PATH --licences PATH` | подмена входов (тесты/CI) | — |

## 5. Матрица совместимости лицензий

Классы: `OPEN` (public domain, без обязательств), `ATTRIBUTION` (нужна атрибуция; сюда же
non-commercial и share-alike — они помечены флагами), `RESTRICTED` (нужно разрешение/подписка),
`UNKNOWN` (условия не прочитаны/не найдены).

| | OPEN | ATTRIBUTION | RESTRICTED | UNKNOWN |
|---|---|---|---|---|
| **OPEN** | OK | ATTRIBUTION_REQUIRED | BLOCKED | BLOCKED_UNKNOWN |
| **ATTRIBUTION** | ATTRIBUTION_REQUIRED | ATTRIBUTION_REQUIRED | BLOCKED | BLOCKED_UNKNOWN |
| **RESTRICTED** | BLOCKED | BLOCKED | BLOCKED | BLOCKED_UNKNOWN |
| **UNKNOWN** | BLOCKED_UNKNOWN | BLOCKED_UNKNOWN | BLOCKED_UNKNOWN | BLOCKED_UNKNOWN |

Правила:

* совместный производный артефакт из `OPEN`+`OPEN` — OK; любое участие `ATTRIBUTION` требует
  атрибуции **каждому** источнику; участие `RESTRICTED` или `UNKNOWN` — запрещено (fail-closed);
* `UNKNOWN × UNKNOWN` тоже блокируется: два неизвестных условия не дают известного;
* публикация: только производные статистики, только `OPEN`/`ATTRIBUTION`, с атрибуцией;
  `RESTRICTED`/`UNKNOWN` не публикуются и не цитируются;
* флаги: `non_commercial` — `EUROSTAT`, `FAO_FAOSTAT`, `FRED_ALFRED`, `OECD_ICIO`,
  `UN_COMTRADE`; `share_alike` — `FAO_FAOSTAT` (CC BY-NC-SA). Для коммерческого использования
  эти флаги проверяются отдельно; матрица их не «разрешает».

Текущее распределение по источникам: `OPEN` 3 (`EIA`, `USDA_PSD`, `USDA_FAS_EXPORT_SALES`),
`ATTRIBUTION` 8, `RESTRICTED` 4 (`IEA`, `ICE_NYMEX_SETTLEMENTS`, `KPLER`, `VORTEXA`),
`UNKNOWN` 0. Журнал: 30 записей, `OPEN` 28 / `RESTRICTED` 1 / `UNVERIFIED` 1; к реестру
привязаны 2 записи (`BLS_PRIMARY`, `FRED_ALFRED_SERVICES`), 28 — это рядовые/первичные записи
(ALFRED:*, BEA, Philadelphia и т.д.), не имеющие отдельного `source_id` в реестре источников.

## 6. Порядок проверки (человеческий, без автоматики)

1. **Условия.** Прочитать страницу условий и страницу данных; зафиксировать цитату, дату, URL.
2. **Запись журнала.** Добавить/обновить запись в `protocols/licence_register.json`: `status`,
   `level`, `conditions`, `terms_sha256` (нормализация `terms-passages-v1`, docs/90), `date`.
   Смена статуса — новая датированная запись, старые не переписываются.
3. **Данные.** Загрузить в git-ignored каталог (или приватный CI-артефакт); в git — только
   метаданные. Никаких сырых третьих данных в коммитах.
4. **Хеш и провенанс.** Посчитать SHA-256 файла/набора, записать байты, строки, диапазон дат,
   `retrieved_at` и notes со ссылкой на датасет/манифест/доки.
5. **Статус.** Только человек ставит `VERIFIED` (или `ACCESS_VERIFIED`, если данных нет).
   Инструмент статус не меняет и не может изменить.
6. **Контроль.** `python tools/source_verification.py --check` → 0; при нарушениях — разбор,
   а не «переклассификация». В CI имеет смысл `--check --json`.
7. **Ревизия.** При изменении условий/URL — перечитать, обновить `terms_sha256`, зафиксировать
   дату; старый хеш остаётся историей.

## 7. Ограничения

1. **Метаданные ≠ юридическая проверка.** Инструмент проверяет полноту и согласованность
   записей, а не соответствие использования лицензии. Классификация лицензий — эвристика по
   тексту (`license_class` + статус журнала); трактовка остаётся за владельцем.
2. **Статусы — ручные утверждения.** Наличие `retrieved_at`/notes проверяемо, факт загрузки —
   нет. Docket не доказывает, что данные действительно получены и корректны.
3. **Данные не проверяются.** Ни ряды, ни их качество, ни PIT-глубина: это отдельные контуры
   (`data_log.json`, docs/166).
4. **Хеши.** У `OECD_ICIO` хеш усечён, у `WORLD_BANK` отсутствует; у `EIA` полный. Усечённый
   хеш — слабое доказательство, инструмент это помечает и не выдаёт за полный.
5. **Журнал не покрывает реестр.** 28 из 30 записей журнала не имеют `source_id` в реестре
   источников; для 13 источников записи нет вовсе. Матрица для них опирается на текстовое поле
   `license`, а не на прочитанные условия.
6. **Вердикты docket производны.** `PARTIAL`/`VERIFIED` в docket — не статусы реестра; нельзя
   цитировать `PARTIAL` как наблюдения или показывать его как `VERIFIED`.
7. **Сеть и время.** Повторной загрузки страниц нет; evidence — снимок на дату реестра. Условия
   могут измениться без уведомления; тогда нужна новая запись/хеш.
8. **Платные источники** не станут `PARTIAL`/`VERIFIED` по метаданным: нужна лицензия и решение
   владельца.
