# AMFE-17 — рекурсивная верификация и контур управляемого самообучения
Версия 0.1 · 2026-11-11. Архитектурное решение; автоматическое самообучение ещё НЕ реализовано.

## 1. Решение
После каждого изменения механизма, интерфейса, данных или метода AMFE запускается замкнутый цикл: спецификация → локальные проверки → интеграционные и регрессионные проверки → сопоставление с наблюдениями → независимая прогнозная оценка → решение о допуске/откате → фиксация результатов → следующий цикл. Повторно проверяются все затронутые механизмы, а не только изменённый блок. Для изменений в общих типах и балансовых инвариантах запускается весь набор тестов.

## 2. Не смешивать три уровня
V1: формальная корректность — типы, единицы, балансы, допустимость, симметрия операций, отсутствие двойного счёта. Автоматизируется уже сейчас.
V2: экономическая адекватность — согласование с независимыми статистическими данными, идентифицируемость, устойчивость к альтернативным объяснениям, анализ ошибок измерения. Требует реальных данных.
V3: прогнозная состоятельность — строго point-in-time rolling-origin OOS сравнение с baseline, качество вероятностей и интервальных прогнозов, устойчивость по режимам и странам. Только после V3 можно говорить о проверенном улучшении прогноза.
Успех V1 не доказывает V2/V3; успех V3 не оправдывает нарушения V1.

## 3. Два контура обновления
Контур А (инженерный): обнаружение дефектов, исправление кода/онтологии/проводок/контрактов, тестирование и откат. Это **не машинное самообучение**.
Контур Б (статистический): обновление оценок параметров, вероятностей и весов моделей после получения новых допустимых наблюдений. Этот контур будет построен позднее и не должен автоматически переписывать учётные тождества.
Предложение новой структуры модели — отдельный исследовательский процесс с протоколом допуска, не скрытая автоправка.

## 4. Реестр зависимостей
Для каждого блока b: входные контракты, выходные контракты, upstream/downstream зависимости, версии схем, набор тестов, известные ограничения, статус реализации. При изменении блока формировать транзитивное замыкание зависимостей; при циклических связях проверять всю сильно связанную компоненту. Общие изменения в единицах, классификациях, времени и финансовых позициях проверять глобально.

## 5. Контрольные ворота
G1: синтаксис, типы, размерности, домены.
G2: бухгалтерские/физические инварианты и отрицательные тесты.
G3: интеграция и регрессия — ранее пройденные тесты не ухудшены.
G4: проверка статистической сопоставимости, винтажей, источников, отсутствия leakage.
G5: OOS сравнение с заранее выбранным baseline и анализ неопределённости.
G6: решение о допуске: ACCEPT, CONDITIONAL, REJECT, ROLLBACK. При недостатке данных — CONDITIONAL, не ACCEPT по умолчанию.

## 6. Защита от самообмана
- Зафиксировать тесты и критерии до настройки модели.
- Разделять обучающие, валидационные и итоговые отложенные периоды; повторное использование тестового периода требует нового честного holdout.
- Не менять задним числом данные или пороги без версионирования.
- Сохранять отрицательные результаты и неуспешные гипотезы.
- Сравнивать с наивными и сильными базовыми моделями; учитывать стоимость усложнения.
- Любое обновление хранит: старую/новую версию, diff, входные данные и винтажи, результаты тестов, ответственного, основание, условия отката.

## 7. Применение к текущему состоянию
docs/39 и tests/test_closed_economy_v01.py: демонстрационный трёхсекторный контур.
docs/40 и tests/test_government_economy_v02.py: демонстрационный четырёхсекторный контур.
Тесты этих примеров — V1, не V2/V3. Перед следующим расширением требуется автоматизировать повторный запуск обоих наборов и отчёт по регрессии. Следующий эксперимент: две страны и валюты; после него обязательно повторно запускать V1 для всех предыдущих примеров, затем новые зеркальные внешнеторговые тесты.

## 8. Минимальная спецификация отчёта каждого цикла
cycle_id, commit_sha, changed_blocks, affected_blocks, tests_passed, tests_failed, invariant_residuals, known_limitations, data_vintages, baseline_comparison (если доступно), decision, rollback_ref. Пустое поле «данные» нельзя выдавать за подтверждение экономической адекватности.

## 9. Приёмка
A01: новая функция не отменяет старые инварианты без явной миграции.
A02: отрицательные тесты обнаруживают преднамеренно испорченные балансы.
A03: изменение общего контракта требует глобального повторного запуска.
A04: ни один шаг не заявляет статистического самообучения без новых наблюдений.
A05: результаты циклов воспроизводимы и допускают откат.
A06: фактические тесты отличаются от запланированных и явно маркируются.
