## Результаты проверки и обнаруженные ограничения
R01. В README верхний раздел «Ближайшая работа» до сих пор указывает на ранний этап ТЗ, хотя docs/42 уже определяет актуальный маршрут. Исправить, не удаляя историческую запись.
R02. Тест v01 использует упрощённое состояние и печатает «double-entry circuit», хотя полного двойного бухгалтерского учёта там нет. В будущем точнее маркировать это как контроль зеркальных финансовых позиций.
R03. Тест v02 использует signed financial positions, а не полный набор секторных текущих, капитальных и финансовых счетов. Это подтверждено комментарием в коде. До этапа 3 требуется завершить этап 2.
R04. В v02 денежные переводы валидируются порядком платежей; модель без овердрафта и центрального банка. Это ограничение примера, не всеобщий экономический закон.
R05. В v02 прямой сбор фирмы экзогенен, не вычисляется из бухгалтерской прибыли; важно не интерпретировать как полноценную налоговую систему.
R06. Утверждение о 10 626 параметрических комбинациях содержится в docs/40, но воспроизводимого параметрического теста в репозитории нет. Статус: заявлено ранее, **не подтверждено в этом аудите**. Добавить тест или исправить утверждение.
R07. Workflow .github/workflows/accounting-regression.yml существует. Фактический статус выполнения GitHub Actions при текущем доступе не установлен; нельзя считать CI зелёным.
R08. Открытые вопросы docs/03 должны оставаться в реестре, пока закрытие не подтверждено решением; наличие более поздних архитектурных документов само по себе не означает закрытие.
R09. Нет подтверждения экономической V2 и прогнозной V3 в существующих программных примерах; результаты V1 не равны доказательству прогностической ценности.
R10. Сводный README содержит последовательные исторические «главные этапы»; верхнее актуальное состояние должно ссылаться на docs/42 и не стирать историю.
R11. Запрошенная пользователем полная сохранность исходного диалога не равна реконструкции в docs/07; для дословной полноты необходим отдельный экспорт переписки, как уже отмечено в README.
