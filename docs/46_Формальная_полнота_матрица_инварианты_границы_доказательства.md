# AMFE-17 — формальная область полноты и доказательство инвариантов (этап 2, шаги 1–6)
Дата: 2026-11-11. Код: src/amfe/accounting_core.py; тесты: tests/test_accounting_core_v06.py.
**Статус:** математическое доказательство структурных инвариантов *для принятого класса проводок*, а не доказательство полноты экономической теории или всей системы национальных счетов. Локальные испытания эквивалентного прототипа: 7 тестов, 432 сценария. Точное удалённое исполнение версии GitHub ожидает подтверждения CI.

## 1. Область и перечень счетов
Сектора S={домохозяйства H, фирмы F, банки B, государство G}; одна страна, валюта, товарная стоимостная единица, без внешнего сектора. Финансовые инструменты J={депозиты (H,F,G актив; B обязательство), банковский кредит (B актив; F обязательство), гособлигации (B актив; G обязательство)}. Реальные активы R={запасы, основной капитал}; в прототипе оба принадлежат фирме. Финансовые позиции хранятся со знаком плюс для активов и минус для обязательств; реальные активы неотрицательны. Денежные потоки, амортизация и активы — условные номинальные стоимости без переоценки.

Классы реализованных конструкторов:
- кредит фирмы и погашение;
- выпуск гособлигаций и погашение;
- выплата зарплаты, трансферты, прямой сбор, дивиденды (перевод между небанковскими секторами);
- производство продукции на склад;
- конечные покупки домохозяйств и государства;
- процентный платёж фирма → банк;
- преобразование запасов в основной капитал собственным производством (упрощённая инвестиция);
- амортизация основного капитала (упрощённая потеря стоимости).

Каждая запись имеет три вектора: C_s — изменение чистой стоимости по текущему счёту; K_(s,a) — изменение стоимости реальных активов; F_(s,j) — изменение подписанных финансовых позиций. Для отдельных экономических статей (например, зарплата, прибыль, налог) дополнительно хранится строковый тип операции. Это пока не полный стандартизованный план счетов SNA.

## 2. Универсальная матрица
Для каждой операции t формируется строка T_t = [C_s(t) | K_s(t) | F_s(t)] по четырём секторам, где K_s=Σ_a K_(s,a), F_s=Σ_j F_(s,j).
Обязательные условия допуска строки:
(A) ∀s: C_s(t) = K_s(t) + F_s(t).
(B) ∀j: Σ_s F_(s,j)(t) = 0 (зеркальность каждого финансового инструмента).
(C) новые позиции неотрицательны для заданных реальных активов и депозитов; знаки кредитных и долговых позиций соответствуют типам инструментов.
Сводная матрица периода — упорядоченный список строк T_t, доступный в результате close() как matrix; строки сохраняют названия типов операций. **Пока не реализованы** самостоятельные столбцы контрагентов и детальная классификация распределения/перераспределения/сбережений по SNA.

## 3. Теорема о сохранении балансов
Предпосылки: (i) начальные финансовые позиции зеркальны по каждому инструменту; (ii) начальная чистая стоимость каждого сектора NW_s(0)=Σ_j F_(s,j)(0)+Σ_a A_(s,a)(0); (iii) принимаются только операции, удовлетворяющие A–C; (iv) нет переоценок, прочих изменений объёма, внешних секторов и неучтённых инструментов.
**Утверждение:** после любой конечной последовательности допустимых операций сохраняются:
1. ∀j Σ_s F_(s,j)=0;
2. ∀s NW_s(T)−NW_s(0)=Σ_t C_s(t);
3. ∀s Σ_t C_s(t)=Σ_t K_s(t)+Σ_t F_s(t);
4. Σ_s [NW_s(T)−NW_s(0)]=Σ_sΣ_t K_s(t).
**Доказательство:** база T=0 следует из (i)–(ii). Для индукционного шага по (B) сумма изменений финансовых позиций каждого инструмента нулевая, значит (1) сохраняется. По определению NW изменение равно сумме финансовых и реальных изменений; по (A) это C_s(t). Складывание по t доказывает (2)–(3). Суммирование по секторам и (B) даёт (4). Условия (C) проверяют допустимость остатков, но не требуются для алгебраического равенства. QED.

**Следствие:** сумма чистых финансовых активов замкнутой экономики равна нулю; сумма чистой стоимости может быть положительна из-за реальных активов. Сама теорема не доказывает, что типы экономических операций исчерпывающи или что их денежная оценка корректна.

## 4. Программная реализация
Accounts.apply() сначала валидирует структуру и уравнения строки, вычисляет новые состояния в копиях, проверяет зеркальность и допустимые знаки, затем атомарно публикует новое состояние. При исключении состояние и журнал не меняются. Accounts.close() суммирует строки матрицы и проверяет секторные мосты между началом и концом периода. Accounts.begin() переносит остатки в следующий период. Decimal исключает двоичные ошибки округления для представимых десятичных сумм; сам по себе не решает вопрос методологии оценки активов.

## 5. Проверки
Тесты: (1) базовый четырёхсекторный сценарий, (2) два периода, (3) гособлигации и дефицит, (4) инвестиции и амортизация, (5) атомарность и ошибки, (6) десятичная арифметика и запрет NaN/Infinity, (7) 432 детерминированных параметрических сценария. Регрессия старых v01–v05 добавлена в workflow; её фактический удалённый статус не подтверждён. Прогностическая V3 и эмпирическая V2: NOT_APPLICABLE.

## 6. Матрица покрытия и границы доказательства

|---|---|---|---|

**Ограничение реализации:** низкоуровневый Transaction допускает любой алгебраически допустимый вектор под разрешённым именем kind. Конструкторы выше задают канонические шаблоны, но сам тип kind пока не является доказательством экономического смысла. Для строгой семантической полноты потребуются типизированные схемы операций и отдельные тесты на недопустимую переклассификацию.

## Решение по допуску
**V1 = CONDITIONAL** для перечисленных классов и ограничений. **Не объявлять этап 2 завершённым:** впереди полноценные счета производства, доходов, использования доходов, накопления, финансовых операций, переоценки и прочих изменений объёма, плюс подтверждение CI. Переход к этапу 3 возможен только после отдельного закрытия соответствующего контрольного ворота.
