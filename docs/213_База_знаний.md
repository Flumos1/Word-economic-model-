# 213. База знаний market intelligence: схема, источники, свежесть

Дата: 2026-11-21. Роль: `dense-vintages`. Статус: **RESEARCH_ONLY, admission=false**; локально,
**не закоммичено** (интеграция — Lead). Основание:
[docs/190](190_Клиентский_пакет_Ормуз_США.md) и [docs/191](191_Маркетинг_нефтегаз.md)
(что продаём и в каких границах), [docs/205](205_Верификация_источников.md) (статусы источников),
[docs/209](209_Исследование_заказчиков.md) (аккаунты), [docs/212](212_Агентная_сеть_market_intelligence.md)
(сеть, которая эту базу наполняет).

Комплект: [`knowledge_base/`](../knowledge_base/README.md), инструмент
[`tools/kb.py`](../tools/kb.py), тесты [`tests/test_kb.py`](../tests/test_kb.py) — 31 проверка.

## 0. Резюме

- Создана **отдельная база знаний** сети market intelligence: 19 записей, 16 источников,
  схема `amfe.kb.entry.v1` и правила, которые проверяются кодом.
- Записи: 6 сегментов, 4 источника, 4 шаблона кейсов, 4 целевых аккаунта, 1 метод.
  **Ни одного `VERIFIED`**: в среде нет сети и подписок, поэтому факты — `HYPOTHESIS` (14) или
  `NOT_FETCHED` (5). Это ограничение метода, а не вывод о рынке.
- `tools/kb.py` умеет `add / search / validate / merge / index / export` (JSON и MD), проверяет
  evidence, лицензию и свежесть, **не ходит в сеть**, не читает часы (дата передаётся явно),
  fail-closed (exit 2, файлы не пишутся при дефекте).
- Свежесть формализована: `review_due = as_of + ttl_days`; просроченное не удаляется, а попадает
  в `stale` индекса и заменяется новой записью.

## 1. Зачем отдельная база

| Контур | Что хранит | Не заменяет |
|---|---|---|
| `knowledge/` | научные реестры AMFE (литература, идеи, методы, онтология) | не является рыночной базой |
| `agents/memory/*.jsonl` | журнал работы ролей (что делали, какие решения) | не хранит факты с лицензией |
| `protocols/source_registry.json` | реестр источников данных модели | не про рыночные аккаунты |
| **`knowledge_base/`** | рыночные знания: сегменты, источники, шаблоны кейсов, аккаунты, метод — с evidence, лицензией и свежестью | не является допущенной моделью и не заменяет научный контур |

Разделение важное: память отвечает на вопрос «что делал агент», база знаний — «что мы знаем, из
какого источника, под какой лицензией и до какой даты это верно».

## 2. Структура и схема

```
knowledge_base/
  README.md            # правила и команды
  schema.json          # JSON-схема + x-rules (семантические правила)
  sources.json         # 16 источников (id, класс, доступ, лицензия)
  entries/seed.jsonl   # 19 записей, append-only JSON Lines
  inbox/               # очередь: <id>.jsonl -> validate -> merge
  index.json/index.md  # собираются tools/kb.py index
```

Запись (`amfe.kb.entry.v1`): `id` (`KB-NNNN`), `kind`, `title`, `summary`, `tags`,
`evidence_status`, `evidence_grade`, `source_ids`, `licence`, `as_of`, `ttl_days`, `review_due`,
`links`, `created`, `updated`, `author_role`, `notes`; опционально `retrieved_at`, `account_id`
(только для `target_account`), `supersedes`, `archived`.

Источник (`amfe.kb.sources.v1`): `id` (`SRC-…`), `name`, `class`, `access`, `licence`, `homepage`,
`url_checked`, `terms_checked`, `terms_hash`, `retrieved_at`, `jurisdiction`, `allowed_use`, `notes`.

Правила, которые проверяет код (полный список — `schema.json` → `x-rules`):

1. `review_due` пересчитывается как `as_of + ttl_days`; расхождение — ошибка.
2. `grade A` — только с `VERIFIED`; `HYPOTHESIS`/`NOT_FETCHED` — только `C` или `null`.
3. `VERIFIED` требует `grade A`, `source_ids`, `retrieved_at`, источника с проверенными условиями и
   доступом не `NOT_AVAILABLE_IN_ENV`.
4. `licence NONE` — только при `NOT_FETCHED`; у `NOT_FETCHED` обязательны причина и блокер в `notes`.
5. В `HYPOTHESIS`/`NOT_FETCHED` запрещены цифры с валютой, процентами и масштабом (млн/млрд/тыс).
6. Запрещены формулировки `admitted`/«допущенная модель».
7. Каждый `links[]` существует в репозитории; каждый `source_ids[]` есть в `sources.json`.
8. `account_id` обязателен ровно для `target_account` и должен быть в
   `marketing/target_accounts.json`.
9. Лицензия записи совместима с источниками: открытая запись не подпирается подпиской.
10. Повтор `(kind, title)` запрещён; изменение — новая запись с `supersedes`.

## 3. Evidence, лицензия, свежесть

| Измерение | Значения | Смысл |
|---|---|---|
| `evidence_grade` | `A` / `B` / `C` / `null` | сила источника: первоисточник / надёжный вторичный / слабый |
| `evidence_status` | `VERIFIED` / `PARTIAL` / `HYPOTHESIS` / `NOT_FETCHED` | что именно утверждаем |
| `licence` | `OPEN` / `ATTRIBUTION` / `PUBLIC_DOMAIN` / `SUBSCRIPTION` / `LICENCE_REQUIRED` / `INTERNAL` / `NONE` | что можно делать с записью |
| `as_of` + `ttl_days` | дата + срок | когда знание устареет (`review_due`) |

Классы свежести в индексе: `fresh` (срок не близко), `due_soon` (≤ 30 дней), `stale` (просрочено),
`UNKNOWN` (дата не передана — часы не читаются). Сейчас все 19 записей `fresh` на 2026-11-21.

## 6. Инструмент `tools/kb.py`

```powershell
python tools/kb.py --check                                  # exit 0 / 2
python tools/kb.py validate --json                          # amfe.kb.validate.v1
python tools/kb.py search "TCO" --kind case_template
python tools/kb.py search "" --stale --today 2030-01-01     # просроченные (нужна дата)
python tools/kb.py add --kind segment --title "..." --summary "..." `
    --author-role gas-lng --as-of 2026-11-21 --tags segment,gas `
    --source SRC-EIA --link docs/191_Маркетинг_нефтегаз.md   # запись в inbox
python tools/kb.py merge                                     # inbox -> entries + архив
python tools/kb.py index --today 2026-11-21                  # index.json + index.md
python tools/kb.py export --format json --out .tmp/kb.json   # или --format md
```

| Команда | Поведение |
|---|---|
| `add` | строит запись, считает `review_due`, проверяет и пишет одну JSONL-строку в `inbox/<id>.jsonl`; при дефекте — exit 2 и **ничего не пишет** |
| `merge` | валидирует весь inbox; при любой ошибке — exit 2 и файлы не меняются; иначе дописывает новые id в `entries/seed.jsonl` и переносит обработанные файлы в `inbox/merged/` |
| `index` | собирает `index.json` и `index.md`: счётчики по `kind`/`status`/`grade`/`licence`, свежесть, дефекты |
| `search` | токен-поиск + фильтры `--kind/--tag/--evidence/--licence/--stale`; порядок по `id` |
| `export` | детерминированный JSON (`amfe.kb.export.v1`) или Markdown; два запуска дают одинаковый файл |
| `validate` / `--check` | схема, обязательные поля, enum'ы, даты, TTL, ссылки, источники, evidence, лицензия, цифры, контакты |

Запись и индексация детерминированы: нет сети, нет чтения часов (для свежести нужен `--today`),
нет случайных id (следующий свободный `KB-NNNN`).

## 7. Процесс пополнения

`inbox → validate → merge → index` — подробно в
[`agents/market_intelligence/kb_workflow.md`](../agents/market_intelligence/kb_workflow.md).

1. Автор кладёт запись в `inbox/` (лучше через `add`, тогда схема и TTL считаются автоматически).
2. `kb.py --check` — если дефект, запись остаётся в inbox с перечнем кодов.
3. `kb.py merge` — валидные записи уходят в `entries/seed.jsonl`, дубли по id пропускаются,
   обработанные файлы архивируются.
4. `kb.py index --today …` — пересборка индекса и отчёт о просроченном.
5. Библиотекарь отчитывается Director: принято/отклонено, просрочено, каких источников не хватает.

## 8. Ограничения

- **Сети нет:** `sources.json` — реестр намерений, а не подтверждённых доступов; `url_checked` и
  `terms_checked` честно `false`.
- **Нет `VERIFIED`:** ни одна запись не подтверждена первоисточником; статусы не завышаются.
- **Лицензии не проверены:** `SUBSCRIPTION`/`LICENCE_REQUIRED` источники нельзя использовать до
  договора; ключи в репозиторий не попадают.
- **База не является моделью:** это знания и evidence, а не прогноз; `admission=false`.
- **Свежесть зависит от даты:** без `--today` индекс помечает всё как `UNKNOWN`, а не «свежее».

## 9. Проверка

31 тест: схема и enum'ы, размер и состав seed, уникальность и порядок id, обязательные поля,
`review_due`, честность evidence, отсутствие цифр и «допущенных» формулировок, разрешимость
источников, существование ссылок, правила лицензий, реальность `account_id`, причина у
`NOT_FETCHED`, CLI (`--check`, `validate --json`), поиск и фильтры, `--stale` без даты → exit 2,
`add` (успех, дубль id, цифра, неизвестный источник), `merge` (успех и отказ без записи),
детерминизм `index`/`export`, классы свежести, битая запись → exit 2, отсутствие сети и часов,
«`--check` ничего не пишет».
