## 1. Что реализовано

Единый пошаговый контур `WorldCore`, который в одном периоде выполняет:

1. **старт периода** — открытие периода в учётном ядре (`amfe.accounts.AccountSystem`);
2. **решения** — инфляция, адаптивные ожидания, правило Тейлора (ставка политики), марковский
   режим, экзогенные факторы сценария (спрос/энергия/труд);
3. **производство** — физический слой: Леонтьев IO `x = (I−A)⁻¹d`, пределы энергии и труда
   (`amfe.resources.scenario.run_scenario`);
4. **доходы/расходы/финансы** — монетарный блок: 12 проводок (10 видов событий) четырёх
   секторов — производство, зарплата, трансферты, налоги, проценты, госзакупки, потребление,
   кредит оборотного капитала, облигации, погашения — и закрытие периода счетов;
5. **внешние операции** — двусторонние торговые кредиты A↔B, закрытие периода BoP/IIP и
   FX-переоценка (`amfe.international.TwoCountryWorld`);
6. **инварианты** — физические, монетарные, внешние и кросс-слойные проверки
   (`amfe.world.integration`); при нарушении — `IntegrationError`, отчёт не создаётся;
7. **отчёт периода** — типизированный `WorldPeriodReport` (+ детерминированный JSON/digest).

Дополнительно: детерминизм по seed, `reset()`, `describe()`, экспорт всего прогона в JSON,
поддержка пользовательского `ExternalAccountsHook` (события зеркалируются в собственный
рекордер ядра).

## 3. Монетарный блок и его уравнения

Физический слой даёт выпуск, конечный спрос и добавленную стоимость `VA_t` в физических
единицах. Денежная оценка — явная и единственная (нет второго счёта стоимости):

```
P_t   = P_{t−1} · (1 + π_t/100)                       (уровень цен)
Y_t   = P_t · VA_t                                    (номинальный ВВП)
C_t   = c · Y_t,  G_t = g · Y_t,  I_t = Y_t − C_t − G_t   (c + g + i = 1)
W_t   = w · Y_t                                        (оплата труда)
F_t   = f · Y_t                                        (трансферты домохозяйствам)
```

Проводки периода (в порядке применения): кредит оборотного капитала (при нехватке ликвидности),
`produce(Y)`, `pay_wages(W)`, валовый выпуск облигаций под кассовый разрыв, `pay_transfer(F)`,
`household_purchase(C)`, `government_purchase(G)`, `pay_direct_tax(T)`, проценты фирмы и
государства банку, погашение кредита фирмы, погашение излишка облигаций. Все суммы — `Decimal`
(квантование 1e-12), все ограничения ликвидности счетов соблюдаются: отрицательные депозиты и
переплата кредита отвергаются самим учётным ядром.

Фискальное правило (прототип, институциональное правило/гипотеза):

```
r_t = i_t/100                                        (ставка политики)
g_t = реальный рост + π_t/100                        (номинальный рост)
pb* = (r_t − g_t)/(1 + g_t) · b_{t−1}                (stabilizing_primary_balance, dynamics.debt)
PB_target = [pb* + λ·(b_{t−1} − b*)] · Y_t            (b* — целевой долг, λ — реакция)
T_t = clip(G_t + F_t + PB_target, tax_min·Y_t, tax_max·Y_t)
```

Проценты: `I_gov = i_t/100 · debt_open`, `I_firm = i_t/100 · loan_open`. Государство выпускает
облигации на валовую потребность в кассе, затем гасит излишек; фирма берёт оборотный кредит под
зарплату/налог/проценты и гасит из выручки. Остаточная задолженность переносится в следующий
период. Таким образом `I_t = Y_t − C_t − G_t` тождественно равно изменению товарных запасов фирмы,
и все счета закрываются без невязок.

## 4. Динамические механизмы (этап 5) в цикле

| Механизм | Класс (docs/38 I10) | Как используется | Где проверяется |
|---|---|---|---|
| Режим инфляционного таргетирования | INSTITUTIONAL_RULE | `InflationTargetRegime`, цель π* | отчёт `dynamics.policy_rule` |
| Адаптивные ожидания | HYPOTHESIS | `AdaptiveExpectations.update(π_t)` → π^e_{t+1} | `expectations_consistent` |
| Правило Тейлора | HYPOTHESIS | `i_t = r* + π^e + φ_π(π^e−π*) + φ_y·gap` | `policy_rule_consistent` |
| Марковские режимы | HYPOTHESIS | seeded-путь 2 режимов; режим сжатия умножает спрос на 0.93 | отчёт `dynamics.regime_*` |
| Долговая динамика | IDENTITY | `debt_step` из `amfe.dynamics.debt` | `debt_identity`, `debt_flow_identity` |
| Стабилизирующий первичный баланс | INSTITUTIONAL_RULE/HYPOTHESIS | фискальное правило выше | бюджетные проводки, debt-ratio |
| NK-детерминированность | HYPOTHESIS (теорема при допущениях) | диагностика Blanchard–Kahn при инициализации | `dynamics.nk_determinacy` |
| Девальвация/шок | SCENARIO | `WorldScenario.fx_rate_path`, `extra_inflation` | отчёт и внешние проверки |

Инфляция в прототипе задаётся явной редуцированной зависимостью
`π_t = π* + slope·gap_{t−1} + extra`, где `gap = VA_t/потенциал − 1`. Это **гипотеза/сценарий**,
а не оценённая кривая Филлипса; ставка политики не влияет на инфляцию в этом контуре (передача
политики — следующий шаг). NK-детерминированность — локальное свойство линеаризованной модели при
данных параметрах, а не прогноз (оговорка `LOCAL_STABILITY_CAVEAT` сохраняется в отчёте).

## 5. Внешний слой (этап 3) в интеграции

Торговля в каждом периоде сбалансирована в numeraire: A экспортирует `V_A` в валюте A,
B экспортирует `V_B = V_A·rate_A/rate_B` в валюте B; каждая операция оформляется торговым
кредитом (`record_trade`), поэтому `CA_A = CA_B = 0`, `FA_A = FA_B = 0`, а валовые внешние
позиции растут. IIP закрывается по тождеству
`IIP_close = IIP_open + FA + revaluation` внутри `TwoCountryWorld.close_period`; ядро дополнительно
проверяет зеркальность (`CA_A+CA_B=0`, `IIP_A+IIP_B=0`) и квитирование кредитов с монетарным
блоком (сумма событий hook равна смоделированной экспортной стоимости).

`IntegrationHook` (реализация протокола `ExternalAccountsHook`, docs/78 §5) регистрирует
события claims/flows/revaluation и передаёт их пользовательскому хуку, если он задан;
числовые «пылинки» переоценки (|amount| ≤ 1e-18) отбрасываются. Девальвация — это шаг FX-курса
в заданный период; FX-переоценка **не является потоком** и отделена от CA/FA.

Связь с учётным ядром на уровне богатства:

```
NW_national(num) = NW_local·rate + NFA(num)
Δ(NW_local) = savings + revaluation                          (проверено accounts)
NFA_close − NFA_open = FA_transactions + revaluation          (проверено international)
```

Мост `wealth_bridge` проверяет обе идентичности и точный перевод в numeraire (включая
трансляционный член `NW_prev·(rate_t − rate_{t−1})` для страны с не-нумерарием). Ядро не
постит внешние потоки в четыре домашних сектора — это осознанная заглушка (см. §6).

## 6. Что реально связано, а что пока заглушка

**Связано по-настоящему:**

- физический выпуск → денежная оценка (`Y = P·VA`), и счета этапа 2 закрываются **каждый период**
  со всеми своими инвариантами (финансовые зеркала, `ΔNW = сбережения + переоценка`, бюджетное
  ограничение государства, закрытая экономика без невязок, три метода ВВП);
- внешние потоки, BoP/IIP, FX-переоценка и хук-события этапа 3;
- ставка политики, ожидания, режимы и долговая идентичность этапа 5 — в решениях и проверках;
- кросс-слойные проверки: физика↔деньги, деньги↔внешний мир, мировое богатство = реальные активы.

**Заглушки/упрощения (честно):**

1. **Домашние счета — закрытая экономика.** `AccountSystem` (docs/77) не имеет счёта остального
   мира; поэтому экспорт/импорт не проводятся через секторы, а наблюдаются хуком и
   согласовываются на уровне национального богатства. Полное открытое SFC-ядро требует
   расширения хартии сектором `row` и внешними инструментами (интерфейс описан в docs/77 §9);
   это следующий шаг, а не заявление о готовности.
2. **Один агрегированный производитель на страну.** Физические IO-секторы (goods/services)
   дают только агрегированную `VA`; промежуточные потоки не отображаются в денежных счетах,
   распределение `VA` на зарплату/прибыль — фиксированные доли `w`, а не поведение/оценка.
3. **Физическая торговля не моделируется.** Стоимости экспорта — доля номинального ВВП
   (`export_share`), сбалансированные в numeraire; количества, цены, транспорт/логистика и
   импортное содержание не связаны с `resources.logistics`/`balances` (только материальный
   баланс IO и «нет двойного счёта» проверяются).
4. **Цены/инфляция — редуцированные сценарные правила** (гипотеза), а не оценка; FX pass-through
   девальвации — экзогенный сценарий.
5. **Финансовый сектор — один банк**, без ЦБ, рынка облигаций, депозитных ставок, дефолтов и
   ликвидностных ограничений сверх неотрицательности депозитов; банк поглощает выпуск
   облигаций государства.
6. **Режимы — синтетический seeded-путь**, а не оценённые вероятности; фискальная реакция —
   прототип институционального правила.
7. **Нет калибровки и данных.** V2/V3 = NOT_APPLICABLE, никаких выводов о реальной экономике.

## 7. Инварианты интеграции

Все проверки собираются в `WorldPeriodReport.checks` (47 имён на период для двух стран;
полный список — в отчёте). Каждая запись — булево значение; числовые невязки — в `residuals`.
`assert_integration` бросает `IntegrationError`, если хоть одна проверка ложна; отчёт создаётся
только при `ok=True`.

| Группа | Проверки |
|---|---|
| Физика | `physical_material_balance`, `physical_value_added_equals_final_uses`, `physical_no_double_counting` (валовой выпуск ≥ добавленной стоимости), `physical_scale_in_unit_interval`, `energy_limit_respected`, `labour_limit_respected` |
| Счета | `accounts_gdp_three_measures`, `accounts_gdp_matches_physical` (`Y = P·VA`), `accounts_expenditure_matches_shares`, `accounts_household_liquidity` |
| Богатство | `net_worth_bridge_local` (`ΔNW = сбережения + переоценка`), `national_wealth_bridge`, `nfa_identity`, `world_net_worth_equals_real_assets`, `external_nfa_mirror` |
| Внешний мир | `external_current_account_mirror`, `external_capital_account_mirror`, `external_financial_account_mirror`, `external_iip_mirror`, `external_bop_identity`, `external_iip_identity`, `external_nonnegative_claims`, `external_mirror_zero`, `external_trade_claims_match` |
| Долг | `debt_identity` (формула `amfe.dynamics.debt.debt_step` на данных счетов), `debt_flow_identity` (точное тождество `debt_{t+1} = debt_t + interest − PB + Δcash`) |
| Политика/ожидания | `policy_rule_consistent` (пересчёт правила Тейлора), `expectations_consistent`, `external_mirror_country` |

Проверка `net_worth_bridge_local` — это и есть требуемое `ΔNW = сбережения + переоценка`; в
отчётности счетов она уже сертифицирована самим `check_report` (тест дополнительно прогоняет
`check_report` по каждому счёту).

## 10. Публичный интерфейс и следующий шаг

```python
from amfe.world import WorldCore, WorldConfig, standard_scenarios

core = WorldCore(WorldConfig(), scenario=standard_scenarios()[0])
result = core.run(periods=12)          # WorldRunResult: .reports, .digest, .ok
report = result.last                   # WorldPeriodReport
report.countries["A"].accounts         # PeriodReport учётного ядра (проверен)
report.checks, report.residuals        # все инварианты периода
core.step() / core.reset() / core.describe()
```

Следующие шаги к калибровке (не входят в эту задачу):

1. **Открытое SFC-ядро**: расширить хартию `accounts` сектором `row` и внешними инструментами
   (интерфейс docs/77 §9) и постить экспорт/импорт/доходы/трансферты в секторы, чтобы получить
   открытый ВВП `Y = C+G+I+NX` вместо моста на уровне богатства.
2. **Секторное отображение IO → счета** (docs/79 §9): несколько производителей/отраслей,
   промежуточное потребление и распределение добавленной стоимости по счетам.
3. **Физическая торговля**: связать `exports/imports` c `resources.logistics`/`balances`, цены и
   количества, а не доли номинального ВВП.
4. **Калибровка (этап 6)**: point-in-time данные, IO-таблицы, энергобалансы, трудовые
   обследования; протокол допуска и OOS-проверка — как для прогнозного трека (docs/76).
5. **Передача политики**: связать ставку с инфляцией/спросом через оценённую кривую, а не только
   диагностически; мониторинг и откат (этап 8) — на этих же инвариантах.
