# 211. Коммерческий слой сайта: `site/business/` (RU + EN)

Дата: 2026-11-21. Исполнитель: роль `dense-vintages`. Статус: **готово локально, не задеплоено и не
закоммичено** (деплой и коммит — решение Lead). Тесты: [tests/test_site_business.py](../tests/test_site_business.py)
— 20 проверок, зелёные вместе с research-сайтом (23 теста `test_site_build`).

Коммерческий слой — отдельный мини-сайт внутри публикации: `site/business/` (RU) и
`site/business/en/` (EN). Research-сайт (`site/*.html`, 8 RU + 8 EN страниц) не меняется по смыслу:
в двух index-страницах появилась одна ссылка на коммерческий слой.

## 1. Что это и чем не является

**Это** витрина коммерческого предложения для нефтегаза: сценарии для решений (бюджет, закупки,
газ/СПГ, API), цены в USD, правила данных и один контакт — `mailto:flumos@gmail.com`.

**Это не** новая модель, не прогноз и не допуск. Все страницы несут `RESEARCH_ONLY` и
`admission=false`; на каждой есть дисклеймер «не прогноз и не инвестиционная рекомендация» и
«не допущена к применению». Статусы не «улучшаются» коммерческой страницей.

Отличия от research-сайта:

| | research-сайт | `site/business/` |
|---|---|---|
| Задача | публикация зарегистрированных результатов | продажа сценариев как услуги |
| Генерация | `tools/site_build.py` (из артефактов) | **вручную**, HTML+CSS, без сборки |
| JS / CDN | нет | нет |
| CSS | `site/assets/style.css` | `site/business/assets/style.css` (свой, mobile-first) |
| Контакт | нет | только `mailto:flumos@gmail.com`, без форм |

Почему без генератора: коммерческий текст, цены и кейсы правит человек. Ручные HTML-файлы не
расходятся с генератором и не требуют пересборки при каждой правке. Цена решения — дублирование
шапки/подвала в 12 файлах; это проверяется тестами (навигация, ссылки, дисклеймер).

## 3. Решения (4 направления)

1. **Ормуз / бюджет** — что будет с бюджетом, маржой, топливом и расходами домохозяйств при Brent
   USD 120–170 и перекрытии пролива; база + стресс, диапазоны, путь по месяцам
   (основание: docs/186, docs/190).
2. **FLAKS / закупки** — TCO поставщиков, риск и бюджет категории, индексация/cap/floor, CFO-отчёт;
   данные обезличиваются (основание: docs/189).
3. **Газ / СПГ** — TTF/JKM, ПХГ, диверсия маршрута, энергоёмкость и издержки (основание: docs/188).
4. **API / Client Pack** — JSON-контракт, ключи/квоты, пакет PDF/DOCX + Excel + JSON + manifest
   (основание: docs/183, docs/192, docs/171).

Формулировки нарочно осторожные: «сценарий на объявленных допущениях», «диапазон — разброс
вариантов чувствительности, а не доверительный интервал», «страновых CPI по газу не считаем».

повреждена (строки выглядят как « 500–10 000», « 000–30 000», « 000–80 000» — первые цифры
потеряны). На сайте использованы диапазоны, согласованные с задачей и с
[marketing/one_pager.md](../marketing/one_pager.md) («пилот 7 500», «20 000–30 000», «25 000–80 000»).
Цифры нужно подтвердить владельцу и починить `pricing.md`, иначе следующий агент снова увидит
битые числа.

API-интеграция отдельной ценой не публикуется: в `pricing.md` её строка тоже повреждена
(« 000–25 000»), поэтому на сайте написано «входит в полный сценарий или считается по объёму».
Это честнее, чем придумать число.

## 5. Кейсы: правило и как добавить PDF

Сейчас на странице `cases.html` — только направления и статус «готовится». Публичных кейсов нет,
и это написано прямо. Правило: **ни одной цифры и ни одного имени клиента, пока нет
опубликованного PDF**.

Как добавить кейс:

1. Собрать PDF из отчёта (не пересчитывая числа вручную).
2. Проверить: нет сырых данных, нет персональных данных, нет названий компаний без письменного
   разрешения. Кейс с названием компании без разрешения — это выдуманный клиент, публиковать
   нельзя.
3. Положить файл в `marketing/cases/<имя>.pdf`.
4. Скопировать в `site/business/cases/<имя>.pdf` (именно эта папка уезжает на Pages).
5. В `cases.html` заменить строку статуса на ссылку:
   `<a href="cases/<имя>.pdf">PDF, N стр.</a>` (для EN — `../cases/<имя>.pdf`).
6. Прогнать `python -m unittest tests.test_site_business` — тест ссылок проверит, что файл есть.

Кейсы на русском и английском не обязаны совпадать файлом: EN-страница может ссылаться на тот же
PDF, если он на английском; иначе честно писать, что кейс только на русском.

## 7. Как обновлять

Сборки нет: правится HTML напрямую.

```powershell
# 1. правим site/business/*.html или site/business/en/*.html (цены, кейсы, тексты)
# 2. проверки (обязательно до публикации)
python -m unittest tests.test_site_business -v     # 20 тестов
python -m unittest tests.test_site_build -v        # 23 теста research-сайта
# 3. локальный просмотр
python -m http.server 8000 --directory site
#    http://127.0.0.1:8000/business/        (RU)
#    http://127.0.0.1:8000/business/en/     (EN)
```

Чеклист правки:

- [ ] дисклеймер `RESEARCH_ONLY · admission=false` есть в подвале каждой страницы;
- [ ] цены только в USD, без «₽» и «руб.»;
- [ ] нет `<img>`, логотипов, названий компаний, «trusted by» и отзывов;
- [ ] нет `http://`/`https://`, `<script>`, форм и трекеров;
- [ ] контакт — только `flumos@gmail.com`;
- [ ] ссылки относительные и ведут на существующие файлы (тест это проверяет);
- [ ] в EN-версии те же числа, статусы и ссылки-аналоги.

Если меняются цены — обновить их в `pricing.html`, `index.html` (CTA), `contact.html` (список) и в
этом документе, иначе тест `test_prices_are_usd_and_complete` пройдёт, а страницы разойдутся.

## 8. Деплой

Ничего дополнительно делать не нужно: `.github/workflows/pages.yml` публикует каталог `site/`
целиком при push в `main` с изменениями в `site/**`. Коммерческие страницы — часть `site/`,
поэтому уезжают тем же артефактом.

- URL: `https://flumos1.github.io/Word-economic-model-/business/` и
  `https://flumos1.github.io/Word-economic-model-/business/en/`.
- Сборка на CI не запускается: workflow только упаковывает `site/` (см. docs/134).
- Откат: revert коммита с `site/business/**`; research-страницы не затрагиваются.
- Ограничение тарифа Pages (приватный репозиторий) — то же, что в docs/134 §2.

## 9. Что нельзя публиковать

- «Допущенную модель», `admission=true`, «ACTIVE», «точность выше рынка», гарантию экономии X%.
- Названия и логотипы клиентов, отзывы, «нам доверяют» — до появления реального разрешения.
- Цифры кейсов без PDF; вероятности событий и политические прогнозы.
- Сырые сторонние данные (FIGARO/WIOD/OECD/Eora) и сырые данные клиента.
- Формы, регистрацию, трекеры, cookie, внешние шрифты/CDN, JavaScript — сайт остаётся офлайн
  статическим.
- Сертификаты и стандарты, которых у проекта нет (ISO, SOC 2 и подобное).
