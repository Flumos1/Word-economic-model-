## 2. Формат записи

Схема `AMFE-GEOPOL-SCENARIO/1.0.0`. Поля обязательны и проверяются до любого счёта:

| Поле | Смысл | Проверка |
|---|---|---|
| `scenario_id`, `title_ru` | стабильный id `[A-Z][A-Z0-9-]+` и имя | уникальность id |
| `family` | `sanctions` / `tariffs` / `conflict` / `chokepoint` / `export_restriction` / `agreement` / `industrial_policy` | из списка; канал должен быть совместим с семейством |
| `actors` | `from` → `to`, коды ISO3 (сторона-инициатор / адресат) | ISO3, непустые списки; для барьеров и переноса спроса `from ∩ to = ∅` |
| `sectors` | отрасли CPA/FIGARO (64 кода) или агрегаты | существуют в таблице, без повторов |
| `channel` | `import_restriction` / `export_restriction` / `chokepoint` / `demand_diversion` / `demand_shock` / `trade_facilitation` | из списка |
| `size` | доля целевого потока/спроса, `(0, 0.95]` | знак не используется: направление задаёт канал |
| `duration` | месяцы, целое `≥ 1` | `≤ 600` |
| `decay` | `none` / `step` / `linear` / `exponential` (число или `half_life_months`) | `exponential` без периода полураспада отклоняется |
| `direction` | `damage` / `benefit` / `both` (P-008) | объявленное намерение, не оценка |
| `source` | `kind=source_id` (id из `protocols/source_registry.json`) либо `kind=assumption` + `replace_with` | для `assumption` замена обязательна; неизвестный `source_id` отклоняется |
| `pit_date` | дата доступности сценария, `YYYY-MM-DD` | формат; для гипотетических — дата объявления допущения |
| `assumptions` | явные допущения | непустой список |
| `companions` | добавки `demand_diversion` / `demand_shock` | не повторяют канал сценария, проверяются отдельно |
| `historical_anchor` | ссылка на эпизод (`fact`, `fact_source`) | только для проверки знака |

Дополнительно протокол задаёт `country_map` (ISO3 → метка набора, например `DEU → DE`) и
`proxies` (ISO3 → блок таблицы с обязательным `note`). Иран в FIGARO 2019 отсутствует, поэтому
`IRN → ROW` — прокси с явной оговоркой; такие сценарии помечаются в отчёте и **не являются
оценкой Ирана**.

Валидация отклоняет: дубли `scenario_id`, совпадение `family + actors + channel`, неизвестное
семейство/канал/направление/отрасль/актор, `size` вне границ, `duration ≤ 0`, битую `pit_date`,
`assumption` без `replace_with`, `source_id` вне реестра, несовместимость канала и семейства.

## 4. Механика: как запись превращается в возмущение MRIO

Используется тот же движок, что и в P2 0.2: `WorldTable`, `WorldSolver`, `A = Z/x`,
`x' = (I - A')^{-1}(y + dy)`, проверки `validate_table`, `perron_root`, `country_core`
([`tools/world_pipeline.py`](../tools/world_pipeline.py)). Нового MRIO-движка нет: библиотека
только собирает объявленное возмущение, решает его и агрегирует.

- **Барьерные каналы** (`import_restriction`, `export_restriction`, `chokepoint`). Масштабируются
  межстрановые коэффициенты `A[строка ∈ to, столбец ∈ from, отрасль ∈ sectors]` на `1 − size`.
  Все три канала — одно и то же сокращение на объявленном направлении; различаются сторона,
  охват и отчётная классификация. Продуктивность после шока проверяется (`ρ(A') < 1`),
  отрицательные коэффициенты запрещены; отказ — fail-closed.
- **`demand_diversion`** — перенос конечного спроса: объём = `size · min(спрос источника,
  суммарный спрос получателей)`; получатели получают пропорционально своему рынку, источник
  теряет ровно перенесённый объём, `Σ dy = 0`. Ограничение `min` не позволяет большому
  внутреннему рынку дать абсурдный перенос.
- **`demand_shock`** — прирост конечного спроса получателя поддержки на `size · y`.
- **`trade_facilitation`** — рост `A` на объявленном направлении на `1 + size`.
- **`duration` и `decay`** объявлены и публикуются как профиль (месяц → множитель), но в решении
  не разворачиваются: числа отчёта относятся к пику шока (`solved_at=peak`), потому что
  сравнительная статика не имеет времени. Это указано в каждом отчёте.

Проверки в каждом отчёте: `validation_pass` (балансы таблицы), `scenario_material_residual`
(`A'x' + y' − x'`), `scenario_productive` (ρ(A')), `feasible`, `balances_pass` (жёсткое
произведение всех условий). Не сошлось — сценарий не публикуется, отчёт не пишется.

Отчёт агрегатный: страновые и отраслевые маргиналы, топ-10, несколько ячеек «страна × отрасль»,
положительные ячейки выгодоприобретателей; никаких `Z`, `x`, `y`, `va`, `delta_A` и
per-sector векторов.

## 5. Асимметрия P-008: выгоды считаются, а не подразумеваются

Для каждого сценария считаются выгоды и ущерб **отдельно** — по знаку Δвыпуска ячеек:
`gain_total = Σ Δx⁺`, `loss_total = −Σ Δx⁻`, доля выгод, отношение выгод к ущербу, наблюдаемое
направление (`damage` / `benefit` / `both`) и согласованность с объявленным.

- если положительных ячеек выше порога нет, отчёт пишет `beneficiaries.status = none` и явное
  «выгод нет: … асимметрия не выдумывается»; барьер, только сокращающий межстрановые
  коэффициенты, в этой сравнительной статике не может дать положительного выпуска;
- если выгоды есть, публикуются страны, отрасли и ячейки-выгодоприобретатели.

## 8. Ограничения

1. **Сравнительная статика.** Нет цен, замещения, эластичностей, динамики ожиданий и обратных
   связей. `duration`/`decay` — объявленный профиль, а не решённый путь; числа относятся к пику.
2. **Только промежуточные поставки.** Барьер масштабирует `A`, а не конечный импорт: тариф на
   потребительские товары (автомобили, электроника) занижен; замещение задаётся отдельным
   `companion`-переносом спроса.
3. **Валовой выпуск ≠ ВВП и ≠ благосостояние.** В количественной модели без замещения сокращение
   импортных затрат уменьшает валовой выпуск импортёра: в `TAR-USA-CHN-2018` US падает сильнее
   CN. Это свойство счёта, а не утверждение о потерях США; отчёт обязан читать так.
4. **Проливы без логистики.** Физическая мощность, маршруты, фрахт, очереди, SPR не
   моделируются (это блок 8, M8); пролив приближается сокращением поставок.
5. **Прокси.** Иран отсутствует в FIGARO (`IRN → ROW`), Тайвань отсутствует (используется Китай);
   такие сценарии помечены `proxy` и не являются оценкой страны.
6. **Одна таблица, один год.** FIGARO 2019 используется и для эпизодов 2018/2022: это структура,
   а не винтаж; PIT-дата относится к доступности сценария, а не к винтажу данных.
7. **Агрегация отраслей.** Узкие товары (галлий, графит, отдельные компоненты) шире кода CPA,
   поэтому сценарий завышает охват отрасли.
8. **Величины — допущения.** `source.kind=assumption`; замена указана в каждом сценарии.
9. **Проверка направления слабая.** Совпадение знака не является причинной оценкой; Иран — на
   прокси; европейский спад в модели имеет другую механику, чем в факте.
10. **Нет слоя вероятностей** (блок 14), **нет эндпоинта `/v1/geopolitics`** и записи в реестре
    модулей — это остаток B6, не входящий в MVP.

## 10. Воспроизведение и тесты

```powershell
# реальный прогон на FIGARO 2019 (данные третьей стороны, локально)
python tools/geopolitics_scenarios.py --protocol protocols/geopolitics_scenarios.json `
    --root data/mrio/figaro --dataset figaro_2019 --out build/geopolitics

# герметичный прогон без данных (построенная таблица с метками протокола)
python tools/geopolitics_scenarios.py --synthetic --out build/geopolitics_synthetic

# только выбранные сценарии
python tools/geopolitics_scenarios.py --only TAR-USA-CHN-2018,AGR-EU-MERCOSUR-2026
```

```powershell
python tests/test_geopolitics_scenarios.py -v
```

23 теста, офлайн, на детерминированной построенной таблице (метки протокола, без данных):

- **валидация**: покрытие B1 (15 сценариев, 7 семейств, 21 страна, 20 отраслей), обязательные
  поля, уникальность id и `family+actors+channel`, границы `size`/`duration`, семейства и каналы,
  `source` и `replace_with`, `pit_date`, `decay`, дубли и подмены, `gating`/`causal_claim`;
- **исполнение**: все сценарии считаются, балансы PASS, ρ(A') < 1, Hawkins–Simon, агрегаты
  сходятся с итогом, отчёты без сырых данных, размер отчёта ограничен;
- **детерминизм**: два прогона — байт-идентичные JSON/MD и digest; digest меняется при изменении
  параметра сценария;
- **асимметрия**: явное «выгод нет» для чистого барьера, выгодоприобретатели при объявленном
  переносе, `Σ dy = 0` для `demand_diversion`, `gain − loss = Δвыпуска`;
- **направление**: 2018 Иран (прокси) и 2022 Россия, 3 из 3, `scope=sign_only`, в блоке нет
  магнитуд; сценарий-прокси помечен и предупреждает, что числа не являются оценкой страны;
- **fail-closed**: нет протокола — exit 2 и ничего не записано; битый протокол — exit 1; неизвестный
  актор/отрасль/`--only` — отказ; `gating=false`/`causal_claim=false` во всех артефактах.

## 11. Что дальше

1. **Двусторонний конечный импорт.** Нужна матрица импорта по партнёрам (или FIGARO с
   destination-разбивкой `y`), иначе тарифы на потребительские товары занижены в разы.
2. **Ценовой канал и эластичности.** Связать с [docs/159](159_Количественный_канал.md) и
   [docs/178](178_Мост_прогноз_мир.md): pass-through в цены, затем в CPI (UC-05/UC-12).
3. **Вероятности.** Слой ожиданий (блок 14) поверх сценариев; сейчас библиотека отвечает «что
   если», а не «с какой вероятностью».
4. **API и реестр.** `/v1/geopolitics` (план API v2), запись модуля в реестре в статусе
   `RESEARCH_ONLY`, место в Client Pack/Simulator UI — остаток B6.
5. **Согласование с M8.** Закрытие Ормуза на 6 месяцев должно давать потерю поставок в пределах
   ±10% от нефтяного модуля (docs/177 A5); здесь эта сверка не заявляется.
6. **PIT-винтажи MRIO.** Для эпизодов 2018/2022 нужны таблицы соответствующих лет, иначе
   проверка направления остаётся проверкой механизма.
7. **Институты (блок 15)** как модификатор сценариев: почему одинаковая санкция даёт разный
   результат.
