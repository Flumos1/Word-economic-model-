## 2. Как использовать

1. **Сначала диагностика, потом кейс.** Кейс — не первое касание: он прикладывается по запросу или
   на созвоне, когда понятно, какое решение болит (бюджет, переработка или закупки).
2. **Выбрать один кейс, не три.** Три подряд читаются как брошюра; один — как разбор задачи.
3. **Проверить пометки.** В файле должны остаться: `RESEARCH_ONLY`, `admission=false`, «не прогноз»,
   «демо на публичных сценариях, не данные компании» (или «синтетический демо-набор»).
4. **Показать границы первыми.** Раздел «Границы» читают до чисел: он снимает главный риск —
   ожидание «допущенного прогноза».
5. **Связать с пилотом.** CTA в каждом кейсе: диагностика 20–30 минут (0), пилот 2–4 недели
   (7 500–10 000 USD), данные по NDA и обезличивание до расчёта.
6. **Перед отправкой** — чек-лист §2.1. Отправляет человек с проверенным адресом, не агент.

### 2.1 Чек-лист перед отправкой

- [ ] адресат и его роль проверены по публичному источнику;
- [ ] в кейсе нет утверждений о финансовых показателях компании-адресата;
- [ ] пометки `RESEARCH_ONLY`, `admission=false`, «не прогноз», «демо/гипотеза» на месте;
- [ ] PDF открыт и проверен (2 страницы, таблицы не разъехались, подвал читается);
- [ ] `python -m unittest tests.test_cases` — зелёный;
- [ ] `manifest.json` соответствует файлам (`python tools/build_cases.py --check`);
- [ ] в CRM поставлена стадия и дата следующего шага.

## 3. Что нельзя

1. **Выдавать демо за данные клиента.** Ни «в вашем случае», ни «по вашим ценам»: демо-набор
   синтетический, числа — иллюстрация механики.
2. **Называть числа прогнозом, вероятностью или доверительным интервалом.** Диапазон — разброс
   объявленных вариантов чувствительности.
3. **Считать маржу НПЗ по нашим числам.** Модуля маржи нет; в кейсе ТАНЕКО «маржинальных» цифр нет
   намеренно, и это проверяется тестом.
4. **Обещать экономию X %, точность выше рынка, замену Bloomberg/WoodMac/Platts.**
5. **Использовать как допуск модели, аудит или юридическое заключение** — статус `RESEARCH_ONLY`,
   `admission=false`.
6. **Цитировать без дисклеймера** и без указания, что это сценарий на объявленных допущениях.
7. **Смешивать аккаунты.** Татнефть и ТАНЕКО — один контур: один владелец, одно касание в 7–10 дней,
   без параллельных писем от разных людей.
8. **Коммитить и рассылать автоматически.** Пакет собирается локально; отправка — только человеком.

## 4. Как заменить демо на данные клиента

Общее правило: **меняются данные и допущения, а не формулы**. Код модели при замене не правится.

| Блок кейса | Сейчас | Заменить на | Кто даёт |
|---|---|---|---|
| Ценовой путь (Brent, дизель, керосин) | сценарий `hormuz_closed_6m` на объявленных допущениях | тот же сценарий + датированные котировки ICE/Platts, если нужен «как сейчас» | аналитик + подписка клиента |
| CPI и домохозяйство | веса и pass-through США (0,036 / 0,030 / 0,35 / 0,15; 90 галлонов) | веса CPI страны клиента, акцизы, НДПИ/демпфер, курс | клиент (экономика/налоги) |
| CAPEX | не считается | инвестиционная программа клиента: чувствительность CAPEX к цене задаётся клиентом | клиент |
| Маржа НПЗ (кейс ТАНЕКО) | не считается | выход фракций, оптовые котировки/нетто-бэк, переменная стоимость переработки, налоговый режим | технологи + коммерция + экономика |
| Закупки (TCO, бюджет, cap/floor) | демо-набор 12 поставщиков, 3 404 400 EUR | 2–4 категории, 2–4 поставщика на категорию, 12 месяцев факта, один договор на поставщика | клиент по шаблонам `pilot/flaks/` |
| Риск страны и пошлины | демо-таблицы | TARIC для пошлин, OECD CRP / WGI для риска | аналитик |
| Веса скоринга | 0,20 / 0,30 / 0,20 / 0,20 / 0,10 | веса, согласованные на воркшопе (сумма 1,0) | CFO/закупки клиента |

Порядок замены:

1. NDA и канал передачи (не публичная ссылка). До NDA файлы клиента не принимаются.
2. Шаблоны `pilot/flaks/suppliers_template.csv.tmpl` и `contracts_template.csv.tmpl` — заполняет
   клиент; строки «ПРИМЕР» удаляются.
3. `python tools/flaks_pilot.py --check` — схема, типы, диапазоны, дубликаты, единицы; ошибок 0.
4. Воркшоп по весам и по порогам cap/floor (фиксируются в отчёте, не «по умолчанию»).
5. Пересборка отчёта с `--generated-at`; два прогона байт-в-байт; SHA-256 в манифест.
6. Обновление кейса: цифры демо-набора заменяются на клиентские **с новой датой и новым источником**,
   пометка «демо» снимается только тогда, когда числа действительно клиентские.
7. После пилота исходные файлы удаляются по регламенту клиента; в репозиторий попадают только
   агрегаты и код.

## 5. Как обновить пакет

```powershell
python tools/build_cases.py                  # Markdown -> DOCX -> PDF + manifest.json
python tools/build_cases.py --no-pdf         # только Markdown и манифест
python tools/build_cases.py --check          # сверка манифеста, ничего не пишет
python -m unittest tests.test_cases -v       # 17 тестов
```

Правила: PDF и `manifest.json` пересобираются вместе; руками хеши не правятся; DOCX — промежуточный
файл в `build/cases/docx` (git-ignored) и в манифест не входит; при изменении текста кейса сначала
правится Markdown, потом пересобирается PDF.

## 7. Границы (честно)

- **Маржи НПЗ нет.** Кейс ТАНЕКО даёт рамку и входные цены, а не маржу; любые «маржинальные» числа
  появятся только на данных клиента.
- **CAPEX компании не считается.** В кейсе бюджета CAPEX — решение клиента на основе ценового пути и
  бюджетного шока.
- **CPI и домохозяйство — США.** Для другого рынка нужны свои веса, налоги и курс.
- **Диапазоны — чувствительность**, не доверительный интервал и не вероятность.
- **Закупки — демо-набор**: поставщики, цены, риск и пошлины вымышлены; TCO — формула, не
  бухгалтерская себестоимость.
- **PDF не байт-детерминирован**; Markdown и структура — детерминированы.
- **Не допуск:** `RESEARCH_ONLY`, `admission=false`, `causal_claim=false`; клиентское использование —
  решение владельца, а не автоматический допуск.
