# 162. Реестр источников данных (G3): что подтверждено, а что допущение

Дата: 2026-11-16. Волна 23 (G3). Статус: **реестр — учёт источников, а не загрузка данных и не
допуск.** Файлы: [protocols/source_registry.json](../protocols/source_registry.json),
[src/amfe/data/source_registry.py](../src/amfe/data/source_registry.py),
[tools/source_registry.py](../tools/source_registry.py),
[tests/test_source_registry.py](../tests/test_source_registry.py) (23 теста). Сеть не используется.

## 1. Зачем

До G3 статус данных был размазан по модулям: `assumption`-записи в oil/agri, «источники» в
`tools/agri_data.py`, лицензии в `protocols/licence_register.json`. Реестр сводит это в один
документ с датами, лицензиями, доступом и **честным статусом**: что реально подтверждено,
что только описано, а что остаётся допущением.

**Главное правило: `CATALOGUED` — не `VERIFIED`.** Никакая запись не может цитироваться как
наблюдаемые данные, пока она не `VERIFIED` (данные реально получены в проект и проверены).

## 2. Статусы

| Статус | Значение | Что разрешено |
|---|---|---|
| `CATALOGUED` | Запись проверена по документации/сайту (URL, издатель, лицензия, покрытие, поля); данные в проект **не загружены** | Ссылаться как на план/возможность, не как на наблюдение |
| `NOT_DOWNLOADED` | Источник нужен, но доступ платный/лицензионный/ручной; данных нет | Только как план; числа из него использовать нельзя |
| `VERIFIED` | Данные реально получены в проект и проверены; `retrieved_at` заполнен, в `notes` указан след (датасет/манифест/доки) | Единственный статус, который можно цитировать как наблюдения |

Валидатор запрещает: `VERIFIED` без `retrieved_at`, `VERIFIED` без `notes`, `VERIFIED` с
неизвестной лицензией; платный источник (`access=paid`) со статусом `VERIFIED`.

## 3. Схема (`AMFE-SOURCE-REGISTRY/1.0.0`)

Корень: `schema`, `date`, `intended_use`, `statuses` (определение каждого статуса), `sources`.

| Поле источника | Тип | Требование |
|---|---|---|
| `source_id` | str | `^[A-Z][A-Z0-9_]{1,63}$`, уникален |
| `name`, `publisher` | str | непустые |
| `url` | str | только `https://`, уникален, без пробелов |
| `license` | str | непустая; классифицируется в `public_domain / open_attribution / non_commercial / commercial / unknown` |
| `access` | enum | `api / file / paid` |
| `coverage` | object | `geography`, `period`, `frequency` — все непустые |
| `fields` | list[str] | непустой список |
| `retrieved_at` | date/null | ISO `YYYY-MM-DD`; `null`, если данных нет |
| `vintage_support` | enum | `full / partial / none / unknown` |
| `status` | enum | `CATALOGUED / NOT_DOWNLOADED / VERIFIED` |
| `notes` | str | след/ограничения; обязателен для `VERIFIED` |

Валидация fail-closed: отсутствие поля, `http://`, неизвестный статус/доступ, дубликаты
`source_id`/`url`, битая дата, пустые поля — ошибка (`SourceRegistryError`), а не «пропуск».

## 5. Связь assumption → source_id

`tools/source_registry.py --assumptions` проверяет oil/agri:

* oil: **17/17** допущений явно помечены `source_class="assumption"` → считаются честными
  ASSUMPTION; 10 текстов напрямую упоминают source_id (EIA/IEA/ICE/OPEC) — это подсказки для
  будущей замены, **не** перевод в наблюдения;
* agri: **5/5** source_id из `tools/agri_data.py` (`USDA_PSD`, `USDA_FAS_EXPORT_SALES`,
  `FAO_FAOSTAT`, `WORLD_BANK`, `UN_COMTRADE`) присутствуют в реестре;
* `agri_missing = []`, `oil_unresolved = []`, `ok=true`.

`resolve_assumption_source()` возвращает `kind=ASSUMPTION` (явное допущение), `SOURCE` (в тексте
есть source_id) или `UNKNOWN` + `suggestions` (только подсказки, без автоматического выбора).
Никакой автоматической верификации: замена допущения — отдельное решение человека с записью в
`protocols/licence_register.json` (если меняются условия) и обновлением модуля.

## 6. CLI

```
python tools/source_registry.py                          # validate + сводка
python tools/source_registry.py --validate --json
python tools/source_registry.py --list --status VERIFIED
python tools/source_registry.py --list --access paid --json
python tools/source_registry.py --missing                # 12 не-VERIFIED (нельзя цитировать)
python tools/source_registry.py --json                   # API-экспорт (детерминированный)
python tools/source_registry.py --template NEW_SOURCE    # шаблон записи (CATALOGUED, null)
python tools/source_registry.py --assumptions            # oil/agri → source_id, ok/exit 1
```

Коды возврата: `0` — валидно/ok; `1` — ошибка валидации, битый реестр, невалидный `source_id` или
неразрешённое допущение. `--json` даёт машиночитаемый отчёт для CI/API.

## 7. Как добавить источник / заменить допущение

1. Взять шаблон: `python tools/source_registry.py --template NEW_ID > /tmp/new.json`.
2. Заполнить `name/publisher/url/license/access/coverage/fields/vintage_support`; `retrieved_at`
   оставить `null`, `status=CATALOGUED` (не завышать).
3. Вставить запись в `protocols/source_registry.json` (сортировка по `source_id` поддерживается
   загрузчиком), прогнать `--validate`.
4. Для `VERIFIED`: загрузить данные в проект, зафиксировать SHA-256/датасет/доки в `notes`,
   указать `retrieved_at`; платные источники остаются `NOT_DOWNLOADED` до отдельного решения.
5. Замена допущения в модуле: указать `source_id` в assumptions/replace_with, обновить тесты
   модуля; при изменении лицензии — новая запись в `protocols/licence_register.json`.

## 8. Связь с другими контурами

* `protocols/licence_register.json` — журнал условий использования; реестр источников **не
  заменяет** его: лицензия здесь — атрибут записи, а изменение условий — отдельная запись журнала.
* `docs/157` (реестр модулей) — там версии модулей; `source_id` связывает паспорт модуля с данными.
* C6/протокол v5 — реестр не участвует в допуске; он лишь фиксирует, какие данные можно цитировать.
* `data_log.json`/`data_plan.json` — журнал фактических загрузок; реестр о статусе источника.

## 9. Ограничения

1. **Статусы — ручные утверждения**: валидатор проверяет формальные инварианты (наличие
   `retrieved_at`/`notes` для VERIFIED), но не может проверить, что данные действительно получены;
   CI-проверки против `data_log.json` пока нет.
2. **Сеть не используется**: URL/лицензии не перепроверяются он-лайн; условия источников могут
   меняться, запись требует ревизии при каждом использовании.
3. Только **3 из 15** источников VERIFIED; 12 не загружены (8 CATALOGUED, 4 paid). Числа из
   CATALOGUED/NOT_DOWNLOADED использовать нельзя.
4. Oil-тексты упоминают источники свободным текстом; это подсказки, а не машинные ссылки. Полная
   замена допущений на `source_id` — следующий шаг (после загрузки и PIT-слоя).
5. Классификация лицензий — эвристика по ключевым словам; она не является юридическим заключением.
6. Реестр не проверяет лицензионную совместимость между источниками (например, FAO NC-SA против
   коммерческого использования) и не хранит сами данные/их хеши.
7. Дублирование: `tools/agri_data.py` содержит собственный инвентарь источников; тест сверяет id,
   но расхождение полей возможно — источник истины постепенно переносится в реестр.
8. Никакого автоматического promotion в VERIFIED нет: только человек после загрузки и проверки.

## 10. Воспроизведение

```

```

Тесты покрывают: загрузку реального реестра (15 источников, 8/4/3), обязательные поля, https/дубли,
статусы и инварианты VERIFIED (честность «CATALOGUED ≠ VERIFIED»), отказ при битом/отсутствующем
