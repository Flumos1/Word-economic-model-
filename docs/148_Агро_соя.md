# 148. Агро-архетип и пилот «соя в Африке»: research-прототип

Дата: 2026-11-16. Волна 21, трек C (docs/144, docs/145). Статус: **research-прототип; не прогноз
и не кандидат на admission**. Пакет: `src/amfe/markets_agri/**`; данные/лицензии:
[tools/agri_data.py](../tools/agri_data.py); тесты: [tests/test_markets_agri.py](../tests/test_markets_agri.py)
(19 тестов, все зелёные). Трек B (`src/amfe/markets`), `world`, frozen-файлы, registry и

## 1. Что это

Автономный **агро-архетип** (docs/144 §2) и его первая конфигурация — **соя в Африке**. Модель
детерминированная, без сети и без внешних зависимостей: чистая Python-арифметика, поэтому её
можно тестировать и переиспользовать до появления реальных данных. Каркас рынков трека B —
**опциональная** зависимость: пакет пробует импортировать `amfe.markets.contracts.MarketModule`
через `try/except` и при отсутствии использует локальный fallback-контракт
(`AgriMarketModule`, `PriceRange`, `AgriModuleResult`). Сейчас `amfe.markets` отсутствует —
`market_framework_available() == False`, и это ожидаемо: пакет полностью работоспособен сам.

Ключевой принцип: **никакого точечного прогноза цены**. Результат — диапазон (low/high) и
эффекты, посчитанные на двух предобъявленных углах допущений (low-impact / high-impact). Каждый
ответ помечен `source_class="assumption"`, `not_a_forecast=True`, `point_estimate=False`.

## 2. Архитектура и API

```
src/amfe/markets_agri/
  __init__.py      публичный API (реэкспорт)
  contracts.py     AgriMarketModule, PriceRange, ScenarioShock, AgriModuleResult, ошибки,
                   опциональная совместимость с amfe.markets (try/except)
  balance.py       SoyRegion, GlobalBalance, тождество спроса/предложения, crush, заменители
  seasonality.py   месячный сезонный профиль (среднее = 1), окна урожая
  solver.py        детерминированный bisection-солвер рыночного клиринга
  pricing.py       ScenarioParameters (границы допущений), цены сои/шрота, фрахт, импортная стоимость
  africa.py        AfricaConfig, проекция импортного счёта и продовольственной инфляции
  soy.py           SoyConfig/SoyScenario, pilot runner, SoyAgriModule, паспорт модуля
```

Публичный API:

```python
from amfe.markets_agri import SoyAgriModule, SoyConfig, SoyScenario, default_regions
module = SoyAgriModule()                 # иллюстративная конфигурация + сценарий по умолчанию
module.passport()                        # паспорт модуля (id, версия, source_class, тесты, docs)
module.validate()                        # проверки конфигурации/баланса
result = module.run()                    # AgriModuleResult
result.price_ranges["soybeans"].low/high # диапазон, USD/t (без точки)
result.effects["africa"]                 # импортный счёт и продовольственная инфляция (диапазоны)
result.to_dict(), result.to_json(), result.digest()
run_pilot()                              # короткая функция: результат как dict
```

Контракт `AgriMarketModule`: `module_id`, `version`, `passport()`, `validate()`, `run()`.
`AgriModuleResult` — frozen dataclass с `price_ranges`, `effects`, `balance`, `seasonality`,
`notes`, `limitations`, детерминированным `to_json()/digest()` (SHA-256 канонического JSON).

## 3. Модель

### 3.1 Баланс и урожай

`production = area × yield` по регионам; глобальное тождество:

```
production + beginning_stocks = crush + other_use + ending_stocks
```

Отрицательные конечные запасы, экспорт больше производства, неположительное использование —
`AgriMarketError` (fail-closed). Погодный шок — мультипликативный шок урожая региона
(`(-1, 0]`), площадь не меняется; в пилоте: Бразилия −15 %.

### 3.2 Сезонность

12 месячных относительных факторов (среднее ровно 1.0): давление урожая Южной Америки (февраль–
май) и США (сентябрь–ноябрь), межсезонье умеренно выше. Применяется как относительный профиль
поверх сценарного диапазона, сам по себе прогнозом не является.

### 3.3 Stocks-to-use и цена

Клиринг: `U(m) = U0·m^(−e_eff)`, `U(m)·(1+u_target) = available_supply`, где `m` — множитель
цены. Солвер — детерминированный bisection (фиксированные допуск/кап итераций, проверка
скобки); при отсутствии корня или выходе за границы `[0.2, 5]` — fail-closed. Сценарий
считается **относительно** базового клиринга того же угла, поэтому базовый множитель = 1.
Заменители повышают эффективную эластичность (`e_eff = e·(1+substitution)`): чем больше
заменителей, тем меньше рост цены.

### 3.4 Crush

`1 т сои → oil_yield 0.185 + meal_yield 0.790 + loss 0.025` (сумма ≤ 1, проверка). Шрот
масштабируется тем же множителем цены с предобъявленной чувствительностью `[1.00, 1.10]`.
Gross crush margin = `oil·0.185 + meal·0.79 − bean` — может сжиматься и уходить в минус; это
показывается, а не сглаживается.

### 3.5 Африка

Один иллюстративный агрегат: импорт сои 4.0 Mt, шрота 6.0 Mt; фрахт baseline $55/т + сценарная
надбавка 10–25 %; импортная маржа 1.05. Импортный счёт = `volume × (price + freight) × margin`.
Эффект продовольственной инфляции = изменение импортного счёта (%) × доля сои в продовольственной
корзине `[0.5 %, 1.2 %]` × pass-through `[0.5, 0.9]` — диапазон в п.п.

## 4. Сценарий и числа (иллюстративные допущения)

Сценарий: **Бразилия −15 % урожая + экспортное ограничение −35 % бразильского экспорта**
(часть ограниченного объёма теряется для мирового рынка из-за торгового трения 20–50 %).

Базовый баланс (assumption): производство **396,2 Mt**, начальные запасы 55 Mt, использование
385 Mt (crush 285 + прочее 100), конечные запасы 66,2 Mt, **stocks-to-use 0,172**.
Сценарий: производство 373,25 Mt (−22,95 Mt), конечные запасы 43,25 Mt (STU 0,112), эффективная
потеря предложения **29,95–40,45 Mt**.

## 5. Данные и лицензии (`tools/agri_data.py`)

Инструмент **офлайн**: не скачивает и не хранит сырые данные, только описывает источники, схему
и правила; `--check` валидирует ручной экспорт (fail-closed). Источники:

| ID | Источник | Что даёт | Лицензия (важно!) |
|---|---|---|---|
| `USDA_PSD` | USDA FAS Production, Supply and Distribution | площади/урожай/запасы/crush/торговля по странам и годам | public domain (US Gov work), атрибуция желательна |
| `USDA_FAS_EXPORT_SALES` | USDA FAS Export Sales / GAIN | недельные продажи/отгрузки, политика | public domain |
| `FAO_FAOSTAT` | FAO | производство/площади/урожай/торговля/балансы | **CC BY-NC-SA 3.0 IGO — только non-commercial, share-alike** |
| `WORLD_BANK` | World Bank Commodity Markets / WDI | месячные цены сои/шрота/масла, макро для Африки | CC BY 4.0 |
| `UN_COMTRADE` | UN Comtrade | двусторонняя торговля HS 1201/2304/1507 | UN Comtrade terms: free tier non-commercial, rate-limited; bulk/коммерческое — подписка |

Схема записи: обязательные `source_id, commodity, region, period, period_type, license, vintage,
source_class`; опционально производство/площадь/урожай/запасы/crush/экспорт/импорт/цены/фрахт.
Правила: сырые данные — вне репозитория; лицензия в каждой записи и несовместимые лицензии не
смешиваются; `vintage` — дата публикации/скачивания; нефинитные/пропущенные значения —
fail-closed. **Важно для продукта:** FAO (NC) и COMTRADE (free tier) ограничивают коммерческое
использование — в коммерческой упаковке нужны отдельные договоры/замены источников.

## 7. Честные ограничения

1. **Это не прогноз.** Уровни (производство, запасы, импорт, цены), эластичности, доли и
   pass-through — округлённые **допущения** (`source_class="assumption"`), не оценки и не
   официальные данные; диапазон — коридор сценария, а не доверительный интервал.
2. **Нет калибровки на реальных данных и PIT-винтажах.** Не проведены бэктест/OOS, нет
   сравнения с историческими эпизодами; поэтому никаких claims о точности.
3. **Reduced-form.** Нет арбитража запасов, фьючерсов, реакции политики, замещения между
   культурами (кроме поправки эластичности), динамики; экспортное ограничение моделируется как
   торговое трение, а не как перераспределение.
4. **Африка — один агрегат**: нет стран/домохозяйств, нет разницы между Северной/Западной/
   Восточной/Южной Африкой; доли продовольственной корзины и pass-through не оценены.
5. **Crush margin может быть отрицательной** при высоких ценах сои — модель это показывает, но
   не претендует на прогноз маржи переработчика.
6. **Лицензии данных**: FAO NC и COMTRADE free tier ограничивают коммерческое использование;
   USDA/World Bank — открытые с атрибуцией. Смешивание лицензий запрещено валидатором.
7. **Не admission**: пакет не подключён к протоколу, registry, world core; источник — только
   исследовательский слой. Следующий шаг — реальные данные по схеме `agri_data.py`, калибровка,
   валидация и только потом (возможно) регистрация кандидата.

## 8. План валидации (следующий шаг, не выполнен)

1. **2012 засуха США**: шок урожая кукурузы/сои США, сравнить знак и порядок изменения цен и
   волатильности с историей; настроить эластичности/запасы.
2. **2021–22**: бразильская засуха 2021/22 + рост фрахта и цен; проверить, воспроизводит ли
   модель направление и грубый масштаб, а не точку.
3. **Экспортные ограничения**: Аргентина (пиковая пошлина/квоты), Индонезия (пальмовое масло,
   2022) как заменитель; сравнить реакцию шрота/масла.
4. **Ошибки и диапазоны**: backtest на 2010–2024, MAE/CRPS диапазонов, покрытие; сравнение с
   наивными бенчмарками (RW, AR(1)).
5. **Африка**: импортные счета и продовольственная инфляция по странам (COMTRADE/FAO/WB) —
   проверить порядок pass-through; только после этого — claims.
