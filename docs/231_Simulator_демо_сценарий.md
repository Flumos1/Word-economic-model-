# 231. Сценарный 30-минутный демо-показ Simulator

Дата: 2026-11-25. Роль: M1 (docs/207, «26.11 — Simulator демо-сценарий»). Код —
[tools/simulator_demo.py](../tools/simulator_demo.py), тесты —
[tests/test_simulator_demo.py](../tests/test_simulator_demo.py). Основа —
[docs/192](192_Simulator_UI.md) (сам Simulator UI), гейт-статус —
[docs/230](230_M1_ClientPack_Simulator_readiness.md).

## 0. Одной строкой

Скриптованный 30-минутный демо-показ из **6 шагов** — по одному на каждый объявленный сценарий
Simulator (`hormuz_base`, `hormuz_stress`, `gas_shock`, `geopolitics`, `institutions`,
`technology`). Скрипт проверяется fail-closed и прогоняется **в процессе**, без сервера и без сети.

**Это не прогноз и не допуск:** каждый шаг обязан вернуть `status=RESEARCH_ONLY`,
`admission=false`, `causal_claim=false` и `digest`; драйвер отказывает при любом другом результате.

## 1. Зачем

По [docs/230](230_M1_ClientPack_Simulator_readiness.md) пункт «Simulator» имел статус
`PASS` для конфигурации, но `NOT YET` для 30-минутного демо. Этот документ и скрипт закрывают
именно этот пробел: тайминг, точные запросы, ожидаемые ключи ответа и автоматическая проверка.

## 2. Структура демо

| Шаг | Минуты | Сценарий | Что показываем |
|---:|---|---|---|
| 1 | 0–3 | `hormuz_base` | пик Brent, бензин, вклад в CPI, расходы домохозяйства; параметры двигаются (Brent 75→95) |
| 2 | 3–7 | `hormuz_stress` | дизель/авиакеросин, качество сырья, фрахт — рост себестоимости |
| 3 | 7–12 | `gas_shock` | TTF/JKM, ПХГ, диверсия; честно: странового CPI у газа нет |
| 4 | 12–18 | `geopolitics` | Δвыпуска страна×отрасль на MRIO, выгоды/ущерб |
| 5 | 18–24 | `institutions` | композит 0–100, премия за риск, Δ инвестиций и роста |
| 6 | 24–30 | `technology` | диффузия → TFP → выпуск и энергия, энергоёмкость |

Каждый шаг несёт `title_ru/en`, `narrative_ru/en`, точный `payload` для `POST /api/run` и список
`expect` — ключей, которые обязаны быть в ответе (всегда включая `digest`).

## 3. Команды

```powershell
python tools/simulator_demo.py --check          # валидация скрипта против таблицы сценариев
python tools/simulator_demo.py --run            # прогон всех 6 шагов в процессе (без сервера)
python tools/simulator_demo.py --runbook        # RU/EN runbook в build/simulator_demo
python tools/simulator_demo.py --runbook-json    # машиночитаемый скрипт
python -m unittest tests.test_simulator_demo
```

`--check` печатает `{"status": "OK", "steps": 6, "scenarios_covered": [...], "simulator_version": "1.2.0"}`.

## 4. Что проверяется fail-closed

- ровно 6 шагов, номера 1..6 без пропусков;
- каждый объявленный сценарий покрыт **ровно один раз** (нет дублей, нет пропусков);
- `payload.scenario` совпадает со `scenario` шага;
- у каждого шага в `expect` есть `digest`;
- двуязычные заголовки и нарративы не пустые;
- минутные интервалы идут по порядку, не пересекаются и укладываются в 0–30;
- `admission` и `causal_claim` документа — строго `false`.

При прогоне драйвер дополнительно отказывает, если модель вернула не `RESEARCH_ONLY`,
выставила `admission=true`/`causal_claim=true` или не отдала ожидаемый ключ.

## 5. Ограничения (честно)

1. Это **демо-скрипт**, а не новый продукт: он ничего не считает сам, только вызывает существующие
   сценарии Simulator.
2. Прогон идёт через `SimulatorApp.run` в процессе — живой HTTP-сервер, TLS, прокси и квоты
   проверяются отдельно ([docs/192](192_Simulator_UI.md) §4/§7; шлюз — [docs/183](183_Governance_и_регламент_релизов.md)).
3. Геополитический шаг в прогоне использует объявленную синтетическую фикстуру (режим `synthetic`),
   чтобы не зависеть от наличия `build/geopolitics/report.json`; с артефактом числа будут другими,
   но контракт и проверки те же.
4. 30 минут — ориентир для разговора с клиентом, а не SLA; длительность зависит от вопросов.
5. Демо не заменяет пилот: данные клиента, NDA и scope — отдельный шаг.
