# 223. Архивариус и межпроектная база знаний

Дата: 2026-11-22. Роль: `archivist`. Статус: **RESEARCH_ONLY, admission=false**; локально,
**не закоммичено** (интеграция — Lead). Основание:
[docs/212](212_Агентная_сеть_market_intelligence.md) (сеть и роли),
[docs/213](213_База_знаний.md) (опыт отдельной KB с evidence и свежестью),
[agents/README.md](../agents/README.md) (память ролей), [docs/216](216_OSINT_план.md) и
[docs/221](221_Факт_паки_Chevron_Total_BP_Cheniere.md) (факт-паки как жанр).

Комплект: [`knowledge_archive/`](../knowledge_archive/README.md),
[`agents/archive/`](../agents/archive/README.md) (роль `archivist`),
инструмент [`tools/archivist.py`](../tools/archivist.py),
тесты [`tests/test_archivist.py`](../tests/test_archivist.py).

## 0. Резюме

- Создана **межпроектная база знаний**, отдельная от `knowledge_base/`: 14 записей — методы,
  источники, правовые рамки, факт-паки, шаблоны; 6 namespace; у каждой записи провенанс,
  лицензия, доступ, evidence, версия и `review_due`.
- Инструмент `tools/archivist.py`: `add / search / validate / index / pack / export / merge`,
  `--check`. Детерминирован (нет сети, часы не читаются), fail-closed (дефект → exit 2,
  файлы не пишутся), пишет только внутри `knowledge_archive/`.
- **Context pack** — главный продукт роли: по проекту, теме и агенту собирается готовый
  пакет с записями, лицензиями, исключениями и пробелами. OSINT, legal, case и Lead получают
  контекст одной командой, а не пересказом по памяти.
- `knowledge_base/` и `tools/kb.py` **не тронуты**: это отдельный контур и чужой write scope.

## 1. Зачем ещё одна база

| Контур | Вопрос, на который отвечает | Чем не является |
|---|---|---|
| `knowledge/` | научные реестры AMFE: литература, идеи, методы, онтология | не про проектные знания и лицензии |
| `knowledge_base/` | рыночные факты сети market intelligence (сегменты, аккаунты, кейсы) | не общий для OSINT/legal/case/Lead |
| `agents/memory/*.jsonl` | что делала роль, какие решения приняла | не хранит знания с лицензией и сроком |
| **`knowledge_archive/`** | «откуда мы это знаем, под какой лицензией, кому можно и до какой даты это верно» | не модель, не прогноз, не юридическое заключение |

Причина появления: знания, которые нужны нескольким проектам (как законно собирать OSINT, как
оформлять доказательство, как передавать контекст), негде было хранить — в KB им не место, в
памяти ролей они терялись. Архив закрывает именно этот слой.

## 2. Структура

```
knowledge_archive/
  README.md              # правила и команды
  schema.json            # схема записи, namespace-реестр, x-rules (20 правил)
  entries/seed.jsonl     # 14 записей, append-only JSON Lines
  inbox/                 # очередь: <id>.jsonl -> validate -> merge
  inbox/merged/          # обработанные файлы очереди (не удаляются)
  context_packs/         # собранные пакеты: <проект>--<тема>--<роль>.json/.md
  index.json / index.md  # собираются tools/archivist.py index
```

Запись (`amfe.archive.entry.v1`) — обязательные поля: `id` (`AR-NNNN`), `schema`, `namespace`,
`kind`, `title`, `summary`, `tags`, `audience`, `evidence_status`, `evidence_grade`, `licence`,
`access`, `provenance`, `source_ids`, `as_of`, `ttl_days`, `review_due`, `owner_role`,
`retention`, `version`, `created`, `updated`, `notes`, `links`; опционально `jurisdiction`
(обязателен для `kind=legal`), `supersedes`, `archived`.

## 3. Схема и правила

| Поле | Значения | Смысл |
|---|---|---|
| `kind` | `method` / `source` / `legal` / `fact_pack` / `template` | как делать / карточка источника / правовая рамка-указатель / сводка фактов / шаблон |
| `namespace` | `global`, `amfe`, `osint`, `legal`, `cases`, `lead` | проектное пространство имён; `global` читают все |
| `evidence_status` | `VERIFIED` / `PARTIAL` / `HYPOTHESIS` / `NOT_FETCHED` | что именно утверждаем |
| `evidence_grade` | `A` / `B` / `C` / `null` | сила источника |
| `licence` | `OPEN` / `ATTRIBUTION` / `PUBLIC_DOMAIN` / `SUBSCRIPTION` / `LICENCE_REQUIRED` / `INTERNAL` / `NONE` | что можно делать с записью |
| `access` | `PUBLIC` / `PROJECT` / `RESTRICTED` | кому архив отдаёт запись в пакет |
| `retention` | `TTL` / `PROJECT` / `PERMANENT` / `LEGAL_HOLD` | сколько живёт и можно ли архивировать |
| `provenance` | origin, origin_type, collected_by, collected_at, method, retrieved_at, sha256 | откуда и как получено |
| `as_of` + `ttl_days` | дата + срок | `review_due = as_of + ttl_days` |
| `version`, `supersedes` | ≥ 1, `AR-NNNN` | история версий без удаления |

Правила, которые проверяет код (полный список — `schema.json` → `x-rules`, 20 пунктов):

1. `id` уникален и возрастает внутри файла; `review_due` пересчитывается и обязан совпадать.
2. `namespace` — только из `x-namespaces`; новый namespace добавляется в схему с владельцем.
3. Провенанс обязателен; `INTERNAL_DOC` origin — существующий путь репозитория, `OFFICIAL_LAW` и
   `OPEN_WEB` — https URL без учётных данных.
4. `VERIFIED` требует grade A, `retrieved_at` и первоисточник; `HYPOTHESIS`/`NOT_FETCHED` — grade
   C или null.
5. `NOT_FETCHED` требует `licence NONE`, `retrieved_at=null` и `notes` с причиной и блокером.
6. В `HYPOTHESIS`/`NOT_FETCHED` запрещены цифры с валютой, процентами и масштабом.
7. Запрещены `admitted`/«допущенная модель», секреты, токены, телефоны, e-mail, платёжные
   реквизиты.
8. `RESTRICTED` несовместим с открытой лицензией; `PUBLIC` — с `SUBSCRIPTION`/`LICENCE_REQUIRED`.
9. `source_ids` ссылаются только на живые записи `kind=source`; `fact_pack` и `legal` обязаны
   цитировать источник (кроме `NOT_FETCHED`).
10. `kind=legal` требует `jurisdiction`; норма не выдумывается — только указатель и порядок
    проверки.
11. Повтор `(namespace, kind, title)` запрещён: изменение — новая запись с `supersedes` и
    `version+1`, цепочка не ветвится.
12. `LEGAL_HOLD` запрещает `archived`; `archived` не попадает в пакеты, но остаётся в истории.

## 4. Провенанс: что именно фиксируется

Провенанс — не «ссылка для вида», а шесть полей, по которым запись можно проверить, не спрашивая
автора:

| Поле | Пример | Зачем |
|---|---|---|
| `origin` | `docs/219_Conoco_факты.md`, `https://eur-lex.europa.eu/…` | где лежит первоисточник знания |
| `origin_type` | `INTERNAL_DOC`, `OFFICIAL_LAW` | насколько силён класс источника |
| `collected_by` | `archivist` | кто отвечает за сбор |
| `collected_at` | `2026-11-22` | когда собрано (не позже `as_of`) |
| `method` | `MANUAL_READ`, `OFFICIAL_PORTAL` | как получено |
| `retrieved_at` | `2026-11-22` или `null` | получено ли фактически |
| `sha256` | 64 hex или `null` | целостность артефакта, если важна |

Правило: `retrieved_at=null` → статус `NOT_FETCHED`, лицензия `NONE`, в `notes` — причина и
блокер. Это защищает от главной болезни баз знаний: «кажется, я это где-то читал».

## 5. Пространства имён и доступ

| Namespace | Владелец | Что внутри | Видимость |
|---|---|---|---|
| `global` | `archivist` | методы, шаблоны, стандарты провенанса | все проекты |
| `amfe` | `archivist` | границы модели, данных, приёмки | свой проект + `global` |
| `osint` | `archivist` | законный сбор, классы источников, факт-паки | свой проект + `global` |
| `legal` | `archivist` | правовые рамки-указатели, доказательственные карточки | свой проект + `global` |
| `cases` | `archivist` | факт-паки заказчиков, шаблоны кейсов | свой проект + `global` |
| `lead` | `archivist` | handoff, ограничения, открытые вопросы | свой проект + `global` |

`access` работает поверх namespace: `PUBLIC` берут любые проекты, `PROJECT` — только свой
namespace и `global`, `RESTRICTED` — свой namespace и явный `--allow-restricted`. Лицензия
записи не может быть «шире» источника: `NONE` — только «не получено», `SUBSCRIPTION` не
становится `PUBLIC`.

## 6. Свежесть, версии, хранение

- Классы: `fresh`, `due_soon` (≤ 30 дней), `stale` (просрочено), `UNKNOWN` (дата не передана —
  часы не читаются). `index --today <дата>` называет просроченные, но не удаляет их.
- Просроченная запись пересматривается: новая версия (`supersedes`, `version+1`, новый `as_of`)
  или `archived`. История остаётся в файле навсегда.
- `retention`: `TTL` (факт-паки), `PROJECT`, `PERMANENT` (методы, шаблоны, карточки источников),
  `LEGAL_HOLD` (правовые записи: архивировать нельзя, пока дело не закрыто).
- Дедупликация: ключ `(namespace, kind, title)`; `merge` дубли пропускает и показывает в отчёте,
  `--check` считает их дефектом.

## 7. Как пополнять

```
роль/проект ─► inbox/<id>.jsonl ─► validate ─► merge ─► entries/seed.jsonl ─► index
```

1. **Заявка.** Автор формулирует одно утверждение, называет origin, дату, аудиторию и проект.
   Если проект не назван — `global` только для методов/шаблонов.
2. **`add`.** Запись собирается кодом: `review_due`, `access`, `retention` по умолчанию,
   `version`; при дефекте — exit 2 и **ничего не пишется**.

   ```powershell
   python tools/archivist.py add --kind method --namespace global `
       --title "Как фиксировать провенанс" `
       --summary "Шесть полей провенанса и запрет записи без источника." `
       --owner-role archivist --audience all --as-of 2026-11-22 `
       --origin docs/223_Архивариус_и_межпроектная_база.md --origin-type INTERNAL_DOC `
       --collected-by archivist --method MANUAL_READ --retrieved-at 2026-11-22 `
       --tag provenance --tag method --link agents/archive/skills.md
   ```

3. **`--check`.** Любой дефект — exit 2 со списком (код, поле, значение). Запись остаётся в
   `inbox/` и не попадает в `entries/`.
4. **`merge`.** Валидирует очередь, дописывает новые id, дубли пропускает, обработанные файлы
   переносит в `inbox/merged/`.
5. **`index --today <дата>`.** Пересобирает `index.json`/`index.md`: счётчики по видам, статусам,
   лицензиям, доступам, хранению, свежесть, дефекты.
6. **Отчёт Lead.** Принято/отклонено, что просрочено, какие пакеты собраны, какие пробелы.

## 8. Как другие проекты используют архив

Пакет собирается по проекту, теме и агенту; в него попадают только разрешённые записи, а всё
исключённое перечислено с причиной.

```powershell
# OSINT: границы сбора и источники
python tools/archivist.py pack --project osint --topic "законный сбор источники" `
    --role osint-scout --today 2026-11-22

# Legal: доказательства и давность
python tools/archivist.py pack --project legal --topic "доказательства давность" `
    --role legal-claim --today 2026-11-22

# Case: факт-паки и границы переноса в кейс
python tools/archivist.py pack --project cases --topic "факт-пак" `
    --role case-writer --today 2026-11-22

# Lead: handoff и ограничения среды
python tools/archivist.py pack --project lead --topic "передача контекста ограничения" `
    --role lead --today 2026-11-22
```

Результат — `context_packs/<проект>--<тема>--<роль>.json` и `.md`. Внутри: записи (с провенансом,
лицензией, evidence, свежестью), `excluded` с причинами (`namespace:legal`, `audience:lead`,
`stale`, `limit`), `gaps` (чего нет), `licence_notices` (что можно делать).

Правила использования в другом проекте:

1. Пакет — единственная форма передачи контекста; пересказ по памяти запрещён.
2. Лицензия каждой записи сохраняется в пакете; `INTERNAL` не выходит за пределы AMFE.
3. `NOT_FETCHED` означает «не получено», а не «не существует»; пробелы пакета нельзя закрывать
   догадкой.
4. Новое знание, найденное при работе, возвращается в архив записью `add`, а не правкой пакета.
5. Пакет не является юридическим заключением или инвестиционной рекомендацией.

## 9. Роли

| Роль | Что делает с архивом |
|---|---|
| `archivist` | владелец: приём, провенанс, версии, дубли, лицензии, свежесть, пакеты, хранение |
| `lead` | заказывает пакеты, получает отчёты о пробелах и просрочке, решает конфликты namespace |
| `osint-scout` | берёт границы законного сбора и классы источников, возвращает журнал коллекции |
| `legal-claim` | берёт рамки-указатели и шаблон доказательственной карточки; нормы проверяет юрист |
| `case-writer` | берёт факт-паки и правила переноса фактов в кейс |
| `evidence-qa` | проверяет, что grade и статус в записях не завышены |
| `licence-auditor` | проверяет лицензии и условия источников |
| `kb-librarian` | связанный контур: рыночные знания идут в `knowledge_base/`, не в архив |

Архивариус **не** поднимает evidence, **не** даёт юридических заключений, **не** трогает
`knowledge_base/`, `tools/kb.py` и память других ролей.

## 10. Инструмент

| Команда | Поведение |
|---|---|
| `--check` | валидация целиком, exit 0 / 2 |
| `validate --json --today <дата>` | машинная сводка `amfe.archive.validate.v1` со свежестью |
| `search "<токены>" --kind/--namespace/--tag/--evidence/--access/--stale` | поиск, порядок по id |
| `add …` | сборка, проверка и запись одной строки в `inbox/`; дефект → exit 2, файлы не пишутся |
| `merge` | очередь → `entries/`, дубли пропускаются, файлы уходят в `inbox/merged/` |
| `index --today <дата>` | `index.json` + `index.md` |
| `pack --project … --topic … --role … --today <дата>` | контекст-пакет `.json` + `.md` |
| `export --format json\|md\|jsonl` | детерминированный экспорт (stdout или `--out`) |

Детерминизм: нет сети, нет часов (даты передаются явно), нет случайных id, все коллекции
сортируются, JSON пишется с `sort_keys`. Fail-closed: `add`/`merge`/`pack` при дефекте не пишут
ничего; `index` — отчёт, он собирается и при дефектах, но возвращает exit 2.

## 11. Ограничения

- **Сети нет:** `origin` — адрес, а не подтверждённый доступ; проверку URL и условий делает
  человек.
- **Нет `VERIFIED`:** в среде нет первоисточников и лицензированных подписок; все записи
  `HYPOTHESIS`/`NOT_FETCHED`/`PARTIAL` — это ограничение метода, а не вывод о мире.
- **Правовые записи — указатели:** статьи, сроки и редакции не приводятся до проверки юристом.
- **Лицензии не проверены:** `SUBSCRIPTION`/`LICENCE_REQUIRED` нельзя использовать до договора.
- **Свежесть зависит от даты:** без `--today` всё помечается `UNKNOWN`, а не «свежее».
- **Архив — не модель:** `admission=false`; запись не заменяет научный контур и KB.
- **Границы проектов:** `PROJECT`-записи не видны другим проектам; перенос — только `PUBLIC` или
  новая запись.

## 12. Проверка

```powershell
python tools/archivist.py --check                    # exit 0
python tools/archivist.py index --today 2026-11-22
python tools/archivist.py pack --project osint --topic "законный сбор" --role osint-scout `
    --today 2026-11-22
python tools/archivist.py search "" --stale --today 2030-01-01
python -m unittest tests.test_archivist
```

Тесты (`tests/test_archivist.py`, **41 проверка**) покрывают: схему и enum'ы, состав seed и
namespace, уникальность и порядок id, обязательные поля, `review_due`, провенанс (включая
`INTERNAL_DOC` и URL-правила), честность evidence, отсутствие цифр и «допущенных» формулировок,
лицензии и доступ, отсутствие секретов и PII, разрешимость `source_ids` и ссылок, дубли и цепочки
`supersedes`, свежесть и просрочку, context pack (namespace, аудитория, `RESTRICTED`, `stale`,
пробелы, детерминизм), `merge` (дедупликация, идемпотентность), `add` (успех, секрет, чужой
namespace, дубль), CLI `--check`, `validate --json`, `export` (JSON/MD/JSONL, детерминизм),
`index`, отсутствие сети и часов, «`--check` ничего не пишет».
