# AMFE-17 — дорожная карта реализации и контрольные ворота
Версия 0.1 · 2026-11-11. План, а не отчёт о выполнении.

## Правила прохождения
**Непрерывное исполнение по умолчанию:** переходить между техническими этапами и подэтапами без промежуточного согласования, если действия покрыты ранее утверждёнными правилами и проходят контрольные проверки. Технические ошибки исправлять и повторно тестировать самостоятельно. **Остановка для вопроса пользователю** нужна при существенных сомнениях, альтернативных архитектурных вариантах с разными последствиями, неразрешимом противоречии или необходимости изменить согласованные принципы. Не превращать каждую штатную ошибку теста в повод для согласования. Не трактовать это разрешение как согласие на будущую установку ПО или существенные внешние расходы.
**Уточнение пользователя:** речь шла о прохождении этапов **без остановок на промежуточное согласование**, а не об установке программ на компьютер. До локального развёртывания ещё далеко, и оно не является предметом этого разрешения. Облачный CI должен быть отдельно проверен; создание workflow не доказывает его успешного запуска.
После каждого этапа цикл V1 формальная проверка → V2 экономическая адекватность (при наличии данных) → V3 OOS прогнозная проверка (когда есть прогнозы) → журнал решения/откат. Неприменимые уровни отмечать NOT_APPLICABLE, а не PASS.

## Непрерывный цикл каждого этапа
(1) сформулировать проверяемые инварианты и критерии;
(2) реализовать минимальный компонент;
(3) запустить позитивные, негативные и граничные тесты;
(4) повторно запустить затронутые старые тесты и проверить интерфейсы;
(5) при наличии данных оценить экономическую адекватность;
(6) при наличии прогнозов выполнить честную OOS оценку;
(7) записать PASS/CONDITIONAL/FAIL и ограничения; исправить/откатить при необходимости;
(8) перейти к следующему шагу только при допустимом результате.

## Непосредственный порядок работ
N1. Проверить фактический запуск GitHub Actions для существующих тестов, устранить ошибки, если обнаружены.
N2. Превратить прототип четырёх секторов в типизированные счета с полным отображением изменений чистой стоимости и финансовых позиций.
N3. Ввести внешнюю торговлю двух стран с отдельными валютами и сопоставимыми стоимостями; добавить тесты зеркальности и валютных пересчётов.
N4. Прогнать регрессию v01/v02 и новые тесты; оформить отчёт.
Не заявлять завершение N1–N4 до подтверждения.

## Критерии остановки для совместного решения
- Неоднозначная учётная конвенция с материальным влиянием на результаты.
- Непреодолимая невязка балансов или конфликт типизированных интерфейсов.
- Неидентифицируемая причинная гипотеза, которую нельзя отличить от альтернатив.
- Требование изменить уже согласованную архитектуру либо допустить несогласованность.
- Переход к существенным затратам или внешним необратимым действиям.

## Статус формулировки «самообучение»
Сегодня реализуются элементы инженерной самопроверки. Статистическое самообучение станет предметом этапа 8, после подключения данных и честной прогнозной оценки.
