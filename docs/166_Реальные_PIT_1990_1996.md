## 1. Что сделано

1. **Расширена реконструкция PIT на все 19 рядов ALFRED-плана** (`protocols/data_plan.json` v0.4.0).
   `tools/reconstruct_pit.py --g4` классифицирует каждый ряд по «линзе» для окна 1990-01…1996-11,
   строит расширенный `data/reconstructed` (16 рядов: 6 — только подлинные архивные колонки,
   9 — объявленная tape-реконструкция, 1 — только `latest.csv`) и пишет агрегатный отчёт покрытия
   `data/reconstructed/g4_coverage.json` (git-ignored). Старое поведение инструмента (6 рядов + досье
   `protocols/pit_reconstruction.json`) не изменилось — 30 старых тестов зелёные.
2. **Зафиксированы дата-план и линзы**: правила, пороги (`MIN_FULL_HISTORY_OBS = 120`,
   `G4_MIN_ARCHIVED_VINTAGES = 12`, `G4_TAPE_MAX_DELAY_MONTHS = 12`,
   `G4_ARCHIVED_START_TOLERANCE_DAYS = 90`), классификация ревизий и mapping в классы protocol v5.
   Честно помечено, где данных нет (`UNVERIFIED_LATE_ARCHIVE`) — такие ряды исключены, а не
   «достроены» поздними отпечатками.
3. **Новая предрегистрация калибровки 0.3** (`protocols/pit_preregistration_0_3.json`): SHA-256
   пин, frozen-пороги, классы/линзы, правила расширенного окна, критерии (C1/C2/C4/C5), запрет
   post-hoc, правило поправок. Значения SPF/сырые ряды не входят.
4. **Тесты** `tests/test_reconstruct_pit_g4.py`: 21 тест на синтетических фикстурах (линзы, классы
   ревизий, построение архивов, PIT-инварианты, отсутствие значений в отчёте, детерминизм, CLI,
   покрытие плана) + контракт предрегистрации (структура, хеши, пины, frozen-пороги).

## 2. Данные и окно

- Источник: ALFRED merged vintages `data/raw/<SERIES>/vintages.zip` (автозагрузка
  `tools/fetch_data.py`, плотный план 147 квартальных дат 1990-03-31…2026-09-30; 18 рядов с
  винтажами + `USREC`). Локально для этого аудита архив пересобран: **37 загрузок, 0 ошибок**
  (19 latest + 18 vintage sets), в git не попадает.
- Окно реконструкции: **1990-01-15 … 1996-11-15**, сетка — 15-е число каждого месяца (83 даты).
- Правило включения наблюдения: месячные — `period_end < vintage_date`; квартальные (GDPC1) —
  `quarter_end + 1 месяц < vintage_date` (консервативно, advance-оценка). Наблюдение после даты
  винтажа не включается никогда — проверяется построителем и повторно через
  `amfe.forecast.data.load_vintages`.
- `data/raw` и `data/reconstructed` — git-ignored; в CI данные восстанавливаются из приватного
  артефакта `data-refresh`.

## 3. Метод линз (калибровка данных, а не модели)

Линза определяется только по датам/количествам винтажных колонок источника и измеренным ревизиям
(никаких forecast-ошибок или результатов оценки):

| Линза | Правило | Класс protocol v5 |
|---|---|---|
| `ARCHIVED_PIT` | подлинный полный архив покрывает окно: первый «плотный» столбец (≥`MIN_FULL_HISTORY_OBS` наблюдений) не позже `start + 90 дней`, и внутри окна ≥12 колонок | `REAL_TIME` |
| `TAPE_RECONSTRUCTED` | архив начинается внутри окна/раньше (не позже `end + 12 мес`), но полного покрытия нет: ранняя часть — объявленный first-print tape | по классу ревизий: `REAL_TIME_RECONSTRUCTED_MARKET` / `RECONSTRUCTED_PIT` / `DIAGNOSTIC_ONLY` |
| `UNVERIFIED_LATE_ARCHIVE` | архив начинается позже `end + 12 мес` — 1990–1996 восстановить честно нельзя | `NOT_AVAILABLE` (исключается) |
| `LATEST_ONLY` | винтажного архива нет (`USREC`), копируется только `latest.csv` | `LATEST_TAPE_ONLY` (источник меток) |
| `MISSING_SOURCE` | нет ни архива, ни `latest.csv` | `NOT_AVAILABLE` (исключается) |

Классы ревизий (объявлены заранее, те же, что в досье docs/108): `ZERO`; `ZERO_WITHIN_ROUNDING`
(max ≤0.01, средняя ≤0.001); `SMALL` (средняя ≤0.05, max ≤0.5); `MATERIAL` — иначе. Для
**протокольных** рядов с трансформацией в единицы цели ревизия меряется в единицах цели
(CPI — п.п. г/г; GDP — п.п. q/q annualised), для уровневых протокольных рядов (ставки, UNRATE) — в
уровнях, как в досье. Для **вспомогательных** рядов — относительная ревизия только по наблюдениям
окна: `ZERO` (0), `ZERO_WITHIN_ROUNDING` (max ≤0.5%, средняя ≤0.1%), `SMALL` (средняя ≤1%, max ≤5%),
`MATERIAL` — иначе. Вспомогательные ряды не входят в компаратор/допуск, поэтому их класс — это
информация о качестве архива, а не допуск.
Для 7 рядов, которые protocol v5 классифицирует сам, класс берётся **дословно из v5**, аудит лишь
воспроизводит его и записывает измеренный класс ревизий рядом.

## 5. Предрегистрация 0.3

Файл: `protocols/pit_preregistration_0_3.json` (23 926 B); пин:
`protocols/pit_preregistration_0_3.sha256.txt` = **`026bab7df83c5a0b8e75b4c1d29897961087eea90f0424af96fad70ff0022263`**
(SHA-256 LF-нормализованного файла); внутренний `content_sha256` =
`f86bfe9ef9c63cb14bf96493abcec6fce58d2f9fe92cf4972e2fa916372a6066` (канонический JSON без самого поля).

Что зафиксировано **до** любых вычислений по расширенному окну:

- **База**: protocol v5 (пин SHA-256), v4 (не меняется), досье реконструкции (пин
  `8154e319…` из `protocols/pit_reconstruction.sha256`), план 19 рядов v0.4.0, окно и frozen-пороги.
- **Линзы и статусы всех 19 рядов** (§4 выше) — классификация не зависит от результатов оценки
  (`outcome_free_declaration`).
- **Расширенное окно**: `W1_EXT` 1990-01…2006-12 — только для T1 C4; `W2` 2007–2019 — held-out OOS,
  не используется для выбора/подбора.
- **Обязательные чувствительности**: REAL_TIME-only срез C4 (не гейтит), срез без
  реконструированных начал, leave-one-episode-out (1990–91, 2001, 2007–09), tape-free начала
  (≥1996-12). Pass, зависящий от реконструированных начал → `CONDITIONAL_DATA_CLASS`, только
  SHADOW_TEST, не PASS.
- **Критерии**: C1 (относительная потеря ≤ порога `nf_sim_thresholds`, RMSE; CRPS только после
  гейта смеси), C2 (DM + полный Romano–Wolf, FWER 0.10), C4 (правило v5 на W1_EXT + срезы),
  C5 без изменений; состояния PASS/CONDITIONAL/FAIL; «нет результата — нет утверждения».
- **Запреты post-hoc**: нельзя менять окна/пороги/классификацию/набор рядов после просмотра
  результата; нельзя подбирать параметры/гиперпараметры на W2 или на просмотренных началах; нельзя
  повышать `DIAGNOSTIC_ONLY`/`NOT_AVAILABLE` ряд до входов допуска без новой версии предрегистрации;
  нельзя редактировать файл — только новая версия с новым SHA.
- **Поправки**: новая версия 0.4 (или следующий свободный номер) с причиной, временем, затронутыми
  критериями и пином; старые отчёты не переписываются.
- **Чего здесь нет**: T2 на реконструированном GDP (запрещено v5/v4), T3 на W1_EXT, подбор
  параметров моделей — для будущей калибровки параметров нужна отдельная предрегистрация.

## 6. Воспроизведение

```powershell
# 1) данные (нужна сеть или приватный артефакт data-refresh; data/raw git-ignored)
python tools/fetch_data.py --out data/raw --log "$env:TEMP\data_log.json" --include-vintages

# 2) G4-аудит + расширенный PIT data root + coverage (data/reconstructed git-ignored)
python tools/reconstruct_pit.py --g4
#    сводка: data/reconstructed/g4_coverage.json; tree_digest = 726f5666a67dfe10…

# 3) тесты (офлайн, синтетика + контракт предрегистрации)
python tests/test_reconstruct_pit_g4.py     # 21 тест
python tests/test_reconstruct_pit.py        # 30 старых тестов, регрессия не сломана

# 4) проверка пина предрегистрации
python -c "import hashlib,pathlib; p=pathlib.Path('protocols/pit_preregistration_0_3.json'); print(hashlib.sha256(p.read_bytes().replace(b'\r\n', b'\n')).hexdigest())"
```

Детерминизм: фиксированные метки времени членов zip (1980-01-01), CSV UTF-8 BOM + `\n`,
побайтовые копии `latest.csv`; повторный `--g4` даёт тот же `tree_digest` (отчёт покрытия исключён
из digest, чтобы перезапись отчёта не меняла дайджест). Тест `test_deterministic_rerun` это
проверяет. `generated_at` переопределяется `AMFE_GENERATED_AT`/`--generated-at`.

## 8. Ограничения и что осталось

1. **Это реконструкция, а не полноценная первичная история**: подлинные архивные колонки есть только
   у `ARCHIVED_PIT` (6 вспомогательных рядов); протокольные CPI/UNRATE идут через объявленный
   first-print tape, ставки — точный tape, GDP — только диагностика. Ревизии и carrier-lag
   раскрыты в досье docs/108 и в coverage-отчёте.
2. **Стартовый зазор плана**: merged-архив `fetch_data.py` начинается с первой плановой даты
   (1990-03-31), поэтому у `ARCHIVED_PIT` рядов январь–март 1990 не имеют винтажной колонки; это
   покрыто объявленным допуском 90 дней, а не tape-реконструкцией.
3. **Три ряда исключены** (`A191RL1Q225SBEA`, `PCEPILFE`, `RSAFS`) — их архивы начинаются позже
   допустимого лага; `latest.csv` не является PIT-заменой и в ранний root не строился.
4. **Отчёт покрытия git-ignored**; в репозитории — эта документация и предрегистрация. Для CI нужен
   приватный артефакт `data-refresh` (в чистом checkout `--g4` без данных завершится ошибкой, тесты
   используют синтетику и не зависят от данных).
5. **Оценок по расширенному окну ещё нет**: предрегистрация фиксирует правила; T1 C4 на W1_EXT,
   REAL_TIME-only срезы и leave-one-episode-out должны быть посчитаны отдельным отчётом с пином
   предрегистрации. T2/T3 не расширяются (v5).
6. **Вспомогательные ряды** (`GCE`, `GCEC1`, `GPDIC1`, `INDPRO`, `PAYEMS`, `PCECC96`) не входят в
   компаратор/допуск; даже будучи `REAL_TIME`, они не расширяют admission-окно автоматически —
   решение об использовании требует отдельного протокольного шага.
7. **Другие треки G4** (нефтяная предрегистрация расширенной сетки, docs/158 §10; поведенческая
   модель спроса) в этой задаче не covered — у них свои предрегистрации/отчёты; этот файл их не
   заменяет.
8. **Независимой проверки (V2)** этого аудита пока не было; предрегистрация и инструмент требуют
   ревью Lead/независимого проверяющего до использования в отчёте по C4.
9. **Локальная сверка со старым досье**: `data/reconstructed` расширен G4 (+9 рядов), поэтому
   data-зависимый `tests/test_reconstruct_pit.py::test_dossier_matches_the_local_build` на локальной
   машине видит расхождение digest со старым `protocols/pit_reconstruction.json`. В чистом CI (без
   `data/reconstructed`) этот тест пропускается, как и раньше; досье в этой задаче не
   перегенерировалось (вне write-scopes, чтобы не менять закоммиченный артефакт). Если Lead хочет
   держать локальную сверку зелёной — либо перегенерировать досье отдельным коммитом, либо сверять
   его на отдельном «6-рядном» root (решение Lead, не блокирует G4-аудит).
