# 125. Реальный MRIO-датасет FIGARO → каноническая схема AMFE (P2, D1-валидация)

Версия 1.0.0 · 2026-11-14. Волна 6, задача `task-14` (трек P2-данных). Инструмент —
[tools/figaro_import.py](../tools/figaro_import.py), тесты —
[tests/test_figaro_import.py](../tests/test_figaro_import.py). Схема-приёмник —
[`amfe.mrio.dataset.v1`](../src/amfe/mrio/schema.py) ([docs/121](121_Данные_MRIO.md)).

Это **первый реальный MRIO-датасет** проекта: не синтетическая фикстура, а полная межстрановая
таблица «продукт × продукт» Eurostat FIGARO, приведённая к `USD_mn`, с блоком RoW, посчитанным
покрытием по ВВП и пройденной D1-валидацией (тождества + P2-гейт). Данные лежат **вне git**:
`data/mrio/figaro/` (сырые ответы API — в кэше, канонический JSON — в подкаталоге датасета).

## 1. Источник и лицензия

| Параметр | Значение |
|---|---|
| Источник | Eurostat FIGARO — EU inter-country input-output table, product by product |
| Код датасета | **`NAIO_10_FCP_IP3`** (блок годов 2018-2021) |
| API | `https://ec.europa.eu/eurostat/api/dissemination/statistics/1.0/data/naio_10_fcp_ip3` — **без ключа** |
| Формат | JSON-stat 2.0, фильтры `format=JSON`, `lang=EN`, `time`, `unit=MIO_EUR`, `c_dest` |
| Лицензия | Eurostat re-use policy (открытые данные, обязательна атрибуция) — код `status` в `SOURCE_MATRIX`: `AVAILABLE_API`, `licence_verified=false` (текст условий не проверялся отдельным лицензионным аудитом) |
| Единицы источника | млн евро, basic prices |
| Годы в наборе | 2018, 2019, 2020, 2021 |

**Важное уточнение к исходной постановке.** В задаче и в docs/121 фигурировал код
`NAIO_10_CP1700` как «FIGARO». Проверка через каталог Eurostat (`catalogue/toc/txt`) показала, что
`NAIO_10_CP1700` — это **национальная** симметричная таблица «затраты-выпуск» стран ЕС (30 гео:
ЕС27 + 3 кандидата), без межстрановых блоков: из неё нельзя собрать MRIO `Z` по парам стран.
Настоящие межстрановые FIGARO-таблицы — семейство `NAIO_10_FCP_*`; для матрицы «продукт × продукт»
выбран `NAIO_10_FCP_IP3` (44,2 млн ячеек в исходном наборе, 50 направлений × 51 источник).
Это исправление записано здесь как факт проверки, а не изменение чужих документов.

Покрытие по ВВП (World Bank `NY.GDP.MKTP.CD`, 2019; мировой ВВП = 88.80 трлн USD):

| Метрика | Значение |
|---|---|
| Поимённые страны | 49 (все с ВВП найдены, 0 пропусков) |
| Доля поимённых стран в мировом ВВП | **87.2771%** |
| Остаток на ROW-блок | 12.7229% |

показать, какая часть мира названа поимённо.

## 3. Каноническая схема и отображение FIGARO → AMFE

Документ — строго `amfe.mrio.dataset.v1` (`src/amfe/mrio/schema.py`), файл
`data/mrio/figaro/figaro_2019/dataset.json`:

| Поле | Как получено |
|---|---|
| `countries` | `c_dest` FIGARO: 49 кодов ISO2 + `WRL_REST` → `ROW` (порядок сохраняется) |
| `industries` | 64 CPA-продукта (`prd_use`/`prd_ava`, без агрегатов и строк добавленной стоимости) |
| `Z[i][j]` | поток из (страна-источник `c_orig`, продукт `prd_ava`) в (страна-назначение `c_dest`, продукт `prd_use`), basic prices, EUR млн → USD млн |
| `y[i]` | конечный спрос строки: сумма 5 колонок конечного спроса (`P3_S13`, `P3_S14`, `P3_S15`, `P5M`, `P51G`) по всем странам-назначениям |
| `x[i]` | валовой выпуск = `Σ_j Z[i][j] + y[i]` (строчная сумма) |
| `va[j]` | добавленная стоимость колонки: строки `B2A3G + D1 + D21X31 + D29X39` при `c_orig = DOM` («Domestic country» — служебный блок FIGARO, **не страна**) |
| `source` | имя/провайдер/URL/код/год/лицензия/`third_party=true`, `row_block: WRL_REST -> ROW` |
| `fx` | `EUR_per_USD`, `USD_per_EUR`, источник и год |
| `units` | только `USD_mn` |

Особенности FIGARO, важные для потребителей:

1. **Замкнутый мир.** В таблице нет отдельной экспортной колонки: экспорт — это межстрановые
   блоки `Z` и конечный спрос страны-назначения. Поэтому `Σva = Σy` выполняется на полном наборе
   стран (проверяется валидатором).
2. **`DOM` не страна.** Это служебный код источника для строк добавленной стоимости; в
   `countries` он не попадает, иначе нарушилась бы размерность и P2-гейт.
3. **Импорт не отделён** отдельной матрицей: он «растворён» в межстрановых блоках (в отличие от
   national SIOT, где есть `stk_flow=IMP/DOM/TOTAL`).
4. **Basic prices, без налогов/маржи** отдельными матрицами; в каноническую схему они не входят
   (docs/121 §6).

## 4. Как воспроизвести

```powershell
# полный цикл: скачать 50 срезов по c_dest, распарсить, собрать, проверить, записать
python tools/figaro_import.py --all --year 2019 --jobs 8

# по шагам
python tools/figaro_import.py --download --year 2019 --jobs 8   # кэш data/mrio/figaro/cache/2019/
python tools/figaro_import.py --build    --year 2019 --jobs 8   # из кэша, без сети
python tools/figaro_import.py --coverage-only --year 2019       # покрытие по ВВП
python tools/figaro_import.py --validate-only                   # перечитать и проверить датасет

# тесты (без сети, маленькая JSON-stat фикстура)
python -m unittest tests.test_figaro_import -v
```

Устройство загрузки и парсинга:

- полный ответ API для года слишком велик (сервер отдаёт `413 Request Entity Too Large`), поэтому
  скачивание **разбито по странам-назначениям** `c_dest`: 50 запросов по ~2.8 МБ (всего ~139 МБ;
  кэш `data/mrio/figaro/cache/<year>/<code>.json`);
- скачивание и парсинг распараллелены через `ProcessPoolExecutor` (`--jobs`, по умолчанию 8);
  прогресс печатается по мере готовности;
- JSON-stat разбирается по bounded-чанкам (`parse_dest_worker` на один срез), а для больших
  одиночных файлов есть потоковый итератор `iter_jsonstat_values` (читает только контейнер
  `"value"` по кускам, без загрузки файла целиком);
- сборка — numpy: блочное заполнение `Z`, векторы `y`, `va`, затем `x = Z·1 + y`;
  EUR→USD одним множителем; округление до 6 знаков (точность 1e-6 млн USD);
- валидация — `amfe.mrio.schema.validate_dataset` (fail-closed: при нарушении тождеств или
  P2-гейта файл не пишется, код выхода 2);
- запись — детерминированная (`dataset_to_bytes`, сортировка ключей, SHA-256 в манифесте).

## 5. D1-валидация: что проверено

`validate_dataset` для 50×64:

- `schema`, `dimensions`, `labels_unique`, `non_negative` — PASS;
- `row_balance` (`x = Z·1 + y`) — PASS, максимальный относительный остаток
  0.0 (машинное округление после EUR→USD и 6 знаков);
- `column_balance` (`x = 1'Z + va`) — PASS, максимальный абсолютный остаток
  0.0 млн USD;
- `global_value_added_equals_final_demand` (`Σva = Σy`) — PASS;
- `aggregate_output_identity` — PASS;
- итоги по странам (`x/y/va`, exports/imports/net_exports, `Σnet_exports = 0`) — рассчитаны и
  записаны в манифест (агрегаты, без матрицы);
- `p2_scale` — PASS (50 ≥ 10, 64 ≥ 30).

Допуск относительный: `|остаток| ≤ tol · max(1, |x|)`; в данных `tol = 1e-4` (записано в
`dataset.tolerance`), но после финального согласования остатки равны **0.0**, поэтому документ
проходит и дефолтный допуск схемы `1e-6`. Промежуточные остатки были следствием округления
исходных значений (3 знака в EUR млн) и перевода в USD, а не рассогласования таблицы.

**Две согласующие поправки (записаны в `source`):**

1. `non_negativity_shift_usd_mn = 30462.025` — отрицательные изменения запасов (и, если есть,
   отрицательные остатки VA) по ячейкам (страна, продукт) сдвинуты в `y/va/x` на одну и ту же
   величину; это 0.034% мирового ВВП 2019 и не меняет ни одного тождества.
2. `column_reconciliation_usd_mn = 0.185` — после округления до 6 знаков `va` колонки
   пересчитана как `x − ΣZ` (разница с исходной VA — 0.185 млн USD на весь мир, т.е. округление).

## 6. Манифест (`manifest.json`)

Манифест — **только агрегаты и хеши**, без значений матрицы: `dataset_id`, `generated_at`,
`status=AVAILABLE`, путь/размер/SHA-256/`digest` канонического документа, счётчики стран/отраслей/
лет/ячеек, `validation` (checks + metrics: остатки, итоги, `x/y/va` по странам, exports/imports),
`source`, `fx`, `coverage` (доля ВВП, поимённые страны, missing, per-country GDP),
`figaro` (код датасета, число срезов, строки VA, колонки конечного спроса, `row_block`),
`cache` и тайминги. Манифест можно коммитить: сырых третьих значений в нём нет.

## 7. Тесты (20, без сети)

`tests/test_figaro_import.py`:

- JSON-stat: обратимость `jsonstat_index`/`jsonstat_coordinates`, `parse_jsonstat_document`,
  потоковый `iter_jsonstat_values` (dict-форма и отказ на файле без `value`);
- парсинг среза `c_dest` → плотный массив `(origin, ava, use)` и сверка с фикстурой;
- сборка: документ соответствует схеме, `Z/y/x/va` проходят тождества (P2-гейт отдельно,
  на крошечной фикстуре ожидаемо FAIL); `DOM` не становится страной, `WRL_REST → ROW`;
- FX: масштабирование значений, `fx` в документе, отказ на 0/отрицательном/NaN/∞ курсе;
- fail-closed: нет блока RoW → ошибка; нарушенное тождество → датасет не пишется;
- запись: `dataset.json` + `manifest.json`, SHA-256 файла = манифест, в манифесте нет `Z`;
- детерминизм: `dataset_to_bytes` дважды байт-идентичен;
- покрытие: проценты, ROW-остаток, missing-страны, гейт ≥80%;
- кэш: повторный вызов `fetch_dest_worker` не ходит в сеть; URL содержит фильтры.

## 8. Ограничения и что осталось

1. **Курс EUR→USD** — официальный среднегодовой (World Bank), а не средний за период
   происхождения потоков; для 2019 это стандартная практика, но точность пересчёта ~0.1%.
2. **RoW — это агрегат FIGARO `WRL_REST`**, а не построенная из остатка ВВП модель; FIGARO
   сам оценивает rest-of-world, поэтому «покрытие 100% с RoW» означает замкнутость таблицы, а
   не независимую оценку остатка. Качество RoW-блока — свойство источника.
3. **Один год за прогон.** Датасет — снимок 2019; 2018/2020/2021 доступны тем же инструментом
   (`--year`), но панель/несколько лет в одном файле схемой `amfe.mrio.dataset.v1` не
   предусмотрены (один файл = один срез).
4. **Только product-by-product SIOT**: supply/use таблицы, налоги на продукты, торгово-транспортные
   маржи, импортные матрицы и основные фонды в каноническую схему не входят (docs/121 §6).
5. **FIGARO — не полный мир**: 49 поимённых стран + RoW; США/Китай/Япония и ЕС названы, но,
   например, Африка кроме ЮАР и большинство стран Латинской Америки — только в RoW. Для полного
   мира нужны OECD ICIO (1995-2022), Eora (190 стран) или WIOD — см. docs/121 §1.
6. **Лицензия**: Eurostat re-use — открытые данные с атрибуцией; сырые файлы в git не попадают,
   публикуются только производные метрики/агрегаты и собственные прогнозы (`licence_policy`).
7. **Данные не коммитятся.** `/data/mrio/` исключён в `.gitignore` (строка добавлена Lead
   2026-11-14), поэтому кэш и `dataset.json` в git не попадают; в git может идти только
   `manifest.json` (по решению Lead, как агрегат без значений).
8. **Не влияет на допуск**: это данные этапов 2–5 (P2), замороженные протоколы, registry и
   существующие `tools/**`/`src/**` не изменялись.
