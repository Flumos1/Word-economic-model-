## 1. Зачем понадобилась v1.1

В WIOD 2016 есть отрицательные ячейки: изменения запасов в конечном спросе (50 ячеек в 2000 и
2014, 30–31 в 2007; минимум −15 161,94 USD_mn в 2007) и отрицательная добавленная стоимость
(1 ячейка в 2000: −0,977; 2 в 2014: минимум −22,174). Схема 1.0.0 требовала `y ≥ 0`, `va ≥ 0`
и отвергала такой датасет (`BLOCKED_CONVERSION`, docs/126). Клиппинг или выбрасывание ячеек
сломали бы баланс — поэтому введены **знаковые корректировки**, а базовые `y`/`va` остаются
неотрицательными.

## 2. Изменения схемы (v1.1.0)

`src/amfe/mrio/schema.py`: `SCHEMA = "amfe.mrio.dataset.v1.1"`, `SCHEMA_VERSION = "1.1.0"`.

| Поле | Тип | Смысл |
|---|---|---|
| `final_demand_adjustments` (`fda`) | signed float[n], опционально | балансирующая часть конечного спроса (отрицательный y, изменения запасов) |
| `va_adjustments` (`vaa`) | signed float[n], опционально | балансирующая часть добавленной стоимости (отрицательный va + остаток закрытия столбца) |
| `schema_version` | str | `1.1.0` (запись) или `1.0.0` (чтение legacy) |

Идентичности (проверяются валидатором, scaled tolerance `|r| ≤ tol·max(1,|x|)`):

```
x = Z · 1 + y + fda
x = 1ᵀ Z + va + vaa
Σva + Σvaa = Σy + Σfda
Σx = ΣZ + Σy + Σfda
```

Неотрицательность: только `Z ≥ 0`, `y ≥ 0`, `va ≥ 0`; `fda`, `vaa` — знаковые. Пустые
корректировки трактуются как нули, поэтому **v1.0.0 == v1.1.0 с нулевыми корректировками**:
документ 1.0.0 читается, валидируется и даёт те же идентичности; документ 1.0.0 с ненулевыми
корректировками отвергается (`SchemaError`), как и v1.1-идентификатор с версией 1.0.0.
Проверены обе версии (`tests/test_mrio_schema_v11.py`, 16 тестов).

Новые метрики отчёта: `schema_version`, `total_final_demand_adjustments`,
`total_value_added_adjustments`, `adjustment_cells` (`{final_demand, value_added}`),
`fda_by_country`, `vaa_by_country`; новые проверки `schema_version`, `adjustments_shape`.
Матрицы в отчётах по-прежнему не публикуются (только агрегаты).

### 3.1 Остатки идентичностей (после раскладки в корректировки)

| Год | max abs row residual | max abs column residual | Σva+Σvaa − (Σy+Σfda) | Σx − (ΣZ+Σy+Σfda) |
|---|---|---|---|---|
| 2000 | 1,0e-09 | 0,0 | 0,0 | 0,0 |
| 2007 | 2,0e-09 | 0,0 | 0,0 | 0,0 |
| 2014 | 7,0e-09 | 0,0 | 0,0 | 0,0 |

Столбцовый остаток равен нулю по построению: WIOD-строка VA не закрывает столбцы точно
(остаток до 2,77 / 1,70 / 64,49 USD_mn на столбец — валюационные/транспортные строки релиза),
и этот остаток **поглощается в `vaa`**, а не скрывается: в манифесте записан
`max_abs_value_added_column_residual` и число затронутых столбцов (2286 / 2288 / 2291 из 2464).

### 3.2 Корректировки

| Год | `fda`: ячеек / сумма / минимум | `vaa`: ячеек / сумма | отрицательных `va` до раскладки |
|---|---|---|---|
| 2000 | 50 / −26 065,244026 / −7 739,195441 | 2 286 / −4,250233 | 1 (min −0,977) |
| 2007 | 31 / −27 258,363118 / −15 161,942148 | 2 288 / −1,137600 | 0 |
| 2014 | 50 / −34 531,893431 / −9 189,237610 | 2 291 / +44,301503 | 2 (min −22,174) |

Смысл `vaa`: (а) отрицательная часть исходного `va`, (б) остаток закрытия столбца. Это
балансирующая величина, а не экономическая категория — так и помечено в досье/манифесте.

### 3.3 Покрытие мирового ВВП (World Bank, NY.GDP.MKTP.CD, current US$)

| Год | Мировой ВВП, USD трлн | ВВП 40 из 43 стран, USD трлн | Доля в мире | Доля RoW + 3 не найденных |
|---|---|---|---|---|
| 2000 | 33,966 | 30,232 | **89,0068 %** | 10,9932 % |

В локальной панели World Bank нашлись 40 из 43 поимённых стран (нет `CYP`, `MLT`, `TWN`;
Тайвань не отчитывается в WB, Кипр/Мальта отсутствуют в загруженной панели), поэтому «43

Мировой агрегат `WLD` получен отдельным запросом (≈110 с, записан в
`data/mrio/wiod_2016/wb_gdp_coverage.json`); без него покрытие честно помечается
`PARTIAL_PROXY`/`UNAVAILABLE`, а не оценивается.

## 4. Сравнение с FIGARO (первый реальный мир, docs/125)

| Свойство | FIGARO 2019 | WIOD 2016 (эта волна) |
|---|---|---|
| Стран × отраслей | 50 × 64 (10,24 млн ячеек Z) | 44 × 56 (6,07 млн ячеек Z) |
| Годы | 2019 | 2000, 2007, 2014 (доступны 2000–2014) |
| Валюта/база | EUR basic prices → USD_mn по FX WB | USD_mn, current prices (база релиза) |
| RoW | блок `WRL_REST` | строка/блок `ROW` (44-й код) |
| Остатки идентичностей | row/col 3e-9, Σva−Σy −1,5e-08 | row 1–7e-9, col 0 (после `vaa`), Σ=0 |
| Покрытие мира | 87,28 % (2019, 49 стран) | 89,01 / 87,31 / 84,65 % (2000/2007/2014, 40 стран) |
| Лицензия | Eurostat re-use (проверить) | **CC BY 4.0** (подтверждено) |
| Схема | v1.1.0-совместим (документ исторически v1.0.0 читается) | v1.1.0 (с корректировками) |

FIGARO — «европейский» MRIO с детальной разбивкой и собственным RoW; WIOD — мировой, но
заканчивается 2014 и имеет отрицательные ячейки, которые теперь корректно раскладываются.
Вместе они дают два независимых мира для P2-калибровки/сравнения.

## 5. Воспроизведение

```powershell
# 1) архив уже скачан: data/mrio/wiod_2016/archive/WIOTS_in_STATA.zip (639 МБ, вне git)
$py = "C:\Users\Рус\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"  # pandas 3.0.1
& $py tools/alt_mrio_import.py --inspect wiod_2016
& $py tools/alt_mrio_import.py --convert wiod_2016 --years 2000 --years 2007 --years 2014
& $py tools/alt_mrio_import.py --coverage --no-fetch        # или без --no-fetch: тянет WLD из WB

# 2) проверки
python tools/mrio_data.py --validate --dataset wiod_2014 --root data/mrio/wiod_2016
python tests/test_mrio_schema_v11.py     # 16 тестов: v1.0/v1.1, корректировки, отказы
python tests/test_alt_mrio_import.py     # 25 тестов: парсер/раскладка/coverage/детерминизм
python tests/test_mrio_data.py           # 34 теста: схема/загрузчик/манифест/CLI (зелёные)
python tests/test_figaro_import.py       # 24 теста: FIGARO-трек (зелёные)
```

Артефакты (вне git, `data/mrio/wiod_2016/`): `wiod_<год>/dataset.json`, `wiod_<год>/manifest.json`
(агрегаты: хеши, счётчики, остатки, корректировки, покрытие), `wb_gdp_coverage.json` (мировой ВВП
и ВВП 43 стран по годам), `archive/` (639 МБ). Размер ~87 МБ на год, поэтому в этой волне
сконвертированы 3 реперных года из 15; полный прогон — та же команда с `--years` по всем годам
(оценка: ~70 с/год, ~1,3 ГБ на диске).

## 6. Ограничения и риски

1. **Только 3 года из 15** (2000, 2007, 2014) — выбраны как реперные; 2014 — последний год WIOD.
   Полный прогон не сделан из-за объёма (~87 МБ/год, свободно 3,8 ГБ на диске) и времени волны.
2. **`ROW` — агрегат**, а не страна: 44-й код нельзя трактовать как отдельную экономику с
   собственной политикой; для C4/калибровки он годится только как замыкающий блок.
3. **`fda`/`vaa` — балансирующие величины**, не экономические категории. `vaa` включает остаток
   закрытия столбца WIOD (валюация/транспорт), поэтому межстрановые сравнения `va` нужно вести с
   учётом `vaa` (в манифесте есть `vaa_by_country`).
4. **Покрытие мира**: 40 из 43 поимённых стран (нет CYP, MLT, TWN в панели WB); доля RoW +
   отсутствующих 10,99–15,35 %. Мировой агрегат WB получен медленным запросом (~110 с) и закэширован;
   при отсутствии кэша статус `PARTIAL_PROXY`/`UNAVAILABLE`, числа не выдумываются.
5. **База цен**: WIOD — current prices, без constant prices/PPP; для P2 сравнение с FIGARO
   (basic prices, EUR) требует FX/дефляторного слоя (в FIGARO-треке он есть, в WIOD — нет).
6. **Парсер**: ценовые/транспортные строки релиза (`TXSP`, `IntTTM`) по-прежнему складываются в
   строку `VA` (как в исходном парсере tracks); отдельного разложения на налоги/субсидии/маржи
   нет — расширение схемы v1.2, если понадобится.
7. **Зависимость от pandas** (только парсинг .dta): системный Python 3.12 без pandas; используется
   встроенный runtime DSH (pandas 3.0.1). Тесты не требуют pandas (фикстуры/чистые функции).
8. **Данные не в git**: `data/mrio/**` локальны; в репозитории только код, схема, тесты и доки.
