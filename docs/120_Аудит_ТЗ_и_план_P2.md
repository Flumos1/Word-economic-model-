# 120. Аудит «ТЗ ↔ факт» и план P2: мировая модель 10+ стран × 30+ отраслей

Дата: 2026-11-14. Автор: Lead. Основание: решение владельца 2026-11-14 (D-161) — приоритет
**P2 (мировая модель) 80%**, продуктовый контур — в поддерживающем режиме; масштаб — **сразу 10+
стран × 30+ отраслей**. Статус: **рабочий план**, не замораживает протоколы и не присваивает
допуск. Параллельные треки: [docs/121](121_Данные_MRIO.md) (данные),
[docs/122](122_IO_SFC_ядро.md) (IO/SFC), [docs/123](123_GVAR_прототип.md) (GVAR),
[docs/124](124_Поддержка_продукта.md) (поддержка продукта).

## 0. Главный вывод

Технического дефекта нет. Разрыв — **контурный**: проект построил очень качественный «судью»
(протокол допуска C1–C6, винтажи, журнал, harness, бюллетень) для узкого прогнозного трека, но
**мировая структурная модель осталась набором исполняемых прототипов без эмпирической калибровки**.
В docs/105 сам проект оценил P2 в **10–15%** и зафиксировал: «узкое место — этапы 2–5 (учётное
ядро, две страны/валюты, реальные ресурсы, динамические механизмы)». После этого волны 5–10 ушли
в этапы 6–7/9 (C4/C6, продукт, теневой трек). Настоящий документ возвращает P2 в приоритет.

### 2.2 Что отсутствует для P2

1. **Данные MRIO/SUT/торговли**: нет OECD ICIO/WIOD/FIGARO/Comtrade, нет IO-таблиц, нет
   межстрановых матриц; нет пайплайна загрузки и лицензионного режима.
2. **Эмпирически калиброванное статическое ядро**: A строится в прототипе, но не на реальных
   таблицах; нет воспроизведения официальных итогов.
3. **SFC-контур на реальных счетах**: инварианты есть на игрушечных данных, нет национальных
   счетов по странам/секторам.
4. **Динамика/оценка**: нет GVAR/state-space на реальных межстрановых рядах, нет OOS.
5. **Сценарии и отчёты по странам/отраслям**: сценарии есть на синтетике, нет отчётов «шок →
   отрасль → страна».
6. **Микроуровень**: нет микро-данных (фирмы/домохозяйства); реалистичный первый шаг — децили
   домохозяйств и распределения по размеру фирм из агрегатов, а не фирменная панель.
7. **Самообучение**: не начато (этап 8).

## 3. Причины разрыва (честно)

1. **Протокол-first**: допуск C1–C6 оптимизирован под точечные/плотностные прогнозы; у него нет
   критериев структурной согласованности → структурная работа не могла «пройти ворота» и
   откладывалась.
2. **Данные**: без MRIO нет мезо/межстранового слоя; лицензионная политика не проработана.
3. **Не было P2-MVP с критериями приёмки и календарём** — только архитектурные документы.
4. **T2 (ВВП) выпал** из v5; продукт сузился до CPI + рецессии.
5. **Самообучение** отложено до данных/динамики.

## 4. Целевая архитектура P2

Пять слоёв, каждый — с критериями приёмки и без смешивания с C1–C6:

```
[1] ДАННЫЕ           MRIO (Z,x,y,va) + SUT + торговля + FX/цены + энергия/труд
                        │  валидация: суммы, размерности, лицензии, manifest
[2] СТАТИЧЕСКОЕ ЯДРО  A = Z/x; x = (I−A)⁻¹y; Hawkins–Simon; агрегация; сценарии
                        │  + SFC: потоки/запасы, чистая стоимость, межстрановое погашение
[3] ДИНАМИКА          GVAR/state-space на межстрановых рядах; режимы; IRF; прогноз
                        │  OOS на агрегатах (ВВП, CPI, торговля) vs AR/наивные
[4] СЦЕНАРИИ/ОТЧЁТЫ   шок энергии/импортных цен/FX → страна × отрасль; JSON/дашборд
                        │  воспроизводимость, идентичности, границы применимости
[5] ИНТЕГРАЦИЯ        один пайплайн data → solve → scenario → report; тесты; docs
```

Продуктовый контур (T1/T3, журнал, бюллетень, теневой трек) остаётся **поддерживающим**: не
меняет статусы, работает по расписанию, не конкурирует за усилия.

## 5. Критерии приёмки P2 (Definition of Done)

**D1. Данные готовы** (docs/121)
- ≥10 стран, ≥30 отраслей, ≥1 год MRIO; страны/отрасли покрывают ≥80% мирового ВВП и торговли.
- Идентичности Z + y = x и итоги по странам сходятся в допуске ≤0,1%; неотрицательность;
  manifest с хешами воспроизводим; лицензии зафиксированы; сырые третьи данные не в git.

**D2. Статическое ядро** (docs/122)
- A = Z/x, ρ(A)<1 и Hawkins–Simon проходят на реальных данных; x=(I−A)⁻¹y воспроизводит x в
  допуске; агрегация по странам/отраслям без двойного счёта; шоки y и A дают согласованные
  отклики; fail-closed на непродуктивных матрицах.

**D3. SFC**
- Матрица потоков/запасов сходится (строки=столбцы), чистая стоимость согласована, межстрановые
  потоки погашаются; шаг периода детерминирован; инварианты на реальных/синтетических счетах.

**D4. Динамика** (docs/123)
- GVAR оценён на реальных межстрановых рядах (≥10 стран, ≥25 лет); стабильность; IRF с
  экономически осмысленным знаком/затуханием; OOS на ключевых агрегатах не хуже AR-бенчмарка
  (или честно зафиксировано, что хуже — это результат, а не провал).

**D5. Сценарии/отчёты**
- 3 обязательных сценария: энергия +50%, импортные цены +10%, FX −20% — отклики по стране ×
  отрасли; отчёт JSON/MD воспроизводим; границы применимости и допущения указаны.

**D6. Интеграция**
- Один воспроизводимый пайплайн `python tools/world_pipeline.py` (data → core → scenario → report);
  тесты; docs; никаких claims о допуске/точности без OOS.

## 7. Данные и лицензии (решение)

- **Основной источник MRIO**: OECD ICIO (45 отраслей, 60+ экономик, 1995–2021) — покрывает
  10+/30+; альтернативы: Eurostat FIGARO (EU+), WIOD (2016 release, 43 страны), Eora (широкий
  охват, лицензия платная/исследовательская).
- **Торговля**: UN Comtrade (агрегаты), WTO stats; **IO/национальные счета**: BEA (US), Eurostat
  (EU), OECD SNA; **макро/цены/FX**: FRED, ECB, OECD.
- **Правило**: сырые третьи данные — только локально/приватно; в git — схема, manifest с хешами,
  производные агрегаты (если лицензия позволяет). Каждый источник — в матрице лицензий docs/121.
- **Что нужно от владельца**: подтвердить лицензионный режим для OECD ICIO/FIGARO (исследовательское
  использование), при необходимости — API-ключи Comtrade/OECD; если доступ закрыт — скачать
  файлы вручную по инструкции docs/121 и положить в `AMFE_MRIO_ROOT`.
