## 0. Короткий ответ

> **Рекомендация: B сейчас, C — следующим шагом. A не рекомендуется.**
> Немедленно: **не активировать prereg 0.3**, оставить `PROPOSED`, T1 — `CANDIDATE`, ничего не
> менять (вариант B). Для разблокировки G4/G6 — выпустить **новую prereg 0.4** с процедурными
> исправлениями V2 и активировать её **до** нового расширенного прогона (вариант C; 0.4 готовит
> владелец, этот документ её не создаёт). Вариант A (активировать 0.3 как есть) создаёт
> post-hoc-активацию и не даёт права называть результат prereg-confirmed.

## 2. Три варианта решения

### A. Активировать prereg 0.3 (PROPOSED → ACTIVE)

Действие: владелец активирует файл как есть (пин и content hash не меняются).

| Ворота | Последствия |
|---|---|
| G4 | Закрывает пункт «активация prereg», но оставляет HIGH-блокер post-hoc активации: G4 нельзя считать пройденным без независимого V2 перевыпуска. |
| G5 | Без изменений: продукты остаются research-only; 0.3 не влияет на Client Pack/API/FLAKS. |
| G6 | Не даёт prereg-confirmed базы; риск: G6-аудит увидит активацию после опубликованного результата. |

Можно утверждать: C4 FAIL 1.0774564 — провизорное свидетельство docs/170; prereg 0.3 зафиксирован
как документ. **Нельзя**: что C4 FAIL — prereg-confirmed результат 0.3; что G4/G6 пройдены; что
T1 изменил статус; что пакет V2-подтверждён.

Блокеры: `post_hoc_activation_risk`, `no_independent_v2_of_reissue`, `prereg_limitations_stale`.

### B. Оставить prereg 0.3 в PROPOSED; T1 — CANDIDATE (без изменений)

Действие: ничего не менять; решение фиксируется как отложенное до V2/0.4.

| Ворота | Последствия |
|---|---|
| G4 | Остаётся открытым по пункту активации prereg; пункт подписи docs/160 уже закрыт (SIGNED_BY_HUMAN 2026-11-20). |
| G5 | Без изменений; Client Pack v2 и MVP-продукты продолжаются в research-only режиме. |
| G6 | Откладывается: нет активированного prereg и независимого V2 для beta-аудита. |

Можно утверждать: C4 W1_EXT FAIL — честное провизорное свидетельство; T1 `CANDIDATE`, C6 0/12,
`ENSEMBLE_REGIME_V4` `SHADOW_TEST`; подпись docs/160 существует и ограничена docs/160.
**Нельзя**: что prereg активирован; что G4/G6 пройдены; что результат prereg-confirmed.

Блокер: `no_independent_v2_of_reissue` (для активации в будущем).

### C. Выпустить новую prereg 0.4 с исправлениями V2

Действие: владелец готовит `protocols/pit_preregistration_0_4.json` (новый файл + новый пин),
только процедурные исправления V2, без изменения окон/порогов/классов/линз; активация 0.4 — **до**
любого нового расширенного прогона. Этот документ 0.4 **не создаёт** — только спецификацию.

| Ворота | Последствия |
|---|---|
| G4 | Требует: 0.4 → независимое V2-ревью 0.4 → новый прогон → отчёт. Только тогда пункт prereg закрывается; docs/170 остаётся историческим свидетельством. |
| G5 | Без изменений; 0.4 не блокирует продукты. |
| G6 | Единственный путь к prereg-confirmed доказательной базе для beta-аудита; требует волны времени и независимой проверки. |

Можно утверждать: план исправлений V2 — это спецификация, а не результат; старые результаты
сохраняются. **Нельзя**: что 0.4 уже существует/активирована; что пороги/классы изменены; что
C4-результат станет prereg-confirmed автоматически.

Блокеры: `requires_owner_new_file`, `requires_independent_v2_of_0_4`,
`requires_new_evaluation_run`.

## 4. Блокеры (почему A не рекомендуется)

1. **`post_hoc_activation_risk` (HIGH).** Оценка docs/170 уже выполнена, а prereg 0.3 создан до неё
   и не активирован; активация после результата — post-hoc. Prereg-дисциплина требует активации до
   прогона; иначе нельзя утверждать, что результат получен по активированным правилам.
2. **`no_independent_v2_of_reissue` (HIGH).** V2 (docs/172) дала `NOT_CONFIRMED` прежней редакции
   пакета. Перевыпуск docs/170 (schema v2) закрывает пункты 1–5 **по заявлению авторов**, но
   независимого повторного V2-ревью перевыпуска в дереве нет. Активировать 0.3 сейчас — закрепить
   непроверенный пакет.
3. **`prereg_limitations_stale` (HIGH).** В `limitations` prereg 0.3 написано «no extended-window
   evaluation has been run under this preregistration yet; no result is claimed», что уже неверно:
   оценка выполнена. Активация без поправки создаёт рассинхронизацию заявленного и фактического.
4. **`signature_scope_note` (LOW).** Подпись G4-SIGN-160 действительна для docs/160 и не является
   активацией prereg; рукописное замечание подписанта («улучшить исследование значимости применения
   модели») нужно учесть в G6-плане, но оно не блокирует выбор B/C.

## 5. Рекомендация и обоснование

**B сейчас + C следующим шагом; A отклонить.**

1. **B безопасен и обратим:** статусы не меняются, T1 остаётся `CANDIDATE`, C6 0/12, ничего не
   «залипает»; провизорное свидетельство docs/170 сохраняется как есть.
2. **A нарушает prereg-дисциплину** (пункты 1–3 §4) и создаёт риск для G6-аудита: активация после
   результата не превращает результат в prereg-confirmed, но выглядит как попытка это сделать.
3. **C — единственный корректный путь** к prereg-confirmed базе: исправления V2 процедурные, без
   изменения порогов/окон/классов; новая активация — до прогона; независимое V2 — до активации или
   параллельно; docs/170 не перезаписывается.
4. **V2 перевыпуска полезна в любом случае** (даже при B): она подтверждает или отклоняет
   перевыпущенный пакет и делает G4-решение информированным; это дешевле, чем 0.4, но не заменяет
   активацию prereg.

Решение требуется от владельца: (а) утвердить B (отказ от активации 0.3 сейчас); (б) санкционировать
подготовку 0.4 по требованиям §6; (в) назначить независимого ревьюера V2 для перевыпуска/0.4.

## 6. Требования к prereg 0.4 (если выбран C; 0.4 не создаётся этим пакетом)

1. Новый файл `protocols/pit_preregistration_0_4.json` + новый `.sha256`-пин; 0.3 не редактируется.
2. Только процедурные исправления V2: REAL_TIME-only срез как отдельный расчёт на 121 начале
   (8 рецессионных → `INCONCLUSIVE`), алиасы `reconstructed-excluded`/`tape-free`, публикация C4 W2
   и leave-one-episode-out, проверка пина prereg, пин coverage digest.
3. Обновить устаревшее ограничение «no extended-window evaluation has been run» и явно
   зафиксировать историю: 0.3 никогда не активировалась; docs/170 — провизорное свидетельство.
4. Не менять окна, пороги, классы, классификацию рядов и состав линз (post-hoc запрет).
5. Активация 0.4 — владельцем, **до** любого нового расширенного прогона; затем независимое V2.
6. Новый прогон и новый отчёт со ссылкой на SHA-256 0.4; старые отчёты не перезаписываются.

## 7. Инструмент decision packet

`python tools/prereg_decision.py` (Markdown) · `--json` (JSON) · `--out PATH` (запись; внутрь
`protocols/` запрещено) · `--generated-at` (детерминизм). Инструмент **только читает** и не меняет
статусы; exit `0` — пакет собран, `2` — fail-closed.

Проверки (все fail-closed): SHA-256 prereg совпадает с пином; `content_sha256` пересчитывается;
статус prereg `PROPOSED`; отчёт `PROVISIONAL`, `admission=false`, `pins_ok=true`,
`slices_complete=true` и ссылается на тот же пин; реестр подписи: `agent_may_sign=false`,
`fail_closed=true`, известные статусы, SHA-256 object/packet пересчитываются, подпись человеческая
(`signer_type=human`), поля и решение валидны; T1 `CANDIDATE`, C6 0; в дереве есть docs/160, 164,
170, 172, 185. Пакет содержит: факты, три варианта с последствиями для G4–G6, таблицу статусов,
блокеры, рекомендацию, требования к 0.4, проверки и дисклеймер.

```powershell
python tools/prereg_decision.py --json --out build/prereg_decision.json
python -m unittest tests.test_prereg_decision -v   # 19 тестов
```

## 8. Ограничения

1. Это **decision brief**, а не решение и не активация: статусы меняет только владелец.
2. Пакет фиксирует состояние на 2026-11-20; при изменении prereg/отчёта/подписи пакет нужно
   пересобрать (пины и хеши проверяются fail-closed).
3. Отсутствие независимого V2 перевыпуска — констатация по дереву документов, а не оценка качества
   перевыпуска; V2 может подтвердить или отклонить его.
4. Ни 0.3, ни 0.4 не меняют T1/C6: prereg — правила оценки, а не допуск; `ACTIVE` невозможен до C6
   (12 разрешённых прогнозов, ≥4 периода) и внешней проверки.
5. Документ не пересчитывает C4/C1/C2/C5 и не пересматривает docs/170/172; числа взяты из отчёта.
