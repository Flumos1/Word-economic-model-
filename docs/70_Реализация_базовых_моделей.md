## 2. Публичный API

```python
import sys; sys.path.insert(0, "src")
from amfe.forecast import (
    DataContext, available_data, available_series, assert_no_lookahead,
    forecast, forecast_all, run_rolling, applicable_models, MODEL_IDS,
)

ctx = DataContext.from_local("2008-06-30", mode="auto")   # вся PIT-информация на origin
f = forecast("BVAR_MINNESOTA", "T1_CPI_YOY", "2008-06-30", 1,
             series_id="CPIAUCSL", mode="auto")
f.to_dict()   # model_id, target, series_id, origin, horizon, point, quantiles[19],
              # probability, estimation_window, effective_steps, data_class,
              # vintage_date, notes
rows = run_rolling("RW", "T1_CPI_YOY", 1, ["2008-01-31", "2008-02-29"], skip_errors=True)
```

* `mode="auto"` (по умолчанию): если для ряда есть винтаж с датой ≤ origin — берётся
  последний такой винтаж (класс `REAL_TIME`), иначе — обрезанный latest (класс
  `PSEUDO_REAL_TIME`).
* `mode="vintage"`: требуется винтаж; иначе `SeriesUnavailable` (явный отказ).
* `mode="latest"`: всегда обрезанный latest; класс `PSEUDO_REAL_TIME`.

Невалидный origin (вне диапазона локальных данных), горизонт вне сетки протокола,
неприменимая пара модель/цель, нехватка истории — исключения
`OriginOutOfRangeError`, `ValueError`, `ForecastError`/`InsufficientData`
соответственно.

## 3. Point-in-time: как гарантируется отсутствие утечки будущего

1. `available_series(name, origin, mode)` для рядов с архивом ALFRED
   (`CPIAUCSL, CPILFESL, GDPC1, UNRATE, GS10, TB3MS`) берёт **колонку винтажа**
   с датой ≤ origin и обрезает её по origin. Для остальных (`USREC` — только latest)
   latest обрезается по origin минус лаг публикации ряда (`RELEASE_LAG_MONTHS`;
   USREC — 12 мес.).
2. `assert_no_lookahead(series, origin)` проверяет, что ни одно наблюдение не позже
   origin (месячные — по месяцу; квартальные — по концу квартала). Нарушение →
   `LookAheadError`.
3. `DataContext.__post_init__` повторно проверяет **каждый** переданный срез, поэтому
   даже собранный вручную контекст не может содержать будущих наблюдений. Модели
   работают только через `DataContext`, других путей к данным у них нет.
4. `DataContext.from_local` валидирует origin по фактическому диапазону локальных
   latest-файлов (до первой/последней точки), origin нормализуется к концу месяца.
5. Цели строятся на протокольном календаре: T1 — y/y месяца `t-1+h`;
   T2 — рост квартала `Q(origin)+h`; T3 — событие в `(t, t+h]`. При устаревшем
   винтаже модель прогнозирует с последнего опубликованного значения до целевого
   периода; фактическое число шагов публикуется как `effective_steps` (≥ h).

Классы данных — по `data_depth.classification_rule` протокола v4: `REAL_TIME` —
все винтажные входы из винтажа, доступного на origin; `PSEUDO_REAL_TIME` — хотя бы
один винтажный вход заменён обрезанным latest (пересмотры истории — это тоже
заглядывание в будущее, поэтому такие прогнозы помечены).

## 4. Цели

| Цель | Формула | Частота | Горизонты | Окно |
|---|---|---|---|---|
| T1_CPI_YOY | `100*(CPI_t/CPI_(t-12)-1)`, headline/core отдельно | M | 1, 3, 6, 12 | 180 мес. |
| T2_GDP_GROWTH | `400*ln(GDP_q/GDP_(q-1))` | Q | 0, 1, 2, 4 | 60 кв. |
| T3_RECESSION | 1, если хотя бы один месяц USREC=1 в `(t, t+h]` | M | 3, 6, 12 | 240 мес. |

Фактические значения для будущего скоринга: `target_actual_series()` /
`target_actual()` берут **latest** и строят T1/T2/T3 по тем же формулам. Первичные
actuals (первая публикация; `actuals.primary` протокола) здесь не собираются —
для них нужен винтаж месяца публикации, это задача оценочного слоя/R3.

## 5. Соответствие R3-спецификации (`models`)

| id | Цели | Точка | Плотность/событие | Окно | Статус в спеке |
|---|---|---|---|---|---|
| RW | T1 | последнее опубликованное y/y | эмпир. квантили h-step ошибок окна | 180 мес. | PROPOSED |
| AO | T1, T2 | T1: среднее по окну; T2: среднее 4 последних кварталов | как RW | 180 мес. / 60 кв. | PROPOSED |
| AR_BIC | T1, T2 | AR(p), p по BIC (max 12 / 4), итерация до h | эмпир. квантили h-step ошибок | 180 мес. / 60 кв. | PROPOSED |
| BVAR_MINNESOTA | T1, T2 | VAR с диагональным Minnesota-приором, p по BIC, итерация | гауссова, σ h-step ошибок; <20 ошибок → шкала RW | 180 мес. / 60 кв. | PROPOSED |
| PROBIT_SPREAD | T3 | probit MLE на спреде GS10−TB3MS, окно 240 мес. | вероятность Bernoulli(p) | 240 мес. | PROPOSED |
| SAHM_RULE | T3 | индикатор Sahm (3-мес. MA ≥ 0.50 пп над 12-мес. min), логистическая калибровка | вероятность Bernoulli(p) | 240 мес. | PROPOSED |
| OWN_NOWCAST_BRIDGE | T2, h=0 | PCA-факторы (1–2) месячной панели + bridge-регрессия 60 кв. | эмпир. квантили остатков bridge | 180 мес./60 кв. | PROPOSED |

Не реализованы осознанно: `DFM_FREDMD` (в спеке `PROPOSED_BLOCKED_ON_REGISTER` —
FRED-MD/QD UNVERIFIED), `SPF_MEDIAN` / `SPF_NEG_GDP_PROB` (SPF исключён до
R2-автоматизации и маппинга), `NOWCAST_NYFED` (control arm, не входит в R3-код).
`T10Y3M` не используется и не загружается (daily-файл; PROBIT по D-131 использует
только GS10−TB3MS).

## 6. Упрощения (задокументированы в коде и здесь)

1. **Плотности RW/AO/AR_BIC**: эмпирические квантили h-step ошибок считаются на
   окне с коэффициентами/средними, замороженными на origin (без переоценки на каждом
   псевдо-origin внутри окна). Ошибки центрируются на точечном прогнозе.
2. **BVAR**: диагональный Minnesota-приор с фиксированным λ=0.2, решение как ridge
   (`(X'X+D)β = X'y + D·b_prior`), приор: среднее 1 на собственный первый лаг каждой
   переменной, 0 на остальные; порядок по BIC. Для T2 VAR оценивается на
   annualised-росте (а не на уровне GDPC1) и квартальных средних UNRATE/GS10/TB3MS,
   где среднее использует только месяцы, опубликованные на origin (смешанная
   частотность через квартальные средние — как в спеке). σ плотности — выборочное
   СКО h-step ошибок; при <20 ошибках берётся шкала ошибок RW и прогноз помечается
   (правило протокола).
3. **T3-метки**: USREC — это хронология NBER без винтажей; метка месяца считается
   известной модели только через 12 месяцев (`NBER_ANNOUNCEMENT_LAG_MONTHS`) —
   консервативная замена дат анонсов NBER, которые ещё не скачаны (R2-уточнение).
   Поэтому обучающие origin'ы T3 ограничены `m ≤ origin − h − 12`.
4. **PROBIT_SPREAD**: регрессор — спред на последнем опубликованном месяце (в
   винтажном режиме он может быть заметно старше origin); MLE методом Ньютона;
   при вырожденном/коротком распределении меток или сингулярной матрице — вероятность
   равна базовой частоте события в окне (с пометкой). p обрезается в [1e-4, 1−1e-4]
   (клиппирование лог-скора [0.01, 0.99] делает оценочный слой).
5. **SAHM_RULE**: индикатор считается по обрезанному UNRATE; калибровка — логит на
   окне 240 мес.; при вырожденном индикаторе (нет сигналов в окне) — базовая частота
   (прямо предусмотрено спецификацией).
6. **OWN_NOWCAST_BRIDGE**: число факторов 1–2 выбирается по доле объяснённой
   дисперсии (заменитель Bai-Ng, максимум 2); PCA по стандартизованным уровням на
   180 мес.; неопубликованные месяцы текущего квартала заполняются AR(1) по каждому
   фактору (упрощение вместо полного факторного/state-space прогноза); bridge на
   60 кварталах; плотность — из in-sample остатков bridge (а не из rolling
   псевдо-ошибок).
7. **Первичные actuals** (first publication) не собираются; `target_actual` —
   вторичные (final) фактические значения. Первичные метрики — задача оценочного слоя.
8. **COVID**: окна/исключения 2020-03..2021-02 не применяются на этапе генерации;
   список origin'ов берётся из `tools/windows.py` / `protocols/evaluation_origins.json`
   оценочным слоем.

## 7. Ограничения и риски

1. **Локальный винтажный грид редкий**: по каждому ряду скачано 10 годовых винтажей
   1996-12..2020-12 (`protocols/data_log.json`), а не месячная сетка ALFRED. Поэтому
   `mode="auto"` формально даёт `REAL_TIME`, но информационная база может быть
   устаревшей на годы:

   | origin (июнь) | использованный винтаж | последнее наблюдение | отставание |
   |---|---|---|---|
   | 1997-06 | 1996-12-12 | 1996-11 | 7 мес. |
   | 2000-06 | 1999-12-14 | 1999-11 | 7 мес. |
   | 2005-06 | 2004-12-17 | 2004-11 | 7 мес. |
   | 2008-06 | 2007-12-14 | 2007-11 | 7 мес. |
   | 2010-06 | 2007-12-14 | 2007-11 | 31 мес. |
   | 2015-06 | 2013-12-17 | 2013-11 | 19 мес. |
   | 2019-06 | 2013-12-17 | 2013-11 | 67 мес. |
   | 2022-06 | 2020-12-10 | 2020-11 | 19 мес. |

   Следствие: прогон W1/W2 в `auto` даст `REAL_TIME`-прогнозы на сильно устаревшей
   информации (пример: origin 2019 использует данные 2013 г.). Для оценки качества
   на W1/W2 до скачивания плотного ALFRED-архива правильнее запускать
   `mode="latest"` и помечать результат `PSEUDO_REAL_TIME`; `REAL_TIME` допустим
   только после пополнения архива винтажей. Origin'ы до 1996-12 в `auto` и так
   попадают в `PSEUDO_REAL_TIME` (в локальном наборе нет винтажей раньше 1996-12).
2. **W1 1990–1996**: винтажей в локальном наборе нет → только `PSEUDO_REAL_TIME`.
3. **USREC** — latest-only; даты анонсов NBER не скачаны (лаг 12 мес. — заглушка).
4. **GDPC1**: винтажи 1996-12-20 и 1999-12-22 содержат короткую историю
   (с 1959Q3 / 1959Q1), поэтому часть ранних origin'ов T2 может получить
   `InsufficientData` — это корректный отказ, а не прогноз.
5. **T2/BVAR смешанная частота**: квартальные средние строятся только по полным
   месяцам, опубликованным на origin; при разных «последних» месяцах входов
   выровненный последний квартал может быть раньше, чем у GDPC1; фактическое число
   шагов публикуется в `effective_steps`.
6. **Качество моделей на реальных данных здесь не оценивается**: smoke-прогон
   проверяет PIT, размеры, монотонность и отсутствие падений; никаких выводов о
   превосходстве моделей из него не следует.
7. **T3 маломощна** (≈8 послевоенных рецессий) — потолок LIMITED_DEPLOYMENT; это
   свойство цели, не реализации.

## 9. SHA-256 модулей (LF-normalised)

Хеш = SHA-256 от байтов файла с заменой `CRLF → LF` (без BOM-изменений; файлы уже
в UTF-8/LF). Task Lead вносит эти значения в `protocols/r3_specification.json`
(`models[].code_hash`); после внесения замораживается `spec_hash` самой
спецификации. Хеши актуальны на 2026-11-11 после последнего прогона тестов.
