# 113. Продуктовый пакет: модель-карточка, JSON-фид и статическая панель

Версия 1.0.0 · 2026-11-12. Волна 6, трек продукта. Задача: `task-5`. Действующий протокол —
**v5 FROZEN** (`protocols/evaluation_protocol_v5.json`, SHA-256 `41d6823e…`); журнал —
[registry/forecasts.jsonl](../registry/forecasts.jsonl) (5 строк, append-only).

Новые файлы: [tools/product_pack.py](../tools/product_pack.py),
[tests/test_product_pack.py](../tests/test_product_pack.py), этот документ и генерируемый каталог
`build/product/` (в git не добавляется — решение Lead). Существующие `tools/**`, `protocols/**`,
`src/**` и журнал не меняются.

Это **отчётность и упаковка** уже полученных результатов, **не допуск**: статус ни одного
кандидата не меняется, новых оценок пакет не производит.

## 1. Что делает инструмент

`python tools/product_pack.py` читает **только закоммиченные артефакты репозитория** (без сети,
без `data/raw/`):

| Вход | Что берётся |
|---|---|
| `registry/forecasts.jsonl` | последняя строка кандидата, его точка и 19 квантилей; точки контрольных плеч `RW`, `EQUAL_WEIGHT_POINT`, `EQUAL_WEIGHT_DENSITY` на том же origin |
| `protocols/first_real_evaluation_report_v5.json` | кандидат, цель, горизонт, статус, `conditional_data_class`, C1/C2/C4/C5/C6, per-episode C4 |
| `protocols/evaluation_protocol_v5.json` + `.sha256` | версия, статус FROZEN и SHA-256 (сверяется с пином) |
| `protocols/r3_specification.json` | версия 1.0.1 и SHA-256 (сверяется с отчётом) |
| `protocols/nf_sim_thresholds.json` + `.sha256` | идентификатор NF-SIM, число порогов, SHA-256 |
| `protocols/comparator_composition_2026-11-11.json` | состав компаратора, дата, SHA-256 |

Пишет пять файлов в `build/product/`:

| Файл | Содержание |
|---|---|
| `model_card.md` | назначение, версии/хеши, что подтверждено (C1/C2/C5 PASS), что нет (C4 FAIL, C6), статус `CANDIDATE`, `conditional_data_class=true`, текущий прогноз, ограничения, ссылки на docs, что публиковать нельзя |
| `forecast_latest.json` | машиночитаемый фид по схеме §2 |
| `dashboard.html` | статическая read-only панель: статус, последний прогноз, 19 квантилей, контрольные плечи, что не подтверждено, C6-счётчик, источники; без JavaScript, без фреймворков и внешних URL |
| `dashboard.md` | та же панель в Markdown |
| `README.md` | что это, как пересобрать, почему это не допуск, лицензионная гигиена |

Запуск:

```powershell
python tools/product_pack.py
python tools/product_pack.py --generated-at 2026-11-12T12:00:00Z --out-dir build/product
python -m unittest tests.test_product_pack -v
```

`--generated-at` фиксирует дату-время снимка; без него берётся текущее UTC. Всё, кроме
`generated_at`, — чистая функция входов: одинаковые входы и одинаковая дата дают байт-идентичные
файлы.

**Fail-closed:** битый/отсутствующий вход, расхождение SHA-256 протокола с пином, R3 или состава
компаратора с записанным хешем, несовпадение версии протокола в отчёте и в замороженном файле,
отсутствие строки кандидата или контрольного плеча в журнале — код выхода `2`, пакет не пишется.

## 2. Схема `forecast_latest.json` (schema_version 1.0.0)

```jsonc
{
  "schema_version": "1.0.0",
  "generated_at": "2026-11-12T12:00:00Z",          // ISO 8601, UTC
  "status": "CANDIDATE",                            // из отчёта
  "status_label": "CANDIDATE",                      // машинная метка из отчёта
  "conditional_data_class": true,                   // из отчёта
  "data_class": "REAL_TIME_RECONSTRUCTED",          // класс данных отчёта
  "report_id": "AMFE-FIRST-REAL-EVALUATION",
  "protocol": {
    "file": "protocols/evaluation_protocol_v5.json",
    "version": "5.0.0",
    "sha256": "41d6823e…153ba4"                      // LF-нормализованный, сверен с пином
  },
  "candidate": "ENSEMBLE_INVERSE_MSE",
  "target": "T1_CPI_YOY",
  "horizon": 1,
  "origin": "2026-11",                              // YYYY-MM, из журнала
  "point": 3.6257264569782937,                      // из журнала
  "quantiles_5_to_95_step_5": [ /* ровно 19 строго возрастающих чисел, 5%…95% */ ],
  "controls": {
    "RW": {"point": 3.7172508442689933},
    "EQUAL_WEIGHT_POINT": {"point": 3.459952754918441},
    "EQUAL_WEIGHT_DENSITY": {"point": 3.459952754918441}
  },
  "c4_status": {
    "pass": false,
    "rmse_pass": false,
    "rmse_relative_loss": 1.0774564457828197,      // W1_EXT, рецессионные месяцы
    "rmse_relative_loss_met": false,
    "conditional_gw_p": 1.144555036934194e-05,
    "favours_comparator_in_recession": true,

    "w2_pass": true,
    "episodes": [
      {"episode": "1990-91", "origins": 8, "rmse_relative_loss": 1.099…,
       "rmse_leave_one_out": 0.642…, "crps_relative_loss": 0.874…},
      {"episode": "2001", "origins": 8, "rmse_relative_loss": 1.067…,
       "rmse_leave_one_out": 0.632…, "crps_relative_loss": 0.981…}
    ]
  },
  "c6_status": {
    "n_resolved": 0,
    "min_forecasts": 12,
    "min_distinct_target_periods": 4,               // protocol.forward_registry
    "pass": false,
    "status": "NO_RESOLVED_FORECASTS"
  },
  "limitations": ["…"],
  "source_hashes": {                                 // LF-нормализованные SHA-256
    "protocol": "41d6823e…",
    "report": "eb8c37b5…",
    "journal": "8d30b84a…"
  }
}
```

Схема намеренно **плоская и самодостаточная**: потребителю не нужно знать внутреннюю структуру
отчёта, а все числа можно проследить до журнала, отчёта или протокола. Сырых сторонних значений в
фиде нет по построению: журнал содержит только собственные прогнозы, отчёт — только производные
метрики и диджесты (`licence_policy`, docs/84).

## 3. Что показывает пакет (снимок 2026-11-12)

- Кандидат `ENSEMBLE_INVERSE_MSE`, T1 CPI г/г h=1, origin **2026-11** (pre-origin запись);
  точка **3.6257**, 90% интервал **[2.4579; 4.7971]** из 19 квантилей.
- **Подтверждено:** C1 PASS (RMSE/CRPS 0.947/0.968 на W1, 0.948/0.954 на W2 при пороге 0.97),
  C2 PASS (Romano–Wolf), C5 PASS — на первой реальной оценке T1 h=1.
- **Не подтверждено:** **C4 FAIL** по RMSE — относительная потеря **1.0775** в 16 рецессионных
  месяцах W1_EXT (1990-91 — 1.099, 2001 — 1.067); CRPS PASS 0.9303 не компенсирует RMSE. **C6 нет**:
  0 из 12 разрешённых прогнозов, нужно ≥4 различных целевых периодов.
- **Статус: `CANDIDATE`**, `conditional_data_class = true` (C4 опирается на реконструированные
  данные 1990–1996, а не на REAL_TIME). SHADOW_TEST/LIMITED_DEPLOYMENT/ACTIVE не достигнуты.

## 4. Тесты

`tests/test_product_pack.py` (20 тестов, все зелёные):

- схема JSON: обязательные поля и типы, 19 квантилей, строгая возрастаемость;
- статусы: `CANDIDATE`, `status_label`, `conditional_data_class=true`, C4 `pass=false`, C6 `0/12/4`;
- консистентность: точка и квантили совпадают со строкой журнала, контрольные точки — со строками
  контрольных плеч, C4/C6 — с отчётом и протоколом, `source_hashes` — с файлами и пином;
- отсутствие сырых третьих данных: в фиде нет actual/observation/raw-ключей, в документах нет
  маркеров сырых значений;
- статичность панели: нет `<script>`, нет внешних URL/фреймворков, есть статус, C6 и C4-числа;
- детерминизм: повторная сборка байт-идентична; при другой `generated_at` файлы отличаются только
  этой меткой;
- неизменность входов: SHA-256 журнала, протокола, отчёта и замороженных файлов после запуска те же;
- fail-closed: пустой корень и испорченный пин протокола дают код 2;
- CLI: `python tools/product_pack.py` как отдельный процесс создаёт все пять файлов.

## 5. Ограничения

1. **Не допуск.** Пакет — снимок состояния, а не решение о допуске; статусы не меняются, C4/C6 не
   пересчитываются.
2. **Один кандидат и одна пара.** Пакет покрывает только `T1_CPI_YOY` h=1 и кандидата из отчёта
   (сейчас `ENSEMBLE_INVERSE_MSE`); T2, T3 и другие кандидаты не входят.
3. **Снимок, а не поток.** `generated_at` фиксирует момент сборки; автоматического обновления нет.
   Пересборка запускается вручную/CI и не коммитится инструментом.
4. **Хеш протокола в отчёте устарел.** В `first_real_evaluation_report_v5.json` записан SHA-256
   `891e26f9…` (редакция до заморозки), тогда как замороженный файл и пин дают `41d6823e…`.
   Инструмент доверяет **пину** `protocols/evaluation_protocol_v5.sha256` и фактическому файлу;
   расхождение версии (5.0.0/5.0.0) проверяется отдельно.
5. **Зависимость от формата отчёта.** Поля C4/C6 берутся из структуры
   `admission.criteria`/`c4_episodes`; смена формата отчёта требует правки инструмента (он упадёт
   fail-closed, а не запишет пустоту).
6. **Без JS и без интерактива.** Панель статическая by design; фильтров, графиков и обновления в
   реальном времени нет.
7. **Файлы в git.** `build/` не в `.gitignore`; добавлять ли пакет в git — отдельное решение Lead
   (задача говорит не коммитить).

## 6. Что публиковать нельзя

- Сырые сторонние наборы данных (FRED/ALFRED, FRED-MD/QD, SPF и любые другие) — никогда:
  `licence_policy` разрешает публиковать только производные статистики (метрики, счётчики, хеши,
  собственные прогнозы). Пакет их и не содержит.
- Нельзя выдавать `CANDIDATE` за «допущенную модель», скрывать C4 FAIL или C6-ноль, снимать
  `conditional_data_class=true` без новой оценки, проходящей C4 без реконструкции.
- Нельзя публиковать пакет как инвестиционную рекомендацию: это исследовательский артефакт.
