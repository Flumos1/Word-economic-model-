## 2. Уравнения и допущения

### 2.1 Диффузия внедрения

Для каждой агрегированной отрасли `i`:

```
x_i(t) = ceiling_i / (1 + ((ceiling_i − start_i)/start_i) · exp(−speed_i · t))
```

Это решение `dx/dt = speed · x · (1 − x/ceiling)`; `t` — годы от старта, `start_i = x_i(0)`.

- `ceiling_i` — **предел** (доля потенциала отрасли), не «оценка насыщения»; `0 < start < ceiling ≤ 1`.
- `speed_i` — **гипотеза о скорости** (1/год), не оценка; при `speed → 0` кривая вырождается в
  константу `start`.
- Замкнутая форма выбрана вместо дискретной рекурсии `x_{t+1} = x_t + r·x_t·(1 − x_t/ceiling)`:
  при больших `r` дискретная схема осциллирует и может выйти за потолок. Здесь монотонность и
  ограниченность выполняются **по построению** и проверяются тестами.
- Полупериод `t½ = ln((ceiling − start)/start)/speed` — аналитический, используется в тестах как
  контроль формы, а не как оценка.

### 2.2 Growth accounting (передача в TFP и выпуск)

Кобб–Дуглас с постоянной отдачей: `Y = A · K^α · L^(1−α)`. Тождество:

```
ln(Y_t/Y_0) = ln(A_t/A_0) + α · ln(K_t/K_0) + (1−α) · ln(L_t/L_0)
```

Единственный канал внедрения — гипотеза H-005:

```
A_t/A_0 = exp(tfp_elasticity_i · (x_i(t) − start_i))
```

`tfp_elasticity_i` читается как «+1 п.п. внедрения → +`tfp_elasticity` % TFP (лог-приближение)».
Это **допущение, а не оценка**: коэффициент несёт на себе всю гипотезу H-005, и именно его первым
должна заменить калибровка (PWT TFP + OECD STI).

`K` и `L` — экзогенные постоянные темпы (`capital_growth`, `labour_growth`): нет инвестиционного
решения, износа, рынка труда и обратной связи спроса. Поэтому «выпуск» здесь — не прогноз, а
арифметическое следствие трёх компонент.

Невязка тождества проверяется на каждом горизонте (`identity_residual ≤ 1e-12` на отрасль,
`≤ 1e-9` на агрегате).

### 2.3 Энергопотребление

```
E_t/E_0 = (Y_t/Y_0)^energy_output_elasticity · exp(−energy_efficiency_gain · (x_t − x_0))
```

Эластичность `< 1` означает «отрыв» энергии от выпуска — это **допущение**, а не измеренное
decoupling; `energy_efficiency_gain` — экономия энергии на единицу внедрения. Энергобаланса,
структуры топлива, цен и физических пределов здесь нет.

### 2.4 Агрегат

- внедрение агрегируется **арифметически** как взвешенная доля: `x_agg = Σ w_i · x_i`;
- TFP, выпуск и энергия — **взвешенное геометрическое среднее** уровней (приём Törnquist, не
  индексная цепь): `ln Z_agg = Σ w_i · ln Z_i`;
- веса `w_i` — фиксированные доли выпуска, сумма = 1 (проверяется); при фильтре `--sector`
  веса перенормируются и в отчёте стоит `weights_renormalised=true`.

Почему геометрическое среднее: при нём growth accounting переживает агрегацию
(`Σ w_i (tfp_i + kapital_i + trud_i) = ln Y_agg`), и тождество остаётся проверяемым. Это
осознанный выбор представления, а не «истинная» агрегация.

## 4. Что можно и чего нельзя утверждать

**Можно (в пределах прототипа):**

- при заданных `ceiling/speed/start` и заданной `tfp_elasticity` — каковы TFP, выпуск и энергия
  на горизонте, и как прирост выпуска раскладывается на TFP / капитал / труд;
- что ускорение внедрения (при прочих равных) даёт больше внедрения и выпуска, замедление —
  меньше; энергопереход — меньше энергии при близком выпуске;
- sensitivity: как меняется результат при изменении `capital_growth`, `tfp_elasticity`,
  `ceiling`, `speed`, `energy_efficiency_gain` **в объявленных диапазонах**;
- что арифметика внутренне согласована (тождество, границы, детерминизм) и воспроизводима
  (SHA-256, байт-идентичные файлы).

**Нельзя:**

- называть числа прогнозом, «вкладом ИИ в ВВП/производительность» или вероятностью;
- утверждать, что `ai_acceleration` «будет»: это сценарий, а не ожидание;
- переносить `tfp_elasticity` на реальную экономику: это допущение, не оценка и не причинный
  эффект (H-005 не проверена и без данных не может быть проверена);
- говорить о страновой/отраслевой точности: отрасли — пять агрегатов, не 50 отраслей OECD ICIO;
- использовать отчёт вне исследовательского контура, в клиентском пакете или API без пометки
  `RESEARCH_ONLY` и без допуска (его нет: `admission=false`).

## 8. Acceptance (фиксируется до калибровки)

Прототип — не прогноз; критерии приёмки нужны, чтобы следующая итерация не «улучшалась на глаз».

- **A1. Логистика.** Для каждого сценария/отрасли: `0 < start ≤ x(t) ≤ ceiling ≤ 1`, путь
  монотонно неубывающий, `x(0) = start`; полупериод совпадает с замкнутой формой. — **выполнено**
  (тесты логистики).
- **A2. Тождество.** `|tfp + α·ln K + (1−α)·ln L − ln Y| ≤ 1e-12` на отрасль и `≤ 1e-9` на
  агрегат для всех сценариев. — **выполнено**.
- **A3. Направления.** `ai_acceleration > baseline > ai_slowdown` по внедрению и выпуску во всех
  отраслях; `energy_transition` даёт меньшую энергию, чем `baseline`, при близком выпуске. —
  **выполнено**.
- **A4. Детерминизм.** Два прогона с одинаковым входом дают байт-идентичные JSON/Markdown и
  одинаковый SHA-256; часы и случайность не читаются. — **выполнено**.
- **A5. Агрегатность.** Ни один числовой список в отчёте не длиннее `horizon + 1`; нет
  стран/сырых рядов; `checks.no_raw_series = true`. — **выполнено**.
- **A6. Fail-closed.** Неизвестный сценарий/отрасль/параметр, кривой `key=value`, значение вне
