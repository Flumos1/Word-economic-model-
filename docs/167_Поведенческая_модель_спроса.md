# 167. Поведенческая модель спроса (G4-B, MVP)

Дата: 2026-11-17. Задача `task-48` (G4-B). Статус: **RESEARCH_ONLY**, `admission=false` — это
прототип поведенческой модели, **не прогноз**, не оценка эффекта шока и не инвестиционная
рекомендация. Реализация: [src/amfe/world/demand_behavior.py](../src/amfe/world/demand_behavior.py)
(SHA-256 `02c54d9b3add8fcb…`); тесты:
[tests/test_demand_behavior.py](../tests/test_demand_behavior.py) (26 тестов, SHA-256
`2e6e12219796b6ea…`); reduced-form канал, который модель может дополнить:
[src/amfe/markets/demand.py](../src/amfe/markets/demand.py) + [docs/159](159_Количественный_канал.md).

Модель заменяет (опционально, по флагу) эластичностный reduced-form `ΔQ/Q = ε·Δp` на явную
поведенческую задачу домохозяйства (CES-корзина + межвременное CRRA-потребление) и фирмы
(CES-замещение энергия/добавленная стоимость). Числа **по умолчанию не меняются**: флаг
`demand_dispatch(..., mode=...)` по умолчанию оставляет reduced-form результат побитово тем же
(проверено тестом).

## 1. Зачем

`docs/159` §8 прямо называет следующим шагом «добавить замещение и доходный эффект — это уже
поведенческая модель, отдельный трек», а `docs/164` (G4) требует для поведенческой модели спроса
**OOS/эластичности из данных, а не допущения**. Этот MVP закрывает первую половину — исполняемую
поведенческую структуру с явными допущениями и проверяемой арифметикой; вторая половина
(калибровка/валидация на данных) — план в §7 и **не выполнена**.

## 2. Уравнения

### 2.1. Домохозяйства: CES-корзина и CRRA во времени

Группы спроса `i ∈ {energy, transport, manufacturing, services}`; цены `p_i,t` заданы экзогенно
(цена = 1 в базе). CES-полезность и индекс цен с эластичностью замещения `σ_h`:

```
U(C) = ( Σ_i α_i^(1/σ_h) C_i^((σ_h-1)/σ_h) )^(σ_h/(σ_h-1))
P_t  = ( Σ_i α_i p_i,t^(1-σ_h) )^(1/(1-σ_h))
q_i,t = α_i (p_i,t / P_t)^(-σ_h) C_t
```

Калибровка на базу: `α_i =` доля группы в базовой корзине домохозяйства, `Y =` базовый месячный
номинальный доход; при неизменных ценах `q_i = α_i Y` (точное совпадение с базой).

Межвременной выбор — CRRA с эластичностью межвременного замещения `eis`, дисконтом `β` и реальной
ставкой `r_m` (месячная из годовой):

```
max Σ_t β^t C_t^(1-1/eis)/(1-1/eis)
s.t. Σ_t P_t C_t / (1+r_m)^t = W + Σ_t Y / (1+r_m)^t
C_t = C_0 (β (1+r_m))^(eis·t),   C_0 из бюджетного ограничения
```

`W` — начальное номинальное богатство (доля месячного дохода, по умолчанию 0); `β` по умолчанию
`1/(1+r_m)`, поэтому базовая траектория потребления плоская. Шок цены действует `shock_duration`
месяцев (по умолчанию — весь горизонт, «постоянный» шок); временный шок сглаживается через
бюджетное ограничение.

### 2.2. Фирмы: CES энергия / добавленная стоимость

Выпуск фиксирован (частичное равновесие); фирма минимизирует затраты CES-связки энергии `E` и
добавленной стоимости `V` с эластичностью `σ_f` и базовой долей энергии в затратах `a_E`:

```
P_f,t = ( a_E p_E,t^(1-σ_f) + (1-a_E) )^(1/(1-σ_f))
E_t / E_0 = (p_E,t / P_f,t)^(-σ_f)
```

Прочие промежуточные входы в MVP не реагируют (явное ограничение).

### 2.3. Агрегация и трение

Базовая величина каждой группы делится на домохозяйственную и фирменную части допущением
`firm_share_by_group`; спрос группы — сумма частей. Медленная подстройка («привычки/контракты») —
тоже допущение: отклонение от базы масштабируется `λ_m`, где `λ_1 = short_run_fraction`, и к
месяцу `ramp` `λ = 1`:

```
q_i,m = q0_i + λ_m (q_model_i,m − q0_i),
λ_m = min(1, srf + (1−srf)(m−1)/(ramp−1))
```

Долгосрочная реакция — поведенческая (эндогенная из CES/бюджета), краткосрочная — поведенческая
реакция, сжатая трением; это заменяет линейный ramp reduced-form, но не выдаёт себя за его оценку.

## 3. Параметры (все — допущения `source_class=assumption`)

| Параметр | Значение по умолчанию | Смысл / источник |
|---|---|---|
| `sigma_household` | 0.80 | CES-замещение групп в корзине домохозяйства |
| `sigma_firm` | 0.35 | CES-замещение энергия/добавленная стоимость у фирм |
| `eis` | 0.50 | межвременная эластичность CRRA |
| `beta_monthly` | `1/(1+r_m)` (≈0.9979) | дисконт; по умолчанию плоская базовая траектория |
| `real_interest_rate_annual` | 2.5% | реальная ставка в бюджетном ограничении |
| `horizon_months` | 6 | горизонт отчёта |
| `ramp_months` | = horizon | горизонт трения |
| `short_run_fraction` | 0.28 | доля долгосрочной реакции в 1-й месяц |
| `shock_duration_months` | = horizon | длительность шока (permanent по умолчанию) |
| `energy_cost_share` | 0.05 | доля энергии в затратах фирмы в базе |
| `firm_share_by_group` | energy 0.55, transport 0.45, manufacturing 0.50, services 0.20 | доля фирменного/промежуточного спроса в базе |
| `initial_nominal_wealth` | 0.0 | богатство в месяцах дохода |

**Почему `sigma_household=0.8` и `sigma_firm=0.35`?** Это не оценки. Они выбраны так, чтобы при
демонстрационной базе (энергия/транспорт/промышленность/услуги = 1/1/3/5) аналитическая
долгосрочная эластичность энергии была ≈ −0.55, а краткосрочная (через `short_run_fraction`) —
≈ −0.15, т.е. совпадала по порядку с допущениями reduced-form `docs/159` — **калибровочный якорь
для непрерывности интеграции, а не проверка и не оценка**. Аналитические формулы:

```
домохозяйство:  ε_h,i = -σ_h (1 - s_i) - s_i          (s_i — доля группы в корзине домохозяйства)
фирма (энергия): ε_f  = -σ_f (1 - a_E)
агрегат (энергия): ε = (1-w_E) ε_h,E + w_E ε_f        (w_E — фирменная доля базы энергии)
```

Для демо-базы: `ε_h,E ≈ −0.814`, `ε_f ≈ −0.333`, агрегат ≈ **−0.549** (≈ reduced-form −0.55);
краткосрочная ≈ −0.549·0.28 ≈ **−0.154** (≈ reduced-form −0.15). Для прочих групп поведенческие
эластичности существенно больше по модулю, чем reduced-form (например, services ≈ −0.92 против
−0.12) — это видимое содержательное расхождение моделей, а не ошибка.

## 5. Интеграция как необязательный режим (флаг)

Новый модуль не меняет поведение по умолчанию: никакие существующие вызовы/числа не меняются.
Интеграционная точка — `demand_dispatch`, режимы `reduced_form` (по умолчанию) и `behavioral`:

```python
from amfe.world.demand_behavior import demand_dispatch, behavioral_demand_response

# по умолчанию — ровно прежний reduced-form результат (тот же dict, без обёрток)
response = demand_dispatch(price_changes, base_quantities, groups)

# опционально — поведенческая MVP
behavioural = demand_dispatch(price_changes, base_quantities, groups, mode="behavioral")
# или напрямую, с явной конфигурацией параметров-допущений
behavioural = behavioral_demand_response(price_changes, base_quantities, groups, config=...)
```

Выход поведенческой модели повторяет структуру reduced-form (`aggregate` / `monthly` / `by_sector`
с `delta_short`/`delta_long`/`relative_*`), поэтому её можно подключить в `tools/quantity_bridge.py`
как альтернативный режим **отдельным решением** (сам инструмент в этой задаче не менялся).
Планируемая интеграция: параметр `--demand-model reduced|behavioral` + отчёт с обеими цифрами и
явной пометкой, что это разные модели, а не «уточнение»; combined output остаётся линейным по
Leontief и не смешивается с legacy-прокси.

## 7. Калибровка vs предположения и план валидации

**Что дано данными:** базовая величина/структура спроса (аргумент `base_quantities`/`groups`) и
цены/Δp из ценового моста (docs/152/159). **Что является допущением и не оценено:** все σ, `eis`,
`β`, `r`, доли фирменного спроса, `energy_cost_share`, трение `short_run_fraction/ramp`. G4-критерий
(«эластичности из данных») **не выполнен** — поэтому `RESEARCH_ONLY`.

План валидации (для G4, не обещание):
1. Оценить `σ_h`, `σ_f` и доли по данным (панель спроса/цен, IV/структурные оценки; литературные
   интервалы как prior), а не подбирать на демо-базе.
2. Взять PIT-ценовые шоки и проверить направление/масштаб на эпизодах 1990/2019/2022 (docs/158/165),
   отдельно кратко- и долгосрочно; это OOS-проверка, а не подгонка.
3. Предрегистрировать сетку параметров и сценарии до прогона (docs/169), отчёт с digest, без
   выбора «лучшего» задним числом.
4. Сравнить поведенческий канал с reduced-form как две модели (не «уточнение»), включить
   чувствительность к параметрам; documented decision, какие числа идут в продукты (если вообще).
5. Расширения: неопределённость/ожидания, ограничения заимствования и богатство (чтобы EIS влиял
   на масштаб), предложение/обратные связи, фирменный канал для неэнергетических входов.

## 8. Ограничения

1. **MVP/RESEARCH_ONLY**, параметры — допущения, не оценки; G4 не пройден.
2. **Частичное равновесие:** цены заданы, выпуск фирм фиксирован, нет предложения, ожиданий,
   обратных связей и равновесия.
3. **Фирменный канал — только энергия**; прочие промежуточные входы в MVP неизменны.
4. **Межвременной канал ограничен:** при постоянном номинальном доходе и `β=1/(1+r)` EIS влияет
   на профиль, но не на масштаб агрегатной реакции; нужны богатство/ограничения заимствования,
   чтобы EIS стал полноценным каналом.
5. **Трение** (`short_run_fraction/ramp`) — допущение; это не структурная модель привычек.
6. **Нет калибровки на реальных данных и OOS**; демо-числа §4 иллюстративны и не являются оценкой
   эффекта шока; reduced-form сравнение — диагностика, не валидация.
7. RC-расхождения с reduced-form по неэнергетическим группам (services и т.п.) содержательны;
   модель не обязана воспроизводить reduced-form.
