## 1. Короткий ответ

> **`WEAK_SUPPORT_MAE_ONLY`, `validated=false`.** На четырёх публичных эпизодах модель угадывает
> **направление 8/8** (все шоки supply-negative — это легко и не дискриминативно),
> **попадает в диапазон 1/8** (12,5%), **MAE середины 0,172** против **0,236** у наивного
> «цена не изменится» (улучшение +0,064 п.п.), среднее смещение **−0,159 п.п.** (систематическая
> недооценка роста). Вывод: диапазоны прототипа **слишком узкие**, магнитуды **недооценены**;
> это честная констатация ограничений, а не «валидация модели».

## 2. Что именно проверяется

Валидация не переписывает модель: берутся четыре документированных эпизода, к ним кодируются
**публичные приближения** фактических изменений цен сои/шрота и **допущения** о размере шока
(`source_class="assumption"`), затем прогоняются публичные компоненты агро-модуля
(`balance → solver → диапазоны цен → проекция Африки`) и мост G2 (`tools/agri_bridge.py`,
read-only). Считаются:

- **направление** — знак середины предсказанного диапазона совпадает со знаком факта;
- **покрытие диапазона** — факт внутри предсказанного low/high;
- **MAE середины** и относительная ошибка (середина используется только для арифметики оценки;
  модуль сам выдаёт диапазон, а не точку);
- **наивный бейзлайн** — «изменение 0», то есть random-walk;
- **`where_worse`** — эпизоды/товары, где модель хуже наивного, не попала в диапазон или
  пере-/недооценила величину.

Вердикт и `validated=false` зашиты в отчёт; никаких claims о точности прогноза или допуске.

иллюстрация переноса ценового шока на импортёра, а не прогноз.

## 6. Ограничения

1. **Факты — округлённые публичные приближения**, а не лицензированные PIT-ряды; ошибки считаются
   против приближений, а не первоисточников.
2. **Шоки — допущения** (урожайность/экспорт/замещение), не оценённые декомпозиции; модель не
   подгоняется под факты (иначе это была бы калибровка, а не валидация).
3. **Четыре эпизода**, все supply-negative → направление не дискриминирует модель; ни
   cross-validation, ни OOS, ни оценки значимости нет.
4. **Середина диапазона для MAE — арифметика оценки**: модуль выдаёт диапазон, а не точку; MAE
   не превращает результат в точечный прогноз.
5. **Мост — ценовой канал** (docs/153): объёмы фиксированы, африканский агрегат иллюстративен и не
   выводится из MRIO; количественного канала в этой валидации нет.
6. **Структура затрат — 2011 год** (OECD ICIO 2016 edition): старые коэффициенты; переход на 2025
   изменит числа, но не метод.
7. **Агро-модуль — assumption-based прототип** (docs/148): уровни и эластичности не откалиброваны
   по реальным данным.
8. **Не допуск**: `validated=false`, в реестр модулей не заводится, протокол/предрегистрация не
   применяются; никаких claims о forecast accuracy.

## 7. Воспроизведение

```powershell
python tools/agri_validation.py                    # реальный кэш моста, если он есть
python tools/agri_validation.py --synthetic-bridge # офлайн-синтетическая структура затрат
python tools/agri_validation.py --json --no-write  # отчёт в stdout, без записи
python tools/agri_validation.py --self-test        # самопроверка инвариантов
python tests/test_agri_validation.py               # 15 тестов
```

Коды возврата: `0` — отчёт собран; `2` — fail-closed (битый/отсутствующий эпизод, недоступный мост
без `--synthetic-bridge`, невалидные входы). Отчёт детерминирован: без `generated_at` и с digest по
содержимому. Тесты покрывают: реестр четырёх эпизодов и fail-closed по неизвестному id, упорядоченность
диапазонов и баланс эпизода (эффективная потеря = производство + ограничение экспорта), скоринг
(направление/покрытие/MAE/наивный, известные числа), чувствительность к размеру шока и экспортному
трению, полноту и согласованность метрик, согласованность `where_worse`, детерминизм, отсутствие
точечных claims и вердикт, интеграцию с мостом, Markdown-рендер, `--self-test`/CLI.
