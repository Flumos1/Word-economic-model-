# 109. T3 (рецессия): первая оценка допуска на REAL_TIME

Дата: 2026-11-12. Статус: **отчёт об оценке, допуск не присвоен** — все шесть пар
(2 кандидата × горизонты 3/6/12) остаются `CANDIDATE`. Официальные документы:
[protocols/ensemble_t3_report.json](../protocols/ensemble_t3_report.json) (сводка) и шесть отчётов
`protocols/ensemble_eval_<CANDIDATE>_T3_h<3|6|12>_v2.json`. Раннер:
[tools/run_t3_evaluation.py](../tools/run_t3_evaluation.py); тесты:
[tests/test_t3_admission.py](../tests/test_t3_admission.py).

Заявление ограничено фактическими критериями harness: C1 не пройден ни одной парой, C2 не пройден
ни одной парой, C5 пройден всеми, C4 к T3 не применяется по протоколу, C6 отсутствует
(`NO_RESOLVED_FORECASTS`). Стадия `CANDIDATE → SHADOW_TEST` не достигнута; `LIMITED_DEPLOYMENT` и
`ACTIVE` не рассматривались.

## 1. Постановка

* Цель — протокол v4, `targets.T3_RECESSION` (kind `event_probability`): событие = 1, если в
  интервале `(t, t+h]` есть хотя бы один месяц рецессии NBER (от месяца после пика до впадины),
  по хронологии, доступной на дату оценки. Горизонты — **3, 6, 12 месяцев**.
* Кандидаты (зарегистрированы до оценки, `protocols/candidates_2026-11-11.json`):
  **`ENSEMBLE_ADAPTIVE`** — основной кандидат; **`ENSEMBLE_EQUAL`** — контроль (равные веса).
  Роль каждого зафиксирована в отчёте (`candidate_role`).
* Окна (`tools/windows.py`, `origins_for`): W1 и W2 раздельно, REAL_TIME.
  W1 для T3 начинается **1996-12** (`windows.target_overrides.T3_RECESSION.W1_start`, D-131:
  винтажи ALFRED для GS10/TB3MS начинаются 1996-12-03, до этого у T3 оставался один REAL_TIME-член
  компаратора). Начала: W1 — 118/115/109, W2 — 153/150/144 для h=3/6/12; все шесть пар прошли без
  потерь: `member_failures = 0`, `candidate_failures = 0`, `actual_missing = 0`,
  `pseudo_origins_skipped = 0`, `data_class = REAL_TIME`.
* Компаратор — замороженный состав
  [protocols/comparator_composition_2026-11-11.json](../protocols/comparator_composition_2026-11-11.json),
  T3: **PROBIT_SPREAD + SAHM_RULE** (потери Brier и log_score, горизонты 3/6/12). Вероятность
  компаратора — **среднее вероятностей двух членов**, как в `tools/run_real_evaluation.py` для T3.
  Члены берутся из тех же point-in-time прогнозов, которые считает слой ансамбля
  (`member_probabilities`); раннер независимо пересчитывает членов через `amfe.forecast.forecast`
  на первых двух началах каждого окна и останавливается при расхождении > 1e-12. В этом прогоне —
  `origins_checked = 2` на окно, `max_abs_diff = 0.0` во всех 12 окнах.
* Факт — `amfe.evaluation.actuals.actual_pair('T3_RECESSION', origin, h)` (хронология NBER на дату
  оценки; для T3 вторичный факт равен первичному, `actuals.rule`).
* Допуск — `tools/evaluate.py::evaluate_admission` с `data_class='REAL_TIME'` и объявленным
  семейством Romano–Wolf из двух кандидатов (`family_size = 2`, FWER 0.10, 10 000 репликаций,
  seed 20261111), поэтому оба отчёта одной пары публикуют одинаковые adjusted p-values.
* C4 к T3 не применяется (`targets.T3_RECESSION.c4_not_applicable`: в месяц рецессии событие почти
  достоверно, условие вырождено) — в отчётах `C4: applies = false, pass = true (by protocol)`.
  C3 не реализован (негейтовый). C6 — `NO_RESOLVED_FORECASTS`: журнал будущих прогнозов пуст.
* Лицензии: в отчёты записаны только агрегаты и SHA-256-дайджесты массивов; сами прогнозы,
  вероятности и факты не сохранены (`licence_note`, docs/84, D-147).

## 3. Что именно не пройдено

* **C1 не пройден ни одной парой.** У `ENSEMBLE_ADAPTIVE` на W2 относительные потери 0.9095–0.9359,
  то есть кандидат на 6–9% лучше компаратора, но до порогов 0.7669–0.8501 далеко; на W1 кандидат
  хуже компаратора (1.008–1.098). У `ENSEMBLE_EQUAL` относительная потеря ровно 1.0 при порогах
  0.70–0.85 — C1 не проходит механически.
* **C2 не пройден ни одной парой.** На W2 у адаптивного кандидата сырые p-values 0.022–0.098
  (Brier: 0.0343/0.0976/0.0440; log_score: 0.0220/0.0790/0.0284), но после Romano–Wolf
  (family_size = 2) они становятся 0.0417–0.1117, а на W1 сырые p-values 0.579–0.862
  (adjusted = 1.0). C2 требует adjusted p < 0.10 на **W1 и W2** для каждой потери — не выполнено.
* **C5 пройден** всеми парами: кандидат не значимо хуже компаратора (p = 0.138–0.978), у
  `ENSEMBLE_EQUAL` — вырожденные p = 0.5.
* **C4** к T3 не применяется по протоколу; **C3** не реализован (негейтовый).
* **C6 отсутствует**: журнал будущих прогнозов пуст, разрешённых прогнозов 0 < 12; стадия
  `SHADOW_TEST → LIMITED_DEPLOYMENT` недостижима.

Итог: **ни одного присвоения допуска нет, статус всех шести пар — `CANDIDATE`**. Ближайшая к
прохождению часть — W2-улучшение адаптивного кандидата по обеим потерям, но оно не достигает
порогов C1 и не подтверждено на W1.

## 4. Ограничения

* **Мало событий.** Послевоенных рецессий около восьми; в окнах всего 10–29 событийных начал на
  окно. Мощность Brier/log_score-тестов низкая, доверительные выводы из p-values делать нельзя.
  Потолок для T3 по протоколу — `LIMITED_DEPLOYMENT`.
* **C6 отсутствует**, поэтому даже при гипотетическом прохождении C1/C2/C5 достижим максимум
  `SHADOW_TEST`; сейчас не достигнут и он.
* **C4 не применяется** — обычная для T3 защита от «рецессионного» смещения отсутствует по
  определению протокола.
* **Romano–Wolf на семействе из двух кандидатов** — консервативно и не учитывает будущие
  кандидаты; ошибка накапливается по парам (target, horizon, loss) и по W1/W2.
* **Порог C1 из NF-SIM** для T3 (0.7055–0.8501) получен симуляцией эквивалентных методов, а не
  наблюдаемой выборкой; при 10–29 событиях он особенно чувствителен к спецификации NF-SIM.
* **Хронология NBER на дату оценки**: факты T3 пересматриваются с задержкой объявления NBER; в
  отчёте это зафиксировано (`actuals.rule`), вторичный факт равен первичному.
* **Компаратор T3 состоит из двух членов** (минимально допустимый состав), поэтому компаратор
  менее устойчив, чем многомодельные компараторы T1/T2.
* Отчёты — `reporting_only`: harness-статусы, не решение о допуске.

## 5. Воспроизведение

```
# полный прогон: 6 пар (2 кандидата × 3 горизонта), W1+W2, ~904 с при 8 процессах
python tools/run_t3_evaluation.py --jobs 8

# быстрая проверка конвейера (по 3 начала на окно, последовательно)
python tools/run_t3_evaluation.py --max-origins 3 --jobs 0 --verify-members 1

# тесты трека (21 тест: схема отчётов, отсутствие сырых значений, согласованность статусов
# с критериями, среднее вероятностей членов, детерминизм дайджестов, no-look-ahead по окнам)
python tests/test_t3_admission.py
```

* Входы: `data/raw` (REAL_TIME-винтажи, `mode=auto`), `protocols/nber_dates.json` (хронология),
  `protocols/evaluation_protocol_v4.json`, `protocols/r3_specification.json`,
  `protocols/comparator_composition_2026-11-11.json`, `protocols/candidates_2026-11-11.json`,
  `protocols/nf_sim_thresholds.json`. Сеть не используется.
* Детерминизм: прогнозы point-in-time детерминированы, bootstrap Romano–Wolf — фиксированный seed
  20261111; повторный прогон даёт те же дайджесты массивов (проверяется тестом). Поле
  `generated_at` — единственное, что меняется между прогонами.
* Хеши frozen-артефактов, использованных в оценке, записаны в
  `protocols/ensemble_t3_report.json → frozen_artefacts`; хеши массивов (факты, вероятности
  кандидата и компаратора) — в блоках `windows` каждого отчёта.
* Записаны только агрегаты и дайджесты; сырые прогнозы/факты не сохранены (licence_note,
  docs/84, D-147).
