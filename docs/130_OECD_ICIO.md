## 3. Что должен сделать пользователь (точные шаги)

1. Браузером открыть `https://www.oecd.org/en/data/datasets/inter-country-input-output-tables.html`
   (не автоматически: OECD отдаёт 403 не-браузерным клиентам).
2. Принять **OECD Terms and Conditions**; сохранить текст условий и дату принятия в
   `data/mrio/oecd_icio/reports/terms.txt` (аудит лицензии).
3. Скачать **релиз ICIO 2025** (1995–2022, 60+ экономик × 45 отраслей, USD million) — блоки
   **1995-2000, 2001-2005, 2006-2010, 2011-2015, 2016-2022**; внутри блоков ReadMe и CSV/архивы
   по годам (точные имена — в ReadMe релиза).
4. Положить **все** скачанные файлы (zip/csv/ReadMe) в `data/mrio/oecd_icio/archive/`
   (каталог не коммитится).
5. Запустить конвертацию: `python tools/oecd_import.py --convert --year 2019`
   (несколько лет: `--year 2018 --year 2019 --jobs 2`; парсер сам определяет раскладку).
6. Проверить D1: `python tools/oecd_import.py --d1` — страны/отрасли, идентичности ≤0,1%,
   покрытие ≥80% мирового ВВП, неотрицательность.

## 4. Парсер и схема v1.1 (готовы к файлам)

`tools/oecd_import.py` реализует:

- **Три раскладки с автоопределением:** long/tidy (`Row Country`, `Row Industry`,
  `Column Country`, `Column Industry`, `Value`, `Year`), wide-матрица
  (столбцы `<ISO3>_<код>` / `<ISO3>:<код>`, строки — страна×отрасль + строки `VA`/`TLS`/`GO`),
  SDMX-CSV (`REF_AREA`/`ACTIVITY`/`OBS_VALUE`). При несовпадении — отказ с перечнем ожидаемых
  колонок (без угадывания).
- **Схема `amfe.mrio.dataset.v1.1`:** `countries`, `industries`, `years`, `units=USD_mn`, `Z`,
  `x`, `va`, `y` (только неотрицательный конечный спрос) и отдельный вектор
  **`inventory_changes`** (изменения запасов, может быть отрицательным). Строковая
  идентичность: `x = Z·1 + y + inventory_changes`; колоночная: `x = 1'Z + va`;
  глобальная: `Σva = Σ(y + inventory_changes)`. Это устраняет блокер схемы v1
  из docs/126 (WIOD упирался в отрицательные запасы).
- **D1-валидация (docs/120 §5):** ≥10 стран, ≥30 отраслей, неотрицательность Z/x/y,
  строковый/колоночный/глобальный баланс в допуске **0,1%**, покрытие ≥80% мирового ВВП.
- **Покрытие:** (а) внутренняя мера ICIO — доля мировой добавленной стоимости вне блока RoW;
  (б) кросс-проверка с World Bank GDP (current USD, файл соседнего трека
  `data/mrio/wb/wb_NY.GDP.MKTP.CD.json`, только чтение) для поимённых стран.
- **Мультипроцессорность:** `--jobs N` — один процесс на год (`multiprocessing` spawn-pool).
- **Отчёты без значений:** `reports/probe.json`, `instructions.json`, `manifest.json`,
  `d1.json` (только счётчики, хеши, допуски, покрытие; матрица Z и значения не пишутся).
- **End-to-end проверка пайплайна** (офлайн-фикстура 10×31, CSV→zip→`--convert`): датасет
  записан (400 806 байт), все проверки D1 `true`; парсер не зависит от конкретного имени файла.

## 5. Сравнение покрытия OECD / FIGARO / WIOD и рекомендация

| Критерий | FIGARO (локально готов) | **OECD ICIO 2025** | WIOD 2016 |
|---|---|---|---|
| Стран | ЕС + торговые партнёры (по годам) | **60+ + RoW** (док.) | 43 + RoW |
| Отраслей | NACE (в наборе) | **45** | 56 |
| Годы | по годам API (локально: 2019) | **1995–2022** | 2000–2014 |
| Единицы | EUR_mn → нужен FX | USD_mn | USD_mn |
| Лицензия | Eurostat reuse (проверить) | OECD Terms (принять вручную) | CC BY 4.0 |
| Доступ | API без ключа | **только браузер** | прямой файл Dataverse |
| Локальный статус | `dataset.json` 107,8 МБ, D1 PASS (docs/120, D-164) | **нет файла, парсер готов** | скачан, конвертация блокирована схемой v1 (docs/126) |
| Покрытие ВВП | поимённые страны + RoW 12,72% → 100% (docs/120) | измерится после загрузки (ожидаемо ~85% + RoW) | можно измерить после v1.1 |

**Рекомендация:**
1. **Стратегически «полный мир» — OECD ICIO** (60+ × 45, 1995–2022, свежие годы): он даёт
   максимальное покрытие и совместим с парсером v1.1; единственный недостаток — ручной шаг
   пользователя и OECD Terms.
2. **Операционно сейчас** — FIGARO: реальный датасет уже есть и D1 пройден; используем его для
   калибровки/сценариев, пока ICIO не загружен.
3. **WIOD 2016** — резерв и исторический ряд 2000–2014; после принятия схемы v1.1
   конвертируется без изменения кода (inventory_changes уже поддержан, docs/126).
4. Как только пользователь положит файлы ICIO в `archive/`, конвертация и D1 запускаются
   одной командой; отчёт `--d1` сразу покажет покрытие ВВП.

## 6. Тесты (23, все зелёные, без сети)

Определение раскладки (long/wide/SDMX), маппинг колонок, long-парсер и отказ на нечисловом
значении, wide-декодирование `<ISO3>_<код>` и пропуск пустых ячеек, чтение CSV из zip,
сборка v1.1 (порядок стран/отраслей, разделение `INV` в `inventory_changes`, отделение
конечного спроса), отказ на неизвестных кодах и отсутствующем годе, D1 PASS на
сбалансированной сгенерированной таблице 10×31, D1 FAIL при нарушенном строковом балансе,
отказ при <30 отраслях, покрытие ВВП (RoW-остаток + World Bank cross-check, порог 80%),
инструкции (блоки, каталог, причина 403), manifest без значений, офлайн-проба и sniff
HTML-ошибки как «не файл», статусы пустого корня и D1 без данных.

```powershell
python -m unittest tests.test_oecd_import -v      # 23 теста, ~1,5 с

python tools/oecd_import.py --convert --year 2019 --jobs 2   # после загрузки файлов

```

## 7. Ограничения

- **Файл ICIO не скачан**, поэтому парсер проверен на фикстурах трёх раскладок, а не на
  реальном релизе; точные имена файлов и порядок кодов отраслей уточняются по ReadMe после
  загрузки (парсер сообщит об отклонении, а не «подгонит» данные).
- OECD Terms не прочитаны и не приняты — это делает пользователь; лицензионный статус ICIO
  остаётся **неподтверждённым** до этого шага.
- Схема `amfe.mrio.dataset.v1.1` реализована в инструменте (документ + валидатор); модуль
  `src/amfe/mrio/schema.py` пока читает только v1 — интеграция v1.1 в `src/**` вне write-области
  этого трека и требует отдельного решения.
- Wayback-копия страницы не извлечена (429 rate limit); обход не применялся.
- Не коммитилось, не пушилось; frozen-файлы, registry, чужие tools не изменялись.
