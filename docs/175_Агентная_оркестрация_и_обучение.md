## 0. Зачем это

Цель — **ускорить разработку без потери честности**: больше параллельных треков, меньше
«зависших» задач, каждая цифра проверяется независимо, каждое изменение попадает в CI и в журнал.
Оркестратор — **Lead**; у него два заместителя по направлениям: научная поставка
(`evaluation-harness`) и продуктовая упаковка (`dense-vintages`).

Ограничение платформы: команда — **8 исполнителей + Lead**. Новых агентов сверх лимита не
создаём; роли переиспользуют существующих участников (см. реестр).

## 2. Конвейер задачи (как мы работаем)

```
intake (Lead) → task card → claim исполнителем → работа в своих write scopes
   → отчёт (файлы, тесты, числа, ограничения) → evidence-review (роль-ревьюер)
   → independent verification (protocol-reviewer, если научный артефакт)
   → интеграция и коммит (Lead) → CI → журнал/решение (Lead)
```

Состояния задачи: `pending → in_progress → review → integrated → completed`; `blocked` — только
с указанием конкретного блокера и владельца разблокировки.

**Правила:**
1. Один файл — один владелец в момент работы; пересечения write scopes запрещены.
2. Исполнитель **не коммитит**; коммит и пуш — только Lead.
3. Frozen-файлы (protocol v4/v5, R3, NF-SIM, comparator composition) не редактируются никем;
   изменения — только новой версией через решение владельца.
4. Каждая задача с числом обязана иметь тест и docs с ограничениями.
5. Две неудачные попытки исполнителя → Lead забирает задачу или переназначает (задача не висит).
6. Независимая проверка не может быть тем же агентом, который делал артефакт.

## 3. Task card (шаблон для постановки)

```
ID/название:
Роль/исполнитель:
Зачем (какой кейс/гейт):            # ссылка на docs/173/174, UC-xx
Входы/пины:                          # файлы, SHA, данные
Write scopes:                        # только свои файлы
Запрещено:                           # frozen/чужие файлы/коммит
Выход:                               # артефакты, тесты, docs
Критерий приёмки:                    # измеримый
Ревьюер:                             # кто проверяет
```

## 4. Definition of Done (общая)

- [ ] изменения только в своих write scopes; frozen/чужие файлы не тронуты;
- [ ] тесты добавлены и зелёные; полная регрессия не сломана;
- [ ] docs с методикой, ограничениями и **честным статусом** (нет admission claims);
- [ ] provenance: SHA-256/пин артефактов; raw-данные не в git;
- [ ] нет коммита от исполнителя; Lead интегрирует;
- [ ] короткий отчёт: файлы, тесты, числа, ограничения, что осталось.

## 5. Обучение ролей («brief» перед задачей)

Каждый исполнитель перед работой получает короткий бриф: **что читать → что можно → что нельзя →
формат отчёта → критерий**. Ниже — базовые брифы.

**evaluation-harness (наука).** Читать: protocol v4/v5, R3, docs/164/170, свой инструмент.
Можно: harness, оценки, предрегистрации, отчёты. Нельзя: менять frozen, объявлять допуск.
Формат: отчёт + tests + docs; числа с digest; статус честный (CANDIDATE/FAIL/NOT_APPLICABLE).
Критерий: воспроизводимость, отсутствие look-ahead, пины.

**protocol-reviewer (независимость).** Читать: проверяемый артефакт + его источники. Можно: только
свой docs-файл. Нельзя: править проверяемое, выдавать себя за человека. Формат: вердикт
(CONFIRMED/WITH_NOTES/NOT_CONFIRMED), таблица пунктов, расхождения с ссылками, «не проверено».
Критерий: 0 непроверенных claims без пометки; перевывод 2–3 чисел.

**baseline-models (модели).** Читать: R3, NF-SIM, docs моделей. Можно: свои src/models + tests.
Нельзя: подгонять на W2, менять протоколы. Формат: код + tests + docs (спецификация, ограничения,
code hash). Критерий: детерминизм, нет look-ahead, честный OOS.

**r2-completion (данные).** Читать: data_plan, licence_register, docs/75/108/166. Можно: свои
tools/данные-протоколы. Нельзя: коммитить raw, выдумывать значения. Формат: coverage audit,
PIT-инварианты, tests, ограничения. Критерий: PIT-даты, missing→skip, детерминизм.

**dense-vintages (продукты).** Читать: docs/171, release_check, product feed. Можно: пакеты,
release-материалы, tests. Нельзя: менять числа моделей, ослаблять проверки. Формат: пакет +
reproducibility + tests + docs. Критерий: детерминизм, fail-closed, RESEARCH_ONLY.

**multiplicity-rw (статистика).** Читать: protocol multiplicity, NF-SIM. Можно: свои tools/отчёты.
Нельзя: снижать FWER, использовать W2 для настройки. Формат: p-values/RW-таблицы, tests.
Критерий: FWER 0.10, воспроизводимость.

**accounting-core (мир).** Читать: docs/127/133/146, MRIO-схемы. Можно: src/accounts/world/
international/markets + tests. Нельзя: frozen, выдавать сценарии за прогноз. Формат: модуль +
балансы + tests + docs. Критерий: S=I+CA, ΣCA=0, детерминизм.

**licence-auditor (права).** Читать: licence_register, terms-доки. Можно: реестр, check_terms,
docs. Нельзя: юридические выводы сверх цитат, raw-данные. Формат: таблица источник→статус→цитата→
дата, расхождения, «не проверено». Критерий: 19/19 покрытие, terms-хеши или честный UNVERIFIED.

## 6. Оркестратор: ежедневный цикл

1. Открыть board: `team_task_list` — что в работе/заблокировано.
2. Проверить отчёты и review; разблокировать зависимости.
3. Интегрировать готовое: прогнать тесты, коммит, пуш.
4. Запустить CI (accounting/weekly/release-check по необходимости), проверить зелёный.
5. Обновить docs/164/173, журнал решений; закрыть/переназначить зависшие задачи.
6. Раздать следующую волну по docs/173 (task-54…59 и новые capability-треки).

## 7. Метрики ускорения (что улучшаем)

- **Cycle time** задачи (создана→интегрирована) — цель ↓.
- **Rework rate** (сколько задач вернулось с ревью) — цель ↓.
- **Failed attempts** на исполнителя (2 → Lead fallback) — цель ↓.
- **CI green rate** — цель 100% на интегрированных коммитах.
- **Provenance coverage** (артефакты с SHA/пином) — цель 100%.
- **Use-case coverage** (из 50: READY/PARTIAL/GAP → движемся к READY) — цель ↑.
