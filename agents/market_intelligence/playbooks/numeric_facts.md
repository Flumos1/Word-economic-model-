# Playbook: числовые факты из открытых источников

Для `osint-scout` и `case-writer`. Цель — числа, которые можно защитить перед CFO, а не «примерно
по памяти».

## Источники по приоритету

1. **S1:** годовой отчёт, 10-K/20-F, официальный пресс-релиз, investor presentation, регулятор.
2. **S2:** официальная статистика (EIA, IEA public, World Bank, OECD, Eurostat).
3. **S3:** отраслевая пресса — только контекст, не факт A.
4. S4/S5 — запрещены в OSINT_ONLY; фиксируются как `NOT_FETCHED`.

## Что извлекать

- добыча: `MBOED` / `MMBOED`, период, факт vs guidance;
- запасы: `BBOE`, тип (proved / proved developed / 2P), дата;
- CAPEX: `$B`, guidance vs факт;
- СПГ: `MTPA`, тракты, доля, offtake, регазификация;
- география: число стран, сегментов, активов;
- всё остальное — только если есть цитата.

## Обязательные поля факта

`label`, `value`, `unit`, `period`, `source_id`, `source_date`, `evidence` (A/B/C), `quote`.
Без `quote` факт не принимается. Без `period` нельзя сравнивать.

## Запреты

- выдумывать, округлять без пометки, смешивать guidance и факт;
- переводить `MBOED` в `MMBOED` без деления на 1000 и пометки;
- смешивать `MTPA` (СПГ) и `bcm` (газ) без формулы;
- выдавать `proved developed` за все `proved`;
- писать revenue/headcount, если этого нет в источнике;
- использовать проценты без источника;
- публиковать число без даты — оно устаревает.

## Проверка

1. Открыть первоисточник, найти цитату, скопировать <= 300 символов.
2. Записать URL, дату, класс S1–S3.
3. Сверить единицу и период.
4. Поставить evidence A (S1) / B (S2–S3) / C (агрегатор).
5. Передать `evidence-qa`; только он ставит финальный grade.
6. В кейс — `facts[]`; в базу знаний — `source_id` и запись.
