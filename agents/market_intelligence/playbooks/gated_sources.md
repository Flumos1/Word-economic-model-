# Playbook: gated-источники и законный доступ (G0–G4)

Статус: обязателен для `osint-scout`, `licensed-data`, `director` и `evidence-qa`. Дополняет
[`lawful_osint.md`](lawful_osint.md) и [`red_lines.md`](red_lines.md), не отменяя их. Режим сети —
**`OSINT_ONLY`** (`subscriptions = 0`): этот playbook даёт язык для gated-источников и порядок
**запроса доступа**, а не доступ. Пока договора/NDA нет, источник не используется.

Главный принцип: **распознать gated-источник — можно и нужно; обойти его — нельзя.** «Условно
закрытый» означает источник с законным путём доступа (подписка, institutional/academic license,
FOIA/public records, судебный реестр, закупочный портал, data room по NDA, API с ключом), а не
источник, который надо «открыть» техническими средствами.

## 1. Классификация G0–G4

| Класс | Название | Что это | Примеры | Доступ | В OSINT_ONLY |
|---|---|---|---|---|---|
| **G0** | Public | открытая публикация | сайт компании, годовой отчёт, пресс-релиз, публичная статистика, открытый судебный реестр | OPEN | собираем |
| **G1** | Registration | бесплатная регистрация организации по ToS | закупочный портал, реестр, API с бесплатным ключом после регистрации | OPEN_REGISTRATION | собираем после проверки ToS |
| **G2** | Licensed | подписка, institutional/academic license, платный API | ценовые и отраслевые БД, терминалы, платные отчёты | SUBSCRIPTION / LICENCE_REQUIRED | **только запрос**, сбора нет |
| **G3** | NDA data room | доступ по NDA и правилам комнаты | data room сделки, due diligence, закрытая презентация контрагента | NDA | **только запрос**, сбора нет |
| **G4** | Restricted / no access | доступа не существует | утёкшие базы, чужие аккаунты, инсайд, чужие ключи, «слитые» переписки | NO_ACCESS | **никогда**, только `NOT_AUTHORIZED` |

Связь с классами источников (`source_hierarchy.md`): G0/G1 — это S1–S3; G2/G3 — S4
(лицензированный датасет), G4 — S5. Класс G не заменяет класс S: первый описывает **доступ**,
второй — **силу источника** и максимальный grade. Понижение доступа не повышает grade.

## 2. Матрица «что можно / что нужно»

| Класс | Что можно без запроса | Что нужно для доступа | Кто подписывает | Что фиксируем |
|---|---|---|---|---|
| G0 | читать, цитировать (<= 300 символов), ссылаться | ничего; проверить robots/ToS | — | URL, дата, цитата, класс S |
| G1 | читать и цитировать в пределах ToS | учётная запись организации, проверка ToS (цитирование, хранение цитат, лимиты) | человек выдаёт логин в секрет-стор | `AUTHORIZED` + ToS-проверка |
| G2 | видеть открытую аннотацию (это S3/B, не S4) | договор/подписка с датой и стороной; право на производные и передачу клиенту; API key в секрет-сторе | человек/Lead, не агент | `REQUEST_PENDING` → `AUTHORIZED`/`NOT_AUTHORIZED` |
| G3 | ничего сверх публичного | подписанный NDA; правила data room; разрешение на цитату и объём | человек/Lead + юрист | `REQUEST_PENDING` → `AUTHORIZED`/`NOT_AUTHORIZED` |
| G4 | ничего | законного пути нет | — | `NOT_AUTHORIZED` + `NOT_FETCHED` |

Отдельно про **FOIA/public records**: это не «закрытая база», а законная процедура запроса
публичного документа у органа власти. Запрос оформляется по правилам юрисдикции, от имени
организации, через человека; ответ может быть отказом — тогда `NOT_AUTHORIZED`, а не «поиск
обходного пути». Агент готовит черновик и перечень документов, отправляет человек.

## 3. Рабочий процесс (7 шагов)

1. **Классифицировать.** Определить G0–G4 и S1–S5 до любого запроса. Если класс неясен — считать
   G2/G3 и не собирать до прояснения.
2. **Проверить условия.** Для G0/G1 — robots.txt, ToS, лимиты, разрешено ли цитирование. Для
   G2/G3 — есть ли уже договор/NDA у организации и до какой даты.
3. **Принять решение.** G0/G1 → сбор. G2/G3 без договора → `access_request.md` и
   `REQUEST_PENDING`. G4 → `NOT_AUTHORIZED`, вопрос закрывается как `NOT_FETCHED`.
4. **Оформить запрос.** Кто (роль, без имён), источник, класс, правовое основание, цель, срок,
   объём, что не копируем. Шаблон — [`access_request.md`](access_request.md).
5. **Передать человеку.** Маршрут: `osint-scout` → `director` → Lead/человек (юрист или закупки) →
   поставщик данных. Агент ничего не подписывает, не оплачивает и не отправляет.
6. **Записать в журнал.** Строка на каждый gated-источник: `request_id`, `role`, `source`,
   `gated_class`, `legal_basis`, `purpose`, `requested_at`, `decision`, `decided_at`, `expires_at`,
   `owner`.
7. **Собирать в пределах разрешённого.** Только то, что покрыто договором/NDA/ToS; цитата — в
   разрешённом объёме; сырые выгрузки — вне git; evidence-статус ставит `evidence-qa`.

## 4. Что запрещено (без исключений)

- Обход paywall в любом виде: кэш, архив, «текст в комментариях», копия платного отчёта.
- Обход авторизации, robots.txt, условий использования, лимитов, капчи; скрытый массовый сбор.
- Использование чужих аккаунтов, ключей, cookie; «попросить коллегу посмотреть под его логином».
- Утёкшие базы, «сливы», купленные базы, инсайд — это G4, а не «источник с риском».
- Нарушение NDA и правил data room: скачивание сверх разрешённого, цитаты без разрешения,
  передача содержимого третьим лицам.
- Покупка персональных данных, деанонимизация, социальная инженерия под видом запроса доступа.
- Давление на поставщика данных, обход отказа, повторные запросы «пока не согласятся».
- Хранение ключей, токенов и логинов в репозитории, отчёте или памяти агента.

## 5. Журнал доступа (access journal)

Журнал — доказательство добросовестности, а не бюрократия. Минимальные поля:

| Поле | Что внутри | Пример |
|---|---|---|
| `request_id` | стабильный id запроса | `AR-2026-0007` |
| `role` | роль-заявитель | `osint-scout` |
| `source` | название и владелец источника | `Price DB (vendor)` |
| `gated_class` | G0–G4 | `G2` |
| `legal_basis` | договор/NDA/ToS/FOIA со ссылкой и датой | `NDA от 2026-11-20, п. 3` |
| `purpose` | решение-релевантная цель | `проверка CAPEX-бенчмарка` |
| `requested_at` | дата запроса | `2026-11-22` |
| `decision` | AUTHORIZED / REQUEST_PENDING / NOT_AUTHORIZED | `REQUEST_PENDING` |
| `decided_at` | дата решения | `—` |
| `expires_at` | срок доступа | `2027-02-20` |
| `owner` | человек, ведущий запрос | `lead` |

Правила журнала:

- одна строка — один источник и одно основание; изменение срока — новая строка, старые не удаляются;
- в журнале **нет** ключей, токенов, логинов, персональных данных и содержимого data room;
- журнал хранится там, где это разрешено договором; в репозиторий попадают только обезличенные
  status-записи (id, класс, статус, срок);
- статус в отчёте и статус в журнале должны совпадать; расхождение — дефект для `evidence-qa`.

## 6. `NOT_AUTHORIZED`: как фиксировать

`NOT_AUTHORIZED` — это нормальный результат, а не сбой. Он означает: законного доступа нет,
источник не используется, значение не подставляется.

Где фиксировать:

1. В отчёте — строка `NOT_AUTHORIZED` с классом G и причиной.
2. В `NOT_FETCHED` — что искали, где, почему не получено, какой блокер.
3. В журнале — `decision = NOT_AUTHORIZED`, `decided_at`, кто решил.

Пример строки отчёта:

```text
Gated: source="Price DB", class=G2, status=NOT_AUTHORIZED, reason="договора нет; запрос отклонён
поставщиком 2026-11-25", blocker="нужна подписка", used=false
NOT_FETCHED: ценовой бенчмарк за 2026 — нет доступа; открытая аннотация даёт только диапазон S3/B.
```

Запрещено: заменять `NOT_AUTHORIZED` «примерной оценкой», брать похожие числа из S3 и называть их
данными G2, скрывать отказ, повторять запрос в обход решения.

## 7. Доступ, договор и режим сети

- Договор/NDA — это **право**, а не смена режима. Пока `mode = OSINT_ONLY`, класс S4 остаётся
  `DEFERRED`, даже если договор появился: снятие режима — отдельное решение человека/Lead с правкой
  `org.json`, тестов и `docs/212`.
- После снятия режима: G2/G3 используются только в пределах договора; `licensed-data` активируется;
  evidence ceiling роли не повышается автоматически — `VERIFIED` по-прежнему подписывает
  `evidence-qa`.
- Ключи и доступы: секрет-стор или переменные окружения, выдаёт человек. Агент не создаёт, не
  запрашивает и не хранит учётные данные; в отчёте — только имя источника и статус доступа.
- Суб-лицензирование, перепродажа и передача сырых данных клиенту — только если это прямо разрешено
  договором; иначе запрещено.

## 8. Evidence и цитирование

- Потолок evidence у `osint-scout` — **`PARTIAL`**, независимо от класса доступа: договор расширяет
  доступ, но не отменяет проверку `evidence-qa`.
- Цитата — не более 300 символов, с URL/идентификатором документа и датой; полные тексты платных и
  NDA-документов в репозиторий не попадают.
- G2/G3-факт без разрешения на цитату передаётся только как пересказ с пометкой ограничений
  договора; если договор запрещает пересказ — факт не передаётся, фиксируется ограничение.
- Триангуляция: ключевой факт подтверждается минимум двумя независимыми источниками; второй
  источник не может быть пересказом первого.

## 9. Чек-лист перед сбором

- [ ] класс G0–G4 определён и записан;
- [ ] для G0/G1 проверены robots/ToS/лимиты;
- [ ] для G2/G3 есть договор/NDA или оформлен access request (`REQUEST_PENDING`);
- [ ] для G4 — только `NOT_AUTHORIZED`, сбора нет;
- [ ] правовое основание и срок известны; ключи вне репозитория;
- [ ] понятно, что цитируем и в каком объёме;
- [ ] санкционная проверка не выявила запрета.

## 10. Чек-лист перед сдачей

- [ ] каждая gated-строка имеет класс, статус и запись в журнале;
- [ ] нет ни одного обхода paywall/авторизации/NDA/лимитов;
- [ ] нет ключей, токенов, логинов и персональных данных;
- [ ] `NOT_AUTHORIZED`/`NOT_FETCHED` заполнены с причиной и блокером;
- [ ] цитаты в разрешённом объёме, полных текстов нет;
- [ ] в отчёте есть `mode: osint (OSINT_ONLY)` и строка «gated: проверено»;
- [ ] `evidence-qa` может воспроизвести вывод по журналу.

## 11. Типичные ошибки

- Называть платный отчёт «публичным», потому что нашлась аннотация: аннотация — S3/B, не S4.
- Оформлять запрос на G4: законного пути нет, это `NOT_AUTHORIZED`.
- Считать `REQUEST_PENDING` разрешением и начинать сбор «пока отвечают».
- Просить у коллеги его логин: это чужой аккаунт, а не доступ организации.
- Хранить API key в `org.json` или в отчёте: ключ живёт в секрет-сторе.
- Цитировать data room без разрешения на цитату и потом «уточнять» у юриста.
- Забыть журнал: без него нельзя доказать, что доступ был законным.
