# Playbook: оценка доказательств (grade A/B/C + статус)

Два независимых измерения, их нельзя смешивать:

- **grade A/B/C** — насколько силён источник;
- **статус** `VERIFIED / PARTIAL / HYPOTHESIS / NOT_FETCHED` — что именно мы утверждаем.

Оценка ставится на строку, не на документ. Один материал может содержать строки всех статусов.

## 1. Grade

| Grade | Что это | Минимальные требования |
|---|---|---|
| **A** | первоисточник получен | ссылка/файл, дата получения, цитата, единицы измерения |
| **B** | надёжный вторичный | издание/агрегатор, дата, ссылка; ясно, чей первоисточник пересказан |
| **C** | слабый или косвенный | открытый комментарий/презентация/след; не подтверждает факт |

Grade **не** повышается за счёт: количества пересказов, авторитета автора, «все так говорят»,
внутренней оценки, похожести на правду.

## 2. Статус

| Статус | Значение | Что разрешено в тексте |
|---|---|---|
| `VERIFIED` | факт из первоисточника, grade A, есть `retrieved_at`, подпись `evidence-qa` | цитировать как наблюдение, с ссылкой и датой |
| `PARTIAL` | часть подтверждена, часть — гипотеза | цитировать с оговоркой «частично подтверждено» |
| `HYPOTHESIS` | рабочая гипотеза (внутренняя карточка, экспертное суждение, сценарий) | только как гипотезу, без цифр-фактов |
| `NOT_FETCHED` | источник допустим, данные не получены | только как «нет данных», с причиной и блокером |

`NOT_FETCHED` — не «ноль» и не «примерно». Подставлять оценку вместо отсутствующих данных
запрещено.

## 3. Таблица решений

| Grade источника | Данные получены? | Статус |
|---|---|---|
| A | да, цитата и дата есть | `VERIFIED` (после QA) |
| A | да, но цитата неполная | `PARTIAL` |
| A | нет | `NOT_FETCHED` |
| B | да | `PARTIAL` (максимум) |
| B | нет | `NOT_FETCHED` |
| C | да | `PARTIAL` только как «сигнал», в выводы не идёт как факт |
| внутренняя оценка | — | `HYPOTHESIS` |
| слух | — | не используется |

## 4. Повышение и понижение

- Повышает только `evidence-qa`; автор может понизить статус сам.
- `PARTIAL → VERIFIED` требует: grade A, `source_id`, `retrieved_at`, дословную цитату, отсутствие
  противоречий с другими A-источниками.
- `VERIFIED → PARTIAL` — при обнаружении расхождения; прошлая запись не удаляется, создаётся
  новая с пометкой `supersedes`.
- Цифра без источника понижает всю строку до `HYPOTHESIS` и блокирует кейс.

## 5. Числа

- Число допускается только с источником и датой; иначе — диапазон с пометкой «допущение» или
  отсутствие числа.
- Нельзя смешивать единицы и валюты без явного пересчёта и указания курса/даты.
- Округление не должно создавать ложной точности: «около 4,6» хуже, чем «4,5–4,7 (допущение)».
- Демо-числа из `docs/208` нельзя переносить в клиентский материал как факт о клиенте.

## 6. Примеры

Плохо:

```text
Выручка компании выросла на 12% (источник: отраслевое издание, без ссылки и даты).
```

Хорошо:

```text
[PARTIAL, grade B] Отраслевое издание сообщает о росте выручки; первоисточник (годовой отчёт)
не получен — NOT_FETCHED. Цифра в кейс не выносится.
```

Плохо:

```text
Buying center доступен, решение принимает CFO.
```

Хорошо:

```text
[HYPOTHESIS] Внутренняя карточка предполагает CFO как владельца бюджета; проверка по раскрытию
и публичным заявлениям — NOT_FETCHED (нет доступа к первоисточнику в среде).
```

## 7. Формат строки evidence

```text
| # | утверждение | grade | статус | source_id | retrieved_at | цитата/якорь | примечание |
```

Пустые `source_id`/`retrieved_at` при `VERIFIED` — дефект, возврат автору.

## 8. Связь с базой знаний

- `knowledge_base/entries/*.jsonl`: `evidence_status`, `evidence_grade`, `source_ids`.
- Правило валидатора: grade A только со статусом `VERIFIED`; `HYPOTHESIS`/`NOT_FETCHED` — grade
  `C` или пусто; `VERIFIED` требует `source_ids` и источника с проверенными условиями.
- Запись без свежести (`review_due`) не принимается: знание стареет.
