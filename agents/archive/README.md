# Архив AMFE — роль `archivist`

Статус: **RESEARCH_ONLY, admission=false**. Локальная межпроектная база знаний: методы,
источники, правовые рамки (указатели, не заключения), факт-паки и шаблоны — с провенансом,
лицензией, доступом и сроком пересмотра. Дата: 2026-11-22. Владелец: роль `archivist`.

Комплект:

| Что | Где |
|---|---|
| межпроектная база | [`knowledge_archive/`](../../knowledge_archive/README.md) |
| инструмент (единственный путь записи) | [`tools/archivist.py`](../../tools/archivist.py) |
| правила схемы | [`knowledge_archive/schema.json`](../../knowledge_archive/schema.json) |
| мандат роли | [`charter.md`](charter.md) |
| навыки роли | [`skills.md`](skills.md) |
| описание и ограничения | [`docs/223`](../../docs/223_Архивариус_и_межпроектная_база.md) |

## 1. Зачем отдельный архив

В проекте уже есть два контура памяти, и оба отвечают на другие вопросы:

| Контур | Что хранит | Чего не делает |
|---|---|---|
| `knowledge_base/` | рыночные знания сети market intelligence (сегменты, аккаунты, шаблоны кейсов) | не общий для всех проектов; не хранит методы, правовые рамки и доказательственные карточки |
| `agents/memory/*.jsonl` | журнал работы ролей: что делали, какие решения приняли | не хранит знания с лицензией и сроком свежести |
| **`knowledge_archive/`** | **межпроектные знания**: методы, источники, правовые рамки, факт-паки, шаблоны — с провенансом, лицензией, доступом и `review_due` | не заменяет `knowledge_base/`, память ролей и научный контур AMFE; не является моделью |

`knowledge_base/` и `tools/kb.py` архивариус **не трогает**: это чужой write scope. Если знание
нужно рынку — оно идёт в KB через `kb-librarian`; если оно нужно нескольким проектам — в архив.

## 2. Что внутри

```
knowledge_archive/
  README.md              # правила и команды
  schema.json            # схема записи, namespace-реестр, x-rules
  entries/seed.jsonl     # 14 записей (append-only JSON Lines)
  inbox/                 # очередь: <id>.jsonl -> validate -> merge
  context_packs/         # собранные пакеты контекста (<проект>--<тема>--<роль>.json/.md)
  index.json / index.md  # собираются tools/archivist.py index
```

## 3. Быстрый старт

```powershell
python tools/archivist.py --check                            # exit 0 / 2
python tools/archivist.py validate --json --today 2026-11-22
python tools/archivist.py search "провенанс" --namespace global
python tools/archivist.py pack --project osint --topic "границы сбора" --role osint-scout `
    --today 2026-11-22
python tools/archivist.py index --today 2026-11-22
python tools/archivist.py export --format jsonl | Select-Object -First 5   # экспорт в stdout
```

Запись не создаётся вручную в `entries/`: только `add` → `merge` (схема, TTL, провенанс и
дедупликация считаются кодом). Инструмент детерминирован (нет сети, часы не читаются),
fail-closed (дефект → exit 2, файлы не пишутся) и пишет только внутри `knowledge_archive/`.

## 4. Как войти в курс (любая модель)

1. Прочитать `agents/archive/README.md`, `agents/archive/charter.md`, `agents/archive/skills.md`.
2. Собрать пакет: `python tools/archivist.py pack --project <проект> --topic "<тема>" --role <роль> --today <дата>`
   и вставить `context_packs/<...>.md` в промпт.
3. После работы — запись через `add` (знание) и запись в память роли (журнал). Это разные контуры.

## 5. Кому архив даёт контекст

| Получатель | Что берёт | Команда |
|---|---|---|
| `osint-scout` | границы законного сбора, классы источников, журнал коллекции | `pack --project osint --topic "законный сбор" --role osint-scout` |
| `legal-claim` | правовые рамки-указатели, доказательственные карточки, порядок проверки нормы | `pack --project legal --topic "доказательства" --role legal-claim` |
| `case-writer` | факт-паки, правила переноса фактов в кейс, шаблоны | `pack --project cases --topic "факт-пак" --role case-writer` |
| `lead` | правила handoff, ограничения среды, открытые вопросы | `pack --project lead --topic "передача контекста" --role lead` |
| `evidence-qa` | границы evidence и запрещённые формулировки | `pack --project amfe --topic "evidence ограничения" --role evidence-qa` |

## 6. Границы

- Только законные источники: открытые публикации, раскрытие, регуляторная статистика,
  лицензированные БД с доступом. Обход авторизации, paywall, robots и лимитов запрещён.
- Персональные данные, контакты, ключи, пароли и сырые сторонние выгрузки не хранятся.
- Правовая запись — **указатель и порядок проверки**, а не юридическое заключение; нормы, сроки
  и статьи не выдумываются.
- Запись архива не является инвестиционной рекомендацией, прогнозом или моделью.
- Архив не коммитится и не публикуется агентом: интеграция — Lead.

## 7. Безопасность

- Секреты и ключи запрещены: валидатор ловит e-mail, телефоны, приватные ключи, токены,
  платёжные реквизиты.
- `INTERNAL`-записи не выходят за пределы AMFE; `SUBSCRIPTION`/`LICENCE_REQUIRED` требуют договора.
- Просроченная запись не удаляется: она попадает в `stale` и заменяется новой версией.
