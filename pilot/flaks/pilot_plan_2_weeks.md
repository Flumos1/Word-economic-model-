# FLAKS — план пилота на 2 недели (10 рабочих дней)

Цель: за 10 рабочих дней пройти путь «данные клиента → проверенный отчёт CFO» на 2–4 категориях и
получить решение go/no-go по объявленным критериям. Пилот не меняет модель: он проверяет, что
существующий движок (docs/184) работает на реальных данных и что отчёт отвечает на вопросы UC-13
(поставщик), UC-14 (бюджет) и UC-16 (индексация).

Статус: **RESEARCH_ONLY**, `admission=false`. Пилот не является допуском модели, закупочной
рекомендацией или инвестиционным советом.

## 1. Участники

| Роль | Кто | Что делает |
|---|---|---|
| Владелец решения | CFO / директор по закупкам | подтверждает веса, cap/floor, читает отчёт, даёт go/no-go |
| Данные | закупки / финансы клиента | заполняет шаблоны, отвечает на вопросы по выбросам |
| Аналитик | FLAKS (роль `dense-vintages`) | `--check`, разбор ошибок, прогон, отчёт, журнал |
| Приёмка | Lead | NDA, приёмка артефактов, запрет на коммит реальных данных |

## 2. Календарь

| День | Работа | Данные / вход | Результат | Критерий дня |
|---|---|---|---|---|
| 0–1 | Kickoff, NDA, согласование контура передачи | подписанный NDA, список категорий, контакт по данным | согласованный канал, шаблоны у клиента | NDA подписан; канал не публичный |
| 1 | Заполнение шаблонов, ответы на вопросы словаря | 12 месяцев факта, 2–4 категории | `suppliers.csv`, `contracts.csv` | заполнены обязательные поля; строки-примеры удалены |
| 2 | `--check` и разбор ошибок | файлы клиента | лог ошибок/предупреждений, исправленная версия | `--check` = exit 0; ошибок валидации 0 |
| 3 | Ревью качества: пропуски, дубликаты, выбросы, единицы | отчёт `quality` | список подтверждённых/исправленных строк | каждый выброс объяснён или исправлен; единицы сведены к канону |
| 4 | Воркшоп по весам и классам A/B/C | CFO/закупки | зафиксированные веса (сумма 1,0), пороги | веса подписаны; лидеры объяснимы построчно |

| 9 | Правки, повторный прогон, SHA-256 | правки данных/весов | финальные артефакты + manifest | два прогона байт-идентичны; хеши совпадают |
| 10 | Приёмка, go/no-go, удаление данных | финальный пакет | решение и журнал | критерии A1–A8 выполнены; исходники удалены по регламенту |

## 3. Критерии приёмки

| № | Критерий | Как проверяется |
|---|---|---|
| A1 | Данные приняты без ошибок валидации | `--check` → exit 0, `quality.errors = 0` |
| A2 | Схема и типы соответствуют словарю | неизвестных/отсутствующих колонок нет; все значения в диапазонах |
| A3 | Качество описано честно | отчёт содержит `missing`, `defaults_applied`, дубликаты, выбросы, единицы; каждое предупреждение объяснено |
| A4 | Анонимизация без утечек | leak-scan = PASS; в JSON/MD/DOCX нет исходных id/имён/номеров договоров |
| A5 | Воспроизводимость | два прогона с одним `--generated-at` байт-идентичны (JSON, MD, DOCX) |
| A6 | Проверки движка | `weights_sum_to_one`, `score_equals_contributions`, `tco_components_sum`, `budget_base_equals_contract_sum`, `interval_ordered` — все true |
| A7 | Отчёт отвечает на UC-13/14/16 | CFO подтверждает: есть сравнение поставщиков, бюджет по сценариям и индексация по договорам |
| A8 | Нет реальных данных в репозитории | `git status` не содержит файлов клиента; в артефактах только псевдонимы и хеши |

Дополнительно (не блокирует пилот, но фиксируется): число предупреждений качества, число
срабатываний cap/floor, расхождение бюджета с фактом на ретро-прогоне (если клиент дал факт).

## 5. Результаты пилота

1. `build/flaks_pilot/<scenario>/flaks_pilot_cfo.docx` — CFO-отчёт.
2. `flaks_pilot.md` и `flaks_pilot.json` — читаемая и машиночитаемая версии.
3. `flaks_pilot_manifest.json` — SHA-256 артефактов и входов, версия модели, сценарий.
4. Журнал решений: веса, объяснения выбросов и cap/floor, решение go/no-go.
5. Короткая записка «что заменить до следующего шага»: TARIC, OECD CRP/WGI, фактические счета и
   фрахт, данные входного контроля.

## 6. Риски и остановки

| Риск | Признак | Действие |
|---|---|---|
| Клиент присылает персональные данные/реквизиты | в файле ФИО, счета, контакты | остановить, вернуть файл, попросить удалить; в отчёт не брать |
| Нет NDA | файлы пришли раньше документов | не открывать, вернуть; пилот не стартует |
| Мало поставщиков в категории | `--check` = 2, «нужно минимум 2» | расширить выборку или объединить категории осознанно |
| Нет действующего договора | `--check` = 2 | добавить active или исключить категорию |
| Один поставщик — несколько договоров | `--check` = 2 | агрегировать до одного договора или отложить категорию |
| Выбросы не объяснены | `quality.status = WARN` | не блокирует, но фиксируется в журнале; без объяснения не использовать в решении |
| Утечка идентификаторов | leak-scan ≠ PASS | прогон остановлен; проверить шаблон и повторить |
| Не воспроизводится | хеши двух прогонов разные | остановить, найти нефиксированный вход (дата/файл) |

Пилот останавливается (без go/no-go), если: NDA не подписан; данные содержат запрещённые
категории; `--check` не проходит после двух итераций; leak-scan не PASS; реальные данные попали в
git.

## 7. Ограничения пилота

- Один договор на поставщика, 4 объявленные категории, 10 стран — см. `data_dictionary.md`.
- Валютные цены не пересчитываются по курсу; валютный риск — только через `fx_share`.
- Пошлины и риск страны — демонстрационные допущения до замены на TARIC/OECD CRP/WGI.
- Сценарии линейны; интервал бюджета — только по CPI (5–95), без нефти/фрахта/FX.
- Отчёт не заменяет юридическую проверку договора и сверку с первичными счетами.
