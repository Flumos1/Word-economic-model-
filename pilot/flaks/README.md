# FLAKS — пилот закупочной аналитики (2 недели)

Папка для обмена данными пилота: шаблоны выгрузки, словарь данных и план. Инструмент обработки —
[`tools/flaks_pilot.py`](../../tools/flaks_pilot.py), описание — [docs/189](../../docs/189_FLAKS_пилот.md).

Статус: **RESEARCH_ONLY**, `admission=false`. Это исследовательский пилот, не допуск модели, не
закупочная и не инвестиционная рекомендация. Числа в шаблонах — **примеры** (помечены «ПРИМЕР»),
они не являются реальными данными и не должны попасть в отчёт как факт.

## 1. Что нужно от клиента для старта

1. Подписанный NDA / соглашение о конфиденциальности (до передачи файлов).
2. Заполненные `suppliers_template.csv` и `contracts_template.csv` (CSV или XLSX) за последние
   12 месяцев: 2–4 категории, 2–4 поставщика на категорию, один договор на поставщика.
3. Контактное лицо по данным (без персональных данных в таблицах) и подтверждение, что выгрузка
   разрешена внутренней политикой.
4. Согласованные веса скоринга (по умолчанию 0,20 / 0,30 / 0,20 / 0,20 / 0,10) и валюта отчёта —
   EUR. Если веса другие, это фиксируется на воркшопе Дня 2.

Объём: обычно 8–50 строк поставщиков и столько же договоров. Полный журнал закупок не нужен.

## 2. Файлы

| Файл | Назначение |
|---|---|
| `suppliers_template.csv` | шаблон таблицы поставщиков: 16 колонок, 4 строки-примера |
| `contracts_template.csv` | шаблон таблицы договоров: 9 колонок, 4 строки-примера |
| `data_dictionary.md` | описание каждого поля, типов, диапазонов и справочников |
| `pilot_plan_2_weeks.md` | план на 10 рабочих дней, результаты и критерии приёмки |

Перед отправкой: **удалите строки-примеры** (все, где в `supplier_id` стоит `EX-SUP-…`) и
заполните свои. Заголовки колонок не переименовывайте: инструмент отвергает неизвестные и
отсутствующие колонки, чтобы опечатка не превратилась в тихо неверный отчёт.

## 3. Как заполнить

1. Откройте `suppliers_template.csv` в Excel/LibreOffice (кодировка UTF-8; разделитель — запятая).
2. Одна строка = один поставщик. `supplier_id` — любой стабильный код (можно уже псевдоним).
3. Заполните обязательные поля из `data_dictionary.md`; необязательные (`name`, `currency`,
   `unit`, `freight_per_unit`) можно оставить пустыми — будут применены объявленные значения по
   умолчанию, и это попадёт в отчёт качества.
4. Откройте `contracts_template.csv`: одна строка = один договор, `supplier_id` должен совпадать
   с таблицей поставщиков. Один поставщик — один договор (MVP).
5. Проверьте файлы командой:

   ```powershell
   python tools/flaks_pilot.py --suppliers suppliers.csv --contracts contracts.csv --check
   ```

   Команда ничего не пишет и печатает отчёт качества. Код 0 — данные приняты, код 2 — есть
   ошибки (файл не создаётся).

6. Полный прогон:

   ```powershell
   python tools/flaks_pilot.py --suppliers suppliers.csv --contracts contracts.csv `
     --scenario base --out build/flaks_pilot --anonymize `
     --generated-at 2026-11-19T00:00:00Z
   ```

## 4. Что будет на выходе

В каталоге `build/flaks_pilot/<сценарий>/`:

| Файл | Что внутри |
|---|---|
| `flaks_pilot_cfo.docx` | CFO-отчёт: резюме, качество данных, скоринг, TCO, бюджет, индексация, проверки, ограничения |
| `flaks_pilot.md` | тот же отчёт в Markdown |
| `flaks_pilot.json` | машиночитаемая версия (`amfe.flaks.pilot.v1`) с качеством данных и вложенным отчётом движка |
| `flaks_pilot_manifest.json` | SHA-256 всех артефактов, хеши входов, версия модели, сценарий |

Отчёт всегда содержит `status=RESEARCH_ONLY` и `admission=false`. Сценарии: `base`,
`inflation_plus_1pp`, `oil_plus_20`, `hormuz_6m`, `stress_combo`.

## 5. NDA и безопасность

- **До NDA файлы не передаются.** Канал передачи согласуется отдельно (защищённое облако клиента
  или его файлообменник); публичные ссылки и мессенджеры не используются.
- Инструмент работает **офлайн**, никуда не отправляет данные и не читает сеть.
- Исходные файлы **не копируются** в отчёт и не коммитятся: в манифесте только SHA-256, без имён
  файлов и идентификаторов поставщиков.
- Анонимизация выполняется **до** расчёта: `supplier_id`, имена и номера договоров заменяются
  последовательными псевдонимами `ANON-SUP-001`, `ANON-CT-001`, `Анонимный поставщик 001`.
  Обратное соответствие не сохраняется; в JSON/MD/DOCX исходных идентификаторов нет.
- Реальные данные нельзя класть в репозиторий. Локальная папка `pilot/flaks/inbox/` исключена из
  git; после пилота файлы удаляются по регламенту клиента.

## 6. Что НЕ присылать

- персональные данные (ФИО, телефоны, e-mail, паспортные данные, зарплаты);
- банковские реквизиты, номера счетов, платёжные поручения;
- полные тексты договоров, переписку, коммерческие предложения и прайс-листы целиком;
- секреты, токены, пароли, ключи, доступы к системам;
- данные, запрещённые к передаче внутренней политикой клиента или NDA.

Нужны только агрегированные строки по шаблону: код, страна, категория, объём, цена, логистика,
срок, OTIF, дефекты, аудит, три компоненты риска и параметры индексации договора.

## 7. Анонимизация на стороне клиента

Клиент может сам заменить коды и имена до отправки — инструмент всё равно выполнит свою
анонимизацию. Если имя поставщика не нужно, оставьте `name` пустым: отчёт использует псевдоним, а
поле попадёт в «значения по умолчанию» отчёта качества. Номера договоров можно заменить любыми
уникальными кодами; они всё равно будут переименованы.

## 8. Ограничения

- Один договор на поставщика; несколько договоров MVP не поддерживает.
- Категория должна содержать минимум 2 поставщика и минимум 1 действующий договор.
- Поддерживаемые категории и страны перечислены в `data_dictionary.md`; неизвестная страна или
  категория — ошибка, а не «молчаливый пропуск».
- Таблицы пошлин и риска страны в движке — объявленные демонстрационные допущения. До
  управленческого решения их нужно заменить TARIC и страновыми индексами (OECD CRP / WGI).
- Отчёт не заменяет юридическую проверку договора и сверку с первичными счетами.

## 9. Кто что делает

| Роль | Ответственность |
|---|---|
| Клиент (CFO / закупки) | заполняет шаблоны, подтверждает веса, проверяет выбросы и cap/floor |
| Аналитик FLAKS | запускает `--check`, разбирает ошибки, готовит отчёт и журнал решений |
| Lead | приёмка, NDA, решение go/no-go, запрет на коммит реальных данных |

Вопросы по формату — до отправки данных; после отправки меняются только шаблоны, а не код.
