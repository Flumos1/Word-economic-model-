# FLAKS — словарь данных пилота (v1.0, 2026-11-19)

Словарь описывает две таблицы пилота: поставщики (`suppliers_template.csv`) и договоры
(`contracts_template.csv`). Формат — CSV (UTF-8, разделитель `,`) или XLSX. Имена колонок
**фиксированы**: неизвестная колонка или отсутствие обязательной — ошибка, а не предупреждение.

Типы: `str` — текст, `num` — число (точка или запятая как десятичный разделитель, пробелы и
апострофы как разделители тысяч), `bool` — `TRUE/FALSE`, `да/нет`, `1/0`, `enum` — значение из
справочника. Пустая ячейка в обязательном поле — ошибка; в необязательном — значение по умолчанию
(попадает в отчёт качества).

## 1. Поставщики (`suppliers`)

| Колонка | Обяз. | Тип / диапазон | Смысл | Пример |
|---|---|---|---|---|
| `supplier_id` | да | str, уникальный | стабильный код поставщика; можно псевдоним | `SUP-001` |
| `name` | нет | str | имя/название; можно не передавать, в отчёте всё равно псевдоним | `ООО Пример` |
| `country` | да | enum, см. §3 | страна поставщика (ISO-2 или название) | `PL` |
| `category` | да | enum, см. §2 | категория закупки | `metal_rolled` |
| `currency` | нет | enum `EUR/USD/CNY`, по умолчанию `EUR` | валюта цены и договора | `EUR` |
| `unit` | нет | enum, по умолчанию единица категории | единица объёма и цены | `кг` |
| `annual_volume` | да | num > 0 | объём за 12 месяцев в единице категории | `500000` |
| `unit_price` | да | num > 0 | цена за единицу в валюте строки | `0.95` |
| `freight_per_unit` | нет | num ≥ 0, по умолчанию `0` | логистика на единицу (тот же базис) | `0.03` |
| `lead_time_days` | да | num, (0, 365] | срок поставки, дней | `12` |
| `otif` | да | num, (0, 1] | доля поставок в срок и полностью | `0.980` |
| `defect_ppm` | да | num, (0, 1 000 000] | дефекты, частей на миллион | `300` |
| `audit_score` | да | num, (0, 1] | результат аудита поставщика | `0.80` |
| `risk_financial` | да | num, [0, 1] | финансовая устойчивость (0 — низкий риск) | `0.18` |
| `risk_supply` | да | num, [0, 1] | риск перебоев поставки | `0.22` |
| `risk_compliance` | да | num, [0, 1] | комплаенс-риск | `0.15` |

`unit_price` указывается в валюте строки. MVP **не пересчитывает** валютные цены в EUR по курсу:
валютный риск учитывается только через `fx_share` в индексации договора. Поэтому валютные строки
сравниваются номинально — это ограничение движка (docs/184 §7), а не курсовая модель.

## 2. Договоры (`contracts`)

| Колонка | Обяз. | Тип / диапазон | Смысл | Пример |
|---|---|---|---|---|
| `contract_id` | да | str, уникальный | номер/код договора; можно псевдоним | `CT-001` |
| `supplier_id` | да | str | должен существовать в таблице поставщиков; ровно один договор на поставщика | `SUP-001` |
| `status` | да | enum `active/candidate` | действующий входит в бюджет; кандидат — только скоринг/TCO | `active` |
| `cpi_share` | да | num [0, 1] или % | доля индексации по CPI | `0.40` или `40%` |
| `ppi_share` | да | num [0, 1] или % | доля индексации по PPI (нефть/фрахт категории) | `0.40` |
| `fx_share` | да | num [0, 1] или % | валютная доля; допустима только для `USD/CNY` | `0.00` |
| `cap_pct` | да | num [0, 25] | верхний предел индексации, % (можно `6%`) | `6` |
| `floor_zero` | да | bool | не применять отрицательную индексацию | `TRUE` |
| `payment_days` | да | int [0, 365] | отсрочка платежа, дней | `45` |

Сумма `cpi_share + ppi_share + fx_share` не может превышать 1,0; остаток — фиксированная часть
(`fixed = 1 − сумма`). Если `fx_share > 0`, валюта поставщика должна быть `USD` или `CNY`.

## 3. Справочники

### 3.1 Категории

| `category` | Название | Единица |
|---|---|---|
| `metal_rolled` | металлопрокат (плоский прокат) | кг |
| `polymer_granulate` | полимерное сырьё (гранулят) | кг |
| `packaging_film` | упаковочная плёнка | кг |
| `contract_logistics` | контрактная логистика (фрахт) | отправка |

Принимаются также русские названия и короткие алиасы: `металл`, `сталь`, `полимер`, `гранулят`,
`плёнка`, `упаковка`, `логистика`, `фрахт`, `транспорт`.

### 3.2 Страны

| Код | Страна | Регион | Риск (допущение) | Пошлина (допущение) |
|---|---|---|---|---|
| `PL` | Польша | EU | 0,22 | 0 % |
| `DE` | Германия | EU | 0,14 | 0 % |
| `CZ` | Чехия | EU | 0,20 | 0 % |
| `IT` | Италия | EU | 0,24 | 0 % |
| `RO` | Румыния | EU | 0,28 | 0 % |
| `TR` | Турция | non-EU | 0,47 | 4,5 % |
| `CN` | Китай | non-EU | 0,42 | 6,5 % |
| `VN` | Вьетнам | non-EU | 0,51 | 8,0 % |
| `IN` | Индия | non-EU | 0,49 | 9,0 % |
| `UA` | Украина | DCFTA | 0,62 | 0 % |

Принимаются названия стран по-русски и по-английски. Риск и пошлина — **демонстрационные
допущения** движка, не TARIC и не рейтинг. До управленческого решения их нужно заменить (docs/189
§8). Другие страны в пилоте не поддерживаются: строка с `FR`, `ES` и т. п. — ошибка, пока
соответствующая строка не добавлена в модель с источником пошлины и риска.

### 3.3 Валюты и единицы

- Валюты: `EUR` (базовая), `USD`, `CNY`.
- Единицы: `кг`, `kg`, `килограмм` → кг; `т`, `t`, `тонна`, `tonne` → кг (объём ×1000, цена и
  фрахт ÷1000); `отправка`, `shipment`, `рейс` → отправка.
- Единица должна соответствовать категории: для трёх товарных категорий — масса, для логистики —
  отправка. Несовместимая единица — ошибка.

## 4. Отчёт качества

| Блок | Что показывает | Блокирует ли |
|---|---|---|
| `missing` | пустые ячейки по каждой колонке (0 = заполнено) | да, для обязательных |
| `defaults_applied` | какие необязательные поля заполнены значениями по умолчанию | нет |
| `duplicates.supplier_id` / `contract_id` | повторяющиеся коды | да |
| `duplicates.supplier_rows` | одинаковые строки поставщиков (по стране, категории, объёму, цене, сроку) | нет, предупреждение |
| `outliers` | IQR ×3 внутри категории при n ≥ 4; выброс — предупреждение | нет |
| `units` | исходные единицы, приведение к канону, коэффициенты | да, при несовместимости |
| `warnings` | логистика > 50 % цены, лид > 90 дней, OTIF < 0,80, дефекты > 5 000 ppm, аудит < 0,50, cap=0, нулевые доли индексации, валюта без `fx_share` | нет |

Статус качества `OK` — предупреждений и выбросов нет; `WARN` — есть, но данные приняты. Ошибки
валидации не попадают в отчёт: прогон останавливается до записи файлов (exit 2).

## 5. Анонимизация

- `supplier_id` → `ANON-SUP-NNN`, `contract_id` → `ANON-CT-NNN` (нумерация по сортировке исходных
  id, поэтому порядок строк в файле не влияет).
- `name` → `Анонимный поставщик NNN`; исходное имя не попадает ни в JSON, ни в Markdown, ни в DOCX.
- Обратное соответствие не сохраняется. В манифесте — только SHA-256 исходных файлов, без имён.
- После сборки выполняется leak-scan: поиск исходных id/имён в JSON, Markdown и XML DOCX; при
  совпадении прогон останавливается (exit 2), файлы не пишутся.

## 6. Ограничения полей

- Один договор на поставщика; несколько строк на одного поставщика — ошибка.
- Одна категория — минимум 2 поставщика и минимум 1 действующий договор.
- `cap_pct` ограничен 25 %; `payment_days` — 365 днями; `lead_time_days` — 365 днями.
- Максимум 5 000 строк и 64 колонки: пилот рассчитан на выборку, а не на полный журнал закупок.
- Формулы скоринга, TCO и индексации — docs/184 §3; пилот их не меняет.
