Data and security

Client data: NDA, anonymisation, local environment

The rule is simple: no files before the NDA, then a minimum of data, anonymisation and deletion after the project. Reports and API responses carry aggregates only — no raw rows and no file paths.

1. NDA before any file

  • The NDA is signed before you hand over any data; before that we only discuss decisions.
  • The channel is the client's secure cloud or file share. No public links, no open drives and no email attachments.
  • The NDA records the data scope, purpose, retention period, deletion procedure and who has access.

2. Anonymisation

  • Identifiers are replaced deterministically: ANON-SUP-NNN, ANON-CT-NNN, names become “Anonymous supplier NNN”. Numbering follows the sort order of the source ids, so row order does not affect the pseudonyms.
  • No reverse mapping is kept. The manifest holds only SHA-256 digests of the inputs, without file names.
  • Leak scan: after the build, files are checked for source names and identifiers; on a match the build stops (exit 2) and no files are written.
  • You may anonymise the data yourself — the tool anonymises it again regardless.

3. Local environment (on-prem)

  • The computation can run in your environment: a local stack with no mandatory external APIs and no cloud dependency.
  • The demo server listens on 127.0.0.1 by default; exposing it is a deliberate decision, with keys and quotas.
  • API responses pass an “aggregates only” check: if raw fields, local paths or external links would be returned, the response is refused instead of served.
  • Access keys are stored as SHA-256 digests; plaintext never appears in responses or logs.

4. No raw: what goes into a report

  • Reports and packages contain aggregates: prices, TCO, shares, ranges, country and sector effects. No raw rows, no full contracts, no observations.
  • Third-party datasets (FIGARO, WIOD, OECD, Eora and similar) are not resold or published; only derived metrics are used, under the source licence.
  • Generated files live outside git (build/); the repository holds code, documentation and aggregates, never client data.

5. Deletion

  • Source data is deleted under the client's policy and within the period fixed in the NDA; on request, earlier.
  • Deletion is confirmed in writing: what was deleted, when, and from which environment.
  • Aggregates and the report code stay with you: the result can be reproduced on your data again.

6. What not to send

  • Personal data, bank details, payment documents.
  • Full contract texts and correspondence: only parameters are needed (status, cpi/ppi/fx shares, cap, floor_zero, payment terms).
  • Complete price lists and supplier quotations.
  • Secrets, tokens, keys, passwords and system access.
  • Any data prohibited by your internal policy or the NDA.

If in doubt, do not send it: we will first discuss in the diagnostic whether an aggregate or a demo template is enough.

What is not here

  • Forms, sign-up, cookies and trackers: the site is static and email is the only channel.
  • Certifications and “compliance” the project does not have: no ISO or SOC 2 claims are implied.
  • A promise that “data never leaves your environment”: you choose the environment, and that is fixed in the NDA.
