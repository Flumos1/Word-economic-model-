# 127. Производительность мирового конвейера: data → static core → scenarios → report

Дата: 2026-11-14. Волна 8. Статус: **инструмент P2 (производительность), к admission-протоколу НЕ
подключён**; frozen-файлы, registry, существующие `tools/` и `src/` не изменялись. Код:
`tools/world_pipeline.py`; тесты: `tests/test_world_pipeline.py` (**22 OK**, ≈21 с). Данные
(read-only) в репозиторий не пишутся и не коммитятся; отчёт — только агрегаты (без матрицы `Z`).

## 1. Зачем и границы

Задача P2 — считать мировую таблицу «60+ стран × 45 отраслей» (2700+ секторов, 7,29 млн ячеек `Z`)
**за секунды**, а не часы, не теряя fail-closed и детерминизма. Конвейер — это
*производительный слой* над уже существующими ядрами (`amfe.mrio.loaders` → канонические данные,
`amfe.world.io_core` → статическое ядро, `amfe.world.sfc_core` → SFC-проверка проводок), а не новая
модель: он не меняет ни схему данных, ни критерии, ни прогнозы и ничего не публикует в admission.

Границы: статическая линейная модель Леонтьева (без цен, динамики, равновесия на рынках труда и
финансов); сценарии — сравнительная статика `x' = (I - A')^-1 y'`; реальных данных в локальном
окружении нет (`data/mrio` пуст), поэтому бенчмарк — на детерминированной синтетике 60×45 той же
размерности, что и реальная таблица P2. Появится FIGARO в `data/mrio` — тот же CLI читает её
read-only (`--dataset`), ничего не записывая в `data/mrio`.

## 2. Архитектура

```
data/mrio/<id>/dataset.json            amfe.mrio.loaders (fail-closed: schema, SHA-256, identity)
        │
        ▼
build:  Z (n×n) → scipy.sparse.csr;  y, x, va (n);  сортировка стран/отраслей (детерминизм)
        │  (синтетика: per-country блоки в ProcessPoolExecutor, стабильные SHA-seeds)
        ▼
validate: формы/знаки/финитность; две балансовые идентичности (Z1+y=x, Z'1+va=x);
          агрегация по странам; невязки и агрегаты — в отчёт (агрегаты, не матрица)
        │
        ├──► static core на СТРАНОВОМ блоке (60×60): io_core.IODataset → LeontiefCore:
        │      A = Z/x, ρ(A), Hawkins–Simon, продуктивность, балансы (плотные, дёшево)
        │
        ▼
solver: A = Z diag(x)^-1 (CSR); ρ(A) — power iteration (Перрон); splu(I - A) — ОДИН раз
        │      baseline x = (I - A)^-1 y; повторные solve на сценарий — 0,27 мс
        ▼
scenarios: energy (Δy), import (ΔA по межстрановым блокам + пересчёт ρ и новая факторизация),
           FX (удорожание импортных затрат в колонках страны + SFC-проверка переоценки)
        ▼
report build/world/world_pipeline_report.json — тайминги, невязки, ρ, HS, агрегаты Δx
          по странам/отраслям, пик памяти; сырые прогнозы/матрица не пишутся
```

Ключевое решение: **два уровня ядра**. Узкое место (LU на 2700²) — sparse; «эталонные» плотные
алгоритмы `io_core` (A=Z/x, ρ(A), Hawkins–Simon, агрегация, шоки) применяются к страновому блоку,
где они дёшевы (60×60) и служат независимой перекрёстной проверкой: полный ρ(A) считается power
iteration по 2700², а Hawkins–Simon на 60×60 подтверждает продуктивность страновой агрегации.

## 3. Параллелизм

- **ProcessPoolExecutor** для трёх стадий: генерация/сборка блоков по странам, валидация
  (построчные невязки по страновым чанкам), агрегация `P Z P'` по странам. `--workers` (по
  умолчанию `min(cpu_count, 8)`; `--workers 1` — последовательный путь без пула).
- **Детерминизм при любом числе воркеров**: (1) сид блока = SHA-256 от `(seed, страна)`, а не от
  порядка выполнения; (2) границы чанков фиксированы по странам, а не по числу воркеров;
  (3) результаты собираются в отсортированном порядке (`pool.map` сохраняет порядок задач);
  (4) `strip_timings(report)` совпадает для `--workers 1` и `--workers 2` — это проверяется тестом.
- **Цена пула на Windows**: spawn-старт ≈1,4 с на пул. Для синтетических блоков (десятки
  микросекунд на страну) параллельная сборка поэтому **медленнее** последовательной; пул окупается
  на реальных таблицах, где чанк — это разбор/валидация/агрегация тысяч значений. Оба числа
  приведены в §4, выбор — за пользователем (`--workers`).

## 4. Тайминги (60×45 = 2700 секторов, 7,29 млн ячеек, 143 069 ненулевых = 1,96 %)

Измерено на локальной машине (Windows, 8 CPU, Python 3.12, NumPy 2.4, SciPy 1.18), один процесс,
`--synthetic --benchmark --workers 1`, медианный прогон:

| Стадия | Время | Примечание |
|---|---|---|
| build (синтетика: блоки + сборка + power-series x + материализация Z) | **62 мс** | блоки 34 мс, сборка 13 мс, x 9 мс, Z 4 мс |
| validate (формы/знаки/балансы/агрегация) | **49 мс** | невязки 9,3e-11 (продукт) и 2,3e-13 (VA) |
| static core (страновой блок 60×60, io_core) | **29 мс** | ρ=0,453107995, Hawkins–Simon PASS |
| factorise `splu(I - A)` на 2700² | **2384 мс** (2,4–3,1 с под нагрузкой) | ~92 % всего прогона: fill-in разреженного LU |
| solve базовый/сценарный | **0,27 мс** | факторизация переиспользуется |
| scenario energy (5 % шок спроса, 180 секторов) | **11 мс** | только solve, Δвыпуск −16 740,46 |
| scenario import (25 % снятие межстрановых блоков) | **2557 мс** | нужна новая факторизация A′ |
| scenario fx (10 % pass-through, страна C01) | **2623 мс** | новая факторизация A′ + SFC-проверка |
| **весь конвейер (build+validate+core+solve+energy)** | **2618 мс ≈ 2,6 с** (2,6–3,4 с под нагрузкой) | |
| **весь конвейер, `--workers 4`** | **6837 мс** | пул: build 1480 мс (spawn ≈1,4 с) |

Память: **пик RSS 130,1 МБ** (energy-путь), **196–199 МБ** (import/fx: вторая факторизация) —
бюджет 2 ГБ соблюдён с запасом ≈10×. Для сравнения: плотный `Z` 2700² — 58 МБ только данными,
а плотный `(I-A)^-1` и LU — сотни МБ; sparse-представление и один `splu` держат пик в разумных
рамках.

Итог: 2700 секторов обрабатываются **за 2,6 с**, из которых 2,4 с — единственная разреженная LU;
сценарии на готовой факторизации — миллисекунды. Цель «секунды, а не часы» достигнута.

## 5. Сценарии (сравнительная статика, детерминированно)

| Сценарий | Шок | Решение | Проверки |
|---|---|---|---|
| `energy` | `Δy = −share · y` на энергетических отраслях (ключевые слова `ENERGY_KEYWORDS`, иначе первые 3 отрасли; `--energy-industries` задаёт явно) | `x' = (I−A)^-1 (y+Δy)` на готовой факторизации | Δy ≥ −y (иначе отказ), материальный остаток ≤1,4e-11 |
| `import` | `ΔA = −share · A_cross` (межстрановые коэффициенты), `A' = A + ΔA` | новая факторизация `I − A'`, `x' = (I−A')^-1 y` | `A' ≥ 0`, ρ(A′)<1 (иначе отказ), перекрёстно — `io_core.technology_shock`-эквивалент на страновом блоке (ρ, HS) |
| `fx` | удорожание импортных затрат в колонках страны: `A'[:, c] × (1+pass_through)` для межстрановых входов | новая факторизация, `x'` | `A' ≥ 0`, ρ(A′)<1; **SFC-проверка** проводки переоценки (одна претензия — один держатель и один эмитент; closing = opening + transactions + revaluation; мировая чистая стоимость = 0) |

Знаки: energy и import → Δвыпуск < 0 (−16 740 и −34 319 в бенчмарке), fx → Δвыпуск > 0
(+293,9): в количественной модели удорожание импорта повышает коэффициенты затрат, ценового
замещения нет — это раскрытое ограничение, а не прогноз.

## 6. Fail-closed (никакого частичного отчёта)

- нет данных → `BLOCKED_DATA`, exit 2 (сообщение указывает `AMFE_MRIO_ROOT`/`--dataset`, docs/121);
- невалидный/нечитаемый dataset, отрицательные коэффициенты, нарушенный баланс, `x ≤ 0` →
  `INVALID`, exit 1; отчёт не пишется;
- непродуктивная технология `ρ(A) ≥ 1`, сингулярная `(I−A)`, отрицательный спрос/выпуск,
  невозможный шок (Δy < −y, `A' < 0`, ρ(A′) ≥ 1) → `PipelineError` (exit 1);
- плотная каноническая конвертация > `DENSE_LIMIT=4096` секторов запрещена (иначе список списков
  JSON съел бы бюджет памяти);
- все проверки — в отчёте (`validation.checks`), отчёт пишется только при `status = OK`.

## 7. Ограничения (честно)

- **Реального FIGARO нет**: `data/mrio` пуст, бенчмарк — на синтетике 60×45 с плотностью 1,96 %
  (плотные домашние блоки 45×45 + 8 импортных входов на строку). Реальная FIGARO плотнее и её
  sparse-LU может быть медленнее (fill-in); время solve масштабируется с числом ненулевых, а не с
  2700². Когда данные появятся, тот же CLI даст настоящие числа — код не меняется.
- **Параллелизм на Windows spawn**: старт пула ≈1,4 с; на синтетике параллельная сборка медленнее
  последовательной, пул окупается на реальных таблицах. `--workers 1` — законный быстрый путь.
- **Вторая факторизация** в import/fx — 2,5–2,6 с: шок меняет `A`, факторизацию нельзя
  переиспользовать; для серии однотипных шоков её можно кэшировать (не сделано).
- **Сценарии — сравнительная статика**: без цен, замещения, динамики и обратных связей
  (FX/import не меняют `y`, энергетический шок не меняет технологию). SFC-проверка — только
  бухгалтерия проводки переоценки, не SFC-модель экономики.
- **Плотные эталонные алгоритмы `io_core`** (ρ, Hawkins–Simon по ведущим минорам) применяются
  к страновому блоку 60×60; для полных 2700² Hawkins–Simon подтверждается эквивалентностью
  ρ(A)<1 для неотрицательной `A` (power iteration), а не перебором миноров.
- **Тайминги зависят от машины и нагрузки**: в тестовом прогоне на той же машине (при параллельной
  нагрузке других процессов) стадия сборки иногда занимала 2,5 с вместо 34 мс; тест использует
  мягкий порог 120 с именно поэтому. Медианные числа §4 — из спокойного прогона.
- Данные не коммитятся; в отчёте нет матрицы `Z` и сырых значений — только агрегаты и хеши.

## 8. Как запускать

```powershell
# полный конвейер на синтетике 60×45 (по умолчанию пул = min(cpu, 8))
python tools/world_pipeline.py --synthetic --build --solve --scenario energy --out build/world

# бенчмарк стадий (для документации/регрессии)
python tools/world_pipeline.py --synthetic --benchmark --workers 1 --out build/world

# реальный канонический dataset (read-only; data/mrio не перезаписывается)
$env:AMFE_MRIO_ROOT = "G:\...\data\mrio"
python tools/world_pipeline.py --dataset figaro --build --solve --scenario import --out build/world

# сценарии: energy (--share), import (--share), fx (--country, --pass-through)
python tools/world_pipeline.py --dataset figaro --scenario fx --country ITA --pass-through 0.10
```

Python API: `synthetic_table(...)` → `validate_table(...)` → `WorldSolver(table)` →
`scenario_energy/import/fx(table, solver, ...)`; `run_pipeline(args)` собирает отчёт,
`strip_timings(report)` доказывает детерминизм, `write_report(report, out_dir)` пишет JSON.

Тесты: `python tests/test_world_pipeline.py` — 22 теста: сборка/балансы, детерминизм по сиду,
параллельная сборка == последовательная, валидация и fail-closed, агрегация == `io_core`,
продуктивность/Hawkins–Simon, solve == плотная инверсия, отказ непродуктивной технологии,
power iteration == плотные собственные числа, сценарии energy/import/fx (+отказы), SFC-проверка,
канонический roundtrip (запись/чтение `amfe.mrio.dataset.v1`), детерминизм отчёта по числу
воркеров, «отчёт без сырых матриц», CLI exit-коды, мягкий бенчмарк 60×45 (<120 с, пик <2 ГБ).
